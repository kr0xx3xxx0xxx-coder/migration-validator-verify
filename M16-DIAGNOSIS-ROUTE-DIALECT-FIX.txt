  [실제 영향 범위 — 사실관계]
  이 함수가 만드는 SQL 은 base SQL 의 SELECT 목록을 `COUNT(*) AS C` 로 갈아끼우고
  GROUP BY/ORDER BY/HAVING 을 제거한 형태다. LIMIT·FETCH FIRST·캐스트 같은
  방언 민감 요소를 새로 붙이지 않기 때문에, 단순 base SQL 에서는 PG 렌더와 오라클 렌더가
  실제로 동일한 문자열이 되는 경우가 많다(아래 [5-2] 실측에서 확인).
  즉 M16 은 '지금 당장 깨지는 결함'이 아니라 **잠재 결함 + 패턴 불일치**이며,
  백로그가 위험 낮음으로 평가한 것과 일치한다. 다만 base SQL 에 방언 고유 문법
  (오라클 FETCH FIRST / ROWNUM, MSSQL TOP, MySQL 백틱 등)이 들어오면 read="postgres"
  파싱이 실패해 조용히 None → SIZE_UNKNOWN 으로 열화되므로 정리 가치는 있다.

■ 4. 수정 내용
  (1) `_count_rows(conn, base_sql, dialect: str = "postgres")` — 방언을 인자로 받아
      파싱 read 와 렌더 dialect 에 그대로 위임한다. 함수 안에 DBMS 분기를 만들지 않았다.
      기본값 "postgres" 를 둔 이유: 방언을 넘기지 않는 기존 2인자 호출부
      (dev 검증 스크립트 routes_limit_dialect_secondary_check.py:334)의 동작을 그대로 보존.
  (2) `_resolve_size_class(req)` 가 **같은 파일의 기존 헬퍼 `_routing_dialect(req)`** 로
      접속 db_type → sqlglot 방언을 도출해 넘긴다. 새 매핑표/새 도출 로직을 만들지 않았고,
      공통 헬퍼 `services.sql_dependency_pruning._to_sqlglot_dialect` 단일 출처를 그대로 탄다.
  (3) 혼합 방언(src≠tgt) 규약: `_routing_dialect` 가 이미
      `s if s == t else "postgres"` 를 구현하고 있어, 기존 3개 수정본
      (agg_diff_route._chunkkey_dialect / exact_diff_route._resolve_key /
       diagnosis_route._confirm_routing)과 **동일 규약이 그대로 적용**된다.
  (4) 안전측 축약 유지: try/except 로 감싼 구조 불변 → 파싱/렌더/실행 실패 시 None 반환,
      classify_table_size(None, None) → SIZE_UNKNOWN. 등급 없이 진행되는 일은 없다.
  (5) S18 가드 파서 경로 불변: `parser.sqlglot_safe_parse.parse_one_guarded` 를 계속 사용한다
      (sqlglot 오라클 WITH 무한 hang 방어). 사용되지 않던 `import sqlglot` 만 함께 제거.
