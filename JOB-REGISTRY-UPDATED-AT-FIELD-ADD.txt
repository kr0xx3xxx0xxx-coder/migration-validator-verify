2. 수정 내용 (순수 추가 — 기존 필드 변경 0건)
────────────────────────────────────────────────────────────────────────
services/batch_execution_state_service.py

(1) 스키마
  _CREATE_SQL 끝에 `updated_at TEXT NOT NULL DEFAULT ''` 추가.
  형식은 기존 시각 컬럼과 동일한 ISO UTC "%Y-%m-%dT%H:%M:%SZ" (C 저장소 updated_at 과도 동형).

(2) 기존 DB 파일 보강 — _ensure_updated_at_column()
  `CREATE TABLE IF NOT EXISTS` 는 이미 있는 테이블의 컬럼을 늘리지 못한다.
  운영 중이던 db/migration_validator.db 를 위해 ALTER TABLE ADD COLUMN 을 1회 수행한다.
  · 경로별 캐시(_UPDATED_AT_READY)로 프로세스당 경로마다 PRAGMA 1회만 점검.
  · _connect() 안에서 수행 — 연결을 새로 열지 않으므로 D8-5 round-trip 계측값 불변
    (tests/test_d8_5_batch_ceremony_reduction.py 의 sess_rt==1 / per_call==2N 전제 유지).
  · 보강 실패해도 raise 하지 않는다(프로젝트 규칙) — 실패 시 부가 필드만 비고 기존 동작은 그대로.
  · 기존 행의 updated_at 은 '' 로 남긴다 — 0 이나 현재시각 같은 추측값을 만들어 넣지 않는다.

(3) 상태 변화 지점 배선 (6곳 — 누락 없이 전수)
  · acquire_run_lock()          생성  : INSERT 시 updated_at = started_at 과 동일 ts
  · update_progress()           진행  : per-call UPDATE 에 updated_at=?
  · _BatchProgressSession.update_progress()  진행 : 세션(단일 연결) 경로에도 동일 쿼리·동일 값
  · request_cancel()            취소  : STOP_REQUESTED 전환 시 갱신
                                        (stop_requested_at 은 '최초 요청 시각'이라 멱등 보존,
                                         updated_at 은 '마지막 변화 시각'이라 중복 요청도 갱신 — 의미 분리)
  · complete_run()              종료  : COMPLETED/STOPPED/FAILED 기록 시 갱신
  · _cleanup_stale()            stale : FAILED_INTERRUPTED 전환 시 갱신

(4) 응답 형상 대칭
  get_execution_status() 의 IDLE(실행 이력 없음) 분기에도 "updated_at": "" 추가.
  행이 있을 때는 dict(row) 로 자동 포함되므로, 두 분기의 키 구성이 어긋나지 않게 맞춘 것.

(5) 범위 밖(의도적 미시행)
  · services/job_registry.py 의 B 어댑터를 updated_at → last_progress_at 으로 매핑하지 않았다.
  · 화면 노출·F7~F10 개편에 활용하지 않았다.
  · updated_at 을 근거로 한 정체 판정/자동 개입을 넣지 않았다(모듈 헤더에 '포함하지 않음'으로 명시).
  지시 4항 그대로 — 저장소에 값이 정확히 쌓이는 것까지만.
