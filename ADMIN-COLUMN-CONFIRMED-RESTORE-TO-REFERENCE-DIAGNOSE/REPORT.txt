1. 지시 1 — 기존 '참고/제외 후보 보기' 표 구조와 합류 가능성
────────────────────────────────────────────────────────────────────────
■ 현재 구조 (ui/tabler_renderer.py, 개별 후보표 renderColSelect 내부)
  · 후보를 _splitByPlan() 이 _indPlanGroup() 기준으로 PRIMARY / REFERENCE 두 리스트로 나눈다.
  · PRIMARY = 기본 후보표, REFERENCE = <details class="ict-ref-cands"> '참고/제외 후보 보기'.
  · 두 영역은 같은 thead·같은 행 빌더(buildRow)를 쓴다 — 표가 하나이고 영역만 둘이다.
  · NON-TARGET-COLUMNS-MERGE-INTO-REFERENCE-TABLE 선례: 엔진 관문에서 떨어진 비후보
    (gb_candidacy_summary.excluded_with_reason)를 '최소 후보 객체'로 합성해 같은 표에
    합류시키는 패턴이 이미 운영 중이다.

■ 판단: 별도 하위 섹션 불필요 — 기존 표에 그대로 얹을 수 있고, 얹는 쪽이 더 낫다.
  근거:
   ① CONFIRMED 관리컬럼은 excluded_with_reason 과 달리 '진짜 후보 객체'다. 서버
      all_groupby_candidates 에 점수·프로파일·reason_text·축 근거를 전부 달고 살아 있다
      (서버는 후보를 지우지 않는다 — 지운 것은 렌더러뿐이었다). 따라서 최소 객체 합성이
      필요 없고 buildRow 가 그대로 그리면 된다.
   ② buildRow 는 이미 관리컬럼 전용 처리를 완비하고 있다 — selectable 계산에서 제외
      (체크박스 disabled + 전용 title), 배지 '정책상 제외(관리컬럼)', 사유 분기,
      기간 컨트롤/'변환 필요' 태그 억제. 즉 행을 다시 통과시키기만 하면 표시가 이미 정합하다.
   ③ 새 섹션을 만들면 '제외 사유를 보는 자리'가 화면에 두 개가 되어, 사용자가 어느 표를
      봐야 하는지 다시 헷갈린다(직전 작업이 배너를 없애고 표 하나로 합친 방향과 역행).

■ 2-4. 컬럼 분석 통합표 (수정 안 함 — 억제 유지)

  중복 노출도 불필요하다. 소스에 이 판단 근거를 주석으로 남겼다.

4. 지시 4 — 진짜 관리컬럼과의 오인 방지
────────────────────────────────────────────────────────────────────────
■ 필요하다고 판단했다. 같은 '정책상 제외(관리컬럼)' 배지를 단 두 행이 참고 표에 나란히 놓이면
  사용자는 둘을 구분할 수 없는데, 하나는 손댈 필요가 없고 다른 하나는 검토가 필요하다.

■ 근거 강도를 3분류로 나눴다 (_adminAuditExclusionKind — 새 판정이 아니라 부착된 축 값 읽기)
    VALUE   : axis_a === true            → 🔒 관리컬럼 확정 배제        (회색 중립)
    WEAK    : axis_b(명칭/코멘트) 단독   → ⚠ 이름 매칭만 — 재검토 권장 (앰버·점선)
    UNKNOWN : 축 필드 미부착(구 스냅샷)  → 🔒 배지 + '근거 상세 확인 불가' 툴팁, 경고 없음

  UNKNOWN 을 따로 둔 이유가 핵심이다. 축 정보가 아예 없는 응답까지 WEAK 로 몰면 '근거 없는
  재검토 권장' 경고가 대량 발생한다 — 판별불가를 단정으로 바꾸지 않는다는 기존 원칙과 정면으로
  어긋난다. 이 경우엔 종전 문구를 그대로 쓴다(회귀 0).
