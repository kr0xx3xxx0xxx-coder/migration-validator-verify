[4. 위험도 판단 — "순수 UI 텍스트" 인가, "라우팅/권한" 인가]
═══════════════════════════════════════════════════════════════════════

**단일 답이 아니다. 잔존 6건은 위험도가 두 갈래로 갈린다.**

▣ 그룹 A — 순수 UI 텍스트/구조. 위험도 **낮음** (❶ 명칭 6건 · ❷ 헤더 2건 · ❹ 배지 주석 · ❺ 헤더 UI)
  · 변경 대상은 `_MV_PAGE_HEADERS` 의 문자열 리터럴과 `<li>` 내부 텍스트뿐.
  · 라우팅 키(tab name)는 건드리지 않으므로 URL hash·localStorage `mv_active_tab`·
    `_persistActiveTab`·딥링크가 전혀 영향받지 않는다.
  · 권한과 무관. 인증은 `BasicAuthMiddleware` 가 **전 라우트 일괄 적용**이고, 메뉴 항목별
    권한 분기·역할 기반 노출 제어는 코드에 **존재하지 않는다**(메뉴 = 단순 `showTab` 호출).
    즉 메뉴를 고쳐도 접근 통제에 구멍이 생길 수 없다.
  · 되돌리기 쉬움(문자열 1:1 치환).
  · 유일한 주의점 : 메뉴 라벨을 판정 기준으로 삼는 e2e 스크립트
    (`scripts/dev_e2e/left_menu_usage_audit_verify.py`, `left_menu_dead_link_precise_verify.py`,
     `left_menu_dashboard_group_reorder_verify.py`, `job_dashboard_stage3_menu_capture.py`)가
    **라벨 정확일치로 노드를 찾는다**. 라벨을 바꾸면 이 4개 스크립트가 깨질 수 있으므로
    라벨 변경 시 스크립트 기대값 동시 갱신이 필요하다.

▣ 그룹 B — 라우팅. 위험도 **중간** (❸ `showTab('single')` 3곳)
  · 이건 텍스트 정리가 아니라 **동작 결함 수정**이다. 고치면 지금까지 백지가 되던 경로가
    실제로 개별검증 화면을 열게 되므로 **동작이 바뀐다.**
  · `'single'` → `'analyze'` 치환은 1단어지만, 부작용 3개를 동반한다:
      (a) 12375행 수정 시 `batchShowRowDetail` 경유 진입이 처음으로 성공 → 그 시점에
          `showTab('analyze')` 의 `_singleEnsureGroupsLoaded(false)` 분기(7186행)가 발동한다.
          이전에는 한 번도 실행된 적 없는 조합이라 **회귀 테스트 필요**.
      (b) 7196행 수정 시 `/api/validation-policy` 가 개별검증 진입에서도 호출된다(신규 네트워크 호출 1회).
      (c) 진입 직전 채워둔 `#sqlInput`·`#batchContextBanner` 가 화면 전환 후에도 유지되는지
          실측 확인이 필요하다(1단계 상태 초기화 로직과의 상호작용 미확인).
  · 권한과는 여전히 무관하다.

▣ 종합 권고
