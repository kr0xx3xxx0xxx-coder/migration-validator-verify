2-1. services/admin_column_override_store.py  (+93행) — 프로젝트 단위 일괄 조회 API 신설
─────────────────────────────────────────────────────────────
  build_override_index(project_id, db_path=None) -> dict | None
      프로젝트의 확정 전체를 **SELECT 1회**로 읽어 색인 생성.
      { project_id, table_column:{(TABLE,COL):row}, project_column:{COL:row}, row_count }
      project_id 가 비면 None(조회하지 않음). 조회 실패는 raise 하지 않고 빈 색인 + error 필드.

  resolve_override_from_index(index, column_name, table_key, current_auto_verdict) -> dict|None
      DB 미접속 **순수 함수**. 우선순위(TABLE_COLUMN > PROJECT_COLUMN > 자동판정)와 STALE 계산은
      기존 resolve_override 와 같은 단일 출처(evaluate_staleness)를 그대로 쓴다 — 판정 규칙을
      두 벌 두지 않았다. 기존 resolve_override / get_override 는 **한 줄도 바꾸지 않았다**.

2-2. services/candidate_subtype_service.py  (+35/-9행) — 조회 방식 전환(판정 로직 불변)
─────────────────────────────────────────────────────────────
  apply_admin_column_overrides(..., override_index=None) 인자 추가.
    ① 주입 색인이 있고 project_id 가 일치하면 그 색인으로 해결(조회 0회).
    ② 주입 색인이 없으면 **이 호출 한정으로 1회만** 색인을 만든다.
       이 함수는 한 테이블의 후보 전체를 한 번에 받으므로, 컬럼마다 resolve_override 를 도는
       기존 방식(컬럼당 최대 2회 connect+SELECT)보다 항상 적다 — 컬럼 M개 기준 2M회 → 1회.
       (개별검증 경로도 이 개선을 그대로 받는다.)
    ③ 다른 프로젝트의 색인이 섞여 들어오면 쓰지 않는다(교차 오염 차단 — 실측 검증됨).
  덮어쓰기 규칙 / *_auto 보존 / note_tags 처리는 **전혀 건드리지 않았다**.
