1. 무엇이 문제였나
────────────────────────────────────────────────────────────────────────
진단(PROGRESS-TRACKING-INSTRUMENTATION-OVERHEAD-DIAGNOSE, docs/PROGRESS_TRACKING_
INSTRUMENTATION_OVERHEAD.md §4-3)이 실측으로 확정한 내용이다. 상세비교 두 엔진
— services/exact_diff/pk_range_chunk.py:175, services/exact_diff/agg_contribution.py:551 —
이 실행 시작부터 종료까지 전 구간 동안 tracemalloc 을 켜 두고 있었다. tracemalloc 은
'모든 메모리 할당'을 추적하므로 행 단위 계측보다 촘촘하다. 그렇게 얻는 값은
metrics.peak_python_mb 단 하나였다.

비용은 진단이 250,000행 A/B 로 이미 측정해 두었다. OFF 1.052초 vs ON 7.585초
(Δ +6.533초, +620.7%). 더 중요한 관찰은 이 비용이 DB read 대기로 희석되지 않는다는
점이었다 — read 대기를 0/0.5/2.0/4.0초로 주입해도 Δ 는 +9.5 ~ +10.4초로 거의 일정했다.
즉 read 가 길어지면 '비율'만 작아 보일 뿐 절대 비용은 그대로 남는다.

진단의 권고는 두 가지였다. ① 기본 OFF 토글 또는 ② 첫 청크만 샘플링. 이번 작업은 ①을
택했다. 값 하나를 얻기 위한 계측이라 '가끔 켜서 본다'가 정확한 사용 방식이고, 샘플링은
"어느 구간이 샘플됐는지"라는 새 해석 문제를 만들기 때문이다.

3. 실측 — 진단의 +620% 가 이번 서버에서도 재현되는가
────────────────────────────────────────────────────────────────────────
진단은 tracemalloc 을 monkeypatch 로 no-op 화해 A/B 했다. 이번에는 monkeypatch 없이
실제 운영 코드 경로(설정 토글)만 바꿔 같은 A/B 를 돌렸다. 250,000행 · 불일치율 0.8% ·
chunk 50,000 · OFF↔ON 3회 교차(순서 편향 제거) · 중앙값.

  pk_range_chunk    OFF 1.084 s | ON 7.795 s | Δ +6.711 s (ON 이 +619.30% 느림)
  agg_contribution  OFF 0.950 s | ON 10.067 s | Δ +9.118 s (ON 이 +960.19% 느림)

진단이 기록한 +620.7% 가 사실상 그대로 재현됐다(+619.30%). 직전 예비 측정에서도
+578.48% / +999.60% 로 같은 자릿수였다. agg_contribution(스트림 엔진)은 진단이 수치를
남기지 않았던 쪽인데, 오히려 배율이 더 컸다 — 이 엔진은 행마다 dict/Decimal 객체를
만들기 때문에 할당 추적의 표적이 더 넓다.

OFF 로 바꿔서 정상적으로 빨라지는가: 그렇다. 위 수치의 OFF 쪽이 신규 기본값이다.
250,000행 기준 엔진당 6.7 ~ 9.1초가 사라진다.

같은 실행에서 판정이 바뀌지 않았음도 함께 확인했다. counts(missing_migration /
value_mismatch / reimport_pks / reimport_total / excluded_target_only / target_only_stored /
mismatch_limit_stopped)가 ON/OFF 완전 일치, 스트림 엔진의 total_reimport_pks·status 도 일치.

증적: 01_ab_measure_250k.log

7. 비판적 검토 — 이 변경이 만드는 위험
────────────────────────────────────────────────────────────────────────
- 메모리 회귀를 '상시' 관측하지 못하게 된다. 지금까지는 모든 run 이 peak 을 남겼으므로
  exact_diff_runs.db 에 힙 추이가 자동 축적됐다. 앞으로는 None 이 쌓인다.
  대응: 토글 ON 경로를 그대로 남겼고(C3 확인), 켜서 측정하는 harness 2개를 제공했다.
  메모리 계약 자체는 test_reimport_stream §58 이 계속 지킨다.
- 과거 run 과 신규 run 의 metrics 형태가 달라진다(수치 vs null). 표시 소비처가 없어
  화면 영향은 0 이지만, 나중에 이 값을 대시보드에 올린다면 "None = 미측정"을 반드시
  구분해 표기해야 한다("0MB"로 보이면 거짓 정보가 된다).
- 설정 저장소가 아직 코드 기본값뿐이다(execution_settings 는 DB 저장이 없다). 운영 중
  토글을 바꾸려면 override_group 호출 또는 재기동이 필요하다. 이번 범위에서 편집 UI 는
  만들지 않았다 — 기존 D7-20 의 HOLD 정책을 그대로 따랐다.
- 남은 우선순위: 진단 5-2 의 2순위(chunk_checkpoint._conn() 의 매회 DDL 재실행 제거,
  8.11ms → 1.39ms)는 이번 작업 범위 밖이며, 별건 세션이 0ecd52a 로 수행했다.
