[1-1] PostgreSQL — services/db_statistics_service.py:_fetch_postgres_key_metadata_impl (467~530행)
  pg_constraint → pg_index 조인으로 그 제약을 뒷받침하는 인덱스의 indisvalid·indisready 를 직접 확인.
    LEFT JOIN pg_namespace pgn  ON pgn.nspname = tc.constraint_schema
    LEFT JOIN pg_constraint pgc ON pgc.connamespace = pgn.oid AND pgc.conname = tc.constraint_name
    LEFT JOIN pg_index pgi      ON pgi.indexrelid = pgc.conindid
    SELECT ... (pgi.indexrelid IS NOT NULL AND pgi.indisvalid AND pgi.indisready) AS indexed
  근거: PostgreSQL 은 PK/UNIQUE 제약이 항상 인덱스를 동반하도록 엔진이 강제해 실무상 거의 항상 True 지만,
  "짐작"이 아니라 카탈로그로 "확인"한 True 로 바꿨다(1:1 조인, fan-out 없음).

[1-2] Oracle — services/db_adapters/oracle.py:fetch_key_metadata (512~584행)
  ALL_CONSTRAINTS.INDEX_NAME(제약이 실제로 참조하는 인덱스명) 을 ALL_INDEXES 에 LEFT JOIN 해 STATUS 확인.
    SELECT cc.column_name, c.constraint_type, c.constraint_name,
           COUNT(*) OVER (PARTITION BY c.constraint_name) AS col_count, i.status
    FROM all_constraints c
    JOIN all_cons_columns cc ON c.owner=cc.owner AND c.constraint_name=cc.constraint_name
                             AND c.table_name=cc.table_name
    LEFT JOIN all_indexes i ON i.owner=c.owner AND i.index_name=c.index_name
    WHERE UPPER(c.table_name)=:1 AND c.constraint_type IN ('P','U')
    indexed = bool(status) and status.upper()=='VALID'
  근거: 오라클은 파티션 인덱스 UNUSABLE, 제약 DISABLE 시 기본 인덱스 drop 등으로 "제약은 있는데 인덱스는
  없는" 상태가 실제 발생한다(§3 실측으로 재현).

[1-3] MySQL — services/db_adapters/mysql.py:fetch_key_metadata (151~232행)
  EXISTS 서브쿼리로 (테이블,컬럼,UNIQUE 인덱스) 조합이 information_schema.statistics 에 실재하는지 확인.
    EXISTS (SELECT 1 FROM information_schema.statistics s
            WHERE s.table_schema=DATABASE() AND UPPER(s.table_name)=%s
              AND UPPER(s.column_name)=UPPER(kcu.column_name) AND s.non_unique=0)
  이름이 아니라 (테이블,컬럼,non_unique=0) 매칭이라 여러 인덱스가 겹쳐도 EXISTS 로 fan-out 없이 단일값.

[1-4] MSSQL — services/db_adapters/mssql.py:fetch_key_metadata (226~314행)
  sys.key_constraints(제약 → unique_index_id) 를 sys.indexes 와 조인해 is_disabled 확인(ALTER INDEX ...
  DISABLE 로 제약은 살아있고 인덱스만 비활성화되는 SQL Server 특유 상태를 잡는 유일한 방법 — information_
  schema 에는 활성화 여부 정보가 없다).
    CASE WHEN EXISTS (
      SELECT 1 FROM sys.key_constraints kcst
      JOIN sys.indexes ix ON ix.object_id=kcst.parent_object_id AND ix.index_id=kcst.unique_index_id
      JOIN sys.tables t   ON t.object_id=kcst.parent_object_id
      WHERE kcst.name=tc.constraint_name AND UPPER(t.name)=? AND ix.is_disabled=0
    ) THEN 1 ELSE 0 END AS indexed
  라이브 SQL Server 인스턴스 부재(기존 fetch_key_metadata 와 동일 제약) — sqlglot tsql 파서로 문법 유효성만
  확인, 단위테스트(가짜 커서)로 배선·집계 규칙 고정.
