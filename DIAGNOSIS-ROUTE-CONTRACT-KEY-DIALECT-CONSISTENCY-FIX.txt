■ 3. Before/After 실측 (지시 3 — 실 DB 불가 → 대체 방식, 명시)
  내부망 복구 여부 먼저 확인 → 전부 단절:
    Oracle_asis 20,233ms DPY-6005 / Oracle_tobe 20,009ms DPY-6005
    PG_Inter_asis 10,029ms timeout / PG_Inter_tobe 10,013ms timeout
    ping 192.168.0.150 → 대상 호스트 연결 불가(2/2), Neon 프리셋 4종도 서버측 거부
  대체: DB 왕복만 캡처 stub 으로 치환하고 dialect 인자를 직접 포착.
        Before 는 파일 되돌리지 않고 `git show HEAD:routes/diagnosis_route.py` 를 별도 모듈로
        로드해 같은 프로세스에서 대조(stash 금지 규칙 준수).

    BEFORE(HEAD)    oracle      chunk_key=(미전달→기본 postgres)  match_key=(미전달→기본 postgres)
    BEFORE(HEAD)    postgresql  chunk_key=(미전달→기본 postgres)  match_key=(미전달→기본 postgres)
    AFTER(작업트리)  oracle      chunk_key=oracle                  match_key=oracle
    AFTER(작업트리)  postgresql  chunk_key=postgres                match_key=postgres

  기능적 귀결(그 dialect 로 실제 렌더되는 NULL probe SQL):
    postgres → SELECT 1 FROM ... WHERE ID IS NULL LIMIT 1              ← 오라클 실행 불가
    oracle   → SELECT 1 FROM ... WHERE ID IS NULL FETCH FIRST 1 ROWS ONLY
  혼합 방언(src=oracle·tgt=postgresql) → postgres 유지(기존 _routing_dialect 규약 그대로).

  한계 명시: 오라클 DB 에서 CHUNK_KEY 가 실제 확정되는지는 이번에 실측 못 함(내부망 단절).
            동일 함수·동일 probe 의 오라클 실측은 07cd4d0 에서 완료된 상태라 새 미지수는 없음.
