2. 요구사항 ② — 3단계 '처리시간' 원본/목적 분리 (조사 → 미적용)
────────────────────────────────────────────────────────────────────────
[결론] 분리 불가. 현재 단일값 표시를 그대로 유지했다(코드 무수정).

[조사 근거 — 코드로 확인]
ⓐ schemas/request_models.py `ValidationSetPreviewRequest` 의 접속정보 필드는
   `src_conn`(원본 접속) · `src_db`(원본 방언) 두 개뿐이다. 목적지 접속정보
   필드가 애초에 정의되어 있지 않다.
ⓑ routes/validation_set_preview_route.py 와 services/candidate_postcount_
   finalize.py 를 `tgt_conn|target_conn|tgt_db` 로 전수 검색한 결과 0건.
   3단계 계산(_run_bounded_sample / _collect_date_bucket_profiles /
   _date_catalog_stats / _augment_lastresort_sum_distinct)은 전부 `src_conn`

ⓒ 3단계 타일의 '목적그룹/목적집계' 는 DB 조회 결과가 아니라 parse_result 의
   select_items 매핑(_mvColPairParts)에서 나온 값이다 — 목적지 질의가 아니다.

즉 "목적 N초" 로 표시할 시간이 존재하지 않는다. 서버가 보내주지 않는 값이
아니라, 목적지 조회 자체가 일어나지 않는다. 2단계(COUNT)가 원본/목적을 각각
실행해 개별 시간을 갖는 것과 구조가 다르다. 억지로 나누면 없는 값을 지어내는
표시가 되므로 적용하지 않았다.

[참고] 이 경로에는 대신 단계별 분해값(processing_steps_ms — postcount_bounded_
sample / enrich_and_gates / date_bucket_profile / fallback_promotion)이 이미
응답에 실려 있다. '원본/목적' 축이 아닌 '작업 단계' 축이라 이번 요구사항과는
다른 정보이고, 지시가 "무리해서 나누지 말 것"이었으므로 손대지 않았다.

4. 요구사항 ④-1 — 5단계 불일치 그룹 기본 펼침
────────────────────────────────────────────────────────────────────────
[한 일]
결과 표를 다시 그리는 모든 경로가 통과하는 단일 지점(_mvWireRowsFromCache →
_mvPkRestoreExpandedRow)에 '기억해 둔 펼침이 없으면 첫 그룹을 편다' 분기를
추가했다(_mvPkAutoExpandFirstRow).

[전부 펼침이 아니라 '첫 번째만' 으로 정한 근거]
ⓐ 이 화면의 상세 패널은 설계상 SINGLE-OPEN 이다. `_mvToggleRowAggDiff` 는
   패널을 열기 전에 `_mvCloseOtherScopePanels('')` + `_mvRemoveAllScopePanels()`
   로 다른 패널을 전부 닫는다. 즉 '전부 펼침'은 이 함수를 N번 부른다고 되는
   것이 아니라 패널 관리 모델 자체를 다시 짜야 한다.
ⓑ 기존 화면 관례도 '동시에 한 그룹'이다. 이미 있는 펼침 상태 보존 장치
   (_mvPkExpandState, REIMPORT-DRILLDOWN-TAB-EXPAND-STATE-PERSIST)는 rowKey 를
   하나만 기억한다.
ⓒ 펼침 1회 = 서버 왕복 2건(prepare 보장 + pk-records 조회)이다. 그룹이 20개면
   탭 진입 즉시 20회가 나간다 — 클릭당 1회이던 비용이 진입 시 N회가 된다.

[사용자 의도를 덮지 않게 한 장치]
실행계획 fingerprint 당 1회만 시도한다(window._mvPkAutoExpandDone).
사용자가 접으면 기존 `_mvPkExpandForget` 이 상태를 지우지만 '시도함' 표시는
남아 있어 재렌더(탭 전환·페이징)마다 다시 펼쳐지지 않는다. 새 실행(fingerprint
변경)에서만 다시 1회 편다. 이미 펼쳐진 패널이 있으면 건너뛴다.
COUNT 게이트 차단·HOLD 는 `_mvToggleRowAggDiff` 안의 기존 분기가 그대로
사유를 표시한다(새 우회 없음).

[실측]
  BEFORE: 펼침 시도 = False / 펼쳐진 그룹 = []          (탭 진입 시 전부 접힘)
  AFTER : 펼침 시도 = True  / 펼쳐진 그룹 = STATUS_CD=P (page 1 · reimport 뷰)

5. 요구사항 ④-2 — 처리시간에 펼침 소요 반영 (조사 → 별도 표시로 배선)
────────────────────────────────────────────────────────────────────────
[조사 결과]
ⓐ 종전 5단계 '처리시간' = window._mvStage5ProcMs = 통계검증 /execute 서버시간
   이며, 그 뒤에 이어지는 그룹 펼침 소요는 포함하지 않았다.
ⓑ 펼침은 클라이언트 즉시 렌더가 아니다. `_mvPkEnsurePrepared`(prepare) →
   pk-records fetch 로 실제 서버 왕복이 있고, 그 소요는 이미 상세 패널 안
   계측 줄('계측 — 준비확인 Nms · scope 조회 Nms · 렌더 Nms')이 재고 있었다.
   즉 '유의미한 시간이 걸리고, 이미 재고 있는데, 처리시간에는 안 들어간다'.

[배선 — 합산이 아니라 별도 표시]
`_mvPkLoadPage` 가 계측 줄을 쓰는 자리에서 (준비확인 + scope 조회 + 렌더)의
합을 window._mvStage5DetailMs 에 남기고 5단계 타일만 다시 그린다(새 계측 없음,
새 서버 왕복 없음). 타일은 '실행 N초 / 상세 N초' 두 줄로 나눠 표시한다.

합산하지 않은 이유: '처리시간'은 저장·재조회·일괄검증이 같은 정의로 함께 쓰는
지표다(= /execute 서버시간). 여기서 클라이언트 왕복 시간을 더하면 화면마다
같은 이름의 값이 다른 것을 뜻하게 되어 정의가 오염된다. 지시도 "합산하거나
별도 표시"였으므로 안전한 쪽을 택했다.

[④-1 로 타이밍 기준점이 바뀌는지에 대한 판단]
바뀐다 — 그리고 그것이 이 표시를 더 정확하게 만든다. 종전에는 사용자가 클릭한
뒤에야 상세 소요가 생겨서 '처리시간'과 시점이 어긋났지만, 기본 펼침 이후에는
탭 진입 직후 자동으로 측정되어 실행 직후 화면에 함께 뜬다. 두 값이 서로 다른
행위를 재는 것은 그대로이므로 줄을 나눠 둔 표기가 그 차이를 드러낸다.

[stale 방지] 실행계획 fingerprint 를 함께 저장하고 표시 직전에 대조한다.
재실행 후에는 옛 상세시간을 붙이지 않고 종전처럼 한 줄만 보여준다.

      다르다'는 비교 표시다.)
3) '판정근거'(basis_text): '원본 1,000,000건 · 문자 단일 PK · 대체키(목적지 PK)

7. 요구사항 ⑥ — '판정근거' 를 4단계 타일에 간단히 보존
────────────────────────────────────────────────────────────────────────
[위치 판단 근거]
새 타일을 만들지 않고 기존 '통계전략' 타일에 얹었다.
ⓐ 4단계 타일 한 줄 상한은 9칸이고 현재 정확히 9칸이다 — 하나 더 만들면 9+1 로
   줄이 갈라진다(기존 규약).
ⓑ basis_text 는 계획기가 '이 전략을 왜 골랐는지' 대는 근거다. 그 전략을 보여주는
   칸에 근거가 붙는 것이 가장 자연스럽다. 목적그룹/원본그룹 타일은 사용자의
   '선택'을 보여주는 칸이라 계획기 근거를 붙일 자리가 아니다.
ⓒ 5단계 '불일치 추출전략' 타일에는 부착하지 않았다(지시 범위가 4단계).
   값 객체에 basis 필드가 없으면 렌더가 건너뛰므로 5단계 표기는 종전과 동일하다.

[축약 방식 — 요구사항 ③ 과 같은 '인라인 간단 + 툴팁 상세' 패턴]
`_mvBasisShort()` 는 서버 문자열을 ' · ' 로 나눈 뒤 키 축(PK / 대체키)을 말하는
조각만 앞에서부터 최대 2개 골라 괄호 부연을 떼어 잇는다. 판정을 새로 하지 않고
부분 문자열을 고를 뿐이며, 근거 산출 로직은 전혀 건드리지 않는다.
키 축 조각이 없으면 첫 조각 하나만 쓴다(문구가 비지 않도록).

[실측]
  원문 : 원본 1,000,000건 · 문자 단일 PK · 대체키(목적지 PK) 확정 · PK 인덱스 · 원격 DB
  인라인: 문자 단일 PK · 대체키 확정            ← 사용자 예시와 동일
  툴팁  : … · 판정근거: 원본 1,000,000건 · 문자 단일 PK · 대체키(목적지 PK) 확정
           · PK 인덱스 · 원격 DB                ← 원문 전체 보존
  5단계 추출전략 타일 basis = 없음(미부착 확인)
표기는 값(전략명)보다 한 단계 작고 흐린 보조 줄(.mv-qr-strat-basis)이며 한 줄을
넘기면 말줄임한다 — 요구사항 ③ 의 '타일을 짧게' 의도를 되돌리지 않게 했다.
