    설계 HASH_BUCKET_ORACLE_PORT_ADAPTER_DESIGN §3(어댑터 분리)·§4(same-DBMS 가드) 중
    "오라클 코드 0줄로 안전 확인이 끝나는 지점"까지만 착수한다(설계 §6.3 step ②).
    
    변경:
      · hash_contract.py — PG 전용 SQL 빌더에서 Base 계약(BaseHashContract) + 위임표(_HASH_CONTRACTS)
        + 팩토리(get_hash_contract / get_hash_contract_pair) + 공통 유틸(pow2_floor) + PEP562 하위호환
        재수출로 재편. exact_diff 의 _CANONICAL_ADAPTERS 선례를 그대로 답습(지연 import 로 순환 방지).
      · dialects_hash/postgresql.py — 현행 PG 표현식(_H32/_canon_component/bucket_expr 등)을 문자 단위로
        그대로 이전. 계약 버전 "hashv1-md5-lenpfx" 불변(방언 접미사 분리는 별칭 개명과 같은 커밋에서).
      · [가드 L3] get_hash_contract_pair — src/tgt 방언이 다르면 계약 자체를 주지 않아 혼합 방언 SQL 이
        물리적으로 생성 불가. 미등록 방언(현재 oracle)도 차단.
      · [가드 L2] adapters/base.resolve_hash_contract 를 db_type 쌍이 살아 있는 마지막 경계
        (multi_scope_adapter 실행 진입, multi-row-diff-resume 라우트)에 배치 — DB 접근 이전 차단.
        접속 미상이면 판단하지 않아 기존 호출 동작을 바꾸지 않는다.
    
    동작 무변경 실측: 계약이 방출하는 SQL 전수(337개 leaf — 표현식/확장 집계 SQL/행 SELECT/
    fingerprint) 리팩터 전후 지문 동일(sha256 7a841886…62d4, 불일치 0건).
