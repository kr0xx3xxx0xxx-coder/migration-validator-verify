3. 진단 핵심 — '3레벨 axis_a 분리'의 실제 의미와 한계
──────────────────────────────────────────────────────────────────────────────

▶ axis_a 는 이미 3-state(True/False/None) 다. None 이 두 하위경우를 합치고 있다:
    N1) 값 미배선 (sample_values 없음)
    N2) 값 있으나 타임스탬프 아님 (코드/번호/순수날짜 — STATUS_CD·DEPT_CD·SCHOOL_CATEGORY·BATCH_ID)

▶ 여기서 반드시 짚어야 할 사실(재현으로 확증):
    axis_a 만으로는 BATCH_ID('B001')·DEPT_CD('D001')·SCHOOL_CATEGORY('중등')를 구별할 수 없다.
    셋 다 N2(값 있으나 비타임스탬프)로 동일하다. 유일한 구분자는 B축(명칭/코멘트)뿐이다.
    (테스트 _NON_TS = ["B001",...] 가 이를 그대로 인코딩 — CD1(구분코드)도 값이 'B001'류다.)

▶ 그러므로 484-485 의 None 반환은 '보호자'이자 '원인'이라는 이중성을 갖는다:
    · B=True 경로(BATCH_ID): None→CONFIRMED 로 배제 유지 = 보호(회귀 방지). False 로 바꾸면
      B=True+A=False→MISMATCH 로 BATCH_ID 배제가 풀린다(=회귀).
    · B=False 경로(SCHOOL_CATEGORY): None→NOT_AUDIT_AMBIGUOUS 로 배지 = 오분류 원인.

  ★ 결론: 'N2 를 B축에 따라 다르게 취급' 하면 두 요구를 동시에 만족한다.
      - B=True + N2 → None 처럼(CONFIRMED 유지) = BATCH_ID 보호   [별도 처리]
      - B=False + N2 → False 처럼(NOT_AUDIT_CONFIRMED) = 배지 제거  [False 처럼 취급]
    이것이 지시가 말한 "Unknown 을 False 처럼 취급할 지점(B=False) vs True/False 와 다르게 별도
    처리할 지점(B=True)" 의 구분이다. BATCH_ID 회귀는 B=True 경로 보호로 원천 차단된다 —
    배지(B=False 경로) 수정은 BATCH_ID 배제와 완전히 독립(다른 분기)이다.

▶ 단, 순수 axis_a 분할의 한계(정직한 보고):
    N2 를 B=False 에서 NOT_AUDIT_CONFIRMED 로 접으면 SCHOOL_CATEGORY 배지는 사라지지만,
    같은 형태인 CD1(구분코드 — 배지의 원래 의도 대상 'cd1류')의 배지도 함께 사라진다.
    또한 운영은 값이 항상 배선되므로(N1 거의 미발생) 이 배지는 사실상 미발화(near-dead)가 된다.
    즉 '3레벨 분리'는 사실상 '값 있는 후보의 애매 배지 비활성' 정책 변경이며, 의도적으로 도입된
    기능(ADMIN-AUDIT-AMBIGUOUS-CANDIDATE-BADGE)의 반경을 되돌리는 결정이다.
    STATUS_CD(정상 차원)와 CD1(정체불명 코드)을 진짜로 구분하려면 axis_a 가 아니라 '양성 신호'
    (저카디 + 열거형/코드형 값 + 의미있는 명칭 _CD/_TYPE/유형/구분)가 필요하다 = heuristic 증가
    (CLAUDE.md 경고 대상) + explainability 필요.
