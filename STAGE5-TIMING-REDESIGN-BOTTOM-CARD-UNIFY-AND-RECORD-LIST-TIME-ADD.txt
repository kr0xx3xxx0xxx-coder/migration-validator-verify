1. STAGE5-TOP-GRID-FLICKER-FIX 구현
────────────────────────────────────────────────────────────
- ui/tabler_renderer.py:_mvPkEnsurePrepared — fetch 시작 직후(값 불변 시점) _mvRepaintStage5Tiles()
  호출 제거. 완료(then)/실패(catch) 콜백에서 1회씩(상호 배타)만 재도장하도록 축소.
- ui/tabler_renderer.py:_mvPkPrewarm — 동일 패턴(수집 시작 직후 재도장) 제거. 값만 갱신하는
  _mvUpdatePkSummaryCell() 은 타일 전체를 갈아치우지 않아 깜빡임 원인이 아니므로 그대로 둠.
- 검증: 코드 diff 로 "값이 바뀌지 않는 시점의 재도장 호출"이 두 함수에서 정확히 제거됐음을 확인.
  화면 녹화/프레임 캡처는 하지 않았다 — 이 경쟁은 서브 300ms 구간이고, 클릭~완료 사이 다른 정당한
  재도장 호출(_mvPkAdoptDetail, 그룹 준비상태 PREPARING→READY 전이마다 값이 실제로 바뀌며 호출)도
  같은 카드를 다시 그려 "재도장 횟수"만으로는 이번 결함(값 불변 재도장)과 정상 동작을 구분할 수
  없었다(실측: 콜드 클릭 1회당 재도장 총 3회 관측 — 그중 1회만 _mvPkEnsurePrepared 발원, 나머지는
  _mvPkAdoptDetail 의 정상적인 상태전이 재도장). 그래서 "제거 대상 호출 자체가 코드에서 사라졌는지"
  를 diff 로 직접 확인하는 방식으로 판정했다.

2. 1번 — 하단 [고정] 카드 값을 상단 '실행시간'과 통일
────────────────────────────────────────────────────────────
ui/tabler_renderer.py:_mvStage5PipelineHtml() — '5단계 불일치 그룹추출' 셀이 읽던 옛 값
(ctx.lastDetailIdx 가 가리키는 그룹의 detail_ms, 캐시재사용 시 과거 콜드스캔값 그대로 노출)을
제거하고, 상단 타일 '실행시간' 칸과 같은 계산 함수(_mvStage5ProcInfo, ui/grid_helpers.py)를 같은
인자(window._mvStage5TileArgs.r)로 그대로 호출 — 단일 출처, 새 계산 없음. 이 값은 통계검증 실행
1회당 한 번만 계측되므로 그룹 클릭·캐시 재사용과 무관하게 항상 동일하다.
관련 주석(ui/tabler_renderer.py:_mvStage5SetGroupPerf 근처)도 "이 값이 [고정] 카드의 유일한
데이터 원천"이라는 이제는 틀린 서술을 정정했다 — 보관 로직 자체(g.detail_ms/ctx.lastDetailIdx)는
남겨뒀다(다른 용도로 쓰일 수 있어 임의 삭제하지 않음, 삭제는 별도 확인 필요).
