```text
작업명 : CLIENT-INSERT-NO-COLLIST-RECLASSIFY-TO-CRITICAL
✅ 작업 완료 - INSERT 컬럼목록 생략 SQL의 클라이언트 사전검증 등급을 WARNING→CRITICAL로 재분류해 서버 판정과 일치시킴

## 목적
INSERT-COLUMNS-REQUIRED-BLOCKING-VS-WARNING-BROWSER-VERIFY(실 브라우저+실 Oracle DB 검증)가 확인한
클라이언트/서버 판정 불일치를 해소한다. 서버(services/sql_validation_service.py::check_sql_pre_parse,
EC_INSERT_COLS_REQUIRED)는 INSERT 대상 컬럼목록이 생략된 이관 SQL을 CRITICAL 성격(차단)으로 이미
판정하고 있었으나, 클라이언트(ui/tabler_renderer.py::_validateSqlFormat, INSERT_NO_COLUMN_LIST)는
같은 형태를 WARNING(진행 허용)으로 분류해 두 판정이 어긋났다. 사용자 결정에 따라 서버 정책(컬럼목록
필수)을 그대로 유지하고 클라이언트를 CRITICAL로 맞춘다.

## 현상
- 조사 재확인 결과(짐작 없이 코드 직접 확인):
  1. ui/tabler_renderer.py:22187 — `_fmtV.level === 'CRITICAL' || _fmtV.level === 'UNSUPPORTED'`
     인 경우에만 API 호출 자체를 차단(배너만 표시하고 /analyze 미호출). WARNING은 이 조건에 해당하지
     않아 서버까지 요청이 그대로 전달됐다.
  2. 개정 전 코드(ui/tabler_renderer.py:16220-16225, 커밋 a3211e0c 기준)는 INSERT 컬럼목록 생략을
     `level: 'WARNING'`으로 반환 → 클라이언트는 통과시키고 서버가 뒤늦게 EC_INSERT_COLS_REQUIRED로
     차단하는 이중 판정(왕복 낭비 + 사용자에게 서로 다른 문구 노출) 구조였다.
  3. 서버가 실제 반환하는 문구(services/sql_validation_service.py:378)는
     "개별검증/일괄검증은 INSERT 대상 컬럼 목록이 명시된 SQL만 지원합니다." — 클라이언트 기존 문구
     ("INSERT 컬럼 목록이 없습니다. 컬럼 매핑 정밀도가 낮아질 수 있습니다.")와 표현이 달라 혼란을 줬다.
  4. `_renderSqlFormatBanner`(ui/tabler_renderer.py:16232-)는 이미 CRITICAL 레벨에 대해 공통
     배너 스타일(🔴 차단 배지 + "이 형식은 분석이 차단됩니다" 안내)을 코드 하나로 처리하고 있어,
     이 사유 전용 문구/컴포넌트를 새로 만들 필요가 없음을 확인.

## 실제조치
- ui/tabler_renderer.py `_validateSqlFormat` 함수의 `INSERT_NO_COLUMN_LIST` 판정을
  `level: 'WARNING'` → `level: 'CRITICAL'`로 변경(16220행대).
- 안내 문구를 서버가 실제 반환하는 문구로 통일:
  "개별검증/일괄검증은 INSERT 대상 컬럼 목록이 명시된 SQL만 지원합니다. 권장 형식: INSERT INTO
  테이블(컬럼1, ...) SELECT ..."
- 함수 상단 요약 주석(레벨별 분류 설명)도 실제 코드와 어긋나 있던 부분(WARNING/CRITICAL 예시가
  바뀌어 있던 기존 오기)을 이번 변경 범위 내에서 함께 정정.
- CRITICAL 처리 경로(API 호출 차단, 배너 렌더)는 기존 공통 로직(22187행, `_renderSqlFormatBanner`
  22241행 CRITICAL 분기)을 그대로 재사용 — 신규 컴포넌트/분기 추가 없음.
- 다른 사유(SELECT_STAR 등)의 WARNING 분류는 변경하지 않음 — grep으로 전체
  `level: 'WARNING'|'CRITICAL'|'UNSUPPORTED'` 반환 지점을 재확인해 이 사유 하나만 정확히
  변경됐음을 코드 레벨로 확인.
- 커밋: 073f699f (main), push 완료.

## 기대효과
- 컬럼목록 생략 SQL 입력 시 [검증 실행] 클릭 즉시(서버 왕복 없이) 클라이언트 단에서 차단되어,
  불필요한 서버 요청/DB 조회가 사라진다.
- 클라이언트/서버 안내 문구가 동일해져 사용자가 서로 다른 두 메시지를 볼 일이 없다.
- 서버 정책(컬럼목록 필수)과 클라이언트 UX가 일치해 "WARNING인데 왜 서버가 막지?" 류의 혼란 해소.
```
