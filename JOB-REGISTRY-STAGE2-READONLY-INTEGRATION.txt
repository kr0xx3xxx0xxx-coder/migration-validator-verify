  A single : chunks_total→total, chunks_done→completed, last_processed_key→current_target,
             progress.last_progress_at→last_progress_at

  C stats  : total_plans, executed_plans, current_plan_table, run_status, updated_at→last_progress_at
  D full   : 실행 구조 없음 → 항상 빈 목록 + 안내 warning(가짜 job 미생성)

■ 정체(stall) 취급 — 표시만, 판정 없음
  · STAGE1 의 last_progress_at 을 그대로 활용해 stall_seconds/stall_basis 계산.
  · 임계값 비교·상태 전환·자동 중단/전환은 넣지 않음(진단 §7 — heartbeat gap 실측 전 임계 확정 금지).
  · 근거 종류를 progress_signal 로 명시: PROGRESS(진행 시각 실재) / START_ONLY(시작 시각 대체) / UNKNOWN.
  · 비활성 job 은 stall_seconds=None(경과 측정 자체를 하지 않음).

■ 읽기 전용 보증
  · SQLite 접근은 전부 mode=ro URI — 이 연결로는 DDL 실행 불가(원본의 CREATE TABLE IF NOT EXISTS 미수행).
  · 운영 DB sha256(앞16) 조회 전 25d78ba31b025471 / 조회 후 25d78ba31b025471 → 동일(무변경).
  · 단위 테스트 2건이 이를 강제(테이블 없는 DB 조회 후 DDL 부작용 0 / 조회 전후 행 내용 완전 동일).
  · 원본의 stale 정리(6h 초과 RUNNING→FAILED_INTERRUPTED)는 write 이므로 미수행 →
    미정리 stale 행이 활성으로 보일 수 있음(주석에 한계 명시, 정리는 원본 경로 책임).
