[1] 신설 core 함수
- services/candidate_recommendation_policy.py : classify_cardinality(n_distinct, *, row_count=None,
  is_pk=False, is_unique=False) -> dict  (순수 함수, 신규)
  · 반환 {cardinality_class, near_unique, is_pk, is_unique}
  · cardinality_class = constant(≤1)/low(≤50)/medium(≤200)/high(≤1000)/very_high(>1000)/unknown
    — 메인 엔진 _classify_groupby_cardinality 와 동일 경계(음수 PG 비율표기 처리까지 동일).
  · near_unique = PK/Unique 이거나 distinct/row_count ≥ 0.9(GB_IDENTIFIER_DISTINCT_RATIO). constant 에는
    비율 near-unique 미적용(단일값은 상수).
  · 이번 Phase 1 범위: 등급 경계 + near-unique 만. 절대 그룹수 상한(60)·날짜 durable 구제는 미적용(2단계).
    row_count/is_pk/is_unique 는 near-unique 판정에만 쓰이고 등급 경계를 바꾸지 않음.
  · 상수 CARD_LOW_MAX=50 / CARD_MEDIUM_MAX=200 / CARD_HIGH_MAX=1000 미러링(엔진 상수와 패리티 테스트로 강제).

[2] 어댑터 구현
- recommender._card_class (services/diagnosis/candidate/recommender.py)
  · classify_cardinality 호출 후 _ENGINE_TO_REC_CARD 로 반환 문자열 매핑 —
    constant→single, low→low, medium→mid, high/very_high→high, 비율 near-unique 우선→near_unique, unknown 유지.
  · 판정 순서(unknown→single→near_unique→등급) 보존. 호출부 스키마(single/low/mid/high) 그대로.
  · 실제 통일 효과: 기존 low≤20 → 50, 기존 mid≤1000 단일 → medium(≤200)=mid / high(200~1000)=high 로 분리.
- groupby_scoring._exclusion (services/diagnosis/groupby_scoring.py)
  · is_pk/is_unique 는 기존대로 먼저 EXC_UNIQUE. 카디널리티 분기만 classify_cardinality 로 치환.
  · _CARD_CLASS_TO_EXC : constant→EXC_SINGLE_VALUE, near_unique→EXC_NEAR_UNIQUE,
    high/very_high→EXC_CARDINALITY_HIGH. 기존 사유코드 그대로 보존.
  · 기본 config(safe_group_max=200, near_unique_ratio=0.9)가 엔진 경계와 동일 → 동작 불변(수치 변화 없음).
