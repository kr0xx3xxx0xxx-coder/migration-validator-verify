1. 지시 전제 정정 (중요)
────────────────────────────────────────────────────────────────────────
지시서는 M17 원인을 "서버 /agg-diff/pk-records 응답에 missing·diff_cols 가 안 채워짐(추정)"으로
잡았으나, 라이브 실측 결과 서버 응답은 정상이었다.

  scope_val=A → key=1 tgt_is_null=False diff_cols=['AMT'] src={AMT:100} tgt={AMT:600}
                key=4 tgt_is_null=True  diff_cols=[]      tgt=None
  scope_val=B/C 도 동일 형태(값불일치 1건 + 목적미존재 1건)

→ routes/agg_diff_route.py 및 services/exact_diff/* 배선 누락 없음 = 서버 수정 대상 없음.

진짜 원인: 클라이언트 CSS 충돌.
  결과표    : ui/execute_result_renderer.py:1485  <table class="mtbl">
  충돌 규칙 : ui/tabler_renderer.py:1714  .mtbl td{ … color:var(--text)!important }
  _mvPkCellSplit 이 td 인라인으로 준 color:#C2410C 가 !important 에 져서 화면에 미반영.
  font-weight 는 해당 규칙에 없어 그대로 적용 → "굵지만 검은 글씨" 증상과 정확히 일치.
  (.mtbl td 는 자손 선택자라 트리 병합 이전의 중첩 표에도 적용 — ADDENDUM 의 "Before/After
   동일 재현(기존 결함)" 기록과 부합. 트리병합 작업의 합성 계약이 PASS 였던 것은 그 검증이
   .mtbl 문맥 밖에서 셀 헬퍼 출력만 확인했기 때문.)

같은 표의 그룹 행 Δ(주황)가 잘 보이는 이유는 색을 자식 div/span 에 주기 때문이며,
같은 파일의 형제 헬퍼 _mvPkCellHtml·_mvPkCell2 도 이미 span 강조 관례를 쓴다.
→ _mvPkCellSplit 의 판정 로직(missing/isDiff)은 그대로 두고 마크업만 기존 관례에 맞춤.

5. 남은 한계 (정직한 기재)
────────────────────────────────────────────────────────────────────────
  - .mtbl td{color:…!important} 규칙 자체는 그대로 두었다. 같은 표 안에서 td 인라인 색을 쓰는
    다른 렌더 지점이 있다면 동일하게 색이 죽는다 — 전수 점검은 별개 작업(광범위 CSS 변경 위험).
  - '완전 일치 레코드'는 드릴다운 목록에 원래 나오지 않는다(재이관 대상만 나열). 해당 케이스는
    값불일치 행 안의 일치 컬럼 셀 무강조로 대체 확인했다.
  - 실측 국면은 단일 GB 축·소형(30행)·P1(전량 나열). 다중 세트/P3 국면은 같은 셀 헬퍼를 쓰므로
    동일하게 고쳐지나 별도 실측은 하지 않았다.
  - 픽스처 테이블 NXDNP.MV_M17_SRC/TGT 는 신규 생성분이며 그대로 남아 있다(스크립트 멱등 재생성).
