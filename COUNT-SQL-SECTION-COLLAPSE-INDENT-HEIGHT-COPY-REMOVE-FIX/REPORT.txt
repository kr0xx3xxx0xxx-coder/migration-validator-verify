1. 요청 요약
────────────────────────────────────────────────────────────────────────
2단계(COUNT 사전검증) 화면의 "COUNT SQL 보기 (원본 · 목적지)" 접힘 섹션을 다음과 같이
조정한다.

  ① 토글 헤더 전체 제거 + 그 공간까지 회수(빈 여백 금지), SQL 은 항상 펼쳐진 상태로 표시
  ② "원본 COUNT SQL" 라벨 소폭 들여쓰기
  ③ "목적지 COUNT SQL" 라벨도 ②와 정확히 같은 값으로 들여쓰기(같은 CSS 값 재사용)
  ④ 원본/목적지 SQL 코드 박스 높이를 기존 대비 2배
  ⑤ 복사 버튼 2개 제거 — DOM 요소뿐 아니라 연결된 클릭 핸들러도 함께 제거(죽은 코드 금지)


────────────────────────────────────────────────────────────────────────
2. 수정 전 구조 — 무엇이 어떻게 그려지고 있었나
────────────────────────────────────────────────────────────────────────
COUNT SQL 섹션은 `ui/tabler_renderer.py` 의 `buildCountSql()` 이 `#countOut` 에
innerHTML 로 통째 조립한다(정적 HTML 이 아니라 JS 템플릿 문자열).

  <div id="countResult"></div>
  <details class="mv-sql-fold" style="margin-top:12px" open>
    <summary onclick="return false;" style="cursor:default">COUNT SQL 보기 (원본 · 목적지)</summary>
    <div class="grid2 mv-count-sql-grid" style="margin-top:10px">
      <div class="sql-panel">
        <div class="sql-hdr">
          <h3>원본 COUNT SQL</h3>
          <button class="btn-copy" onclick="copySQL('cntSrcBox',this)">📋 복사</button>
        </div>
        <pre class="sql-box mv-count-sql-box" id="cntSrcBox">...</pre>
      </div>
      ... (목적지도 대칭 구조)
    </div>
  </details>

여기서 확인된 사실 두 가지가 이번 수정의 전제였다.

  · 이 <details> 는 이미 `open` + `summary onclick="return false;"` 라 실제로는
    접기/펼치기가 동작하지 않는 '항상 펼쳐진 상태'의 껍데기였다. 즉 토글 헤더는
    35px 짜리 라벨 줄만 차지하고 기능은 제공하지 않고 있었다 → 요구 ①의 "토글 자체 삭제,
    항상 보이게" 는 기능 손실 없이 성립한다.
  · 라벨(h3)에는 들여쓰기가 전혀 없었고(computed padding-left/margin-left 모두 0px),
    SQL 박스에도 고정 높이가 없어(min-height:0 / height:auto) 내용 줄 수만큼만 자라는
    자연 높이였다. 요구 ④의 "기존 min-height 가 N px 이면 2N px" 은 그대로 적용할 수 없어,
    실제 렌더 높이를 먼저 실측한 뒤 그 2배를 부여하는 방식으로 해석했다(아래 5-④).

3. JS 참조 관계 사전 확인 (요구사항: 오늘 SQL-INPUT-HEIGHT 작업 때처럼 먼저 확인)
────────────────────────────────────────────────────────────────────────
복사 버튼을 지우기 전에 `copySQL` 과 `cntSrcBox`/`cntTgtBox` 의 참조처를 전수 조사했다.

  [copySQL 정의]
    ui/js_sql_preview.py:205  function copySQL(id, btn)      ← 유일 정의
    ui/tabler_renderer.py:29677  window.copySQL = copySQL     ← 전역 export

  [copySQL 호출처]
    ui/tabler_renderer.py:24688  copySQL('cntSrcBox',this)   ← 이번에 제거
    ui/tabler_renderer.py:24695  copySQL('cntTgtBox',this)   ← 이번에 제거
    ui/js_sql_preview.py:151     copySQL('srcBox',this)      ← 통계검증 SQL preview(존치)
    ui/js_sql_preview.py:158     copySQL('tgtBox',this)      ← 통계검증 SQL preview(존치)
    ui/tabler_renderer.py:11564  btn.onclick = copySQL(data-copy-target) ← 배치 SQL 패널(존치)

  [cntSrcBox / cntTgtBox 를 쓰는 다른 코드]
    ui/tabler_renderer.py:25053~25056  renderCountResult() 가 COUNT 실행 후 실제 실행된
      전체 SQL(source_count_sql / target_count_sql)을 두 <pre> 의 textContent 로 덮어쓴다.
      → <pre> id 계약은 반드시 유지해야 하며, 이번 수정에서 id/클래스는 그대로 두었다.
    tests/test_count_gate_cmdbar_rewire.py:115  cntSrcBox 존재 여부만 확인 → 영향 없음

판단:
  · 인라인 클릭 핸들러(onclick 속성)는 버튼과 함께 사라지므로 이 화면의 복사 기능은 완전 제거된다.
  · 전역 `copySQL` 함수 자체는 통계검증 SQL preview 와 배치 SQL 패널이 여전히 호출하는
    공용 함수이므로 삭제 대상이 아니다. 이를 지우면 4단계 통계검증 SQL 복사와 배치 화면
    복사가 ReferenceError 로 깨진다. 따라서 "죽은 코드"가 되는 것은 버튼과 그 onclick 뿐이며,
    그 둘만 제거했다. (실측으로도 제거 후 전역 copySQL 존재 = true 확인 — 아래 5-⑤)

[4-1] ui/tabler_renderer.py — buildCountSql() 의 #countOut 템플릿

[4-2] ui/tabler_renderer.py — CSS

  :root{--mv-count-sql-box-h:149.25px;--mv-count-sql-label-indent:10px}
  .mv-count-sql-section{margin-top:12px}
  .mv-count-sql-grid .sql-hdr h3{padding-left:var(--mv-count-sql-label-indent)}
  .mv-count-sql-box{... 기존 그대로 ... ;min-height:var(--mv-count-sql-box-h)}

  · 들여쓰기는 규칙 '한 개'가 두 라벨을 동시에 잡는다. 칸별 개별 지정을 만들지 않았으므로
    두 값이 어긋날 수 있는 경로 자체가 없다(요구 ③의 "같은 CSS 값 재사용"을 구조로 보장).
  · 높이는 min-height 만 부여했다. 기존 규칙(height:auto / max-height:none /
    overflow-y:visible)은 그대로 남겨, 2배 높이보다 긴 SQL 은 예전처럼 자연 확장되고
    잘리지 않는다. 즉 '하한만 2배'이지 클리핑을 새로 만들지 않는다.
  · margin-top:12px 은 기존 <details> 의 인라인 값을 그대로 승계했다. 바깥 요소와의 간격은
    변하지 않고, 사라진 것은 토글 헤더가 쓰던 세로 공간뿐이다.

7. 비판적 검토 (구조·운영·부채 관점)
────────────────────────────────────────────────────────────────────────
· 긍정적 효과 : 기능하지 않던 껍데기 토글(항상 open + onclick return false)을 걷어내
  DOM 과 화면을 동시에 단순화했다. 들여쓰기·높이를 인라인 style 이 아닌 CSS 변수로
  단일 출처화해, 이후 값 조정이 한 줄 수정으로 끝난다.
· 구조적 문제점 : 이 섹션은 여전히 web_server/tabler_renderer 안의 JS 템플릿 문자열이라
  HTML 구조 변경이 파이썬 문자열 편집으로 이뤄진다(비대화 지속). 이번엔 순증 없이
  치환·삭제 위주라 라인 수는 늘지 않았으나, 구조적 부채 자체는 남아 있다.
· 운영상 위험 : 낮음. 서버 재기동만으로 반영되고, 되돌리려면 커밋 1개 revert 로 충분하다.
