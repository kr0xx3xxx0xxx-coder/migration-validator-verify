1. 문제(구조적 허점 재확인)
──────────────────────────────────────────────────────────────────────
개별검증 결과를 검증 그룹에 등록하는 드롭다운(#singleGroupSelect)은
services.batch_group_service.get_groups 로 후보를 조회한다. 이 조회는
project_id 정확일치만 필터하고, 그룹에 이미 바인딩된 DB 방언
(validation_batch_group.src_dbms_type / tgt_dbms_type)과 '지금 검증 중인
세션의 방언(원본/목적지)'이 일치하는지는 전혀 확인하지 않았다.
  · get_groups 의 SELECT 에는 애초에 src/tgt_dbms_type 컬럼조차 없었다
    (드롭다운이 방언 정보를 받을 수단 자체가 없음).
결과: 오라클 검증 결과를 PostgreSQL 로 바인딩된 그룹에 그대로 등록할 수
있었다(조용히 틀린 이력 생성 위험).

2. 수정 범위(드롭다운 / get_groups 계층 한정 — 지정 제외 파일 무수정)
──────────────────────────────────────────────────────────────────────
※ agg_diff_route.py / store.py / diagnosis/profiler.py 는 건드리지 않음
  (다른 터미널이 tabler_renderer.py 의 다른 영역도 편집 중 → 내 2개 hunk만
   부분 스테이징하여 커밋, 타 터미널 변경은 워킹트리에 그대로 보존).

(a) services/batch_group_service.py
    - get_groups SELECT/문서에 src_dbms_type, tgt_dbms_type 추가(순수 additive,
      기존 소비자 무영향).
    - annotate_group_dialect_compat(groups, sess_src_dbms, sess_tgt_dbms) 순수
      헬퍼 신설(DB 접근 없음, 단위테스트 가능):
        · 세션 방언 미전달(둘 다 None) → 어떤 표시 필드도 부착하지 않음
          (일괄검증 등 기존 호출부 완전 무영향).
        · 그룹 축(src/tgt) 방언이 '바인딩되어 있고' 세션 방언과 '다르면' 불일치.
        · 그룹 방언 미바인딩(빈 값/미인식) → 불일치로 보지 않음(첫 등록 시
          세션 방언으로 바인딩되므로 정상).
        · 방언 별칭은 services.dialects.resolver.normalize_dbms_name 로 canonical
          정규화(pg→postgresql 등).
        · 각 그룹에 dialect_mismatch(bool)/registerable(bool)/
          dialect_mismatch_reason(str) 부착.

(b) routes/batch_group_route.py
    - GET /api/batch-groups 에 선택 파라미터 sess_src_dbms, sess_tgt_dbms 추가.
      하나라도 전달되면 annotate_group_dialect_compat 로 방언 호환성 부착.
      미전달이면 기존과 동일(표시 필드 없음).

(c) ui/tabler_renderer.py (개별검증 등록 드롭다운 로더 2곳)
    - mvGroupFetchList(projectId, sessSrcDbms, sessTgtDbms): 세션 방언을 쿼리로
      전달(옵션 인자 — 인자 없는 일괄검증 batchLoadGroups 는 무영향).
    - singleLoadGroups(): 현재 개별검증 접속 select(srcDb/tgtDb)의 방언을 읽어
      전달. registerable===false 그룹은 <option disabled> + 라벨에
      '⚠ 방언 불일치(등록 불가: 사유)' 표기 → 사용자가 선택 자체를 못 함(=등록 차단).
      이전 선택 그룹이 불일치로 비활성되면 선택을 해제하고 안내 표시.

  [차단 방식 근거] 기존 UX(정책상제외/비활성 표기)와 일관되게 '드롭다운에서
  선택 불가(disabled)'로 등록을 원천 차단하는 쪽을 기본으로 채택.

4. 비판적 검토(잔여 리스크 · 후속 권고)
──────────────────────────────────────────────────────────────────────
- 본 수정은 '드롭다운 선택 차단'(클라이언트 게이트) + '서버측 방언 호환성

  계산되나, 최종 등록 엔드포인트 /single/save 에는 방언 게이트를 넣지 않았다

  호출해 불일치 gid 로 POST 하는 우회는 이론상 가능.
  → 후속 권고: routes/single_save_route.py 에 그룹 바인딩 방언 vs 세션 방언
    하드 게이트(차단) 1줄 추가(defense-in-depth). 별도 작업으로 분리 권장
    (해당 파일은 본 지시 범위 밖).
- 그룹 방언 미바인딩(신규 그룹)은 의도적으로 통과시켜 첫 등록 시 바인딩되게 함.
