판정: CURRENT 1개 + INACTIVE 1개로 정상 순환 중이며, ACTIVE 정체나 status NULL(=아카이브 대기)
      로그가 없다. archived='NO' 는 NOARCHIVELOG 에서 정상값이며 곧바로 재사용 가능한 상태다.
관찰(변경 아님, 참고용):
  - 그룹 2개 / 10MB / 멤버 1개는 Oracle Free 기본 구성 그대로다. 대량 적재 시 스위치가 매우 잦고
    (오늘 asis 92회 ≈ redo 920MB), 멤버 다중화가 없어 리두 파일 1개 손상 시 복구 여지가 없다.
  - NOARCHIVELOG 이므로 이제 온라인 백업/시점복구(PITR)는 불가하다. 복구 수단은 정상 종료 후
    콜드 백업뿐 — 실 데이터가 아닌 테스트 픽스처 용도라 수용 가능하나 사실로 남긴다.

4. 기존 아카이브 로그 잔존 확인 — 그대로 남아있음 (삭제 안 함)
────────────────────────────────────────────────────────────────
asis v$archived_log (deleted 별 집계)
| deleted | 개수  | 용량      | 최초 생성           | 최종 생성           |
|---------|-------|-----------|---------------------|---------------------|

tobe: v$archived_log 0행 (원래부터 NOARCHIVELOG).

→ 어제 확인값(1,460개 / 13.885GB)과 개수·용량이 **정확히 동일**하다. 즉 전환은 신규 적재만
   중단시켰고 과거 파일은 자동 삭제되지 않았다(예상대로).
경로: /opt/oracle/product/26ai/dbhomeFree/dbs/arch1_<seq>_1224959854.dbf
      (최신 3건 샘플: arch1_5934 / arch1_5933 / arch1_5932)

잔존 용량 명시: **13.885 GB (1,460개)** — 이번 지침대로 삭제하지 않았다.
한계(정직히 명시): v$archived_log 의 deleted='NO' 는 DB 카탈로그 기준이다. 호스트에서 OS 명령으로
   파일을 지웠다면 카탈로그에는 여전히 'NO' 로 남는다. 실제 파일 잔존 여부의 최종 확인은 호스트 셸
   (ls/du) 이 필요하며 SQL 읽기 전용으로는 판정 불가하다. 다만 아래 6번의 FS 여유 추정치가
   어제 대비 거의 변동 없음(-0.25GB)이라 **삭제되지 않았을 가능성이 높다**.

7. 종합 판정 및 잔여 리스크
────────────────────────────────────────────────────────────────
[해소됨]
  - asis ARCHIVELOG 무한 적재 → 중단 확인. ORA-00257(Archiver error)로 일반 계정 접속이
    전면 거부되던 장애 원인은 근본 해소됐다(아카이버 STOPPED, 아카이브 대기 로그 0).
  - 대량 픽스처 적재(100만행) 시 redo 증가가 더 이상 아카이브 파일로 축적되지 않는다.

[잔여 — 이번 지침상 조치하지 않음]
  1) 과거 아카이브 13.885GB(1,460개)가 그대로 점유 중. FS 여유가 817GB라 급하지 않으나,
     회수하려면 호스트에서 RMAN(delete archivelog all) 또는 OS 삭제가 필요하다. (삭제 금지 지침 준수)
  2) asis TEMP 4.258GB 는 대량 정렬 이후 자동 축소되지 않는다(어제와 동일 수치).
  3) NOARCHIVELOG 이므로 온라인 백업·시점복구 불가. 테스트 환경이라 수용 가능하나,
     실 데이터 이관 대상 DB에는 같은 조치를 적용하면 안 된다.
  4) 리두 그룹 2개 × 10MB × 멤버 1개(다중화 없음)는 기본 구성 그대로 — 대량 작업 시 스위치가
     잦다. 성능/안정성 개선 여지가 있으나 구조 변경이므로 이번 확인 범위 밖이다.

[코드/설정 변경 없음]
  - DB 설정 변경 0건, DDL/DML 0건, 프리셋 파일 변경 0건.
  - 신규 파일은 확인용 읽기 전용 스크립트 2개뿐(scripts/dev_e2e/).
