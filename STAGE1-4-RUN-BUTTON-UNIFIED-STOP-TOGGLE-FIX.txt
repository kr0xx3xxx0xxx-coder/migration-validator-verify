1. 재현 및 원인 확인 (신규 코드 작성 전 실측, before)

200ms 간격으로 폴링(scripts/dev_e2e/stage1_4_run_button_toggle_diagnose.py)한 결과:

  t=44.550s(2차 클릭 직후, renderCalls=1): [이전][COUNT 실행중… disabled][■ 중단][다음▶]
  t=44.757s(207ms 후, renderCalls 1→7 로 급증): [이전][COUNT 실행중… disabled][다음▶]  ← '■ 중단' 소멸
  t=57.662s(COUNT 완료, /count 응답 57.646s, renderCalls=12): [이전][COUNT 다시 실행][다음▶]

원인: bd56c0a(STAGE-EXEC-STOP-BUTTON-IMPLEMENT)가 disabled 된 메인 버튼 옆에 '■ 중단'을 별도 형제
엘리먼트로 1회성 삽입했는데, mvCommandBarRunAction 의 락 상태 렌더 분기(_mvCmdBarActionHtml)는
그 형제 엘리먼트를 전혀 모델링하지 않는다. 클릭 0.2초 뒤 다른 경로(진행카드/헤더 갱신 등)가
_mvRenderCmdBar()를 재호출하면 #mvCmdBarActions.innerHTML 이 config 기준으로 통째 재생성되며
형제 엘리먼트가 사라진다 — 이후 COUNT가 끝나는 약 13초 동안 중단 버튼이 보이지 않았다.

[화면만 문제] vs [기능 자체 소실] 구분 실측(수정 전 기준):
버튼이 안 보이는 상태에서 콘솔로 _mvSingleAbortRun() 을 직접 호출 → COUNT 가 실제로 즉시 취소됨
("사용자가 COUNT 실행을 중단했습니다" 정상 표시). 서버 CancelToken 체인(M43 진단서 항목1)은 살아있고,
결함은 순수히 [화면 표시 문제] — 사용자가 누를 수 있는 버튼이 안 보였을 뿐, 중단 기능 자체는
소실되지 않았다.

2. 구현 (확정된 설계 5개 규칙 그대로 적용)
────────────────────────────────────────────────────────────────
ui/tabler_renderer.py 수정:
- mvCommandBarRunAction: abortable 액션은 클릭 즉시(동기) 같은 버튼 자체를
  disabled=false, className='mv-btn-danger', textContent='■ 중단', onclick=_mvSingleAbortRun 으로
  토글한다. 별도 형제 엘리먼트 생성 코드(createElement/insertBefore) 완전 제거.
- _mvCmdBarActionHtml: 락 상태에서 abortable 이면 항상 같은 '■ 중단' 버튼 HTML을 반환한다
  (disabled 스피너 분기와 별개 분기 신설). 재렌더가 몇 번 일어나든 결과가 항상 동일 —
  단일 진실 출처(window._mvCmdBarLocks)만 보고 그리므로 중간 소멸이 구조적으로 불가능해졌다.
- _mvCmdBarStopClick(btn) 신설 — '■ 중단' 버튼의 유일한 onclick 진입점, _mvSingleAbortRun() 호출.
- abortable: true 를 1~4단계 실행 액션 5개(runAnalyze/​_mvCountStageAction/​
  runRevalidateFromCandidate/​runGenerate/​runExecute) 전부에 부여. 1·3단계(runAnalyze·
  runRevalidateFromCandidate)는 실제로는 순식간에 끝나 중단 실익이 없지만, 사용자 확정 설계에 따라
  화면 동작 일관성을 위해 포함했다.
