I-4. 5단계 이탈 시 상세비교 폴링 무한 지속 (ui/tabler_renderer.py)
────────────────────────────────────────────────────────────────

증상
  showSingleStep(pane 전환 함수)이 pane 만 숨기고 _mvRiStopPolling()을 호출하지 않아, 5단계
  (결과확인)에서 그룹 상세비교(/agg-diff/pk-records 1초 폴링)를 켠 채로 다른 단계로 이동하면
  폴링이 화면 밖에서 무한히 계속됐다.

I-5. 조합축 SQL 미실행 안내문구 소실 (ui/js_sql_preview.py)
────────────────────────────────────────────────────────────────

증상
  GROUP BY 2축 이상이면 4단계 화면의 결합 SQL은 실제로 실행되지 않는데, 이를 알리던 안내문구
  (2026-07-28 STATS-EXECUTE-STEP4-GENERATED-SQL-LABEL-ACCURACY-FIX 추가, git show 28973dbb)가
  이후 STAGE4-5-STRATEGY-TIMING-AND-TEXT-CLEANUP-FIX 요구사항 2 로 코드째 삭제되고, 이어진
  STAGE4-5-STATUS-TIMING-COMBO-LABEL-STRATEGY-RELOCATE-FIX 에서 대체 문구(ON 박스)까지
  체크박스 라벨 한 줄로 흡수돼, SQL 박스 자체에는 아무 표기도 남지 않았다.

조사 (git log/blame으로 원문 확인 — 새로 창작하지 않고 그대로 복원)
  git show 28973dbb (최초 도입, 2026-07-28):
    ⚠️ <strong>이 SQL은 참고용입니다 — 실제로는 각 축을 독립적으로 실행합니다.</strong>
    <div>아래 조합 SQL(GROUP BY ${_gbLine})은 실행되지 않습니다. 통계검증 실행 시
    <strong>단일 축 ${_gbArr.length}세트</strong>(${_gbArr.map(esc).join(' / ')})로 분해해
    축별로 따로 집계·비교합니다.</div>
    <div>실제 실행된 SQL과 세트 구성은 <strong>5단계(결과 확인)</strong>에서 확인할 수 있습니다.</div>

  git show 486b1a17 (STAGE4-5-STRATEGY-TIMING-AND-TEXT-CLEANUP-FIX 요구사항 2, 위 박스를
  #genSqlComboOffText 채 삭제) → git log 이후 STAGE4-5-STATUS-TIMING-COMBO-LABEL-STRATEGY-
  RELOCATE-FIX 가 대체 ON 박스마저 걷어내고 체크박스 라벨 1줄(#gbIncludePairLabel)로 통합.

수정 (ui/js_sql_preview.py, renderSQL 의 _comboNotice 조립부 + mvToggleComboPair)
  - 원문 그대로 #genSqlComboOffText div 를 복원(조합 체크박스 위, 같은 _comboNotice 컨테이너 안).
  - 표시 조건은 원문과 동일하게 미체크(OFF, _pairOn=false)일 때만 노출 — 체크(ON) 시에는 실제로
    조합이 실행되므로 "실행되지 않는다" 문구는 숨긴다(display:${_pairOn?'none':'block'}).
  - mvToggleComboPair 에 offEl.style.display 토글을 되돌려, 체크/해제 시 재생성 없이 즉시 반영.
  - 실행 배선(gbIncludePair 체크박스·include_pair 전달)은 무변경.

  _gbLine 관련: 삭제 당시 이 변수는 이 문구가 마지막 소비처라 함께 제거됐었다(STAGE4-5-STRATEGY-
  TIMING-AND-TEXT-CLEANUP-FIX 요구사항 2 주석). 복원 시 별도 변수를 되살리는 대신 동일 값을
  `_gbArr.map(esc).join(', ')` 로 인라인 계산해 동일 문구를 만든다(불필요한 변수 재도입 없음).
