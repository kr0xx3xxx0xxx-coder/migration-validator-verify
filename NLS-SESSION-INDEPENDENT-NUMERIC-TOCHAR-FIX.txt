  · 세션 독립성 : AFTER 열의 '.,' 와 ',.' 가 **전 케이스 동일** → 세션 설정에 의존하지 않는다.
  · 무회귀      : AFTER '.,' == BEFORE '.,' **전 케이스 동일** → 기존 정상 세션의 출력이 한 글자도
                  바뀌지 않았다(로케일을 고정할 뿐 값의 문자열 표현을 바꾸지 않았음을 실측으로 확인).
  · 선행 0 복원(REGEXP_REPLACE)도 그대로 작동 — 0.5 → '0.5'('.5' 아님).

[축 C] 운영 canonical row hash 실값(STANDARD_HASH MD5) — 정합성 최종 증명
  대상: row_hash_expr([(AMT,NUMERIC),(NM,TEXT)]) · 4행(12.5/0.5/-1234.5/123456789)
                                    asis(1523)   tobe(1524)
    BEFORE  세션 '.,' == 세션 ',.'      False        False    ← 세션만 달라도 해시 전량 불일치(거짓 불일치)
    AFTER   세션 '.,' == 세션 ',.'      True         True     ← 해소
    무회귀  BEFORE '.,' == AFTER '.,'   True         True     ← 기존 결과 완전 보존
  · BEFORE 의 두 세션 해시 집합은 4건 중 3건이 서로 달랐다(일치한 1건은 123456789 — 소수부가 없어
    소수점 문자가 등장하지 않는 값). 즉 소수부를 가진 모든 행이 거짓 불일치로 뜨는 상태였다.

[축 D] 길이 포매팅 경로 — 값 불변 실증
  TO_CHAR(LENGTH(v),'TM9') 결과가 BEFORE/AFTER · 두 세션 모두 전 케이스 동일(4/4, 2/2, 7/7, 11/11 …).
  → 정수라 소수점 문자가 출력에 등장하지 않는다. 이번 통일 적용은 값에 영향 0.

[축 E] 다형 경로 한계 — 이번 범위에서 제외한 실측 근거
  E-① 숫자에 대한 무서식 TO_CHAR((x)) 는 여전히 세션을 따른다:
        세션 ',.' → 12.5 가 '12,5' / 1234567.891 이 '1234567,891' 로 렌더됨(양 인스턴스 동일).
  E-② 문자 인자에 서식을 붙이면 실행 불가:
        TO_CHAR(('ab,cd'))                                       → 'ab,cd'  (정상)
        TO_CHAR(('ab,cd'),'TM9')                                 → ORA-01722 unable to convert
                                                                    string value containing 'a' to a number
        TO_CHAR(('ab,cd'),'TM9','NLS_NUMERIC_CHARACTERS=''.,''') → ORA-01722 (동일)

    3인자 고정은 구조적으로 불가(§4-E ②). 실행 가능한 대안은 두 가지다.
      대안 A) 오라클 연결 시점에 `ALTER SESSION SET NLS_NUMERIC_CHARACTERS = '.,'` 를 1회 실행.
              타입 무관하고 값 표현을 바꾸지 않으며 exact_diff 오라클 경로 전체를 한 번에 덮는다.
              단 커넥션 풀을 공유하는 다른 기능의 세션 상태까지 바꾸므로 **되돌리기 어려운 구조 변경**에
              해당한다 → 이번 지침 범위 밖으로 두고 별도 승인 후 진행할 것을 권장.
      대안 B) 해당 경로에 컬럼 타입 정보를 전달해 숫자 컬럼만 3인자 형태로 렌더. 정확하지만 호출부
              (agg_diff_route 등)까지 시그니처가 번지므로 비용이 크다.
    권장: 대안 A(단일 지점·저비용·값 불변). 승인 후 별도 작업으로 진행.

R2. F1(HASH_BUCKET 오라클 이식) 착수 시 신규 오라클 해시 구현체에 동일 고정을 반드시 포함할 것.
    현재는 팩토리가 오라클에 대해 None 을 반환해 호출 자체가 차단되어 있어 노출 위험은 없다.
