1. 현재 PG hash 계약 (hash_contract.py) — 구성과 목적
────────────────────────────────────────────────────────
HASH_BUCKET 은 문자/UUID/복합 MATCH_KEY 를 canonical 인코딩 → 32bit hash → bucket(& n-1)
으로 나눠 한 번의 집계로 원본/목적 비교. 계약 fragment:
  A md5(x)                          입력→32 hex 다이제스트(결정적)
  B left(md5,8)                     앞 8 hex(=32bit)
  C ('x'||hex8)::bit(32)::bigint    8hex→부호없는 32bit 정수(0..2^32-1)
  D h & (n-1)                       2^k bucket 분할(비트 AND, modulo 회피)
  E trim_scale(x::numeric)::text    숫자 canonical(12.50==12.5)
  F x::text / G length()::text / H CASE NULL 마커  canonical 길이접두 결합
  I sum(h32)                        bucket 내 키/행 hash 합(순서무관)
  _H32 = (('x'||left(md5(%s),8))::bit(32)::bigint)

────────────────────────────────────────────────────────
2. 오라클 실행 불가 원인 (실측 — asis/tobe 라이브)
────────────────────────────────────────────────────────
PG 계약식을 오라클에 직접 실행 → 별칭(ORA-00911) 이전에 표현식 자체가 다지점 차단:
  md5('abc')          ORA-00904 "MD5" invalid identifier (함수 없음)
  left('abc',3)       ORA-00904 "LEFT" invalid identifier (함수 없음)
  (...)::bit(32)      DPY-4010  :BIT 바인드 오인(:: 캐스트 문법 없음)
  1::bigint           DPY-4010  :BIGINT 바인드 오인
  trim_scale(12.50)   ORA-00904 "TRIM_SCALE" invalid identifier (함수 없음)
  255 & 7             ORA-00923 FROM keyword not found (& 는 비트연산자 아님)
  → 배경의 "ORA-00907" 은 실측상 위 6종. 결론 동일: 별칭 개명만으로는 도달 불가.

────────────────────────────────────────────────────────
3. 오라클 대체식 1:1 대응 (실측 성공 — exact_diff 운영검증 함수군)
────────────────────────────────────────────────────────
  A md5           → LOWER(RAWTOHEX(STANDARD_HASH(x,'MD5')))
  B left(,8)      → SUBSTR(...,1,8)
  C ::bit32::big  → TO_NUMBER(hex8,'XXXXXXXX')           [부호없는 32bit]
  D & (n-1)       → BITAND(h, n-1)
  E trim_scale    → REGEXP_REPLACE(REGEXP_REPLACE(TO_CHAR(x,'TM9'),'^\.','0.'),'^-\.','-0.')
  F ::text        → TO_CHAR(x)  (날짜 TO_CHAR(...,'YYYY-MM-DD"T"HH24:MI:SS.FF6'))
  G length        → TO_CHAR(LENGTH(v))       H/I CASE·sum 문법 공통

  [실측값] md5('abc')=STANDARD_HASH('abc','MD5')=900150983cd24fb0d6963f7d28e17f72 동일
           TO_NUMBER('ffffffff','XXXXXXXX')=4294967295(2^32-1)  BITAND(255,7)=7
           TO_CHAR(12.50,'TM9')=12.5

  [32bit 정수·bucket 동등성 — canonical 5종, 오라클 실측 == 표준 md5(=PG)]
    S:3:abc                          ora 3276922494 == py 3276922494   bucket&127 126==126
    S#N                              ora 10499643   == py 10499643     bucket&127  59== 59
    D:4:12.5                         ora 584801104  == py 584801104    bucket&127  80== 80
    T:26:2026-07-26T00:00:00.000000  ora 1817468297 == py 1817468297
    hbw1S:3:abc(salt)                ora 976348671  == py 976348671
  → STANDARD_HASH MD5 는 표준 MD5 라 PG md5()·Python hashlib.md5 와 바이트 동일.
    TO_NUMBER X = PG ::bit(32)::bigint(부호없는), BITAND = PG &. 계약 1:1 동등 확정.
    (PG 라이브 대조는 이번 세션 Neon 쿼터 소진·Inter 서버 설정으로 접속 불가 →
     md5 표준성으로 Python 교차검증. 오라클 실측은 asis/tobe 둘 다 성공.)
