작업명 : M67-CONN-PAIRS-MOVE-TO-SQLITE

✅ 작업 완료 - 검증 경로(Pair)를 브라우저 localStorage → 서버 SQLite(mv_conn_pair)로 이관(다대다 지원 실클릭 검증) + PostgreSQL 기본 Pair 강제 재등장/삭제차단 하드코딩 제거(8번 항목, directive 개정 65483f1 반영)까지 완료

════════════════════════════════════════════════════════════════════════
1. 배경 / 범위
════════════════════════════════════════════════════════════════════════
- DB-CONNECTION-PROFILE-LOSS-ON-RESTART-DIAGNOSE 후속 — 진단 결과 개별 DB 접속 프로필
  (mv_db_preset)은 이미 SQLite 영속이었고, "검증 경로"(Pair)만 브라우저 localStorage 전용이라
  시크릿모드 종료·캐시 삭제·다른 브라우저/PC 전환마다 사라졌다.
- 이번 범위는 M67 개선안 3번(구조변경) 중 "검증 경로(Pair)" 저장 위치 이관만. 활성 접속(접속중)
  재검증 로직과 프로젝트 선택 재검증 로직은 지시대로 손대지 않았다(코드 확인: _restoreActivePath,
  mv_active_path, mvRestoreWorkProject 전부 무수정 — 여전히 localStorage 기반 재검증 유지).

    pair_name             TEXT
    source_profiles_json  TEXT               -- [{name,dbms}, ...] 참조만(민감정보 없음)
    target_profile_name   TEXT
    target_dbms           TEXT

  같은 (원본 profile 집합, 목적지) 조합만 create_pair() 가 신규 삽입 대신 기존 행을 반환해 가볍게
  흡수한다.
