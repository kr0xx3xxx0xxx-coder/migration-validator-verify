4. [요구사항] 풀 재사용 판단 — "최초 1회" 채택 및 사유
────────────────────────────────────────────────────────────────────────
결론: **connect() 시점 1회만 실행**. 매 checkout 재실행은 불필요.

사유 (코드 근거 + 실측 근거 둘 다):
 (a) services/connection_pool.py 는 `_is_pg(key)` 로 **PostgreSQL 만** 풀링한다.
     비-PG(Oracle/MySQL/MSSQL)는 checkout 마다 새 물리 연결을 만들고(return_conn 에서
     즉시 close) 풀에 보관하지 않는다. 즉 오라클은 '커넥션 1개 = 물리 세션 1개' 이므로
     connect() 1회 실행이 곧 모든 오라클 세션 커버다.
     실측(BEFORE/AFTER 동일): pool_is_pg_for_oracle=false,
       checkout 1회차 reused=false / 2회차 reused=false,
       metrics = physical_open 2, reuse 0, returned 0, closed 2, idle_total 0
     → 반납 자체가 일어나지 않고(returned 0) 전부 close(2) 되므로 재사용 세션이 없다.

 (b) ALTER SESSION 은 세션 파라미터라 그 세션이 살아있는 동안 유지된다(실측 확인).
       - 같은 커넥션에서 왕복 3회 후: ['.,', '.,', '.,']
       - 고정 적용 후 실 테이블 쿼리 5회 반복 후: ['.,','.,','.,','.,','.,']
       - 대조로 세션을 ',.' 로 바꾸면 그 세션 내내 ',.' 로 유지됨(설정이 휘발되지 않음 증명)

 (c) request_connection_scope 의 요청 내 커넥션 재사용도 **같은 물리 세션**이라 재실행 불필요.
     실측: 같은 key 로 _cmn_db_connect 2회 → same_proxy=True, nls_1st='.,', nls_2nd='.,',
           TO_CHAR((12.5))='12.5'

 (d) 향후 오라클 풀링을 켠다면 여기가 아니라 checkout 경로에 재적용을 걸어야 한다
     (DRCP 세션 purity 도 함께 검토 필요) — 해당 취지를 메서드 docstring 에 명시해 두었다.

5. [요구사항] 실측 검증 ① 세션 파라미터 실제 고정 확인
────────────────────────────────────────────────────────────────────────
대상: 내부망 오라클 asis(:1523) / tobe(:1524), 스키마 NXDNP, 드라이버 oracledb thin.
      접속정보/비밀번호는 프리셋에서 로드하고 출력하지 않음.
쿼리: SELECT value FROM nls_session_parameters WHERE parameter='NLS_NUMERIC_CHARACTERS'

  구분      | asis      | tobe      | TO_CHAR((12.5))
  ----------|-----------|-----------|-----------------
  BEFORE    | '.,'      | '.,'      | '12.5'
  AFTER     | '.,'      | '.,'      | '12.5'

주의(중요): 이 두 인스턴스는 NLS_TERRITORY=AMERICA 라 세션 기본값이 **원래부터 '.,'** 다.
따라서 위 표만으로는 "고정이 실제로 동작하는가" 를 구분할 수 없다(무영향은 증명되지만
고정 자체는 증명 안 됨). → 아래 §6 에서 세션 기본값이 ',.' 인 인스턴스를 충실히 재현해
결정적으로 검증했다.

6. [요구사항] 실측 검증 ② S14 지점 거짓 불일치 재현 → 해소 (결정적)
────────────────────────────────────────────────────────────────────────
세션 변경이 어려운 게 아니라, 두 인스턴스가 이미 '.,' 라 차이가 안 드러나는 상황이었다.
그래서 **드라이버 경계만 가로채** 어댑터의 고정 실행 '전' 시점에 세션을 ',.' 로 만들어
"NLS_TERRITORY=KOREA/GERMANY 인스턴스" 를 충실히 재현했다(어댑터 코드는 무수정).

검증 지점: S14 5곳 중
  · SCOPE WHERE 동등비교 — agg_contribution.py:843 / exact_diff_route.py:204
    `TO_CHAR((col)) = '<val>'`
  · chunk compare 균일 캐스트 — dialects/oracle.py:584 `TO_CHAR(Q0.col)`

[6-1] 실 테이블 데이터(NXDNP.MV_ORA_XDIFF_SRC, 소수 표현식 C_NUM/2)

  항목                              | A. 고정 미적용(수정 전) | B. 고정 적용(수정 후)
  ----------------------------------|-------------------------|----------------------
  세션 NLS_NUMERIC_CHARACTERS       | ',.'                    | '.,'
  캐스트 없는 진짜 행수 (=1.5)      | 1                       | 1
  SCOPE WHERE TO_CHAR(...)='1.5'    | 0   ← 거짓 불일치       | 1   ← 해소
  chunk 캐스트 샘플 5건             | 1,5 / 3 / 4,5 / 6 / 7,5 | 1.5 / 3 / 4.5 / 6 / 7.5
  판정 false_mismatch               | true                    | false

  → 실제로 존재하는 1건을 0건으로 오판하던 거짓 불일치가 고정 후 사라졌다.

[6-2] DUAL 리터럴 대조 + 3인자 대조군(선행 수정이 여전히 유효한지)

  항목                                    | ',.' 세션 | '.,' 고정 후
  ----------------------------------------|-----------|-------------
  TO_CHAR((12.5))  (균일 캐스트)          | '12,5'    | '12.5'
  COUNT WHERE TO_CHAR((12.5))='12.5'      | 0         | 1
  TO_CHAR((12.5),'TM9',nlsparam) (대조군) | '12.5'    | '12.5'
  → 3인자 경로는 원래부터 세션 무관(선행 수정 정상), 균일 캐스트만 세션 의존이었음이 확인됨.

[6-3] 문자 컬럼 안전성 (3인자였다면 ORA-01722 로 실패했을 지점)
  고정 적용 세션에서 `TO_CHAR((C_VARCHAR2))` 실행 → 정상 10건 반환, ORA-01722 없음.
  → 세션 고정 방식이 타입 무관하다는 점(이번 채택의 핵심 이점)을 실증.

[6-4] 원본/목적 양측 대칭 (exact_diff raw_connect 경로)
  양측 모두 기본값 ',.' 인스턴스로 가정하고 raw_connect(=OracleAdapter.connect 재사용) 연결:
    asis: nls='.,', TO_CHAR((12.5))='12.5'
    tobe: nls='.,', TO_CHAR((12.5))='12.5'   → symmetric=True
  → 양측 canonical 문자열이 동일해져 교차 인스턴스 거짓 불일치가 구조적으로 제거됨.
