✅ 작업 완료 - ORACLE-CONN-ERROR-TIMEOUT-MISCLASSIFICATION-FIX - ORA-03136을 접속 실패(연결 시간 초과) 계열로 재분류하고 오류코드 기반 판정 단계를 앞세움, 요구사항 3(방언별 실행 상한)은 조사 결과 2026-07-28 커밋 53d61bb에서 이미 구현 완료로 확인되어 신규 구현 없음

────────────────────────────────────────────────────────────────────────
1. 결함 요지
────────────────────────────────────────────────────────────────────────
ORA-03136(inbound connection timed out)은 클라이언트가 SQLNET.INBOUND_CONNECT_TIMEOUT 안에
**인증을 마치지 못해** 서버가 접속을 끊을 때 나는 오류다. 즉 쿼리는커녕 접속조차 성립하지
않은 상태이므로 의미상 접속 실패다.

그런데 판별기가 이를 쿼리 타임아웃으로 보고 있었다.

  services/db_adapters/oracle.py:126 (수정 전)
    def is_query_timeout_error(self, exc) -> bool:
        s = str(exc).lower()
        return "dpi-1067" in s or "ora-03136" in s or "call timeout" in s
                                   ^^^^^^^^^^^^^^^^^ 접속 단계 오류가 쿼리 타임아웃 표지에 섞여 있음

이 판정이 상위 categorize_conn_error 로 그대로 전파되어, 접속조차 안 된 상황에서
아래 문구가 사용자에게 나갔다 — **사실과 정반대의 안내**다.

  "쿼리 실행 시간 초과 (접속은 정상 — 실행 시간이 제한을 초과했습니다).
   현재 제한: 60초 (환경변수 MV_COUNT_STATEMENT_TIMEOUT_MS = 60000 ms). …"

부수 피해가 하나 더 있었다. db_query_service.is_connection_lost_error 는 '연결 시간 초과'를
재시도 대상으로 보지만 위 정정 문구는 재시도 대상이 아니다(쿼리 타임아웃은 재접속해도 같은
상한에 걸리므로 의도된 설계). 따라서 오분류된 ORA-03136 은 **일시적 접속 장애인데도 재시도
경로에서 제외**되고 있었다.

■ 확장성 평가
  · 확장 자체는 쉽다 — 전부 평면 튜플이고 소문자 부분문자열 매칭이라 한 줄 추가로 끝난다.
    새 표지를 추가해도 다른 분기에 영향이 없고, 위 (b)는 음성 판정이라 오탐 방향이 안전하다
    (모르는 메시지는 기존 fallback ③ '연결 시간 초과'로 떨어진다).
  · 그러나 **배치가 구조적으로 잘못돼 있다.** (b)는 오라클/PG/MySQL/MSSQL 표지가 방언 중립
    서비스 파일 하나에 뒤섞여 있다. 새 방언·새 드라이버 메시지를 지원하려면 어댑터가 아니라
    공용 서비스 파일을 고쳐야 하고, 이는 CLAUDE.md 가 경계하는 'heuristic 하드코딩 증가' 그 자체다.
    (a)는 어댑터가 소유하는데 (b)만 밖에 있어 비대칭이기도 하다.
  · 권장 방향(이번 범위 밖, 별도 지침 필요):
      BaseDbmsAdapter.is_connect_phase_error(exc) 를 추가하고 (b)를 방언별 어댑터로 이관.
      기본 구현 False, 각 어댑터가 자기 표지만 소유. 인터페이스 추가라 어댑터 9종을 모두
      건드리므로 사용자 승인이 필요한 규모다.
  · 표지 미등록 시 실제 위험도: 접속 단계 오류가 (b)에 없으면 (a)의 방언 표지에 걸리는
    경우에만 오분류가 난다. 즉 '표지가 없다 = 즉시 오분류'가 아니라 '(a)와 문자열이 겹칠 때만
    오분류'다. 이번 ORA-03136 은 (a)에 명시적으로 들어 있어 확정 오분류였던 특수 사례다.

8. 비판적 검토 (남는 위험)
────────────────────────────────────────────────────────────────────────
· fallback ③('timeout' 문자열 → 연결 시간 초과)은 그대로 남겼다. 어댑터 표지에도 없고 접속
  단계 표지에도 없는 미지의 쿼리 타임아웃 메시지는 여전히 '연결 시간 초과'로 떨어진다.
  이 기본값을 바꾸려면 새 카테고리('분류 불가' 등)가 필요한데 지시가 신규 카테고리를 금지했고,
  기존 테스트가 이 기본값에 의존한다(MySQL "Can't connect to … (timed out)" 등). 현행 유지가
  안전하다고 판단했다. → 요구사항 2의 하한선("표지가 명확한 접속단계 오류는 정확히 분류")은 충족.
· 재시도 정책 변화: ORA-03136 이 '연결 시간 초과'가 되면서 is_connection_lost_error 가 True 가
  되어 재시도 대상에 다시 포함된다. 접속 단계 타임아웃은 일시적 요인이라 재시도가 타당하지만,
  서버측 INBOUND_CONNECT_TIMEOUT 이 상시 짧게 설정된 환경이라면 재시도가 반복될 수 있다.
  현재 재시도는 상한이 있는 구조라 무한 반복은 아니다(테스트로 True 임을 명시적으로 고정).
· ORA-12535/ORA-12609 는 실측 없이 오라클 공식 의미(접속 협상 단계 timeout)만 근거로 추가했다.
  둘 다 수정 전에도 '연결 시간 초과'로 분류되던 메시지라 판정 변화는 없고(위 [S] 표 확인),
  코드 표지 목록에 넣어 문장 변화에 강해지도록 한 것이다.
