근본 원인(코드 근거):
- ui/js_stage_gate.py 는 `window.MvStageGate = {...}` 로만 노출한다. 실 브라우저는 window===globalThis
  라서 이 대입이 곧 전역변수 `MvStageGate` 도 만든다.
- ui/tabler_renderer.py 의 `_mvCanNavStep`(6264행)/`_mvCanNavTab`(6305행)/`_mvWfStageAccessible`(6244행)은
  `if (!window.MvStageGate) return ...` 로 존재를 확인한 뒤, 본문에서는 `window.` 접두어 없이
  bare `MvStageGate.canNavigateStep(...)` / `MvStageGate.isTabAccessible(...)` 를 호출한다(6267·6269·
  6313행). 실 브라우저에서는 정상 동작(window===globalThis 이므로 bare 참조가 곧 window 참조).
- 그런데 tests/test_one_click_full_run.py 의 node DOM 스텁은 `windowStub` 이라는 **별개의 순수 객체**를
  만들어 `globalThis.window = windowStub` 로만 연결한다(249~276행) — 브라우저의 window===globalThis
  불변식이 깨진다. 그 결과 `window.MvStageGate = {...}` 는 windowStub 객체에만 프로퍼티를 추가할 뿐
  전역 스코프에 `MvStageGate` 라는 이름을 만들지 않는다.
- 위 세 함수 본문의 bare `MvStageGate.xxx(...)` 호출은 이 하니스에서 `ReferenceError: MvStageGate is
  not defined` 를 던지고, 세 함수 모두 `catch (e) { return true; }` 로 감싸져 있어 예외가 삼켜지며
  "이동 가능(true)"으로 항상 오판된다 → 상단 탭 disabled 계산(`disabled: !navClickable`)이 항상 False.
