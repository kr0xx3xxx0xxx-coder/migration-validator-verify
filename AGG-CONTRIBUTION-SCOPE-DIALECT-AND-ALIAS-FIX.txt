[1] 무엇을 고쳤나 — services/exact_diff/agg_contribution.py (지시대로 이 파일만)
  Before(:840-841)  SELECT * FROM (...) __sc WHERE (col)::text = 'v'
    · __sc   : 밑줄 선두 비인용 별칭 → 오라클 ORA-00911
    · ::text : 오라클이 `:text` 를 바인드 변수로 오인 → DPY-4010
    → 결과가 틀리는 결함이 아니라 '실행 자체가 불가'. raise 금지 규칙 탓에 사용자에겐
      HOLD/AGG_QUERY_FAILED 로만 보이는 조용한 차단이었다.

  After
    (1) _scope_eq_expr 로 4방언 분기 — oracle=TO_CHAR((c)), mysql=CAST AS CHAR,
        mssql=CAST AS NVARCHAR(4000), postgres=기존 ::text 유지.
        새 패턴 발명 없이 exact_diff/dialects/oracle.py 의 _txt 캐스트를 그대로 재사용했고,
        routes/exact_diff_route.py 의 동명 헬퍼와 계약을 맞췄다. 방언은 각 측 접속 db_type
        에서 공통 헬퍼 _to_sqlglot_dialect 로 도출(_conn_dialect) — 혼합 방언도 각 측 대응.
    (2) 별칭 __sc → mv_agg_scope_src / mv_agg_scope_tgt (mv_reimport_src·mv_scope_src 규칙과 통일).
        이름 참조 없는 위치라 SQL 의미 불변.
    (3) [지시 범위에서 한 걸음] 바깥층 _agg_sql 이 여전히 PG 전용(__K/__agg 밑줄 별칭·::text·
        GROUP BY 1)이라 (1)(2)만으로는 최종 문장이 오라클에서 다시 막힌다. 지시 3번의
        "After = 실행가능"을 충족시키려 db_type='oracle' 일 때 같은 파일에 이미 있는 위임
        (_pk_agg_sql → dialects/oracle.pk_agg_sql, unique_key=False)로 넘기기만 했다.
        새 빌더 없음·산출 컬럼 순서 동일(소비자 _row() 는 위치 기반)·PG 본문 무변경.

[3] Before/After 렌더 대조 (오라클, 원본측 — 실행 직전 SQL 그대로 캡처)
  BEFORE  SELECT (ORDER_ID) AS __K, MIN((ORDER_YM)::text) AS __G, count(*) AS __N,
                 SUM((ORDER_AMT)) AS __S0
            FROM (SELECT * FROM (...) __sc WHERE (ORDER_YM)::text = '202601') __agg
           GROUP BY 1 ORDER BY 1
          차단요인 3종 검출 : ::text(DPY-4010) / 밑줄 선두 비인용 별칭(ORA-00911) / GROUP BY n
  AFTER   SELECT (ORDER_ID) AS "__K", MIN(TO_CHAR((ORDER_YM))) AS "__G0", COUNT(*) AS "__N",
                 SUM((ORDER_AMT)) AS "__S0"
            FROM (SELECT * FROM (...) mv_agg_scope_src
                   WHERE TO_CHAR((ORDER_YM)) = '202601') "__agg"
           GROUP BY (ORDER_ID) ORDER BY (ORDER_ID)
          차단요인 0종. 목적측 별칭도 mv_agg_scope_tgt 로 대칭.
  ※ 정직한 한계 : sqlglot 파싱은 Before 도 통과시켜 판별자가 못 된다. 위 판정은 파서가 아니라
    '과거 실측으로 확인된 차단요인 3종의 유무'로 내렸다.
