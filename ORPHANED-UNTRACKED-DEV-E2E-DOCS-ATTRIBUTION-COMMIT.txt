2. 귀속 방법 — 증거 계층
==============================================================================
지침대로 E:\verify_reports 완료보고서와 대조하되, 파일명 유사도만으로는 오귀속 위험이
커서 아래 3계층 증거를 사용했다.

  S (주 증거)  : 파일 자신의 헤더(docstring/제목줄)가 선언한 작업명
                 예) stats_chunk_tradeoff_measure.py 헤더 →
                     'STATS-VALIDATION-CHUNKED-VS-SINGLE-TRADEOFF-DIAGNOSE'
  E1 (교차)    : 다른 완료보고서 본문이 그 파일명을 언급
  E3 (참고)    : 파일명 ↔ 보고서명 토큰 유사도

[중요] URGENT-WORKINGTREE-UNCOMMITTED-STACK-COMMIT-RECOVERY.txt 는 111건 전체를
나열한 인벤토리 보고서라 모든 파일에 매칭된다. 이를 증거로 쓰면 전부 그 작업으로
오귀속되므로 증거 집합에서 제외했다.

111건 중 105건은 헤더가 작업명을 스스로 선언해 S 로 확정했고, 나머지 6건은 아래와 같이
수동 확정했다.

  _hb_orbranch_40.py / _hb_wave2_orbranch_scaling.py / _hb_wave2_variance.py
      → 헤더 선언 없음. 세 파일 모두
        hash_bucket_sort_avoidance_viability_diagnose.py 를 import 하는 파생 측정
        스크립트이고, 해당 완료보고서 본문이 파일명을 언급(E1) →
        HASH-BUCKET-STRATEGY-SORT-AVOIDANCE-VIABILITY-DIAGNOSE
  hash_bucket_wave2_realistic.py
      → 헤더가 'HASH-BUCKET-...-VIABILITY-DIAGNOSE' 로 축약 표기돼 자동 추출 실패.
        E1 로 동일 작업 확정
  _PLAIN-JOIN-WRAPPING-EXPLAIN-PLANS.txt
      → 실행계획 원문 산출물(스크립트 아님). 파일명 + 완료보고서 본문 언급 →
        PLAIN-JOIN-WRAPPING-NECESSITY-DIAGNOSE
  reg_dt_live_clickthrough_verify.py
      → 헤더 선언이 'REG-DT-BADGE' 로 잘려 인식됨. 파일 내 전체 슬러그
        'REG-DT-BADGE-LIVE-CLICKTHROUGH' 확인 후 적용
