  들어 있으나 _mvCountColumns() 에 해당 열이 없어 화면에는 표시되지 않는다(죽은 필드).
  표시 계층 작업이므로 이 필드는 건드리지 않았다.

3. 변경 내용
────────────────────────────────────────────────────────────────────────
[3-1] 1단계 결과 중복 표시 제거
  2단계 렌더가 _mvCountGridData(= _mvWithPrevStageStatus 래퍼) 를 거치지 않고
  _mvCountColumns() / _mvCountRows() 를 직접 사용하도록 바꿨다. 그 결과 '쿼리검토' 열이
  구조적으로 생성되지 않는다. _mvCountGridData/_mvCountGridHtml 함수 자체는 일괄검증 등
  다른 호출부가 있어 무수정으로 남겼다(범위 밖 영향 차단).

[3-2] 그리드 → 타일 7개
  _mvRenderGrid / _mvCountGridHtml / pageInfo / mv-tab-host 호출을 걷어냈다. 이들이
  정렬 헤더·정렬 화살표·'초기 순서'·페이지네이션의 발생원이다.
  신설 함수: _mvCountTilesHtml / _mvPaintCountTiles / _mvRenderCountHeaderOnly.

  타일 CSS(.mv-qr-tiles / .mv-qr-tile / .mv-qr-tile-label / .mv-qr-tile-box /
  .mv-qr-tile-val)와 타일 1개 빌더(_mvQrTileHtml)는 1단계 것을 그대로 재사용했다.
  클래스명은 1단계(query review)에서 유래했지만, 규격을 한 곳에서 관리하려고 공용으로 쓴다.
  → 2단계 전용 CSS/규격을 새로 만들지 않았다(규격 이원화 방지, CSS 변경 0줄).

[3-3] 값 계산 로직 무수정
  라벨/순서 = _mvCountColumns() 그대로:
    원본 테이블 | 목적 테이블 | 검증항목 | 원본 건수 | 대상 건수 | 차이 | 상태
  값 = _mvCountRows() 결과 그대로(천단위 구분·차이 부호·'-' 표기 전부 기존 그대로).
  상태 타일은 기존 배지(_mvStatusIcon), tooltip 은 기존 <field>Tip 을 박스 title 로 보존.
  _countState 분기·COUNT 게이트 카드·COUNT SQL 접힘·오류 상세 표시는 전부 무수정.

  · 'No' 열은 그리드 순번이라 타일에서는 의미가 없어 제외했다(1단계와 동일 처리).
  · 처리시간 타일은 만들지 않았다. 지침이 "현재 COUNT 사전검증이 실제로 보여주는 필드를
    그대로 가져오라"고 했고, 2단계 처리시간은 이미 상단 공통 '2단계 처리시간' 슬롯에
    표시되고 있어 새 항목을 추가하지 않았다. (1단계는 별도 지침으로 처리시간 열을
    신설했던 경우라 사정이 다르다.)

[3-4] 라벨 먼저·값 나중 (1단계와 동일 동작)
  진입점 3곳에 배선했다.
    · _mvShowCountSqlGate()  — 게이트 진입 시 라벨 강제 렌더(force=true)
    · renderCountSqls()      — countOut 재생성으로 #countResult 가 새 빈 div 가 되므로 라벨 복구
    · _applySinglePane()     — 2단계 pane 진입 시(1단계 훅과 대칭)
  force=false 는 이미 값이 그려져 있으면 덮어쓰지 않는다 → 재진입 시 COUNT 결과가 사라지지 않는다.

[3-5] 카드 헤더 보조문구 삭제
  '원본·목적지 건수 비교 — 불일치 시 통계검증 보류' 를 제거했다. 두 가지 이유다.
    ① 앞부분은 타일 라벨(원본 건수/대상 건수/차이)이 이미 항목별로 표시하는 중복 안내다
       (1단계 보조문구 삭제와 동일 기준).
    ② 뒷부분은 현재 동작과 어긋난다 — COUNT 불일치는 비차단이고, 화면도 'COUNT 불일치는
       검증을 중단하지 않습니다'라고 안내한다. 실제 차단 사유(목적지 0건 등)는 COUNT 게이트
       카드가 따로 표시한다. 즉 존치하면 문구와 동작이 어긋난 상태가 유지된다.
  제목 'COUNT 사전검증' 은 유지했다.

6. 구조적 검토 (기술부채 관점)
────────────────────────────────────────────────────────────────────────
· 긍정: 1단계에서 만든 타일 CSS/빌더를 재사용해 CSS 추가 0줄. 규격이 한 곳에 모여 있어
  이후 3~5단계 적용 시에도 같은 방식으로 확장 가능하다.
· 남은 부채 ①: 타일 클래스명이 'mv-qr-*'(query review 유래)라 2단계 이후에서는 이름과
  의미가 어긋난다. 3~5단계까지 적용이 끝난 뒤 중립적 이름(예: mv-stage-tile-*)으로
  일괄 개명하는 편이 낫다 — 지금 개명하면 1단계 회귀 위험만 커진다.
· 남은 부채 ②: _mvCountRows() 가 화면에 쓰지 않는 필드(insCols/selCols)를 계속 만든다.
  표시 계층 작업 범위 밖이라 손대지 않았다.
· 남은 갭: 상위 단계 변경으로 무효화되어 countOut 이 통째로 비워지면(_clr('countOut'))
  #countResult DOM 자체가 사라져 라벨도 함께 사라진다. 이는 before 와 동일한 동작이라
  회귀는 아니며, 재분석 시 _mvShowCountSqlGate 경로로 라벨이 복구된다.
· web_server.py 는 건드리지 않았고, 변경은 ui/tabler_renderer.py 표시 계층에 한정된다.
