작업명 : REG-DT-BADGE-TEXT-REMARKS-TRIPLE-INCONSISTENCY-FINAL-FIX
✅ 작업 완료 - REG_DT 개별 후보표의 배지·선정사유·비고 세 곳을 단일 판정(selectable)으로 통일, before(모순)/after(일치) 실측 확인

────────────────────────────────────────────────────────────────────────
1. '정책상제외' 배지 조건 규명 (추측 없이 코드 추적)
────────────────────────────────────────────────────────────────────────
개별 후보표(ui/tabler_renderer.py buildRow)의 '추천'란 배지는 다음 단일 값에서 나온다:
  badgeSt = _recBlocked ? 'BLOCKED' : (!selectable ? 'EXCLUDED_BY_RULE' : disp.status)
  selectable = !isSumPolicyExcl && !isRuleExcl && !isAdminAudit
  · isRuleExcl   = (selection_status === 'EXCLUDED_BY_RULE')
  · isAdminAudit = _isAdminAuditCol → admin_audit_verdict === 'CONFIRMED'
즉 '정책상제외' 배지는 selection_status=EXCLUDED_BY_RULE(또는 CONFIRMED 관리컬럼)일 때 뜬다.

REG_DT 실측(oracle_reg_dt_postcount_repro.py, 실 오라클 MV_ORA_DEMO_SRC postcount 경로):
  selection_status = AVAILABLE_ADDITIONAL   (EXCLUDED_BY_RULE 아님)
  recommendation_status = SELECTABLE, display_badge_label = 선택가능
  admin_audit_verdict = NAMING_VALUE_MISMATCH, naming_value_mismatch_flag = True
  is_admin_audit_column = False, date_bucket_candidate = True, recommended_bucket = month
→ REG_DT 는 EXCLUDED_BY_RULE(원래 배제) 가 아니라 NAMING_VALUE_MISMATCH(제외 아님·후보 유지·
  검토 권유) 케이스이므로 '정책상제외' 배지는 이 컬럼에 붙어서는 안 되는 라벨이다.

배지 자체는 이미 selectable(=selection_status) 기반이라 REG_DT(AVAILABLE)는 '선택가능'이 정상이다.
문제는 '비고'와 '선정 사유'가 배지와 '다른 조건'을 각자 참조한 데 있었다:
  · 비고 기간 컨트롤(드롭다운+변환필요 버튼): 조건 = (isDateBucket && !isAdminAudit)  ← selectable 미참조
  · 선정 사유(_candDecisionReason): date_bucket 이면 '선택할 수 있습니다' 문구를 selectable 무관하게 반환
그 결과 selection_status=EXCLUDED_BY_RULE 인데 date_bucket=True 인 (stale) 후보에서
배지='정책상제외' / 사유='선택할 수 있습니다' / 비고=기간드롭다운+변환필요 의 삼중 모순이 발생한다.

────────────────────────────────────────────────────────────────────────
2. 통일된 판정 소스 구조 (세 곳이 하나의 selectable 를 공유)
────────────────────────────────────────────────────────────────────────
ui/tabler_renderer.py (커밋 807f02e) — 개별표에 한정, 단일 판정 = selectable:
  ① 배지        : 종전대로 selectable 기반 (변경 없음, 이미 단일 출처)
  ② 비고 기간컨트롤: (isDateBucket && !isAdminAudit) → (isDateBucket && selectable)  로 게이트 통일
  ③ 비고 '변환 필요' 태그 제거: (_isAdminAuditCol) → (!selectable) 로 확대
  ④ 선정 사유   : _candDecisionReason(c, isGb) → _candDecisionReason(c, isGb, selectable)
                  isDate 분기 앞에 'if (isDate && selectable === false) return 제외 사유' 추가
                  (선택불가 후보에는 '선택 가능' 날짜 문구를 반환하지 않음)
selectable = !isSumPolicyExcl && !isRuleExcl && !isAdminAudit 이므로 관리컬럼(CONFIRMED)은 종전과
동일하게 숨겨지고, selectable=true 인 정상 날짜후보(REG_DT: AVAILABLE)는 종전대로 렌더된다.
JS 에서 재판정하지 않고 호출부가 이미 계산한 selectable 만 전달·참조한다(단일 출처 존중).

배치 후보표(_buildUnifiedRow)는 date_bucket 이면 배지를 항상 '참고후보'로 쓰고 체크박스도 항상
disabled 이라 '정책상제외' 모순이 애초에 없다 → 회귀 위험을 피해 이번 수정 범위에서 제외(현행 유지).
