작성일: 2026-07-28

────────────────────────────────────────────────────────────────────────
1. 배경
────────────────────────────────────────────────────────────────────────
선행 작업 STATS-COUNT-STEP-TIMEOUT-PARITY-FIX 로 2단계 COUNT 비교 SQL 에도
실행 시간 상한(COUNT_STATEMENT_TIMEOUT_MS, 기본 60000ms,
env MV_COUNT_STATEMENT_TIMEOUT_MS)이 도입되었다. 그 결과 "2단계 COUNT 에는
타임아웃이 없다"는 전제로 작성된 주석·문서 서술이 사실과 어긋난 상태로 남았고,
선행 작업 완료 시 별건으로 명시되었다. 이번 작업은 그 2곳(및 문서 내 동일
취지의 잔여 서술)을 현재 사실에 맞게 동기화한 것이다.

범위 원칙: services/stats_execute_service.py 와
docs/STATS_VALIDATION_CHUNKED_VS_SINGLE_TRADEOFF.md 두 파일의 주석/문서
텍스트만 수정한다. 코드 로직은 일절 건드리지 않는다.

────────────────────────────────────────────────────────────────────────
2. 수정 전 사실관계 확인 (근거)
────────────────────────────────────────────────────────────────────────
문서를 고치기 전에 코드에서 현재 사실을 먼저 확인했다.

- services/db_query_service.py:270
    COUNT_STATEMENT_TIMEOUT_MS = int(_os.environ.get("MV_COUNT_STATEMENT_TIMEOUT_MS", "60000"))
  → 기본 60000ms, env 이름 MV_COUNT_STATEMENT_TIMEOUT_MS 확정.

- services/db_query_service.py:561
    def _cmn_db_fetch_count(db_info: dict, sql: str, *, statement_timeout_ms: int | None = None) -> int:
  → timeout 인자가 실제로 존재한다("인자 없음"이라는 기존 서술이 사실과 다름).
    docstring(:564~569)상 미지정(None)이면 COUNT_STATEMENT_TIMEOUT_MS 를 쓰고,
    4단계와 동일 메커니즘(env 주입 + DBMS 어댑터 registry apply_query_timeout)을
    재사용하며, 초과 시 드라이버 예외가 호출측 기존 실행오류 경로로 처리된다.

- services/db_query_service.py:264~268
    값 선택 근거(내부망 PG 3,000만 행 정상 COUNT(*) 가 24.6초 → 30초 급은 오탐,
    COUNT 는 뒤이을 GROUP BY 보다 항상 가벼우므로 60초 초과도 무의미)
  → 문서 보강 시 이 근거를 그대로 인용했다(임의 수치 창작 없음).

5. 남는 이슈 / 판단 근거
────────────────────────────────────────────────────────────────────────
- 이번 작업은 사실 동기화이며 동작 변경이 전혀 없다. 실 DB 재실측은 수행하지 않았고
  필요하지도 않다. 문서에 새로 적은 수치(60000ms, 24.6초, env 이름)는 전부
  db_query_service.py 소스 주석·선언에서 그대로 인용한 값이다.
- 진단 문서의 §3~§5 실측 수치(처리량, 청크 배수, 중단 시나리오)는 이번 변경과
  무관하므로 손대지 않았다. 이들은 4단계 통계검증 SQL 기준 측정치이고 2단계 COUNT
  타임아웃 도입으로 값이 달라지지 않는다.
- 라인 참조(§2-1 의 :47, :270 등)는 소스가 바뀌면 다시 어긋날 수 있는 구조적 취약점이다.
  이번엔 실측으로 맞췄으나, 문서에 라인 번호를 적는 관행 자체가 유지비를 만든다는 점은
  남는 부채로 기록해 둔다(상수명 기준 표기가 더 안전).
