────────────────────────────────────────────────────────────────────────
1. 선택한 방식과 이유 — "제거" 가 아니라 "안내 문구"
────────────────────────────────────────────────────────────────────────
지침이 준 두 선택지 중 **안내 문구 추가**를 택했다. 코드 영향이 더 적을 뿐 아니라,
"제거" 는 이번 지침이 금지한 데이터 스키마 변경을 간접적으로 유발하기 때문이다.

  [제거를 택했을 때 발생하는 부작용 — 실제 코드 경로로 확인]
   · ui/tabler_renderer.py:_pfCollectAdvanced() 는 화면에 렌더된 [data-pf-field] 요소만
     훑어 advanced_options 를 재구성한다(:14650~14676).
   · 따라서 spec 에서 encoding/nencoding 을 지우면, 사용자가 오라클 프로필을 한 번이라도
     "수정→저장" 하는 순간 db_presets_*.json 의 encoding/nencoding 키가 조용히 사라진다.
     → 지침의 "JSON 키 자체는 이번에 삭제하지 말 것(스키마 미변경)" 과 정면 충돌.
   · 값은 JSON 에 남아 있는데 화면 어디에도 안 보이는 '숨은 상태' 가 되는 구간도 생긴다.

  [안내 문구 방식의 영향 범위]
   · 변경은 spec 항목 2개의 note 문자열뿐 — 렌더 로직·수집 로직·저장 경로 무접촉.
   · 데이터 스키마 무변경, 기존 preset 값 보존, 사용자 오해(=설정했다고 착각)는 해소.

  [죽은 설정임을 확인한 근거 — 실코드 확인]
   · services/db_adapters/oracle.py:112~138 connect() : makedsn + user/password/dsn 만 사용.
     encoding/nencoding 을 읽는 구문 없음.
   · services/db_connection_service.py : 'encoding' 문자열 자체가 0건.
   · 저장소 전체에서 이 키를 참조하는 곳은 scripts/dev_e2e/* 5개뿐이며, 전부 프리셋 JSON 의
     키를 payload 로 복사만 할 뿐 서버가 무시한다.
   · 즉 oracledb 4.x 가 파라미터 자체를 지원하지 않고 항상 UTF-8 로 고정 → 값은 무의미.
