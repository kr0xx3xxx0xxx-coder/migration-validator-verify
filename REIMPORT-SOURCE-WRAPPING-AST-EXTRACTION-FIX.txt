[2] 수정 내용 — routes/agg_diff_route.py 1개 파일
────────────────────────────────────────────────────────────────────────────
 (1) `_wrapping_extract_feasibility(raw, dialect) -> (feasible, code, text)` 신규 — AST 사전 판정
     `_raw_union_present` 와 동일한 4요소 규약을 그대로 따른다:
       ① 함수 안 try import(선택적 의존 방어)  ② error_level=IGNORE(부분 파싱 허용)
       ③ 실패 시 폴백 방향을 명시적으로 선택   ④ 원문 무변형(읽기 전용 분석)
     검사 항목은 `_extract_aliased_inner_select` / `_union_aliased_inner_select` 의 전제를 그대로 반영:
       INSERT 문 여부 · INSERT 컬럼 목록 명시 · 본문 SELECT/UNION · 브랜치별 projection 수 일치 ·
       SELECT * 부재. 원인 코드 8종(SQLGLOT_UNAVAILABLE / PARSE_FAILED / NOT_INSERT /
       NOT_SELECT_BODY / UNION_BRANCH_NOT_SELECT / NO_INSERT_COLUMN_LIST /
       PROJECTION_COUNT_MISMATCH / SELECT_STAR) + 한글 사유 문구.
     ※ 이 함수의 폴백은 '안전측 True' 가 아니라 **원인 확정 False** 다. 파서를 못 쓰거나 파싱이
       실패하면 하위 추출도 같은 parse_one 을 쓰므로 추출 실패는 가능성이 아니라 확정 사실이다.
       안전측 판단은 호출측이 내린다 — 판정과 정책을 분리했다.

 (2) `_reimport_simple_shape_evidence(req, raw, dialect) -> True/False/None` 신규 — 2차 근거
     AST 판정이 불가할 때만 쓴다. sqlglot 없이 동작하는 출처만 사용:
       ① req.parse_result 의 union_type / union_branches / joins
          ('union_type' 키 자체가 없는 옛 payload 는 근거로 인정하지 않는다)
       ② services.sql_cte_utils(정규식 폴백 보유) 의 CTE 이름 · 물리 테이블 수 · INSERT 대상 테이블
     단순 1:1 확정 조건: UNION/JOIN 근거 없음 + CTE 없음 + 물리 원본 정확히 1개 +
     'INSERT INTO x' 확인 + 단순 재파생 정보(select_items·insert_cols·from_table) 보유.
     하나라도 미충족이면 None(근거 없음) → 호출측이 안전측 유지.

 (3) `_reimport_source_needs_wrapping` 의 `_union is None` 분기 수정
     기존: 무조건 True(S1). 변경: **wrapping 이 확정 실패하고(1) + 2차 근거가 단순 1:1 이라고
     적극 반증할 때(2)에 한해** False(기존 _derive_row_sqls 경로 유지). 그 외는 종전대로 True.
     sqlglot 가용 환경에서는 이 분기 자체를 타지 않으므로 판정·성능 모두 완전 무변경이다.

 (4) `_wrapping_hold_reason(err, raw, dialect)` 신규 + `_pk_resolve` 배선
     wrapping 실패로 HOLD 할 때 AST 로 특정한 실제 원인을 "[원인: …]" 으로 덧붙인다.
     원인을 특정하지 못하면 원문 그대로 반환한다(문구 날조 금지).

[3] 요구사항 3 — HOLD 유지 vs 기존 경로 유지, 실측 근거에 따른 선택
────────────────────────────────────────────────────────────────────────────
 지침이 제시한 두 방향을 **케이스별로 갈라서** 적용했다. 근거는 [1] 의 실측이다.

 ▶ 방향 A "HOLD 유지 + 정확한 사유" 를 선택한 케이스 — B2 B3 B4 C2 E1 F1 H1 (7건 전부)
   이들은 wrapping 이 **적극적 근거로** 선택된 형태다(UNION 검출 / CTE 검출 / 물리 원본 2개↑).
   여기서 단순 _derive_row_sqls 로 내리면 어떻게 되는지는 이미 측정돼 있다 — 같은 함수의 FN 측
   실측(SQLGLOT-USAGE-CONSISTENCY-AUDIT-DIAGNOSE [2] 2-1)에서 동일테이블 UNION 이 단순 재파생으로
   흘렀을 때 **원본 25만행 중 12.5만행만 비교, 재이관 대상 150건 중 75건만 산출, 남은 12.5만행
   전부가 '목적지 단독' 으로 오분류**됐다. 오류도 HOLD 도 아닌 조용한 과소집계다.
   → 기능을 살리자고 조용히 틀린 숫자를 내는 교환은 하지 않는다. HOLD 를 유지하고 사유만 사실로 맞췄다.

 ▶ 방향 B "기존 경로 유지" 를 선택한 케이스 — `_union is None` + 단순 1:1 반증 확보
   이 경로에서 True 는 '안전한 감싸기' 가 아니라 **확정 HOLD** 다([1] 차단 시뮬레이션에서 입증:
   단순 1:1 A1/A2 까지 100% HOLD). 즉 안전측이 얻는 것이 없고 기능만 죽는다.
   또한 여기서 유지하는 경로는 S1 이전에 정상 동작하던 바로 그 경로이며, 근거 없이 되돌리는 것이
   아니라 **파서 없이도 확인 가능한 독립 근거(parse_result 의 union/join + 정규식 폴백 CTE/테이블 수 +
   INSERT 대상 확인)가 단순 1:1 을 적극 반증할 때만** 유지한다.
   → '모르면 감싼다(S1)' 는 그대로다. 바뀐 것은 '모른다' 의 정의뿐 — 반증이 있으면 모르는 게 아니다.

 ▶ 채택하지 않은 대안: '추출 실패 시 무조건 단순 경로로 폴백'.
   B2/C2/F1 같은 UNION·CTE 형태까지 단순 재파생으로 흘러 위 25만행 사례를 재생산한다. 기각.

   케이스                     AST 원인코드                 표시 사유

   B2 UNION ALL(컬럼목록 X)   NO_INSERT_COLUMN_LIST      INSERT 대상 컬럼 목록이 SQL 에 명시돼
                                                        있지 않습니다(INSERT INTO t SELECT …
                                                        형태 — 컬럼 목록을 명시하면 지원됩니다)

                                                        다릅니다(INSERT 2개 / SELECT 1개)
