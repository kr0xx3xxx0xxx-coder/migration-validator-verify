3. [1번] 데이터 변경 감지 — 변경 없음 · 되돌리기 후 재검증(실 오라클 스모크)
────────────────────────────────────────────────────────────────────────────
 (직전 완료보고의 실측 결과를 그대로 인용 — 이번 되돌리기 후 동일 드라이버로 재실행해 동일 결과 확인)

 환경 : 포트 8000, Oracle asis→tobe, NXDNP.MV_COMBO_SRC/TGT(각 1,200행),
        GROUP BY = STATUS_CD + DEPT_CD(조합), SUM = AMT.
 대상 그룹 : STATUS_CD='A' · DEPT_CD='D01'
        원본 CNT=100 / SUM=100,299   목적 CNT=100 / SUM=99,299
        → COUNT 는 완전히 같고 SUM 만 다르다. COUNT 만 비교했다면 절대 감지 못 했을 형태다.

   +----+--------------------------------------+------------------+----------+---------+--------+
   | 단 | 동작                                 | 목적 SUM(실 DB)  | run_id   | reused  | 재이관 |
   +----+--------------------------------------+------------------+----------+---------+--------+
   |1-a | 그룹 최초 클릭(새 스캔)              | 99,299           | R1       | false   | 100건  |
   |1-b | 접었다 다시 펴기                     | 99,299           | R1(동일) | 캐시적중| 100건  |
   |1-c | 목적 데이터 수정(ID 401~450 AMT+10)  | 99,299 → 99,799  | -        | -       | -      |
   |1-d | 4단계 통계검증 재실행(항상 새 실행)  | 화면 요약 99,799 | -        | -       | -      |
   |1-e | [대조군] group_summary 없이 prepare  | 99,799           | R1(예전) | true    | 100건  |
   |1-f | [실제 클릭] 같은 그룹 클릭           | 99,799           | R2(신규) | false   |  50건  |
   +----+--------------------------------------+------------------+----------+---------+--------+

   · 1-e = 수정 전 코드 동작을 같은 서버에서 재현한 대조군. 데이터가 바뀐 뒤에도 reused=true,
     source=memory_cache 로 이관 전 결과 100건을 그대로 반환 = 이번에 고친 결함 그 자체.
   · 1-f = 수정 후 실제 클릭. invalidated=true, 새 run R2, 재이관 50건(수정 반영된 최신 결과).
   · 전/후 요약 : BEFORE(수정 전 재현) = 100건(stale) / AFTER = 50건(최신)
   · 픽스처 원상복구 : 목적 AMT 되돌려 SUM 99,299 복원 완료(finally 블록).
   · 되돌리기 작업이 1번에 영향을 주지 않았음이 이 재실행으로 확인됐다(결과 완전 동일).

 자체 테스트 : tests/test_stage5_detail_cache_staleness_guard.py 10/10 통과
               (2번 store 함수 테스트 1건만 제거, 1번 감지 로직 테스트는 전부 유지).
