✅ 작업 완료 - SINGLE-SAVE-SSLMODE-PRESET-RESTORE-FIX : /single/save preset 환원 경로의 sslmode 누락을 복원해 비SSL Inter DB 등록 차단(METADATA_BLOCKED) 해소

────────────────────────────────────────────────────────────────────────
1. 무엇이 문제였나 (근본원인)
────────────────────────────────────────────────────────────────────────
개별검증 5단계에서 [그룹 등록]을 누르면 화면은 /single/save 로 저장 payload 를 보낸다.
이때 화면이 보내는 sources 필드는 ui/js_source_owner.py:241 _soOwnerBuildActiveSources() 가
만드는데, 이 함수는 "원본 프로필이 2개 미만이면 빈 배열을 반환"한다(profs.length < 2 → []).
즉 원본이 1개인 일반적인 개별검증에서는 화면이 항상 sources=[] 를 보내고,
서버는 services/single_validation_save_service.py:66 _resolve_authoritative_sources 에서
"src_db 접속정보를 등록된 preset 으로 환원"하는 폴백 경로를 탄다.

그 환원을 담당하는 함수가 services/source_profile_resolver.py 의 preset_to_source() 이고,
이 함수는 preset 에서 db_type/host/port/dbname/user/password/name/connection_id 8개 키만
꺼내는 화이트리스트였다. 여기에 sslmode 가 없었다.

한편 db_presets 는 sslmode 를 preset 최상위가 아니라 advanced_options 안에 보관한다.
실측한 저장값은 다음과 같다.
  PostgreSQL_Inter_asis     advanced_options.sslmode = 'disable'
  PostgreSQL_Inter_tobesrc  advanced_options.sslmode = 'disable'
  PostgreSQL_nxdnp_src      advanced_options.sslmode = 'disable'
  PostgreSQL_NEW_asis       advanced_options.sslmode = 'require'
  PostgreSQL_asis           (sslmode 키 없음)

그리고 접속 어댑터 services/db_adapters/postgresql.py:87 은
  kwargs['sslmode'] = db_info.get('sslmode') or 'require'
로, 값이 없으면 require 를 기본값으로 쓴다.

두 사실이 합쳐져 다음 연쇄가 발생했다.
  화면 sources=[] → preset 환원 → sslmode 유실 → 어댑터가 require 로 접속 시도
  → 비SSL 서버(192.168.0.150)가 SSL 미지원 → 접속 실패
  → ensure_official_metadata 가 metadata 수집 실패(FAILED)
  → single_official_register_service.py:491 이 registration_status='METADATA_BLOCKED' 로 등록 차단

sslmode 강제가 실제로 접속을 끊는다는 것도 직접 확인했다. 같은 Inter DB 에
  sslmode=disable → 접속 성공
  sslmode=require → 실패: 'server does not support SSL, but SSL was required'

즉 화면에서 sources 를 명시로 넣어주면 저장되고, 화면 기본 경로(sources 비움)로는 막히던
비대칭이 그대로 재현된 것이다. 이 갭은 직전 작업(SINGLE-SNAPSHOT-WHITELIST-EXPLAINABILITY-
FIELDS-ADD)의 검증 스크립트가 sources 를 명시 전달해 우회하면서 주석으로 남겨둔 그 지점이다.

"sslmode 를 저장하지 않은 프로필"의 동작이 수정 전과 완전히 동일하게 유지된다.

4. 다른 sslmode 값 회귀 확인
────────────────────────────────────────────────────────────────────────
검증 스크립트: scripts/dev_e2e/single_save_sslmode_other_profiles_regression.py
수정 전(HEAD) 모듈을 git show 로 임시 로드해 같은 입력으로 나란히 비교했다.

(1) 환원 dict 에 실리는 sslmode 값
  프로필                     preset 저장값   before    after
  PostgreSQL_asis            (없음)         (없음)    (없음)
  PostgreSQL_NEW_asis        require        (없음)    require
  PostgreSQL_Inter_asis      disable        (없음)    disable
  PostgreSQL_Inter_tobesrc   disable        (없음)    disable
  PostgreSQL_nxdnp_src       disable        (없음)    disable
  MariaDB_asis / DB2_asis / Oracle_asis  → 전부 (없음), before=after 동일

(2) 실제로 드라이버(psycopg2)에 도달하는 실효 sslmode — 어댑터 호출을 가로채 실측
  프로필                     before 실효   after 실효   동일 여부
  PostgreSQL_asis            require       require      동일
  PostgreSQL_NEW_asis        require       require      동일
  PostgreSQL_Inter_asis      require       disable      변경(의도된 수정)
  PostgreSQL_Inter_tobesrc   require       disable      변경(의도된 수정)
  PostgreSQL_nxdnp_src       require       disable      변경(의도된 수정)

이 (2)번 표가 회귀 여부의 결론이다. sslmode=require 프로필과 sslmode 미지정 프로필은
수정 전후로 드라이버에 도달하는 값이 require 로 완전히 동일하다 — 동작 변화가 없다.
(1)번 표에서 PostgreSQL_NEW_asis 가 "(없음) → require" 로 바뀐 것처럼 보이는 것은
dict 에 키가 명시적으로 들어갔다는 뜻일 뿐, 어댑터가 어차피 require 를 기본값으로 채우므로
실효 동작은 같다. 실제로 값이 달라지는 것은 disable 프로필 3개뿐이고, 그것이 이번 수정의
목적 그 자체다. 비-PostgreSQL 프로필(MariaDB/DB2/Oracle)은 sslmode 자체가 무관하며
before=after 로 변화 없음을 확인했다.

라이브 접속 결과:
  PostgreSQL_Inter_asis / _tobesrc / nxdnp_src → sslmode=disable 로 접속 성공
  PostgreSQL_asis, PostgreSQL_NEW_asis (Neon)  → TLS 핸드셰이크는 통과했으나 서버가
    "Your project has exceeded the data transfer quota" 로 거부.
    이는 Neon 계정의 데이터 전송 쿼터 소진(서버측 사유)이며 코드·sslmode 와 무관하다.
    따라서 require 프로필의 "라이브 저장 end-to-end" 는 이번에 실행할 수 없었고,
    대신 위 (2)번 실효값 실측과 아래 음성 대조로 require 경로가 정상임을 확인했다.
  음성 대조: 비SSL Inter DB 에 일부러 sslmode=require 로 접속하면
    "server does not support SSL, but SSL was required" 로 실패한다.
    → require 가 무시되거나 임의로 바뀌지 않고 그대로 강제됨을 반증적으로 확인.
