[해석]
  - DB 3호스트는 이 PC 위의 VM 이 아니라 별도 머신에서 구동 중이며,
    SSH 만 열려 있고 SMB/RDP/WinRM 이 모두 닫혀 있어 Linux 게스트로 판단됨
    (PostgreSQL 이 Debian 빌드로 응답한 것과 일치).
  - 따라서 "Windows 서비스 시작 유형: 자동" 개념이 이 호스트들에 직접 적용되지 않으며,
    자동시작 여부는 각 게스트의 systemd(systemctl is-enabled) 또는
    컨테이너 restart policy, 그리고 VM 을 호스팅하는 상위 PC 의 VirtualBox
    자동시작 설정에서 결정됨.
  - 이 PC 에서는 해당 설정을 조회할 수단이 없고(SSH 자격증명 미보유),
    지시상 변경도 금지이므로 미확인 상태로 남김.

[재발 방지를 위해 확인이 필요한 지점 — 변경 없이 제안만]
  1. VM 을 호스팅하는 상위 PC 의 VirtualBox VM 자동시작 등록 여부
     (VBoxAutostart 서비스 또는 로그온 시 자동 기동 스크립트)
  2. 각 게스트 내 DB 서비스 enable 여부
     postgres : systemctl is-enabled postgresql / docker inspect --format '{{.HostConfig.RestartPolicy.Name}}'
     oracle   : systemctl is-enabled oracle-xe-23ai (또는 컨테이너 restart policy)
     mariadb  : systemctl is-enabled mariadb
