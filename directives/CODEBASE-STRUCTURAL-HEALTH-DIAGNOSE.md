코드 수정 없이 조사·측정만 해줘.

배경: 오늘 여러 작업에서 "근본 구조(ui/tabler_renderer.py가 파이썬 문자열 안에
거대한 JS를 품고 있음)는 그대로이며 이번 전환은 증상 완화이지 원인 제거가 아니다"
(F5 시리즈), "tests/ 디렉토리 자체가 1,248개 파일까지 비대화된 상태 — 별도 검토
여지"(M66) 같은 언급이 반복됐지만, 정확한 수치로 측정된 적은 없다. 이번에 전체
코드베이스를 실측해서 구조 건강도를 파악한다.

────────────────────────────────────────────────────────────
1. 파일별 크기·책임 분포 실측
────────────────────────────────────────────────────────────
- 전체 소스(`.py`, 그리고 `ui/tabler_renderer.py` 안에 내장된 JS 부분도 별도로)의
  파일별 라인 수를 큰 순서대로 나열해라(상위 20개).
- `ui/tabler_renderer.py`가 정확히 몇 줄인지, 그중 순수 파이썬 코드 대 내장 JS
  문자열의 비율이 대략 어느 정도인지 측정해라.
- 상위 몇 개 파일이 이 프로젝트 전체 소스 라인 수의 몇 %를 차지하는지 계산해라.

────────────────────────────────────────────────────────────
2. "한 파일이 너무 많은 책임을 진다"는 징후 확인
────────────────────────────────────────────────────────────
- `ui/tabler_renderer.py` 안에 실제로 몇 개의 서로 다른 화면/기능(1~5단계, 일괄검증,
  전수검증, 검증경로, 프로젝트 관리 등)이 섞여 있는지 대략 나열해라 — 이게 "단일
  책임 원칙"에서 얼마나 벗어나 있는지 가늠할 수 있게.
- 다른 서비스 파일들(`services/` 아래) 중에서도 비슷하게 큰 파일이 있는지, 있다면
  어떤 책임들이 섞여 있는지 확인해라.

────────────────────────────────────────────────────────────
3. `tests/` 디렉토리 비대화 실측
────────────────────────────────────────────────────────────
- `tests/` 아래 파일 개수, 총 라인 수, 파일명 패턴(batch_*, candidate_* 등)별
  분포를 측정해라.
- 오늘 M66이 발견한 "디렉토리 통째로 넘기면 빠른데 개별 파일 나열하면 느려지는"
  현상이, 이 비대화 자체와 얼마나 관련 있는지 판단해라.

────────────────────────────────────────────────────────────
4. 실무 영향 평가
────────────────────────────────────────────────────────────
- 이 구조가 실제로 오늘 하루 여러 작업에서 걸림돌이 됐던 구체적 사례가 있는지
  되짚어봐라(예: 완료 모듈이라 신중해야 하는 범위가 넓어짐, 검색/수정 시 실수
  가능성 등 — 오늘 실제로 겪은 구체적 사건과 연결지어라).
- 지금 당장 리팩터링이 급한지, 아니면 "알고 있으되 당장 손 안 대도 되는" 수준인지
  판단해라 — 오늘 F5 시리즈가 이미 "증상 완화 우선, 구조 개선은 별도"라고 결론
  냈던 것과 일관되게 판단해라.
