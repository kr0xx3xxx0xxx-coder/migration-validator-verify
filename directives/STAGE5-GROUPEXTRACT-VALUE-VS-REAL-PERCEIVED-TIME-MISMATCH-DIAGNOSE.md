작업명 : STAGE5-GROUPEXTRACT-VALUE-VS-REAL-PERCEIVED-TIME-MISMATCH-DIAGNOSE

배경(스크린샷 3장 근거, 순서대로): 5단계 진입 직후(1번) "5단계 불일치 그룹추출"
0.00초 → R01 그룹 클릭(2번) 후 11.56초로 변경 → G01 그룹 클릭(3번) 후 12.18초로
변경. 사용자가 실제로 클릭했을 때 체감 시간은 두 번 다 **1초 미만**이었다(상세
레코드가 거의 즉시 나타남). 그런데 화면에 표시되는 값은 11.56초, 12.18초로
실제 체감과 10배 이상 차이난다.

사용자 지적: "5단계 불일치 그룹추출"이라는 제목 자체가 "불일치 레코드 추출"이
아니라 "불일치 그룹 추출"이라고 되어 있다 — 이름부터 사용자가 클릭해서 보는
동작(레코드 추출)과 다른 걸 가리키는 것 아니냐는 의심.

────────────────────────────────────────────────────────────
코드 무수정, 정밀 조사만
────────────────────────────────────────────────────────────
1. 이 값(11.56초, 12.18초)이 정확히 어느 시점에 어떻게 계산되는지 코드로
   추적해라 — "가장 최근 클릭한 그룹의 detail_ms"라는 게 오늘 이미 확인된
   설계인데, 그 detail_ms가 "지금 이 클릭에서 실제로 걸린 시간"인지, 아니면
   "이 그룹이 처음 추출됐을 때(과거 어느 시점)의 기록값을 그대로 재사용"하는
   건지 명확히 구분해라.
2. 만약 후자(과거 기록값 재사용)라면 — 사용자가 지금 보는 "1초 미만" 체감은
   "캐시된 결과를 화면에 그리는 시간"이고, 표시되는 "11.56초/12.18초"는
   "이 그룹을 최초로 스캔했을 때(과거, 아마 오늘 앞서 어느 시점) 실제로 걸렸던
   시간"일 가능성이 있다 — 이게 맞는지 실측으로 확인해라. 정확히 언제 이
   그룹들이 최초로 추출됐었는지(오늘 앞선 세션들 로그·DB 기록) 추적 가능하면
   추적해라.
3. 실제로 재현해라: 완전히 새로운 그룹(한 번도 클릭 안 한 그룹)을 골라서
   클릭하고, 그 실제 소요시간(네트워크 요청 시작~응답 도착, 브라우저 devtools
   또는 서버 로그 타임스탬프)을 재고, 그 직후 화면에 표시되는 "5단계 불일치
   그룹추출" 값과 실측 시간이 일치하는지 확인해라.
4. 사용자가 지적한 "제목이 그룹추출이지 레코드추출이 아니다"는 의심에 대해
   명확히 답해라 — 이 값이 실제로 무엇을 재는 값인지(그룹을 찾는 시간인지,
   그 그룹의 레코드를 뽑는 시간인지) 코드 정의 그대로 밝혀라.
