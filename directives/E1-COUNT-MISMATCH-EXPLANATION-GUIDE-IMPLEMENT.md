작업명 : E1-COUNT-MISMATCH-EXPLANATION-GUIDE-IMPLEMENT

LLM-ADDITIONAL-USE-CASE-SURVEY.txt(§5·§7, E1 항목)와
LLM-ADMIN-COLUMN-JUDGMENT-SCOPE-AND-DESIGN-DIAGNOSE.txt(M50, LLM 연동 인프라
설계)를 먼저 읽고 시작해줘. 승인 완료 — 이 프로젝트 최초의 실제 LLM 연동이니
각별히 신중하게 진행해라.

배경: 2단계 COUNT 사전검증에서 건수 불일치가 뜨면, 지금은 원인에 대한 설명이
전혀 없다. E1은 "간접 활용"(판정에는 관여 안 하고 설명·안내만) — 이미 계산된
COUNT 차이·집계 통계량을 바탕으로, 사람이 읽기 쉬운 원인 후보 안내문을 생성한다.

────────────────────────────────────────────────────────────
1. LLM 연동 인프라 (M50 설계 재사용)
────────────────────────────────────────────────────────────
M50이 이미 확정한 설계를 그대로 재사용해라 — 새로 설계하지 마라:
- 연동은 표준 라이브러리 `urllib.request`로 Ollama OpenAI 호환 API 직접 호출
  (신규 패키지 금지).
- 기본 OFF + 미기동/장애 시 fail-open Noop 폴백(기존 하드코딩 문구로 대체) +
  circuit-breaker.
- 캐시는 `db/migration_validator.db` 신규 테이블, model_id+prompt_version으로
  자동 무효화, 원문 응답 저장(설명가능성).

────────────────────────────────────────────────────────────
2. E1 안전조건 4가지 (필수, 오늘 조사가 못박은 것)
────────────────────────────────────────────────────────────
(a) 화면에 표시되는 판정값·수치는 전부 서버 계산값만 사용 — 모델이 만든 숫자를
    화면에 절대 표시하지 마라.
(b) 모델에는 집계 통계량(건수 차이, 컬럼별 요약 등)만 전달하고, 실제 레코드 값은
    전달하지 마라(개인정보·민감정보 유출 방지).
(c) 단정문 금지 — "원인은 X입니다"가 아니라 "먼저 확인해볼 것: X" 같은 제안형
    문장으로만 생성하도록 프롬프트를 설계해라.
(d) LLM 미기동 시 기존 하드코딩 문구로 폴백(1번의 fail-open과 동일).

────────────────────────────────────────────────────────────
3. 신뢰 표기 규칙 (오늘 조사 §7-3)
────────────────────────────────────────────────────────────
- LLM이 생성한 문장에는 출처 표기(모델명·생성시각)를 붙여라 — 1번에서 캐시에
  이미 저장하기로 한 model_id/생성시각을 화면에 그대로 노출하면 된다.
- 판정 배지·수치(COUNT 값 자체 등)에는 LLM 표기가 절대 붙으면 안 된다 — 이 영역은
  이번 작업과 무관하게 그대로 유지돼야 한다.

────────────────────────────────────────────────────────────
4. 적용 범위 (개별검증 우선, 일괄은 이번 범위 아님)
────────────────────────────────────────────────────────────
이번 지침은 **개별검증(2단계 COUNT 사전검증) 화면 한정**으로 진행해라. 일괄검증
확장(오늘 조사가 제안한 "행별 안내가 아니라 배치 요약 1건" 형태)은 이번 범위가
아니다 — 개별에서 먼저 안전성을 확인한 뒤 별도로 검토한다.

────────────────────────────────────────────────────────────
검증(필수, 실측)
────────────────────────────────────────────────────────────
- 실제 COUNT 불일치를 재현해서, 안내문이 실제로 생성되는지, 안전조건 4가지가
  전부 지켜지는지(단정문 없는지, 실 레코드 값이 모델에 안 들어가는지 등) 확인.
- LLM(Ollama)이 기동 안 된 상태에서 정상적으로 기존 하드코딩 문구로 폴백되는지
  확인(이 프로젝트 실사용 환경 상당수가 인프라 없이 돌아갈 수 있으니 이 폴백이
  핵심).
- 판정 배지·COUNT 수치 자체에는 LLM 관련 표기가 전혀 안 붙는지 확인.
- 캐시가 정상 작동해서 같은 상황 재요청 시 모델을 다시 안 부르는지 확인.
- 관련 테스트 서브셋 + baseline 대조, 신규 회귀 0건.
- CLAUDE.md 필수 회귀(virtual/complex) 최종 1회.
- 완료보고: 파일:라인, 인프라 구현 내역, 안전조건 4가지 각각 검증 결과, 폴백
  동작 확인, 커밋해시. 작업명 첫줄/마지막줄.
