작업명 : COMBO-UNVERIFIED-FALSE-CONFIDENCE-STATUS-DISPLAY-CHECK

코드 수정 없이 조사·실측만 해줘.

배경: GROUPBY-COMBO-NOTICE-RELOCATE-AND-DEFAULT-COMBO-FEASIBILITY-DIAGNOSE에서
"조합(다축 동시) 검증"은 체크박스(옵트인, 기본 OFF)로 유지하기로 결론났다.
사용자가 중요한 위험을 지적했다: "각 축을 개별로 조회하면 문제없는데, 그
축들의 조합에서만 드러나는 진짜 불일치가 있을 수 있다. 체크박스를 안 켜고
넘어가면, 사용자가 상단 '상태' 표시(예: 🟢 일치)만 보고 실제로는 검증 안 된
부분이 있는데도 '정상'이라고 잘못 믿을 위험이 있는 것 아니냐."

────────────────────────────────────────────────────────────
1. 코드로 확인
────────────────────────────────────────────────────────────
- 모든 개별 축이 일치(불일치 0건)이고, 조합 체크박스는 안 켠 상태일 때, 4/5단계
  상단 "상태" 칸이 정확히 뭐라고 표시되는지 확인해라 — 무조건 "🟢 일치/정상"
  으로 뜨는지, 아니면 "조합 미검증"이라는 사실이 이 상태 표시 자체에도 반영
  되는지(예: 다른 색, 다른 문구, 배지 등) 확인해라.
- 오늘 만든 "조합 미검증" 경고 배너가, 이 경우(개별 축은 전부 일치)에도 여전히
  뜨는지 확인해라 — 배너 로직이 "불일치가 있을 때만" 뜨는 건지, "조합을 안
  켰으면 개별축 결과와 무관하게 항상" 뜨는 건지 확인해라.

────────────────────────────────────────────────────────────
2. 실제로 재현
────────────────────────────────────────────────────────────
개별 축은 전부 일치하지만 조합에서만 불일치가 드러나는 인위적 픽스처를 만들어서
(예: REGION_CD 축은 개수만 맞고, STATUS_CD 축도 개수만 맞는데, 실제로는
REGION_CD+STATUS_CD 조합별로 보면 서로 다른 조합으로 뒤바뀐 데이터), 조합
체크박스를 끈 채로 4~5단계를 실행해서 화면이 실제로 어떻게 보이는지 확인해라.

────────────────────────────────────────────────────────────
3. 판단
────────────────────────────────────────────────────────────
- 지금 화면이 이 위험(거짓 안심)을 실제로 방지하고 있는지, 아니면 사용자
  우려가 실재하는 문제인지 판단해라.
- 문제가 실재한다면, 상단 "상태" 칸 자체를 개선하는 방안을 제안해라(예: 개별
  축은 전부 일치해도 조합 미검증이면 "🟡 일치(조합 미검증)"처럼 무조건 확정
  적인 "일치"로 표시하지 않는 방식 등) — 구현은 하지 마라, 조사·제안까지만.
