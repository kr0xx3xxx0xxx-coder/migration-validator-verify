작업명 : M74-A3-PG-SCRIPT-EXPAND-AND-B1TOB7-BATCH-REVERIFY

BACKLOG.md M74 항목(A3, B1~B7)을 먼저 읽고 시작해줘. 승인 완료. 코드 무수정
(scripts/dev_e2e 신규 스크립트 추가는 허용), 순수 실측 조사 작업이다.

배경: scripts/dev_e2e/ 라이브 스크립트가 오라클:PostgreSQL=50:4로 극단 편중된
게 B1~B7 항목들이 "PG 접속실패로 미실측"에 반복적으로 막힌 근본 원인이었다.
오늘 P13 재측정 작업에서 PostgreSQL_Inter_asis(내부망)와 PostgreSQL_tobe
(클라우드 Neon) 접속이 안정적으로 성공한 사례가 있으니, 인프라 자체는 지금
쓸 수 있는 상태일 가능성이 높다.

────────────────────────────────────────────────────────────
1. PG 라이브 스크립트 확충
────────────────────────────────────────────────────────────
B1~B7 각 항목이 필요로 하는 PG 라이브 재현/검증 스크립트를 최소한으로 만들어라
(50:4 비율을 억지로 맞추라는 게 아니라, B1~B7을 실제로 검증하는 데 필요한 만큼만).

────────────────────────────────────────────────────────────
2. B1~B7 일괄 재실측
────────────────────────────────────────────────────────────
각 보고서에 이미 남겨진 재실행 커맨드를 참고해서(BACKLOG.md 근거 보고서들 확인),
PostgreSQL 환경에서 하나씩 재검증해라:
  - B1: PK_RANGE_CHUNK 정렬순서
  - B2: JOIN pushdown 비용
  - B3: alias-derive 래핑(오라클 문법특정 결함이라 PG 무관 판정된 것 — 이것도
        PG에서 문제 없음을 확인만 하면 됨)
  - B4: 문자PK 경계값 재확인
  - B5: agg_contribution scope캐스트(문자열 대조만)
  - B6: N1-P1 해시경로 개선폭(정량수치는 오라클 전용이라 PG에서는 정성적
        확인만 가능할 수 있음 — 안 되면 안 된다고 명시)
  - B7: NLS_COMP=BINARY 대응 PG측 세션 고정 여부

접속이 안 되거나 재현이 안 되는 항목이 있으면, 억지로 만들지 말고 "여전히 확인
불가(사유)"로 정직하게 남겨라.
