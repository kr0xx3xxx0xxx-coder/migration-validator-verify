작업명 : C-DRIVE-LEGACY-SOURCE-CHECK-AND-X-DRIVE-CONSOLIDATE

**주의: X:\Projects\Migration_Validator에는 절대 쓰기/수정을 하지 마라 — 지금 다른
작업(M67/N1-P1/N1-P2)이 그 저장소를 동시에 건드리고 있을 수 있다. 이번 지침은
C드라이브 조사와 X드라이브에 대한 읽기 전용 조회(git log, git status, 파일
수정일자 확인 등)만 하면 되고 쓰기 작업이 없으니 병행 진행 가능하다 — 다른 작업이
끝나길 기다릴 필요 없다.**

배경: 소스 저장소 위치가 과거 C:\projects\migration-validator에서
X:\Projects\Migration_Validator로 이전됐다(오늘 모든 완료보고서가 X드라이브
경로를 사용 중). 혹시 C드라이브 옛 소스에 X드라이브로 안 옮겨진 변경사항이
남아있는지, 또는 최근 누군가 실수로 C드라이브 쪽에 작업해서 X드라이브와
어긋난 부분이 있는지 확인이 필요하다.

────────────────────────────────────────────────────────────
1. C드라이브 옛 소스 상태 확인
────────────────────────────────────────────────────────────
`C:\projects\migration-validator`(또는 실제 옛 경로)가 지금도 존재하는지 확인하고,
존재한다면:
- **파일 수정일자(mtime)를 기준으로 최근에 손댄 흔적이 있는지 먼저 훑어라**(예:
  `find . -newer <기준시각>` 류, 또는 디렉토리 전체를 수정일자 내림차순 정렬해서
  상위 파일들 확인) — git 커밋 여부와 무관하게 "누가 최근에 이 폴더 파일을 열어서
  저장했는지"를 가장 빠르게 알 수 있는 방법이다.
- git log로 마지막 커밋 시각·해시를 확인해서, X드라이브 저장소의 히스토리와
  비교해라(X쪽은 읽기 전용 조회만) — C드라이브가 X드라이브보다 최신인 커밋을
  갖고 있다면(즉 X로 옮겨진 이후 C에서 뭔가 더 작업된 흔적), 정확히 어떤 파일이
  다른지 diff로 확인해라.
- `git status`로 C드라이브에 커밋 안 된 미반영 변경사항이 남아있는지도 확인해라.

────────────────────────────────────────────────────────────
2. X드라이브가 최신 기준이 맞는지 재확인 (읽기 전용)
────────────────────────────────────────────────────────────
X:\Projects\Migration_Validator의 최근 커밋들(오늘 하루 작업분 포함)이 실제로
C드라이브에는 없는 최신 상태인지 교차 확인해라. **`git log`/`git status`/`git diff`
같은 읽기 전용 명령만 쓰고, 어떤 파일도 수정·생성·삭제하지 마라.**

────────────────────────────────────────────────────────────
3. 처리
────────────────────────────────────────────────────────────
- C드라이브에 X드라이브보다 최신이거나 C에만 있는 유의미한 변경이 발견되면,
  **바로 병합하지 말고** 정확히 어떤 파일·어떤 내용인지 완료보고에 상세히 남기고
  판단을 기다려라(실수로 최신 작업을 덮어쓸 위험이 있는 작업이니 신중하게).
- C드라이브가 단순히 X드라이브 이전 시점의 완전한 부분집합(더 옛날 상태, 새로운
  게 없음)으로 확인되면, C드라이브 디렉토리를 삭제해도 안전한지 판단해서
  완료보고에 "삭제해도 안전함/위험함"을 명시해라(실제 삭제는 하지 마라 — 판단만).
- 그 외 X드라이브에 옮겨지지 않고 남아있는 관련 파일(스크립트, 설정, 픽스처 등)이
  있다면 목록으로 정리해라.

완료보고: 1~3 결과, C/X 두 저장소의 정확한 차이(있다면), 안전한 정리 방향 제안.
실제 삭제나 강제 병합은 하지 말고 조사·비교까지만.
