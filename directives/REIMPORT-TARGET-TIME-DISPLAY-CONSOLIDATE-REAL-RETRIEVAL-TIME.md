배경: "전체 재이관 대상 : 101건 (23.22초 · 저장 데이터)"의 "23.22초"가
과거(TTL 없는 캐시로 며칠 전) 콜드 스캔 실측치를 그대로 보여주고 있어
혼란을 준다. 이 문구 바로 아래 별도로 "현재 페이지 조회 0.12초 · 내부 DB
0.01초 미만 · 서버 0.01초 미만 · 전체 요청 0.12초 · 화면 0.01초 미만"이
또 있는데, 이건 완전히 다른 작업(로컬 인덱스 페이지 조회)을 잰 것이다.

사용자가 재설계 방향을 확정했다:
1. "23.22초" 자리에는, 과거 원본 스캔 시각의 값이 아니라 "이번 조회에서
   실제로 걸린 시간"(캐시 히트면 빠르게, 콜드 스캔이면 느리게 — 그때그때
   정직하게 측정)이 나와야 한다. 캐시 자체(데이터 재사용)는 그대로 유지하되,
   시간 계측만 매번 새로 해라.
2. 하단의 "현재 페이지 조회 · 내부 DB · 서버 · 전체 요청 · 화면" 5개 항목
   줄은 완전히 제거해라 — 이 정보는 전부 위쪽 "(N초 · 캐시출처)" 표시 하나로
   통합해서 보여주면 된다는 게 사용자 판단이다.

   detail_elapsed_ms(원본 콜드스캔 실측치)를 그대로 노출하지 말고, 이번 조회

   다만 주 표시값 자리에는 "이번 조회 실제시간"이 오게 해라.

   유지해라(이건 오늘 이미 잘 만들어진 기능이다) — 시간 값만 교체하는
   것이다.
