작업명 : P13-SAME-DBMS-PHYSICALLY-SEPARATED-PG-RETEST

BACKLOG.md P13 항목(오늘 확정된 재측정 경로, CLOUD-PG-PHYSICALLY-SEPARATED-ENV-
CONNECTION-TEST.txt)을 먼저 읽고 시작해줘. 승인 완료.

배경: P13(통계검증 parallel_sides 효과 재측정)을 위해 오늘 오라클↔클라우드
PostgreSQL 조합을 시도했으나, 통계검증 "실행" 단계 자체가 원본↔목적 동일 DBMS
에서만 지원되는 구조적 제약이 확인돼 실패했다. 재측정하려면 **동일 DBMS(둘 다
PostgreSQL)인데 물리적으로 분리된 쌍**이 필요하다 — 내부망 PostgreSQL(원본) +
클라우드 PostgreSQL(목적).

────────────────────────────────────────────────────────────
구현
────────────────────────────────────────────────────────────
1. 내부망 PostgreSQL(192.168.0.150, 기존 PostgreSQL_Inter_asis 프리셋 등 재사용
   가능하면 재사용)을 원본으로, 클라우드 PostgreSQL(Neon, 기존 PostgreSQL_tobe
   프리셋)을 목적으로 하는 검증 경로를 구성해라. 신규 픽스처가 필요하면 오늘
   CLOUD-PG-PHYSICALLY-SEPARATED-ENV-CONNECTION-TEST에서 쓴 것과 유사한 소규모
   테이블(TB_ 접두어는 samples/virtual_tables.py 데모 DDL과 충돌 위험이 있으니
   피해라)로 만들어라.
2. 이 물리분리 환경에서 parallel_sides ON/OFF 두 조건으로 통계검증 실행을 각각
   여러 번(최소 3회씩) 실행해서 실제 시간을 측정해라.
3. P13이 원래 재측정하려던 것 — "원본/목적이 물리적으로 다른 호스트에 있을 때
   parallel_sides가 실제로 효과가 있는지, 효과가 불안정한 원인이 디스크 I/O
   공유 때문이었는지"를 이 환경에서 검증해라.

────────────────────────────────────────────────────────────
검증
────────────────────────────────────────────────────────────
- ON/OFF 각 3회 이상 실측 시간 기록, 평균·분산 비교.
- 결과가 안정적으로 개선되는지, 여전히 들쭉날쭉한지 명확히 판정해라.
- 스크린샷 또는 로그 근거 포함.
- 코드 변경이 없는 순수 측정 작업이면 회귀테스트는 생략 가능 — 단, 혹시 코드를
  건드렸다면 관련 테스트 서브셋 + baseline 대조, CLAUDE.md 필수 회귀 포함.
- 완료보고: 측정 환경 상세, ON/OFF 각각의 실측표, 결론(P13을 이제 종결할 수
  있는지, 아니면 여전히 불안정한지). 작업명 첫줄/마지막줄.
