작업명 : F4-ADMIN-OVERRIDE-4ITEMS-SCOPE-DIAGNOSE

코드 수정 없이 조사만 해줘. BACKLOG.md F4 항목과 근거 보고서
`AMBIGUOUS-ADMIN-COLUMN-MANUAL-OVERRIDE-UI-CONNECT.txt` §5를 먼저 읽고 시작해줘.

배경: F4는 4개 서로 다른 잔여 한계를 하나로 묶어놓은 항목이다. 이번 지침은 4건 각각을
"바로 구현 가능(저위험)" vs "완료 모듈/서버 정규화를 건드려야 해서 승인 필요(고위험)"
로 재분류하는 조사다. 4건을 한 번에 구현 지침 내지 말고, 이 조사로 먼저 나눠라.

1. 확정 조회 키(table_key)에 스키마가 없는 문제 — 이걸 고치려면 정확히 어느 서버
   함수(테이블 식별자 정규화)를 손봐야 하는지, 그게 이 기능 하나만 쓰는 전용 함수인지
   아니면 다른 여러 기능이 공유하는 "완료 모듈"급 공통 함수인지 확인. 공유 함수면
   위험도를 높게 재평가.
2. PROJECT_COLUMN(프로젝트 전체) 범위 확정 UI 부재 — 저장소·API·판정 로직은 이미
   지원한다고 원문에 적혀 있으니, 정말 UI 추가만으로 끝나는지(백엔드 무수정) 코드로
   재확인. UI 추가만이면 저위험으로 분류.
3. 확정 사유 메모(memo)·확정자(decided_by) 입력 UI 부재 — 마찬가지로 UI 추가만으로
   끝나는지 확인(저장 컬럼은 이미 있고 빈 값으로만 저장되는 상태라고 원문에 명시됨).
4. 낙관적 반영이 자동선정 pool 재배치를 하지 않는 문제 — 이건 안내 문구로만 처리
   중이라는데, 실제로 재배치까지 구현하려면 어느 모듈을 건드려야 하는지, 그 모듈이
   완료 모듈인지 확인.

4건 각각 파일범위·완료모듈 해당여부·예상 위험도를 표로 정리하고, "지금 승인 없이 바로
착수 가능한 것"과 "승인 필요한 것"을 명확히 갈라줘.
