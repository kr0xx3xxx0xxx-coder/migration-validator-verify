BACKLOG.md M66 항목과 F5-TIER2-BATCH3-IMPLEMENT.txt §5~6을 먼저 읽고 시작해줘.
코드 수정 없이 조사만 해줘.

배경: `test_batch_*.py`/`test_wrapper_results*.py`/`test_candidate_*.py`/
`test_column_candidate_*.py`(~140파일) 전수 실행이 실제 테스트 실행 이전(pytest
--collect-only 단계, import 시점)부터 60초 넘게 무응답이다. 배치1·2 때는 같은
글롭이 정상 완주했는데 배치3 시점엔 막혔다.

────────────────────────────────────────────────────────────
원인 파일 이분탐색
────────────────────────────────────────────────────────────
`pytest --collect-only`를 파일 그룹을 절반씩 나눠가며 실행해서, 정확히 어느 파일
(또는 파일들)이 collect 단계에서 멈추는지 좁혀라. 방법 예시:
- 140개 파일을 두 그룹으로 나눠 각각 `--collect-only` 타임아웃(예: 30초)을 걸고
  실행 — 멈추는 쪽만 남기고 다시 반씩 나누는 걸 반복.
- 원인 파일을 찾으면, 그 파일의 어느 부분(모듈 레벨 import, fixture, 클래스 정의
  등)이 실제 DB 접속을 시도하는지 확인.

────────────────────────────────────────────────────────────
원인 확정 후
────────────────────────────────────────────────────────────
- 그 파일이 실제로 실 DB(db/migration_validator.db 등)에 접속을 시도하는지, 접속
  대상이 응답 없는 상태인지(예: 잘못된 접속 정보, 방화벽 등) 확인.
- 이게 "테스트 코드 자체의 문제"(모듈 레벨에서 접속하면 안 되는데 그렇게 짜여있음)
  인지, "환경 문제"(원래는 되는데 지금 이 환경에서만 안 됨)인지 판단.

완료보고: 원인 파일 특정 결과, 근본 원인, 이게 테스트 코드 문제인지 환경 문제인지
판단과 근거. 코드 수정은 안 했으면 그대로, 아주 명백한 사소한 수정(예: 모듈 레벨
접속을 fixture로 옮기는 것)으로 안전하게 해결 가능하다고 판단되면 그 수정까지
진행해도 된다 — 단, 애매하면 진단만 하고 멈춰라.
