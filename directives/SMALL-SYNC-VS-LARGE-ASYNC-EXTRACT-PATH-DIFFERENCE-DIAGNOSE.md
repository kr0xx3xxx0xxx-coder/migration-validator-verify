작업명 : SMALL-SYNC-VS-LARGE-ASYNC-EXTRACT-PATH-DIFFERENCE-DIAGNOSE

코드 수정 없이 조사만 해줘.

배경: 오늘 STAGE5-CARD-REMOVE-ITEM24-AND-PER-GROUP-STORAGE-VERIFY에서, 불일치
그룹 상세추출 결과 저장이 "소규모/동기 경로는 프로세스 내 in-memory(서버
재시작 시 소멸), 대규모/비동기 경로는 파일 영속"으로 갈린다는 게 확인됐다.
정확히 어떤 기준으로 두 경로가 나뉘는지 명확히 확인이 필요하다.

────────────────────────────────────────────────────────────
조사 항목
────────────────────────────────────────────────────────────
1. 정확히 어떤 조건(행수 임계값? 전략 종류? 사용자가 누른 버튼의 종류?)으로
   "소규모/동기" 경로와 "대규모/비동기" 경로가 갈리는지 코드로 명확히 찾아라.
2. 각 경로의 정확한 이름/진입점(함수명, 라우트)을 밝혀라.
3. 사용자 입장에서 "내가 지금 어느 경로를 타고 있는지" 화면에서 구분 가능한
   방법이 있는지 확인해라(있다면 뭘로 구분하는지, 없다면 없다고 명시).
4. 왜 이렇게 두 경로로 나뉘어 설계됐는지(성능/자원 이유 등 추정 가능하면
   설명, 커밋 이력에 근거 있으면 인용) 확인해라.
5. 오늘 실제로 쓰인 픽스처(MV_SCATTER50M, 5천만행)가 몇 번째 그룹부터 어느
   경로를 탔는지, 실측 또는 코드 근거로 확인해라.

────────────────────────────────────────────────────────────
완료보고
────────────────────────────────────────────────────────────

  오늘 실제 사례 적용 결과.
- 코드 수정 없음. 작업명 첫줄/마지막줄.
