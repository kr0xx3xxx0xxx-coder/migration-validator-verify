작업명 : CLOUD-PG-PHYSICALLY-SEPARATED-ENV-CONNECTION-TEST

BACKLOG.md P13 항목(병렬성능 재측정 불가 — 원인: 검증환경이 원본/목적 물리적으로
분리 안 됨)을 먼저 읽고 시작해줘. 승인 완료.

배경: 지금까지 검증 환경은 원본(오라클)과 목적(PostgreSQL)이 같은 물리 호스트에
같이 떠 있어서 디스크 I/O를 나눠 쓰는 문제가 있었다. 사용자가 클라우드 PostgreSQL
접속정보를 이미 갖고 있다 — 오라클(로컬)을 원본으로, 클라우드 PostgreSQL을 목적으로
잡아서 진짜 물리적으로 분리된 환경을 만든다.

**접속정보(호스트/계정/비밀번호)는 사용자가 이 터미널에 직접 입력하게 하고, 절대
채팅(Claude 웹)으로 전달받지 마라 — 이미 사용자가 알고 있으니, 이 세션에서
직접 물어보고 입력받아라.**

────────────────────────────────────────────────────────────
1. 연결 프로필 등록
────────────────────────────────────────────────────────────
사용자에게 클라우드 PostgreSQL 접속정보(호스트/포트/DB명/계정/비밀번호)를 직접
물어봐서, 앱의 기존 DB 프로필 등록 기능("데이터 준비" 메뉴)으로 목적(Target) DB
프로필을 새로 만들어라 — 오늘 만들었던 다른 프로필들과 같은 방식으로.

────────────────────────────────────────────────────────────
2. 검증 경로(Pair) 생성
────────────────────────────────────────────────────────────
기존 오라클 원본 프로필(Oracle_asis 등)과 방금 만든 클라우드 PostgreSQL 목적
프로필을 조합해서 새 검증 경로를 만들어라.

────────────────────────────────────────────────────────────
3. 일반검증 연결 테스트 (개별·일괄 둘 다)
────────────────────────────────────────────────────────────
- 개별검증: 이 새 경로로 1~5단계를 실제로 한 번 끝까지 실행해서, 오라클→클라우드
  PostgreSQL 간 실제 네트워크를 타는 상황에서도 정상적으로 검증이 완료되는지 확인.
- 일괄검증: 이 경로로 간단한 일괄검증도 한 번 돌려서 정상 작동 확인.
- 특히 네트워크 지연이 실제로 있는 환경이니, 오늘 하루 종일 다뤘던 여러 기능
  (좀비 세션 정리, 비동기 job 등)이 이 지연 환경에서도 문제없이 작동하는지
  자연스럽게 관찰해라(별도로 재현하려 하지 말고, 이번 테스트 도중 이상 징후가
  보이면 기록만 해둬라).

────────────────────────────────────────────────────────────
검증(필수)
────────────────────────────────────────────────────────────
- 연결 프로필·검증 경로가 정상 생성됐는지 확인.
- 개별검증 1~5단계가 실제로 끝까지 성공하는지(스크린샷 포함) 확인.
- 일괄검증도 최소 1건 정상 완료 확인.
- 이 과정에서 발견된 이상 징후가 있다면(성능이든 기능이든) 완료보고에 기록해라 —
  당장 고치라는 게 아니라 관찰 기록.

완료보고: 연결 프로필 생성 결과, 개별/일괄 검증 실행 결과(스크린샷 포함), 관찰된
특이사항. 이 작업 자체로 코드 수정은 발생하지 않아야 한다(순수 연결·검증 테스트).
