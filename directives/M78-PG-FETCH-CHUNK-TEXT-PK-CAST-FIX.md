작업명 : M78-PG-FETCH-CHUNK-TEXT-PK-CAST-FIX

BACKLOG.md M78 항목을 먼저 읽고 시작해줘. 승인 완료.

배경: PostgreSQL `make_pg_fetch_chunk`(`postgresql.py:479` 부근)가 문자(varchar)
PK 컬럼의 경계값을 바인드 파라미터로 넘길 때 명시적 타입 캐스트가 없어서,
"숫자로 노출된 문자 PK"(예: '00123' 같은 문자열)를 조회하면
`character varying >= integer` 쿼리오류가 즉시 발생한다. 재현 스크립트가 이미
있다(scripts/dev_e2e/pg_text_numeric_pk_cast_repro.py 등, M74 조사에서 확인됨).

────────────────────────────────────────────────────────────
구현
────────────────────────────────────────────────────────────
`make_pg_fetch_chunk`에서 key 컬럼을 bind할 때, 컬럼이 문자열 타입인 경우
명시적으로 `::text`(또는 실제 컬럼 타입에 맞는 캐스트)를 붙여서 암묵 캐스트
오류를 방지해라. 숫자 PK는 기존 그대로 두고, 문자 PK 케이스만 고쳐라 —
컬럼 타입 정보를 이미 갖고 있는지 확인하고, 있으면 그걸로 캐스트를 조건부
적용해라.

────────────────────────────────────────────────────────────
검증(필수, 실제 클릭)
────────────────────────────────────────────────────────────
- 기존 재현 스크립트(pg_text_numeric_pk_cast_repro.py)를 다시 돌려서, 이제
  쿼리오류 없이 정상 조회되는지 확인해라.
- 숫자 PK 케이스는 회귀 없이 그대로 정상 동작하는지 확인해라.
- 실제 화면(개별검증)에서 문자 PK 테이블로 5단계 청크조회까지 end-to-end로
  돌려서 정상 완료되는지 확인해라.
- 관련 테스트 서브셋 + baseline 대조, 신규 회귀 0건.
- CLAUDE.md 필수 회귀(virtual/complex) 최종 1회.
- 완료보고: 파일:라인, 재현 스크립트 재실행 결과(전/후 비교), 숫자PK 회귀
  없음 확인, end-to-end 검증 결과, 커밋해시. 작업명 첫줄/마지막줄. 코드 변경이
  있으니 서버 재기동 필수, 재기동 시각·HEAD 커밋 해시 명시.
