1. [버그] "상세 추출 상태" 배지가 추출 완료 후에도 "미확인"으로 남음

증상(스크린샷 근거): 그룹 행을 클릭해 펼치면 실제로 101건 레코드가 정상 조회되는데
(추출 자체는 성공), 그 행의 "상세 추출 상태" 컬럼은 계속 "미확인"으로 남아있다.
접었다 다시 펴도 마찬가지다.

원인을 추적해줘 — 추출 성공 후 그 그룹의 상태를 "완료"로 갱신하는 지점이 없거나,
상태를 갱신은 하는데 배지를 다시 그리는 로직이 안 불리는지 확인. 오늘 만든
`services/stage5_group_store.py`의 `update_detail`(상태 갱신 함수)이 실제로 호출되고
있는지, 호출된다면 그 결과가 화면에 반영되는 경로가 끊겼는지 코드로 확인.

2. [버그] 그룹을 접었다 다시 펴면 캐시 재사용 없이 매번 재추출됨
────────────────────────────────────────────────────────────
증상(스크린샷 근거): 같은 그룹(R01)을 두 번 펼쳤을 때 "상세 불일치 처리 총 소요시간"이
각각 10.59초, 8.56초로 다르게 나온다 — 매번 새로 추출하고 있다는 뜻(캐시가 있으면
즉시 응답해야 함).

오늘 M56 완료보고서는 "재진입 시 재추출 없이 서버 저장값 그대로 표시(캐시 재사용)"를
검증했다고 기록돼 있는데, 그건 **페이지 새로고침 재진입** 시나리오였을 가능성이 있다 —
이번 증상은 **같은 페이지에서 접었다 펴는(아코디언 토글)** 경우다. 두 경로가 실제로
다른 코드를 타는지 확인하고, 아코디언 재확장 시에도 1번의 상태(완료 여부)를 먼저
확인해서 이미 추출된 그룹이면 캐시된 결과를 바로 보여주고 재추출하지 않도록 고쳐라.

**1번과 2번은 같은 뿌리 원인일 가능성이 높다** — "이 그룹이 이미 추출됐다"는 상태
추적 자체가 아코디언 토글 경로에서 안 되고 있는 것으로 추정된다. 원인 규명 후 한 번에
고쳐도 된다.

3. [레이아웃 재설계] "고급 성능정보" → "검증성능정보"로 명칭 변경 + 범위를 1~5단계
   전체로 확장
────────────────────────────────────────────────────────────
배경(사용자 재설계 요청): 5단계는 "결과 확인" 탭이다 — 여기서 보여줄 성능정보는
5단계(그룹 추출)만이 아니라 **1단계(쿼리검토)~5단계(결과확인) 전체 파이프라인의
소요시간**이어야 실제로 쓸모가 있다. 목적은 "이 테이블은 어느 단계가 병목인지"를
사용자가 한눈에 파악해서 개선 지점을 찾을 수 있게 하는 것이다.

수정 방향:
- 명칭을 "고급 성능정보"에서 **"검증성능정보"**로 변경(코드 내 라벨 문자열).
- 상단 고정 영역에 1~5단계 각각의 소요시간을 보여줘라 — 이미 각 단계 탭/타일에
  개별적으로 표시되고 있는 시간값(1단계 쿼리검토, 2단계 COUNT, 3단계 후보선정,
  4단계 통계검증 실행, 5단계 상세추출)을 새로 계산하지 말고 그러모아서 한 곳에
  정리하는 형태로. 어느 데이터 소스(세션 상태, DB 저장값 등)에서 각 단계 시간을
  가져올 수 있는지 코드로 확인해서 재사용해라.
- 그룹별(펼침 패널 안)로는 복잡한 성능정보를 넣지 말고, **추출 소요시간 한 줄** 정도로
  단순화해라(예: "추출 소요: 8.56초"). 기존 "고급 성능정보"의 세부 항목(측정 기준·
  단계별 브레이크다운 등)은 상단 "검증성능정보" 영역으로 옮기고 그룹 펼침 패널에서는
  제거.
- 상단 "검증성능정보" 영역이 그룹 클릭에 따라 갱신되는 부분(그 그룹의 추출 시간 등)과,
  항상 고정인 부분(1~5단계 전체 소요시간)을 시각적으로 구분해서 배치해라.

4. [컬럼 축소] 상세 레코드 테이블에 검증과 무관한 컬럼(SEQ_NO/ITEM_NM 등)이 나옴
────────────────────────────────────────────────────────────
증상(스크린샷 근거): 상세 레코드 테이블이 이관 SQL의 전체 컬럼(PK_STR, REGION_CD,
STATUS_CD, AMT, QTY, SEQ_NO, ITEM_NM)을 다 보여주는데, 이 중 3단계에서 실제로 선택한
후보 컬럼(REGION_CD/STATUS_CD/AMT/QTY)이 아닌 SEQ_NO/ITEM_NM은 검증과 무관해서
보여줄 필요가 없다.

수정: 상세 레코드 테이블의 컬럼을 **PK + 실제 후보 컬럼(그 그룹의 GROUP BY 축 +
SUM 대상)만**으로 좁혀라. 새로 계산하지 말고, 이미 어딘가에 있는 "이번 실행에 쓰인
후보 컬럼 목록"(3단계 선택 결과)을 그대로 재사용해서 테이블 렌더 시 컬럼을 필터링해라.
PK는 항상 포함(행 식별용).

검증(필수, 실제 클릭)
────────────────────────────────────────────────────────────

  ITEM_NM 같은 무관 컬럼은 안 나오는지 확인.

  나오는지 확인(하드코딩이 아니라 실제 선택값 기반인지).
