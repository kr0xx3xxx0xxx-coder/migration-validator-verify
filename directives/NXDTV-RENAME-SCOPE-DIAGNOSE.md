작업명 : NXDTV-RENAME-SCOPE-DIAGNOSE

코드 수정 없이 조사·설계만 해줘.

배경: 프로젝트의 정식 명칭은 "데이터이관 검증프로그램, nxDTV(Data Transfer
Verification)"이다. 지금 폴더명·제품 화면 표시명·문서 전반에 걸쳐 "Migration
Validator"라는 이름이 쓰이고 있는데, 이걸 nxDTV로 바꾸는 게 얼마나 큰 작업인지
범위를 먼저 파악한다.

────────────────────────────────────────────────────────────
1. 폴더명 변경 범위(X:\Projects\Migration_Validator → nxDTV 등)
────────────────────────────────────────────────────────────
- 이 절대경로가 코드/설정/스크립트 안에 하드코딩된 곳이 있는지(있으면 나열).
- 폴더명만 바꿔도 되는지, 아니면 프로젝트 커스텀 지침(Claude Code project custom
  instructions)이나 다른 도구 설정에도 이 경로가 박혀있어서 같이 바꿔야 하는지.

────────────────────────────────────────────────────────────
2. 제품 화면 표시명 변경 범위
────────────────────────────────────────────────────────────
- 화면에 "Migration Validator" / "데이터 이관 검증 플랫폼"이 뜨는 지점을 전부
  찾아라(사이드바 로고 영역, 페이지 타이틀, 기타 UI 텍스트).
- 이걸 nxDTV / "데이터이관 검증프로그램"으로 바꾸는 게 단순 문자열 교체 수준인지,
  아니면 로고 이미지·파비콘 등 별도 리소스도 있는지 확인.

────────────────────────────────────────────────────────────
3. 코드 내부 참조 범위
────────────────────────────────────────────────────────────
- 클래스명·모듈명·변수명·주석 등에 "migration_validator"/"MigrationValidator"류
  이름이 얼마나 광범위하게 쓰이는지 대략적인 규모(파일 수·건수)를 파악해라(전수
  나열은 필요 없고, 규모 파악 수준으로).
- DB 파일명(`db/migration_validator.db`)도 바꿀 대상인지, 바꾼다면 기존 데이터
  마이그레이션이 필요한지.

────────────────────────────────────────────────────────────
4. 검증 저장소(verify repo) 이름
────────────────────────────────────────────────────────────
지금 완료보고를 push하는 저장소 이름 자체(`migration-validator-verify`)도 바꿀지는
이번 조사 범위가 아니다 — 그건 별도로 사용자가 결정할 사안이니 언급만 하고 넘어가라.

────────────────────────────────────────────────────────────
5. 단계별 착수 제안
────────────────────────────────────────────────────────────
1~3의 규모를 바탕으로, 한 번에 다 하지 말고 단계를 어떻게 나누는 게 안전한지
제안해라(예: 폴더명 먼저 → 화면 표시명 → 코드 내부 참조 순으로, 또는 다른 순서).
각 단계의 위험도(완료 모듈 건드리는지 여부 포함)도 함께 평가해라.

완료보고: 1~5 결과, 예상 총 작업량, 착수 순서 권고. verify 저장소에 진단 보고서만
push(코드 변경 없음).
