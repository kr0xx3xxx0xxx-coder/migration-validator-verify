작업명 : DB-CONNECTION-SOURCE-AUDIT-UNNECESSARY-LOAD-CHECK

코드 수정 없이 조사만 해줘.

배경: 오늘 M69(좀비세션 정리), M75(COUNT 병렬 ThreadPoolExecutor), M79(통계검증
이기종 지원) 등 여러 작업이 원본/목적 DB 커넥션을 만들고 병렬로 여러 개 띄우는
로직을 건드렸다. 전체적으로 DB 연결 관리에 불필요한 낭비나 부하 유발 요소가
있는지 종합 점검이 필요하다.

────────────────────────────────────────────────────────────
1. 커넥션 생성/해제 패턴 전수 확인
────────────────────────────────────────────────────────────
- 원본/목적 DB(오라클/PostgreSQL) 커넥션을 만드는 지점들을 찾아서, 각각 커넥션
  풀을 쓰는지, 매번 새로 연결하는지 확인해라.
- 커넥션이 작업 완료 후 확실히 반환/종료되는지 확인해라 — try/finally나 context
  manager로 보장되는지, 예외 발생 시에도 누수 없이 정리되는지.
- 오늘 병렬화된 지점들(COUNT side-parallel, 4단계 통계검증 병렬, 이기종 통계검증)
  이 각각 커넥션을 몇 개씩 동시에 여는지 확인해라 — 필요 이상으로 많이 열지는
  않는지.

────────────────────────────────────────────────────────────
2. 실제 DB 세션 수 실측
────────────────────────────────────────────────────────────
- 오라클(v$session)과 PostgreSQL(pg_stat_activity)에서, 이 프로젝트가 붙인
  실제 세션 수를 실행 전/중/후로 관찰해라 — 개별검증 한 번 돌리는 동안 세션
  수가 얼마나 늘었다가 정상적으로 줄어드는지.
- 좀비/유휴 세션이 쌓이는지(오늘 M69에서 다룬 것과 별개로, 정상 실행 흐름에서도
  불필요하게 오래 열려있는 세션이 있는지) 확인해라.

────────────────────────────────────────────────────────────
3. 원본/목적 DB 부하·속도 영향 확인
────────────────────────────────────────────────────────────
- 지금 켜져 있는 병렬 기능들(COUNT, 4단계)이 원본/목적 DB에 동시에 여러 쿼리를
  쏘는 게, 그 DB 자체의 다른 워크로드(다른 사용자·다른 세션)에 부하를 줄 수
  있는 구조인지 확인해라 — 예를 들어 커넥션 풀 크기 제한이 있는지, 무제한으로
  늘어날 수 있는 구조인지.
- 커넥션 자체를 맺는 데 드는 오버헤드(특히 클라우드 Neon처럼 TLS 핸드셰이크
  비용이 있는 원격 DB)가 전체 실행시간에서 차지하는 비중이 얼마나 되는지
  대략적으로 가늠해라(오늘 P13 재측정 결과 등 기존 실측 자료 활용 가능).

────────────────────────────────────────────────────────────
완료보고
────────────────────────────────────────────────────────────
- 발견된 불필요한 커넥션/누수 위험 지점(있다면 파일:라인과 함께).
- 실측 세션 수 관찰 결과.
- 부하·속도 영향에 대한 판단(문제 있음/경미함/문제없음, 근거와 함께).
- 코드 수정 없음. 작업명 첫줄/마지막줄.
