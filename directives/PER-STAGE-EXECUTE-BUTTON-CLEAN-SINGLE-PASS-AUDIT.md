코드 수정 없이 조사만 해줘(문제 발견 시 수정 여부는 완료보고 후 별도 지시).

배경: 개별검증 1~5단계(쿼리검토/COUNT사전검증/후보컬럼선정/통계검증실행/결과확인)
각각의 "실행" 버튼을 눌렀을 때, 한 번에 깔끔하게(누수 없이, 중복 없이, 불필요한
낭비 없이) 정상 진행되는지 전수 점검한다. 오늘 발견된 몇 가지(워크플로 토큰
검증, N1 전략표시 불일치, DB커넥션 누수 등)와 연결될 수 있으니 그 맥락도 참고해라.

사용자가 이미 알고 있는 사실: **몇몇 탭은 실행 버튼을 두 번 눌러야 진행되는
경우가 있다.** 이게 의도된 UX(예: 1차 클릭=준비, 2차 클릭=확정)인지, 아니면
실제로는 한 번에 되어야 하는데 결함으로 두 번 눌러야만 되는 것인지 판단해라.

────────────────────────────────────────────────────────────
단계별 점검 항목 (1~5단계 전부)
────────────────────────────────────────────────────────────
각 단계마다:
1. 실행 버튼 클릭 1회로 의도한 동작이 완전히 끝나는지, 아니면 실제로 2번 눌러야
   하는지 확인해라. 2번 눌러야 한다면, 그게 코드에 의도적으로 그렇게 설계된
   것인지(주석/커밋이력 확인), 아니면 버그인지 판단해라.
2. 버튼을 눌렀을 때 발생하는 네트워크 요청(브라우저 콘솔/서버 로그)을 확인해서,
   불필요하게 같은 요청이 중복으로 나가는 게 있는지 확인해라.
3. DB 커넥션이 이 단계 실행 중에 열렸다가, 그 단계가 끝나면 정상적으로
   반납/종료되는지 확인해라(오늘 M80에서 다룬 것과 같은 종류의 점검을 5단계
   전체에 대해 반복).
4. 오늘 발견된 워크플로 토큰 메커니즘(services/workflow_stage_guard.py)이
   각 단계 전환마다 올바르게 갱신되는지, 혹시 특정 단계에서 토큰 갱신이 누락돼
   다음 클릭이 실패할 潜在 위험이 있는지 확인해라.
5. 오늘 발견된 N1(화면표시-실행전략 불일치)과 비슷한 종류의 "화면에 뜬 정보와
   실제 서버가 한 일이 다른" 사례가 다른 단계에도 있는지 확인해라.
