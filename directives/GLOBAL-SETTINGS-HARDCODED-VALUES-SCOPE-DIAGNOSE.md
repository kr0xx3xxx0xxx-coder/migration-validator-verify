작업명 : GLOBAL-SETTINGS-HARDCODED-VALUES-SCOPE-DIAGNOSE

코드 수정 없이 조사·설계만 해줘.

배경: 지금 이 도구는 개별검증/일괄검증/전수검증(준비중) 3가지 모드가 있는데, DB
타임아웃·재시도 횟수·조합축 자동계획 상한·저장 상한·표본 전환 임계값 등 여러 설정값이
코드 곳곳에 하드코딩돼 있고, 하나로 전역화하면 안 되는 것도 있다(개별=응답성 중시,
일괄=수백 테이블 누적이라 더 보수적이어야 함, 전수=아직 설계 자체 없음). 오늘 F7이
만든 `services/exact_diff/execution_settings.py`의 "설정 그룹별 블록" 패턴
(SingleExecuteAsync 그룹)이 이 구조의 좋은 선례로 보인다.

────────────────────────────────────────────────────────────
1. 하드코딩 값 전수조사
────────────────────────────────────────────────────────────
아래 카테고리별로 코드에 흩어진 값을 파일:라인과 함께 전부 나열해줘:
- SQL 실행 타임아웃(60초 상한 등)
- DB 접속 재시도 횟수/대기시간
- 조합축 자동계획 상한(100그룹, 오늘 스크린샷에서 본 그것)
- 저장 상한(representative_limit=20, F2가 다룬 그것)
- 표본 전환 임계값(STATS_SAMPLE_ONLY로 전환되는 기준)
- 동시성 상한(F7의 max_concurrent_jobs 등)
- 기타 발견되는 매직넘버(재현 가능한 임계값 성격의 것들)

각 값이 지금 어느 모드(개별/일괄/전수)에서만 쓰이는지, 여러 모드에서 같은 값을
공유하는지도 표로 정리해줘.

────────────────────────────────────────────────────────────
2. 이미 있는 설정 인프라 파악
────────────────────────────────────────────────────────────
`services/exact_diff/execution_settings.py`의 구조(그룹별 블록, 환경변수→정책→기본값
3단 롤백)를 정확히 분석하고, 이 구조를 다른 하드코딩 값들에도 확장 적용할 수 있는지
설계.

────────────────────────────────────────────────────────────
3. 계층 구조 설계
────────────────────────────────────────────────────────────
"전역 공통 + 모드별 오버라이드" 구조를 제안해줘 — 어떤 값이 정말 전역 공통이어도
안전한지(예: SQL 타임아웃), 어떤 값이 모드별로 반드시 달라야 하는지(예: 표본 전환
임계값 — 일괄은 더 보수적이어야 할 수 있음) 근거와 함께 구분. 전수검증은 아직 설계가
없으니 "빈 틀만 만들어두고 나중에 채우는" 형태로 자리만 잡아두는 걸 제안해도 됨.

────────────────────────────────────────────────────────────
4. 착수 범위·위험도
────────────────────────────────────────────────────────────
이 작업이 "완료 모듈"에 해당하는 파일을 얼마나 건드리게 되는지, 한 번에 다 하지
말고 어떻게 단계를 나누는 게 안전한지(카테고리별로 나눠서 하나씩 전역화하는 등)
제안.

변경 없음).
