작업명 : STAGE5-AUTOSTART-ARCHITECTURE-DIAGNOSE

코드 수정 없이 조사·설계만 해줘.

배경: 지금 4단계(통계검증, GROUP BY 집계 비교)가 끝나면 5단계(상세비교, 불일치
그룹의 실제 행 단위 대조)가 **사용자 개입 없이 자동으로 백그라운드에서 시작**된다.
이게 오늘 하루 반복된 여러 혼란(4단계 탭에 "5단계 진행중" 배지, 4단계 완료 후에도
버튼이 잠기는 이유를 사용자가 모름, 재실행 시 이전 결과 잔존 등)의 근본 원인일
가능성이 있다. 사용자가 제안한 대안 2가지:
  (A) 5단계 탭에 실제로 진입하는 순간 상세비교 시작
  (B) 5단계 화면에 별도의 명시적 "불일치 추출" 버튼을 만들어 사용자가 눌러야 시작

────────────────────────────────────────────────────────────
1. 현재 자동시작 구조 파악
────────────────────────────────────────────────────────────
- 4단계 완료 시 5단계 상세비교를 트리거하는 정확한 코드 지점을 찾아라.
- 왜 자동시작으로 설계됐는지(커밋 이력·주석·설계문서에서) 근거를 찾아봐라 — 클릭 한
  번 절약 목적인지, 살아있는 DB 커넥션/세션을 재사용해야 하는 기술적 이유가 있는지,
  아니면 다른 이유인지.
- **핵심 확인**: 5단계가 필요로 하는 입력(4단계가 찾은 불일치 그룹 목록)이 이미
  DB/저장소에 영속화돼 있는지, 아니면 메모리 상에서만 다음 단계로 즉시 전달되고
  저장은 안 되는지. 저장이 안 되고 있다면 "끊어서 나중에 시작"하는 구조로 바꿀 때
  이 저장 로직을 추가로 만들어야 한다.

────────────────────────────────────────────────────────────
2. 체크박스-세트개수 불일치 재확인 (부가 발견, 같은 화면 영역)
────────────────────────────────────────────────────────────
스크린샷 근거: "단일축만 실행(조합 REGION_CD+STATUS_CD — 예상 210그룹 — 자동계획
상한(100) 초과 — 제외됨)" 체크박스가 **체크된 상태**인데, 실행 상태 표시는 "세트
1/2 실행 중"으로 뜬다. 사용자는 "3이어야 하지 않냐"고 의문을 제기했다.
실제로 몇 세트가 도는 게 맞는지(조합이 자동 제외됐으니 단일축 2개=2세트가 맞는지)
코드로 확정하고, 그게 맞다면 "왜 체크박스가 여전히 체크 가능한 상태로 남아있는지"도
확인해라 — 자동 제외 상태에서는 체크/해제가 실제 실행 세트 수에 아무 영향을 못 준다면
(항상 2세트로 고정), 그건 진짜 "선택지"가 아니라 그냥 정보 표시인데 체크박스
(상호작용 가능한 UI)로 남아있는 게 사용자에게 "내가 뭔가를 바꿀 수 있다"는 잘못된
인상을 준다. 자동 제외 상태에서는 체크박스를 비활성 정보 표시로 바꾸는 게 맞는지
검토.

────────────────────────────────────────────────────────────
3. 대안 (A) vs (B) 비교 설계
────────────────────────────────────────────────────────────
각각의 장단점, 예상 코드 변경 범위(파일 목록), 위험도를 정리:
- (A) 5단계 탭 진입 시 자동시작: 사용자 클릭 없이 여전히 자동이지만, 최소한 "5단계
  화면을 보고 있을 때만" 시작되므로 4단계에서 몰래 도는 문제는 해소. 다만 사용자가
  5단계 탭을 열자마자 자동으로 시작되는 것에 놀랄 수 있음(요청 없이 시작).
- (B) 명시적 버튼: 가장 명확하지만, 클릭 한 번이 추가됨. 오늘 다른 단계들과의
  일관성(1~4단계는 전부 명시적 버튼 클릭으로 시작)을 고려하면 오히려 이게 기존
  패턴과 더 잘 맞을 수 있음.
- 오늘 하루 고쳐온 여러 항목(M43/M47/M54의 잠금·배지·알림 로직 다수)이 (A) 또는
  (B) 채택 시 각각 얼마나 단순해지거나 아예 필요 없어지는지도 정리(제거 가능한
  코드가 있다면 그것도 가치임).
