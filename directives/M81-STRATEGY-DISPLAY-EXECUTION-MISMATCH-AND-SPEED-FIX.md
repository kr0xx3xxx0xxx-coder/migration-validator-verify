1. [최우선] N1 — 화면 표시 전략과 실제 실행 전략 불일치 수정
────────────────────────────────────────────────────────────
배경: 계획 카드는 `choose_compare_strategy` 결과(대개 DIRECT_STREAM_COMPARE)를
표시하지만, `tabler_renderer.py:17677`의 "totalRows>50000이면 useStream" 로직이
실행 시 무조건 `PK_RANGE_CHUNK_COMPARE`를 명시 전송하고, `agg_diff_route.py:
55-56`의 "명시 요청 존중" 규칙이 전환판정을 재호출하지 않아 조용히 CHUNK로
확정된다. 실행 후 모순경고(`tabler_renderer.py:28603`, selected≠actual)도
이 경우 발동하지 않는다.

이 문제를 다음 두 가지 중 더 적절한 쪽으로 고쳐라(코드를 먼저 조사해서 판단해라):
(a) 화면 표시 자체를, 실제로 실행될 전략(useStream 임계값까지 반영한 최종
    판정)을 기준으로 보여주도록 계획 카드 로직을 수정 — "계획 따로, 실행
    따로"인 이원화 구조를 하나로 합쳐라.
(b) 계획과 다르게 실행이 확정되는 경우, 모순경고 배지가 반드시 발동하도록
    고쳐서 최소한 사용자에게 알려지게 해라.
가능하면 (a)가 근본 해결이니 우선 시도하고, 구조상 어렵다면 (b)로 안전망을
확보해라.
