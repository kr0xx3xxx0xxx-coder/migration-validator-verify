작업명 : ORACLE-CENTRIC-VERIFICATION-GAP-AUDIT

코드 수정 없이 조사만 해줘. 이건 오늘 하루가 아니라 프로젝트 전체 이력에 걸친
질문이다.

배경: 이 프로젝트의 실측 검증 대부분이 오라클(Oracle_asis→Oracle_tobe 등)을
기준으로 이루어져 왔다. 사용자가 "오라클 기준으로 검증·수정된 것 중, PostgreSQL→
PostgreSQL 조합에서는 검증이 안 됐거나 실제로는 안 맞을 수 있는 게 있는지"를
물었다.

────────────────────────────────────────────────────────────
1. verify 저장소 전체 완료보고서를 훑어서, "오라클로만 검증하고 PostgreSQL은
   검증 안 한 채로 끝난" 항목을 찾아라
────────────────────────────────────────────────────────────
verify 저장소(X:\Verify\_rpt_push)의 완료보고서 전체(수백 건)를 대상으로, 다음
패턴을 찾아라:
- 실제 클릭검증/실측이 오라클 픽스처로만 이루어지고, "PostgreSQL은 코드 읽기로만
  확인" 또는 "PostgreSQL 미실측" 같은 한계 문구가 명시된 것.
- 특히 오늘 하루 다룬 것들 중 방언별로 다르게 동작할 만한 것들(HASH_BUCKET의
  STANDARD_HASH/MD5 함수, NLS/collation 관련, 날짜 형식, PK_RANGE_CHUNK 정렬,
  좀비 세션 정리(M69, PostgreSQL 전용으로 만들어짐 — 오라클은 원래 안전하다고
  확인됐지만 그 반대, 즉 "PostgreSQL 특유 문제가 오라클에서도 똑같이 발생하는지"
  는 안 물어봤을 것) 등을 우선적으로 훑어라.

────────────────────────────────────────────────────────────
2. 4방언(오라클/PostgreSQL/MySQL/MSSQL) 어댑터 구조에서, PostgreSQL 경로만
   유독 미검증인 로직이 있는지 확인
────────────────────────────────────────────────────────────
`services/dialects/` 또는 `services/db_adapters/` 계열 코드에서, 오라클 분기는
실측 검증된 흔적(완료보고서 참조)이 있는데 PostgreSQL 분기는 코드만 존재하고
실제로 돌려본 기록이 없는 곳이 있는지 찾아라.

────────────────────────────────────────────────────────────
3. 결과 정리
────────────────────────────────────────────────────────────
발견한 항목들을 다음 기준으로 분류해라:
- 심각(실제로 PostgreSQL→PostgreSQL에서 틀린 결과가 나올 수 있는 것)
- 경미(검증만 안 됐지 코드 구조상 방언 무관하게 동일하게 동작할 가능성이 높은 것)
- 확인 불가(짐작만 가능, 실측해봐야 아는 것)

완료보고: 발견된 항목 목록(근거 보고서 인용), 분류, 우선순위 추천. verify 저장소에
진단 보고서만 push(코드 변경 없음).
