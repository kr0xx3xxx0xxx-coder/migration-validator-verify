작업명 : M43-SERVER-RESTART-AND-LIVE-PORT8000-REVERIFY

배경: STAGE-EXEC-CROSS-STAGE-CONTAMINATION-AND-STOP-BUTTON-FIX(1~4순위)가 로컬 커밋까지
완료됐다고 보고됐으나, 사용자가 실제 서비스 포트(127.0.0.1:8000)에서 직접 확인한 결과
4단계 실행 버튼이 여전히 "실행 중···"(비활성 텍스트)만 뜨고 멈춤 버튼이 안 보였다.
이 프로젝트에 이미 기록된 원칙 위반이다: "브라우저 검증은 반드시 사용자가 실제 접속하는
서버(포트 8000, 인증 ON)에서 진행할 것 — 별도 격리 서버로 검증하지 말 것" +
"코드 수정 후 서버 재기동을 안 하면 안 고쳐졌다는 오인이 반복된다".

1. 지금 127.0.0.1:8000에 떠 있는 서버 프로세스가 STAGE-EXEC-CROSS-STAGE-CONTAMINATION-
   AND-STOP-BUTTON-FIX의 최종 커밋(741b988/bd56c0a/c889dd2/ac9d88a/6a2a52d/deabc96) 이후
   코드로 떠 있는 상태인지 먼저 확인. PID·기동 시각·현재 워킹트리 HEAD 커밋 해시를 대조.
   이전 코드로 떠 있으면(재기동 안 됨) 서버를 재기동한다.
2. 재기동 후 실제 포트 8000, 인증 ON 상태에서 Playwright로 아래 4가지를 실측 재확인하고
   각각 스크린샷을 남길 것(이번엔 반드시 이 포트에서, 격리 서버 금지):
   a) 4단계 통계검증 실행 중 — 버튼이 "■ 중단"(클릭 가능)으로 바뀌는지, 클릭 시 실제로
      멈추는지(서버 쿼리도 죽는지)
   b) 2단계 COUNT 실행 중 — 동일하게 멈춤 버튼 확인
   c) 4단계(또는 다중세트) 실행 중 3단계 GB/SUM 체크박스·조합 체크박스·관리컬럼 확정
      버튼을 클릭 시도 — 오버레이로 막히는지(pointer-events 차단)
   d) 4단계 실행 중 2단계 COUNT를 재실행해서 무효화 배너가 뜬 뒤, 그 배너가 나중에
      조용히 사라지지 않고 유지되는지
3. 사용자가 이번에 보여준 정확한 재현 조건(NXDNP.MV_SCATTER50M_SRC/TGT, 5천만행,
   REGION_CD+STATUS_CD, Oracle_asis→Oracle_tobe)과 최대한 동일한 조건으로 재현할 것.
4. 위 4가지 중 하나라도 여전히 옛 동작을 보이면(재기동했는데도 안 고쳐진 것처럼 보이면),
   원인을 코드 레벨까지 추적해서 정직하게 보고할 것 — "재기동했다"는 주장만으로 완료
   처리하지 말고, 스크린샷의 실제 버튼 텍스트/클릭 가능 여부까지 눈으로 확인 가능하게 남길 것.

검증(필수): 서버 재기동 시각과 워킹트리 HEAD 커밋 해시를 완료보고 맨 앞에 명시.

에 저장 후 push. 완료보고 작업명 첫줄/마지막줄.
