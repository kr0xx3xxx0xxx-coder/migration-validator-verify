작업명 : STAGE5-COLD-CLICK-TIME-GAP-CONSISTENCY-DIAGNOSE

코드 수정 없이 조사만 해줘.

배경: M96에서 "재실행 후 재클릭" 시나리오는 이미 해결했다(4단계가 매번 새로
계산한 요약값과 캐시된 값을 대조해 무효화). 사용자가 이번엔 다른 시나리오를
물었다:

"5단계 화면을 계속 열어둔 채로 오래 방치하다가(재실행 없이, 같은 세션), 나중에
처음으로(콜드, 캐시 없음) 어떤 그룹을 클릭해서 상세를 조회하면 — 그 사이(4단계
실행 시점~클릭 시점) 원본/목적 데이터가 다른 경로로 계속 바뀌었을 수 있는데,
그때 뽑히는 상세 데이터를 여전히 '그 4단계 실행 결과에 대한 검증 데이터'라고
볼 수 있는가?"

즉 M96은 "이미 캐시된 걸 재사용할 때"의 문제였고, 이번 질문은 "최초 콜드
스캔 자체가, 4단계 실행 시점과 다른(더 최신인) 시점의 데이터를 보고 있는 것
아니냐"는 문제다.

────────────────────────────────────────────────────────────
조사 항목
────────────────────────────────────────────────────────────
1. 그룹을 처음 클릭했을 때(콜드, 캐시 없음), 그 상세추출이 정확히 "언제"의
   데이터를 보는지 확인해라 — 클릭하는 바로 그 순간 원본/목적에 실시간으로
   접속해서 현재 데이터를 가져오는 게 맞는지 코드로 확인해라.
2. 4단계 실행 시점(T1)과 사용자가 실제로 그룹을 클릭하는 시점(T2, 훨씬 나중일
   수 있음) 사이에 원본/목적 데이터가 바뀌면, 실제로 무슨 일이 생기는지
   확인해라 — 예를 들어:
   - T1에는 불일치였던 그룹이 T2 시점엔 이미 다른 이유로 일치하게 바뀌어서,
     상세 조회 결과가 "재이관 대상 0건"으로 나올 수 있는지
   - 반대로 T1에는 일치였는데 T2엔 다른 문제가 생겨서, 화면(4단계 요약)엔
     "일치"로 뜨는데 실제로 클릭해서 보면 다른 문제가 섞여 보일 수 있는지
   - 이런 경우 화면에 "데이터가 바뀐 것 같다"는 안내가 뜨는지, 아니면
     아무 설명 없이 그냥 그 시점의 결과만 조용히 보여주는지
3. M96의 데이터변경 감지 가드가 이 "최초 콜드클릭" 케이스에도 적용되는지
   확인해라 — M96은 "캐시된 run이 있을 때 그 캐시의 기준값과 대조"하는
   방식이었는데, 캐시 자체가 없는 최초 클릭이면 대조할 기준값이 없어서
   이 가드가 애초에 작동 안 하는 구조인지 확인해라.
4. 이게 실제로 문제가 되는 상황인지 판단해라 — "검증 데이터로서의 유효성"
   측면에서, 이 시차 자체가 정상적인 것인지(모든 실시간 조회 시스템이
   갖는 당연한 특성), 아니면 사용자에게 명확히 고지해야 할 사항인지 판단해라.

완료보고
────────────────────────────────────────────────────────────

  4단계 실행 시점과 5단계 클릭 시점이 너무 벌어지면 경고를 준다든지) 제안
  해라(구현은 하지 마라 — 조사·제안까지만).
