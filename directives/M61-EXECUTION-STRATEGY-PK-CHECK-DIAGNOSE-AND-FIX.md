작업명 : M61-EXECUTION-STRATEGY-PK-CHECK-DIAGNOSE-AND-FIX

BACKLOG.md M61 항목을 먼저 읽고 시작해줘.

배경: `routes/agg_diff_route.py::_resolve_execution_strategy()`가
`services/strategy/strategy_transition.py::choose_compare_strategy()`를 호출할 때
`pk_kind=PK_SINGLE_NUMERIC, pk_indexed=True`를 하드코딩해서 넘겨, 내부 "PK 종류가
CHUNK에 안 맞으면 차단"하는 안전장치(NOT_CHUNK_CAPABLE_PK)가 이 경로에서 실질적으로
절대 발동하지 않는다.

────────────────────────────────────────────────────────────
1. 판정 — 의도된 단순화인지 놓친 배선인지
────────────────────────────────────────────────────────────
코드 커밋 이력·주석에서 이 하드코딩의 근거를 찾아라. 왜 실제 PK 종류를 전달하지
않고 고정값을 썼는지(예: 상위 DIRECT_COMPOSITE_PK 분기가 이미 PK 안전성을 걸러줘서
이 시점엔 항상 참이라고 가정했을 가능성 등) 확인.

────────────────────────────────────────────────────────────
2. 수정 (결함으로 판정된 경우)
────────────────────────────────────────────────────────────
결함이면, 실제 PK 종류/인덱스 여부를 정확히 조회해서 전달하도록 배선해라(이미
다른 곳에서 PK 메타데이터를 조회하는 기존 함수가 있으면 재사용, 새로 만들지 마).
의도된 설계로 확인되면(예: 상위 분기가 이미 보장) 그 근거를 코드 주석으로 명시만
하고 수정하지 않아도 된다 — 완료보고에 어느 쪽인지 명확히 표시.

────────────────────────────────────────────────────────────
검증(필수)
────────────────────────────────────────────────────────────
- 수정했다면: PK가 CHUNK에 부적합한 실제 케이스를 재현해서, 이제 NOT_CHUNK_CAPABLE_PK
  가 정상 발동하는지 확인.
- 수정 안 했다면(의도된 설계 확인): 왜 안전한지 근거를 실측으로 재확인.
- 관련 테스트 서브셋 + baseline 대조, 신규 회귀 0건.
- CLAUDE.md 필수 회귀(virtual/complex) 최종 1회.
- 완료보고: 1번 판정 근거, 2번 조치 내역, 검증 결과, 커밋해시(수정한 경우). 작업명
