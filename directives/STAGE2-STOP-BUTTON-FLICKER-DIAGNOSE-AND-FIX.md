작업명 : STAGE2-STOP-BUTTON-FLICKER-DIAGNOSE-AND-FIX

배경: M43(STAGE-EXEC-CROSS-STAGE-CONTAMINATION-AND-STOP-BUTTON-FIX)에서 신설한 2단계
COUNT 멈춤 버튼이, 실서버(포트 8000) 재기동 후 실측 결과 "실행 중 잠깐 나타났다가
사라진다"는 게 확인됐다. 코드가 반영은 됐다(버튼이 한 번은 뜸)는 뜻이니, 재기동
문제가 아니라 다른 코드가 버튼 상태를 중간에 덮어쓰는 새 버그다.

1. 먼저 재현: 실제 포트 8000, 대용량 COUNT(5천만행급, NXDNP.MV_SCATTER50M_SRC/TGT 등
   사용자가 이전에 쓰던 것과 동일 조건)로 2단계 COUNT를 실행하면서, 버튼 DOM 상태
   (텍스트/클래스/onclick)를 짧은 간격(예: 200ms)으로 폴링해서 로그로 남겨라. 정확히
   몇 초 시점에 "■ 중단" → 원래 상태로 바뀌는지, 그 사이 어떤 다른 fetch/재렌더 호출이
   있었는지(네트워크 탭·콘솔 로그 함께 기록) 특정하라.

   **가장 중요 — 버튼이 사라진 뒤에도 실제 중단 기능이 살아있는지 반드시 구분해서
   확인할 것**: 버튼 사라진 시점 이후에 (a) 그 버튼이 원래 있던 자리를 눌러보거나
   (b) 개발자도구 콘솔에서 abort 함수를 직접 호출해서, COUNT 쿼리가 실제로 즉시
   취소되는지 실측하라. 결과를 아래 두 가지로 명확히 구분해서 보고할 것:
   - [화면만 문제] 기능은 살아있는데 버튼만 안 보임(콘솔 직접 호출로는 멈춤)
   - [기능 자체 소실] 버튼이 사라진 뒤로는 어떤 방법으로도 중단이 안 됨(더 심각,
     "사용자가 대용량 COUNT를 실수로 돌리면 끝날 때까지 아무것도 못 하는" 상태)
   후자로 확인되면 완료보고 맨 위에 [심각] 표시하고 최우선으로 다룰 것.
2. M43 작업 시 3순위(_mvSyncRunLockedControls)와 2순위(멈춤 버튼) 코드가 서로 다른
   시점에 커맨드바를 각자 재렌더하면서, 한쪽이 다른 쪽이 세운 버튼 상태를 덮어쓰는
   경쟁 상태(race)가 의심된다. mvCommandBarRunAction / _mvSyncRunLockedControls /
   COUNT 진행 중 주기적으로 호출되는 다른 렌더 함수(있다면)들이 버튼 HTML을 각자
   따로 만들어 서로 경합하는지 코드 추적으로 확인.
3. 원인이 확인되면, 버튼 상태를 단일 진실 출처(single source of truth) — 예를 들어
   _countInProgress 플래그 하나만 보고 모든 재렌더 지점이 동일한 로직으로 버튼을
   그리도록 — 로 통합해서 고쳐라. 임시방편(재렌더 주기만 늦추는 식)은 쓰지 말 것.
4. 4단계 멈춤 버튼도 같은 원인(공유 렌더 함수)일 수 있으니 동일 조건으로 재현 확인.

검증(필수, 서버 재기동 포함):
  - 재기동 시각·워킹트리 HEAD 커밋 해시를 완료보고 맨 앞에 명시.
  - 수정 후 같은 방식(200ms 폴링 로그)으로 2·4단계 각각 COUNT/실행 시작부터 끝까지
    멈춤 버튼이 사라지지 않고 유지되는지, 실제로 클릭해서 멈추는지 재확인.
  - 실제 포트 8000, 인증 ON, 격리 서버 금지.
  - 관련 테스트 서브셋 + baseline 대조, 신규 회귀 0건.
