작업명 : F14-F15-ORACLE-MSSQL-METADATA-PROVIDER-VARCHAR-CAPACITY-WARNING-WIRE

두 작업은 같은 도메인(VARCHAR 실효수용량 경고)이지만 어댑터 파일이 다를 수 있다.
먼저 실제로 같은 파일을 건드리는지 확인하고, 겹치면 순차로, 안 겹치면 순서 상관없이
처리해줘. 지시된 범위 외 파일 수정 금지.

배경: PostgreSQL은 VARCHAR/NVARCHAR 실효 저장용량 축소 경고가 이미 있는데, 오라클은
metadata provider 배선이 없어 운영 화면에 안 뜨고(F14), MSSQL은 컬럼 메타 조회 자체가
구현 안 돼 있어(F15) 같은 경고가 아예 불가능하다.

────────────────────────────────────────────────────────────
1) F14 — 오라클 metadata provider 미배선
────────────────────────────────────────────────────────────
PostgreSQL의 VARCHAR 실효수용량 경고가 어느 provider/서비스에서 나오는지 먼저 추적하고,
오라클 어댑터에 동일한 provider가 왜 배선 안 됐는지(구현은 있는데 배선만 없는지, 구현
자체가 없는지) 확인. 배선만 없으면 연결, 구현 자체가 없으면 PostgreSQL 패턴을 참고해
VARCHAR2 byte/char 의미(S13 백로그 참고 — 이미 알려진 사각지대)까지 고려해서 구현.

────────────────────────────────────────────────────────────
2) F15 — MSSQL 컬럼 메타 조회 자체 미구현
────────────────────────────────────────────────────────────
MSSQL은 F23(fetch_key_metadata 미구현, 이미 해결완료로 기록됨) 때와 유사하게 어댑터
`connect()` 미구현 등으로 컬럼 메타 조회 자체가 안 되는지 먼저 확인. F23 해결 커밋을
찾아서 그때 어디까지 됐고 뭐가 남았는지부터 파악한 뒤, VARCHAR/NVARCHAR 구분 조회를
추가.

────────────────────────────────────────────────────────────
