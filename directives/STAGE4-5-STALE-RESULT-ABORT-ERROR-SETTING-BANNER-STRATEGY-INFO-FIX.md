────────────────────────────────────────────────────────────
1순위 [버그, 원인 미조사] — 중단 후 재실행 시 이전 실행 결과가 남아있음
────────────────────────────────────────────────────────────
재현: 4단계 통계검증 실행 중 중단 → 다시 실행 → 이전 실행의 결과(실행시간·상태 등)가
새 실행 결과인 것처럼 화면에 남아있음(스크린샷 근거: 12.13초/불일치가 재실행 후에도
그대로 표시됨).
먼저 원인을 코드로 추적해줘 — 중단 시 결과 상태를 초기화하는 지점이 있는지, 재실행
시작 시점에 이전 결과를 지우는 로직이 있는지 확인. 그 다음 재실행 시작 시 이전 결과를
명확히 초기화(빈 상태 또는 "실행 중"으로 전환)하도록 수정.

────────────────────────────────────────────────────────────
2순위 [버그, 원인 미조사] — 내부 취소 신호 원문이 그대로 에러창에 노출됨
────────────────────────────────────────────────────────────
재현: 3단계에서 후보추천 실행 중 중단 → 4단계로 넘어가 실행 → "SQL 생성 오류: signal
is aborted without reason"이라는 브라우저 alert가 뜸(AbortController의 원시 에러
메시지가 그대로 노출된 것으로 추정).
원인 추적 후, 이런 내부 취소 신호(AbortError 등)는 사용자에게 노출하지 말고 조용히
무시하거나(정상적인 취소이므로 에러가 아님), 노출해야 한다면 "이전 요청이 취소됨"
같은 이해 가능한 문구로 바꿔줘. 진짜 SQL 생성 오류(문법 오류 등)와는 구분해서, 진짜
오류는 계속 에러창에 그대로 뜨게 유지할 것.

────────────────────────────────────────────────────────────
3순위 — "설정 실행당시/현재 다름" 배너가 항상 뜨는 오탐 수정
────────────────────────────────────────────────────────────
`ui/grid_helpers.py:2049-2060`(오늘 STAGE4-TAB-LABEL-LAG-AND-PRIOR-STAGE-LOCK-SCOPE-
DIAGNOSE.txt §3에서 이미 위치 특정됨) — 이 배너가 "실제 실행 세트 개수"가 아니라
"정책 상한(예: 100)"과 비교하고 있어, 사용자가 상한 미만으로 선택하면 아무것도 안
바꿔도 항상 뜬다. 실제 실행 당시 세트 구성과 현재 세트 구성을 정확히 비교하도록 수정
(정말 달라졌을 때만 배너가 뜨게).

────────────────────────────────────────────────────────────
4순위 — 4·5단계 "전략" 정보를 더 풍부하게
────────────────────────────────────────────────────────────
현재(오늘 M51로 SQL 하단에 배치됨) "전략 표본 집계 STATS_SAMPLE_ONLY" 배지 하나뿐이라

예상 소요시간 vs 실측 소요시간, 규모 등급 등 — 3단계/전략 결정 서비스가 이미 계산해서
갖고 있는 값들을 코드로 찾아줘)를 함께 노출하는 형태로 확장. 새 계산 로직을 만들지
말고, 이미 존재하는 값을 가져다 붙이는 것으로 한정. 5단계도 동일하게(아래 6순위와
함께).

────────────────────────────────────────────────────────────
5순위 — 5단계 진입 시 4단계 탭 "진행중" 표시 재검토
────────────────────────────────────────────────────────────
오늘 STAGE4-TAB-LABEL-LAG-AND-PRIOR-STAGE-LOCK-SCOPE-DIAGNOSE.txt가 "5단계 진행
중이면 4단계 탭에 그 상태를 미러링하는 의도된 설계"라고 결론 내렸었는데, 사용자가
실제로 써보니 부자연스럽다고 재검토 요청. 그 진단서의 항목1 상세 내용을 다시 읽고,
"의도된 설계"를 유지하되 문구/시각적 표현을 더 명확하게 바꿀지(예: 4단계 자체는
'완료'로 두고 별도의 작은 보조 표시로만 5단계 진행 상태를 알리는 등), 사용자와 함께
최선의 표현 방식을 판단해서 개선. 완전히 없애는 것(4단계를 무조건 '완료'로만 표시)은
5단계 자기치유 로직과의 연결을 끊을 수 있으니, 그 진단서가 지적한 위험을 재확인하고
진행할 것.
