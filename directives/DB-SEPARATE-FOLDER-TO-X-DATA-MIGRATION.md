작업명 : DB-SEPARATE-FOLDER-TO-X-DATA-MIGRATION

배경: 사용자가 X:\Projects 밑에 여러 프로그램을 각각 폴더로 개발할 예정이고, 로컬
SQLite DB는 프로그램 소스 폴더에 종속되지 않도록 별도 공용 위치(X:\Data\)에 두려고
한다. 테이블 이름공간 충돌·장애 전이 위험 때문에 완전 통합(DB 파일 1개 공유)이 아니라
**프로그램별 파일은 분리하되 위치만 소스 폴더 밖**으로 두는 절충안으로 이미 합의됐다
(이번 프로그램은 X:\Data\migration_validator.db 로 이동).

────────────────────────────────────────────────────────────
1. 전수 조사 (먼저, 코드 수정 전)
────────────────────────────────────────────────────────────
현재 이 프로젝트가 여는 모든 .db 파일 경로를 전수 확인해줘:
  - db/ 폴더 안의 실제 .db 파일 목록(migration_validator.db, chunk_checkpoints.db 등
  현재 몇 개인지)
  - 각 파일을 여는 코드 지점(services/*.py 등)에서 경로가 어떻게 계산되는지 —
    하드코딩된 상대경로("db/xxx.db")인지, 공통 설정 모듈을 거치는지, 아니면 각자
    따로 계산하는지(중복 계산 지점이 있으면 나중에 하나 놓치기 쉬우니 전부 나열)
  - db/schema.sql, db/init_db.py도 경로 하드코딩이 있는지
  - 테스트/스크립트(tests/, scripts/dev_e2e/, scripts/dev_fixtures/)가 db 경로를
    참조하는 지점도 별도로 나열(운영 코드와 테스트 코드를 구분해서 표로 정리)

────────────────────────────────────────────────────────────
2. 설계
────────────────────────────────────────────────────────────
조사 결과를 바탕으로, DB 경로를 **단일 진실 출처**로 만드는 방법을 설계해줘:
  - 이미 공통 설정 지점이 있으면 그걸 재사용해서 base 디렉터리만 X:\Data\
    Migration_Validator\(또는 적절한 하위폴더)로 바꾸는 형태를 우선 검토.
  - 공통 지점이 없고 각자 하드코딩돼 있으면, 신규 공통 모듈(가칭 db_paths.py)을 만들고
    환경변수(예: MV_DATA_DIR, 기본값은 지금처럼 프로젝트 내 db/ 폴더 — 하위호환 유지)로
    override 가능하게 설계.
  - 기존 db/ 폴더의 실제 파일들을 X:\Data\Migration_Validator\로 이동(복사 후 원본은
    이름을 바꿔 보관, 삭제하지 않음 — robocopy 원칙 재사용).

────────────────────────────────────────────────────────────
3. 구현
────────────────────────────────────────────────────────────
설계에 따라 코드 반영. 이번 프로그램(Migration Validator) 하나만 옮기는 것이므로
"여러 프로그램이 공유하는 폴더 구조"까지 미리 만들 필요는 없음 — 이번 프로그램용
하위폴더 하나만 X:\Data\ 밑에 만들면 됨(다른 프로그램은 각자 착수 시 자기 폴더를
따로 만들 것).

────────────────────────────────────────────────────────────
검증(필수)
────────────────────────────────────────────────────────────
- 서버 재기동, 실제로 X:\Data\...의 DB 파일을 열어서 읽고 쓰는지 확인(기존 db/ 폴더
  파일이 아니라 새 위치의 파일이 갱신되는지 실측 — 예를 들어 뭔가 하나 저장해보고
  새 위치 파일의 mtime이 갱신되는지 확인).
- 환경변수 미설정 시 기존 동작(프로젝트 내 db/ 폴더) 그대로 유지되는지도 확인(하위호환).
- 관련 테스트 서브셋(DB 접근하는 테스트 다수) + baseline 대조, 신규 회귀 0건.
- CLAUDE.md 필수 회귀(virtual/complex) 최종 1회.
- 원본 db/ 폴더 파일은 삭제하지 말 것(이름 변경 등으로 보관).
- 완료보고: 1번 조사표, 2번 설계 근거, 3번 반영 내용, 검증 결과, 재기동 시각·HEAD
  커밋 해시, 커밋 해시. 작업명 첫줄/마지막줄.

안 되는 전수조사+구조변경 작업)
