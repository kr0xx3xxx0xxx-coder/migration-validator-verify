작업명 : C1-C2-OLLAMA-DIRECT-USE-SCOPE-AND-IMPLEMENT

C1-C2-PIPELINE-IMPACT-MEASURE-STEP1.txt(오늘 완료, 스코프 48.8% 확정)와
LLM-ADMIN-COLUMN-JUDGMENT-SCOPE-AND-DESIGN-DIAGNOSE.txt(M50, 직접 활용 안전설계
원칙 확립)를 먼저 읽고 시작해줘. 승인 완료 — 다만 이건 오늘 만든 E1/일괄실패요약
(간접 활용, 판정 미개입)과 성격이 다르다. **이번엔 컬럼 의미 분류(GROUP BY/SUM
후보 판정)에 직접 관여하는 직접 활용이라 M50이 확립한 안전원칙을 그대로 적용해야
한다.**

배경: 사전 완전무매치 컬럼 중 화면에 실제 노출되는 것의 48.8%가 최종까지
CT_GENERAL_GROUP/CT_UNKNOWN_REVIEW로 애매하게 남는다(실측 확정). 이 중 LLM이
컬럼명·코멘트를 보고 의미 유형을 보완 추론할 수 있는 자리(C1)와, 코멘트 해석을
보완할 자리(C2)에 LLM을 3차 근거로 넣는다.

────────────────────────────────────────────────────────────
1. M50 안전원칙 그대로 적용 (필수, 타협 불가)
────────────────────────────────────────────────────────────
- LLM은 **규칙기반 축이 전부 결론을 못 낸 자리(CT_GENERAL_GROUP/UNKNOWN_REVIEW로
  이미 확정된 경우)에서만** 호출되는 3차 근거다 — 확신 있는 규칙기반 결론을
  LLM이 뒤집는 경로는 절대 만들지 마라.
- **비대칭 반영**: LLM 응답으로 "이 컬럼은 특정 의미유형이다"처럼 더 구체적인
  분류로 승격은 가능하되, 반대로 규칙기반이 이미 확정한 판정을 LLM이 자동으로
  해제/하향하는 경로는 만들지 마라(오탐 비용 > 미탐 비용 원칙).
- 실제 삽입 지점을 코드로 정확히 특정해라(짐작 금지) — `candidate_subtype_
  service`의 어느 분기가 CT_GENERAL_GROUP/UNKNOWN_REVIEW로 귀결되는지 정확히
  찾아서, 그 직후에만 LLM 호출이 들어가도록 해라.

────────────────────────────────────────────────────────────
2. LLM 연동 인프라 (E1/일괄실패요약 그대로 재사용)
────────────────────────────────────────────────────────────
오늘 만든 인프라(`urllib.request` 직접호출, 기본OFF+fail-open+circuit-breaker,
SQLite 캐시, 모델은 `gemma3:4b`)를 그대로 재사용해라 — 새로 설계하지 마라. 별도
`prompt_version`으로 다른 두 기능과 캐시 분리해라.

────────────────────────────────────────────────────────────
3. 안전조건 (오늘 원칙 적용, 판정 개입용으로 재해석)
────────────────────────────────────────────────────────────
(a) 최종 화면에 표시되는 판정 배지에는, LLM이 기여했다는 사실과 그 근거를
    명확히 표기해라(F19가 이미 만든 `score_contributions`/배지 툴팁 선례
    재사용 — LLM 기여분도 그 방식으로 설명 가능하게).
(b) 모델에는 컬럼명·코멘트·정규화된 메타데이터(타입 등)만 전달하고, 실제 데이터
    값 원문은 전달하지 마라(민감정보 유출 방지 — E1/일괄실패요약과 동일 원칙).
(c) 모델 응답을 그대로 신뢰하지 말고, 이미 정의된 의미유형 카탈로그 안의 값으로만
    매핑되게 검증해라(모델이 카탈로그에 없는 임의의 유형을 만들어내는 것 방지).
(d) 미기동/장애 시 기존 CT_GENERAL_GROUP/UNKNOWN_REVIEW 그대로 유지(폴백).

────────────────────────────────────────────────────────────
검증(필수, 실측)
────────────────────────────────────────────────────────────
- 오늘 실측에서 애매하게 남았던 실제 컬럼(예: BATCH_ID류)을 재현해서, LLM이
  실제로 더 구체적인 유형으로 승격시키는지, 그 근거가 화면에 정확히 표기되는지
  확인.
- 규칙기반이 이미 확신 있게 판정한 컬럼(CT_GENERAL_GROUP이 아닌 것)은 LLM 호출
  자체가 안 일어나는지 확인(호출 스코프 정확성).
- LLM 미기동 시 기존과 동일하게(회귀 없이) 애매 판정 그대로 유지되는지 확인.
