1. [최우선] count_precheck_service.py 배치루프 scope 적용
────────────────────────────────────────────────────────────
`count_precheck_service.py:946` 부근의 `for row in targets:` 루프를
`request_connection_scope`로 감싸서, 테이블당 3회 물리 핸드셰이크를 2회로
줄여라 — 같은 목적의 `batch_count_only_service.py:243`이 이미 쓰는 패턴을
그대로 재사용해라.

────────────────────────────────────────────────────────────
2. agg_diff_route.py:311 커넥션 누수 수정
────────────────────────────────────────────────────────────
`scn = _pg_raw_connect(...); tcn = _pg_raw_connect(...)`가 try 블록 밖에 있어
두 번째 연결 실패 시 첫 번째가 누수되는 문제 — 같은 파일 435행의 정답 패턴
(scn=tcn=None 선언 → try 안에서 connect → finally에서 None체크 후 close)으로
통일해라.

────────────────────────────────────────────────────────────
3. count_execution_planner._pg_fetch_scalar 풀 사용
────────────────────────────────────────────────────────────
scope가 활성일 때는 이 함수도 raw connect 대신 풀을 타도록 고쳐라.

────────────────────────────────────────────────────────────
4. (선택, 시간 남으면) batch_route.py:1041↔1203
────────────────────────────────────────────────────────────
close가 finally 블록 밖에 있는 것도 finally로 옮겨라(심각도 낮음, 우선순위
