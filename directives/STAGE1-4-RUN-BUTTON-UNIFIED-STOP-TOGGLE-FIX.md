작업명 : STAGE1-4-RUN-BUTTON-UNIFIED-STOP-TOGGLE-FIX

배경: M43(STAGE-EXEC-CROSS-STAGE-CONTAMINATION-AND-STOP-BUTTON-FIX)에서 2·4단계에
별도 멈춤 버튼을 신설했는데, 실서버(포트 8000) 재기동 후 실측 결과 "실행 중 버튼이
잠깐 나타났다가 사라진다"는 깜빡임 버그가 확인됐다. 원인은 별도 버튼 요소가 기존
실행 버튼 렌더 로직과 경합(race)하는 구조 때문으로 의심된다. 사용자가 설계를
아래와 같이 단순화하기로 확정했다 — 별도 버튼을 없애고 기존 버튼 하나를 토글한다.

────────────────────────────────────────────────────────────
확정된 설계 (전 단계 공통, 이전 지침의 "별도 버튼" 방식은 폐기)
────────────────────────────────────────────────────────────
버튼은 각 단계마다 **하나의 DOM 요소**만 존재한다. 클릭 시점·몇 번째 클릭인지와
무관하게 아래 규칙을 그대로 적용한다:

  1. 사용자가 실행 버튼을 클릭한다(1·3단계의 유일한 실행, 또는 2·4단계의 1차
     [쿼리 생성] 클릭이든 2차 [실행] 클릭이든 구분하지 않는다).
  2. 클릭 즉시 그 버튼의 라벨/onclick을 "■ 중단"으로 바꾸고 클릭 가능(활성) 상태로
     만든다. 서버 처리가 실제로 몇 초 걸리든, 순식간에 끝나든 상관없이 클릭하는
     즉시 무조건 전환한다(빠르게 끝나는 케이스에서 중단 버튼이 아주 잠깐만 보이고
     바로 원래대로 돌아가는 것은 정상 — 그 찰나에도 데이터/상태 오염이 없어야 한다).
  3. 처리가 끝나면(성공/실패/사용자가 중단 눌러서 취소됨 등 결과와 무관하게) 같은
     버튼이 원래 라벨/onclick으로 복귀한다.
  4. 이 규칙을 1·2·3·4단계 전부에 동일하게 적용한다. 1·3단계는 실제로는 순식간에
     끝나 중단이 실익 없지만, 화면 동작 일관성을 위해 넣는다(사용자 확정).
  5. 버튼 상태는 단일 진실 출처(예: 단계별 in-progress 플래그 하나)로만 결정하고,
     그 플래그를 보고 렌더하는 코드 경로를 하나로 통합한다 — 여러 함수가 각자
     따로 버튼 HTML을 그려서 경합하는 지금 구조(2순위 신규 버튼 렌더 + 3순위
     _mvSyncRunLockedControls 가 서로 다른 시점에 개입하는 구조)를 없앨 것.

────────────────────────────────────────────────────────────
1. 재현 및 원인 확인 (신규 코드 작성 전 먼저)
────────────────────────────────────────────────────────────
실제 포트 8000, 대용량 COUNT(NXDNP.MV_SCATTER50M_SRC/TGT, 5천만행급, 사용자가 이전에
쓰던 것과 동일 조건)로 2단계를 실행하면서 버튼 DOM 상태(텍스트/클래스/onclick)를
200ms 간격으로 폴링해 로그로 남겨라. 몇 초 시점에 상태가 바뀌는지, 그 사이 어떤
다른 fetch/재렌더 호출이 있었는지(네트워크·콘솔 로그 포함) 특정해서 지금 구조의
정확한 경합 지점을 확인하라.

**버튼이 사라진 뒤 실제 중단 기능이 살아있는지도 구분 확인할 것**(수정 전 상태
기준): 버튼이 안 보이는 시점에 개발자도구 콘솔에서 abort 함수를 직접 호출했을 때
COUNT가 실제로 즉시 취소되는지 실측. [화면만 문제] vs [기능 자체 소실]을 구분해서
완료보고에 남겨라(후자면 이번 재설계로 완전히 해소되는지도 확인).

────────────────────────────────────────────────────────────
2. 구현
────────────────────────────────────────────────────────────
위 "확정된 설계" 5개 규칙 그대로 1~4단계 실행 버튼에 적용. 2순위가 만든 별도 멈춤
버튼 요소는 제거하고, 기존 실행 버튼(mvCommandBarRunAction 등)의 라벨/onclick을
in-progress 플래그에 따라 토글하는 단일 렌더 경로로 재작성.
