────────────────────────────────────────────────────────────
구현
────────────────────────────────────────────────────────────
`get_by_fingerprint(fp)`가 메모리 캐시 미스일 때, 바로 None을 반환하지 말고 **DB
(exact_diff_run 테이블)에서 같은 fingerprint로 저장된 완료 run이 있는지 먼저
조회**해라. 있으면 그 run 정보로 메모리 캐시를 재구성(rehydrate)해서 반환 — 재스캔을
건너뛴다. DB에도 없으면 기존대로 None 반환(새 스캔).

새 저장 구조를 만들지 마 — 이미 `exact_diff_run` 테이블에 fingerprint를 조회할 수
있는 컬럼이 있는지 먼저 확인하고, 없으면 최소한의 조회 로직만 추가(스키마 변경이
필요하면 그 범위와 위험도를 완료보고에 먼저 밝히고 계속 진행해도 되는지 스스로
판단 — 위험이 크면 구현 대신 설계만 하고 멈춰도 된다).
