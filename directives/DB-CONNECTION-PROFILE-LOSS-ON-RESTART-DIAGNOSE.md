작업명 : DB-CONNECTION-PROFILE-LOSS-ON-RESTART-DIAGNOSE

코드 수정 없이 조사만 해줘.

배경: 개발서버를 껐다 켠 뒤 브라우저로 다시 접속하면 (1) 프로젝트 선택 상태가
풀려있고 (2) 만들어뒀던 원본/목적 DB 연결 프로필(검증 경로)이 사라져서 매번 새로
구성해야 한다. **그런데 PostgreSQL 연결은 살아남고, 다른 DBMS(짐작건대 오라클)
연결은 사라지는 것으로 보인다.**

────────────────────────────────────────────────────────────
1. DB 연결 프로필 저장 위치·방식 확인
────────────────────────────────────────────────────────────
"검증 경로 목록"(스크린샷의 그 화면)에 뜨는 연결 프로필이 실제로 어디에
저장되는지(DB 테이블인지, 파일인지, 메모리인지) 확인해라. PostgreSQL 프로필과
오라클(또는 다른 DBMS) 프로필이 **서로 다른 저장 방식**을 쓰고 있는지 확인 —
예를 들어 하나는 DB에 영속 저장되고 다른 하나는 서버 프로세스 메모리에만 있어서
재기동하면 사라지는 구조인지.

────────────────────────────────────────────────────────────
2. 실제 재현
────────────────────────────────────────────────────────────
가능하면 실제로 오라클 연결 프로필을 만들고 서버를 재기동해서, 정말 사라지는지
재현해라(PostgreSQL 프로필도 같이 만들어서 대조군으로 삼아라 — 정말 PostgreSQL만
남는지 확인).

────────────────────────────────────────────────────────────
3. 프로젝트 선택 상태 소실도 같이 확인
────────────────────────────────────────────────────────────
"작업 프로젝트" 선택 상태가 재기동 시 풀리는 것도 같은 원인(세션/메모리 기반
저장)인지, 아니면 별개 메커니즘인지 확인.

완료보고: 1~3 결과, 근본 원인(DBMS별로 저장 방식이 다른지, 의도된 설계인지 결함인지),
수정 방향 제안. 코드 수정은 하지 말고 결과만 알려줘.
