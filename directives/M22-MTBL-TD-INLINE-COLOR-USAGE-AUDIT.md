작업명 : M22-MTBL-TD-INLINE-COLOR-USAGE-AUDIT

코드 수정 없이 조사만 해줘. BACKLOG.md M22 항목을 먼저 읽고 시작해줘.

배경: `.mtbl td { color: ... !important }` CSS 규칙이 M17 문제의 원인이었는데(그때는
`_mvPkCellSplit`이 색을 자식 span으로 옮겨서 해소), 규칙 자체는 여전히 남아있어 `.mtbl`
표 안에서 td에 인라인 color를 직접 주는 다른 렌더 지점이 있으면 동일하게 색이 죽을
위험이 있다.

1. `.mtbl` 클래스가 적용되는 모든 표 렌더 지점을 찾고, 그 안에서 td에 직접 인라인
   `style="color:..."` 또는 `.style.color = ...`를 주는 코드가 있는지 전수 검색.
2. 있다면 각각 M17처럼 자식 span으로 옮겨야 하는지, 이미 안전한 패턴(span 사용)을
   따르고 있는지 분류.
3. 규칙 자체(`.mtbl td { color: ... !important }`)를 제거하거나 완화하는 게 안전한지도
   검토(다른 어딘가 이 규칙에 의존하는 코드가 있는지 확인) — 다만 이번 지침은 조사만,
   실제 CSS 규칙 변경은 하지 마.

완료보고: 전수 검색 결과(파일:라인별 위험지점 목록, 있다면), 규칙 제거 안전성 판단,
착수 필요 여부(위험지점이 실제로 있으면 후속 지침 필요, 없으면 "발현 지점 없음"으로
백로그 종결 제안). verify 저장소에 진단 보고서만 push(코드 변경 없음).
