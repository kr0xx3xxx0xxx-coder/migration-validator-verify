작업명 : P13-ORACLE-PARALLEL-EXCLUSION-REASON-VERIFY-AND-EXTEND

BACKLOG.md P11/P13 항목과 STATS-SET-PARALLELISM-CONDITIONAL-ENABLE-FIX.txt(P11 구현
완료본)를 먼저 읽고 시작해줘. 사용자 결정: 오라클도 병렬 켜지도록 조건 확대 진행,
단 먼저 왜 제외됐는지 확인 후 안전하면 적용해라.

────────────────────────────────────────────────────────────
1. 오라클 제외 이유 확인 (필수 선행)
────────────────────────────────────────────────────────────
P11 구현(`_stats_set_parallel_auto_enabled` 등 조건부 ON 로직)에서 오라클을 명시
제외한 근거를 코드 주석·커밋 메시지·STATS-SET-PARALLELISM-CONDITIONAL-ENABLE-FIX.txt
본문에서 찾아라. "오라클은 풀 우회 구조상 명시 제외"라고 BACKLOG에 적혀 있는데, 이게
정확히 어떤 메커니즘 때문인지(커넥션 풀 재사용 방식이 PG와 달라서 병렬 연결 시 실제로
문제가 생기는지, 아니면 그냥 미검증이라 보수적으로 뺀 것뿐인지) 코드로 확인.

────────────────────────────────────────────────────────────
2. 안전성 재현 테스트
────────────────────────────────────────────────────────────
실제 오라클 asis/tobe 연결로, 같은 세트를 병렬(level 2) 방식으로 강제 실행시켜서
(임시로 조건 우회) 결과가 순차 실행과 완전 동일한지, 커넥션 관련 에러(ORA-XXXX)가
안 나는지 실측. 1번에서 확인된 우려가 실제로 재현되는지가 핵심.

────────────────────────────────────────────────────────────
3. 조건 확대 (1·2번에서 안전 확인된 경우만)
────────────────────────────────────────────────────────────
안전하면 조건부 ON 로직에서 오라클 제외를 풀어라. **P11이 이미 쓴 안전장치 그대로
유지**: kill-switch(MV_STATS_SET_PARALLEL_AUTO), 임계치 env
(MV_STATS_SET_PARALLEL_MIN_ROWS), 4조건(대규모+다른물리DB+풀여유) 중 "PostgreSQL"
조건만 "PostgreSQL 또는 오라클(안전확인됨)"로 확장. 새 위험이 있다면(예: 오라클만의
추가 안전장치가 필요) 그것도 함께 반영.
**2번에서 위험이 재현되면 여기서 멈추고 코드 변경하지 마 — 결과만 정리해서 보고.**

────────────────────────────────────────────────────────────
4. P13 재측정 (3번 완료된 경우, 5천만행 오라클로)
────────────────────────────────────────────────────────────
NXDNP.MV_SCATTER50M_SRC/TGT(5천만행) 등으로, 이제 실제로 병렬이 켜지는 오라클
환경에서 순차 대비 개선폭을 실측. P11이 100만행 PG에서 본 -6.3%(작은 개선)와
비교해서, 원래 백로그가 근거로 든 -41~55% 개선이 5천만행 규모에서 실제로 나오는지
확인.
