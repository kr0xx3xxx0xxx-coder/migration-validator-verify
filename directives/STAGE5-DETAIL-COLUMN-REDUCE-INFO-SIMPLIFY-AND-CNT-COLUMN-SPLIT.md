────────────────────────────────────────────────────────────
1. 상세 레코드 테이블 컬럼을 PK + 후보 컬럼만으로 축소 (재확인, 필수)
────────────────────────────────────────────────────────────
증상: 상세 레코드 테이블이 이관 SQL의 전체 컬럼(PK_STR, REGION_CD, STATUS_CD, AMT,
QTY, SEQ_NO, ITEM_NM)을 다 보여주는데, 이 중 실제 검증에 쓰인 후보 컬럼(예:
REGION_CD/STATUS_CD/AMT/QTY)이 아닌 SEQ_NO/ITEM_NM은 검증과 무관해서 보여줄 필요가
없다.

수정: 상세 레코드 테이블의 컬럼을 **PK + 그 실행에 쓰인 후보 컬럼(GROUP BY 축 +
SUM 대상)만**으로 좁혀라. 새로 계산하지 말고, 이미 어딘가에 있는 "이번 실행에 쓰인
후보 컬럼 목록"(3단계 선택 결과)을 그대로 재사용해서 테이블 렌더 시 컬럼을 필터링해라.
PK는 항상 포함.

────────────────────────────────────────────────────────────
2. 그룹 상세 정보 블록 간소화
────────────────────────────────────────────────────────────
그룹을 펼쳤을 때 검색조건 폼 아래에 뜨는 정보 블록을 다음과 같이 정리:
- "이 그룹 원본 N건·목적 N건·차이 N건" 줄 — **제거**
- "재이관 대상 N건 이상(0.00%) (현재 목록) 조기중단" 배지 줄 — **제거**
- "이 건수는 행 레코드 기준..." 설명 문구 — **제거**(위 두 줄과 함께 사라지는 게
  자연스러움)
- "목적 미존재 N건(0.00%)·값 불일치 N건(0.00%)" — **제거**(항상 0.00%로만 표시돼
  의미 없음)
- "목적 단독 N건(0.00%) — 재이관 비율에 미포함" — **제거**
- "※ 수집이 조기중단되어..." 각주 — **제거**
- "실행경로 X·전략 Y·selected=actual" 줄 — **그대로 유지**(조사 완료 — 실제로
  "실행경로"는 3종류(DIRECT_COMPOSITE_PK/LEGACY_PATH/SCHEDULER_PATH), "전략"은
  2종류(DIRECT_STREAM_COMPARE/PK_RANGE_CHUNK_COMPARE)가 상황에 따라 실제로 갈리는
  의미 있는 정보임을 코드로 확인함. 이 줄은 절대 건드리지 마라).
- "추출 소요 N초·세부 성능정보는 위 '검증성능정보' 영역에서 확인" 줄 — **제거**(오늘
  이미 상단 고정 영역으로 옮겨졌으니 여기 남은 안내문 자체가 중복).

정리 후 남는 건 "실행경로/전략" 줄과 실제 레코드 테이블뿐이어야 한다.

────────────────────────────────────────────────────────────
3. 검색조건 폼 완전 제거 (범위 확대)
────────────────────────────────────────────────────────────
오늘 앞선 작업(STAGE5-DETAIL-TABLE-HEADER-LABEL-AND-COLOR-FIX)이 "GROUP BY 기준/
그룹 값"은 제거하고 "불일치 유형/PK 검색"은 실제 서버 조회조건이라는 이유로 남겨
뒀는데, 사용자가 재검토 후 **이 둘도 함께 제거**하기로 결정했다. 그룹 인라인 펼침
화면의 검색조건 폼(`_mvRiBuildFilterBar` 등, showAxis 여부와 무관하게)을 전부
제거해라 — 그 결과 조회되는 API 호출에서도 관련 파라미터(`mtype=`/`pk=`)가 안 실려도
되도록(기본값으로 전체 조회) 처리. 단, 스코프 없는 "전체 그룹 한번에 추출" 화면은
이번 지침 범위가 아니면 그대로 둘지, 함께 제거할지 판단해서 완료보고에 근거를 남겨라
(이 지침의 취지는 "그룹 단위로 이미 좁혀진 뒤에는 추가 검색이 불필요"이므로, 전체
그룹 화면처럼 애초에 안 좁혀진 경우는 검색이 여전히 유용할 수 있음 — 다만 최종 판단은
맡긴다).

────────────────────────────────────────────────────────────
4. 그룹 목록 헤더 — CNT를 별도 컬럼으로 분리
────────────────────────────────────────────────────────────
증상(스크린샷 근거): 그룹 목록 그리드의 "목적지 집계"/"원본 집계" 컬럼이 CNT/AMT/QTY를
한 셀 안에 여러 줄로 합쳐서 보여준다.

수정: "목적지 집계"/"원본 집계" 컬럼 앞(또는 "판정" 컬럼 바로 뒤)에 **"목적카운트"/
"원본카운트"** 별도 컬럼을 신설해서 CNT 값만 그쪽으로 옮겨라. 기존 "목적지 집계"/
"원본 집계" 컬럼에서는 CNT를 빼고 AMT/QTY만 남겨라. 헤더 순서는 "판정 → 목적카운트 →
원본카운트 → 목적지 집계 → 원본 집계 → 상세 추출 상태"로.

이건 2번(그룹 펼침 상세 화면)과 다른 화면(그룹 목록 자체)이니 혼동하지 말 것 — 목록
행 자체의 헤더/셀 구조를 바꾸는 작업이다.
