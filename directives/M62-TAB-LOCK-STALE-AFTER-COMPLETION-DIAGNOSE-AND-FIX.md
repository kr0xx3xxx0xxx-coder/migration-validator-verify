작업명 : M62-TAB-LOCK-STALE-AFTER-COMPLETION-DIAGNOSE-AND-FIX

STAGE2-COUNT-INFLIGHT-TAB-LOCK-DIAGNOSE-AND-FIX.txt(오늘 완료된 M62)를 먼저 읽고
시작해줘. 이건 그 작업이 만든 회귀로 보인다.

배경(스크린샷 근거): COUNT 사전검증 실행 완료 후(실행시간·불일치 상태까지 정상
표시됨)에도, 상단 탭(1단계 쿼리검토)이 여전히 클릭 안 됨. "◀ 이전" 버튼으로 1단계로
갔다가 다시 2단계로 돌아오면 그제서야 상단 탭 이동이 정상화됨.

────────────────────────────────────────────────────────────
1. 재현 및 원인 조사
────────────────────────────────────────────────────────────
COUNT 실행을 완료시킨 뒤, 상단 탭 클릭이 계속 막혀있는지 실제로 재현해라.

원인을 추적해라 — 오늘 M62가 만든 `_mvCountInflightLock()`은
`_singleViewStep === 'count' && _countInProgress`를 반환하는데, COUNT가 끝나면
`_countInProgress`는 false가 되는 게 맞다. 그런데도 탭이 계속 disabled로 남아있다면,
이건 오늘 M60에서 겪었던 것과 같은 패턴일 가능성이 높다 — **상태값(_countInProgress)은
정상적으로 바뀌는데, 그 값을 반영해서 탭 DOM을 다시 그리는 재렌더링이 COUNT 완료
시점에 트리거되지 않는 것.** `_renderSingleStepNav`가 COUNT 완료 직후 다시 호출되는지,
아니면 "이전" 버튼 클릭처럼 다른 이벤트가 트리거하는 전체 재렌더에 얹혀서만 갱신되는지
확인해라.

────────────────────────────────────────────────────────────
2. 수정
────────────────────────────────────────────────────────────
COUNT 완료 시점(성공/실패/불일치 등 결과가 화면에 반영되는 바로 그 지점)에 탭 네비게이션
DOM도 함께 다시 그리도록(또는 최소한 그 시점의 탭 disabled 상태만 갱신하도록) 배선해라.
오늘 M60이 "그룹 배지 미갱신" 버그를 고칠 때 쓴 패턴(전체 재렌더 대신 필요한 부분만
갱신하는 좁은 함수)을 참고해도 된다.

────────────────────────────────────────────────────────────
3. 다른 단계도 같은 문제가 있는지 전수 확인 (사용자 우려사항)
────────────────────────────────────────────────────────────
사용자가 "다른 탭들도 다 마찬가지일 것 같다"고 의심했다 — 오늘 4단계(통계검증
실행)·5단계 관련해서도 비슷한 "실행 완료 후 잠금 미해제" 패턴이 있는지 확인해라.
`_mvAnyRunActive()`나 그 소비 함수들이 실행 완료 시점에 탭 재렌더를 트리거하는지
전수 점검해서, COUNT와 같은 문제가 있는 지점이 더 있으면 함께 고쳐라.

────────────────────────────────────────────────────────────
검증(필수, 실제 클릭)
────────────────────────────────────────────────────────────
