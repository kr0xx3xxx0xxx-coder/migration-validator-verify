작업명 : DATA-EXTRACTION-SPEED-AND-STRATEGY-CONFORMANCE-CHECK

코드 수정 없이 조사만 해줘.

배경: 오늘 5단계 데이터 추출(불일치 그룹 상세) 관련해서 여러 발견이 있었다 —
M76(첫 클릭만 유독 느림, 웜캐시 추정), M77(예상 총소요 벤치마크 수정), 전략
선택(DIRECT_STREAM_COMPARE/PK_RANGE_CHUNK/HASH_BUCKET) 등. 이번엔 데이터 추출
경로 전체를 놓고, 속도에 영향 미치는 요소와 "선택된 전략대로 실제로 실행되는지"
를 종합 점검한다.

────────────────────────────────────────────────────────────
1. 추출방식이 실제 선택된 전략대로 실행되는지 확인
────────────────────────────────────────────────────────────
- 전략 선택 로직(strategy_transition.py 등)이 결정한 전략(DIRECT_STREAM_COMPARE/
  PK_RANGE_CHUNK/HASH_BUCKET 등)이, 실제 실행 시점에 그대로 반영되는지 확인해라
  — 화면에 표시된 전략명과, 실제로 실행되는 SQL/코드 경로가 일치하는지 추적해라.
- 선택된 전략과 실제 실행 경로가 어긋나는 지점(예: 조건에 따라 자동으로 다른
  전략으로 폴백되는데 화면 표시는 안 바뀌는 경우 등)이 있는지 찾아라.

────────────────────────────────────────────────────────────
2. 속도에 영향 미치는 요소 전수 점검
────────────────────────────────────────────────────────────
- 인덱스 유무, 정렬 비용(오늘 M68에서 다룬 CTE+JOIN+윈도우함수 재정렬 문제 등),
  청크 크기, 병렬화 여부(오늘 다룬 원본/목적 병렬) 등 이미 알려진 요소들을
  종합 정리해라.
- 아직 파악 안 된 새로운 속도 영향 요소가 있는지 코드를 다시 훑어서 확인해라 —
  예를 들어 불필요한 재조회, 캐시 미활용, N+1 쿼리 패턴 등.

────────────────────────────────────────────────────────────
3. 속도 개선 여지 판단
────────────────────────────────────────────────────────────
- 위에서 찾은 요소들 중, 실제로 개선하면 체감 효과가 클 만한 것과, 이미 충분히
  최적화돼서 손댈 필요 없는 것을 구분해라.
- 개선 우선순위를 매겨서 제시해라(비용 대비 효과 기준).

────────────────────────────────────────────────────────────
완료보고
────────────────────────────────────────────────────────────
- 전략-실행 일치 여부 확인 결과(불일치 있으면 구체적 사례).
- 속도 영향 요소 목록(이미 알려진 것 + 새로 발견한 것).
- 개선 우선순위 제안(근거와 함께).
- 코드 수정 없음. 작업명 첫줄/마지막줄.
