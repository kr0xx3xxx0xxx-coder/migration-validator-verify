작업명 : M49-BIND-HOST-ENV-VAR-AND-DEPLOYMENT-CHECKLIST

DEPLOYMENT-IP-HOST-HARDCODING-SCOPE-DIAGNOSE.txt(조사 완료본)를 먼저 읽고 시작해줘.

배경/결정 사항: 실배포 대상(클라우드/사내망/다양한 물리서버)이 현장마다 달라서, TLS·
방화벽·네트워크 구성은 앱 코드에 특정 방식을 못 박지 않고 전부 "배포 시 인프라 계층에서
결정"하는 것으로 확정했다. 앱이 할 일은 host/port를 환경변수로 바꿀 수 있게 하는 것뿐이고,
TLS는 리버스 프록시(nginx 등)를 기본 권장으로 하되 강제하지 않는다.

────────────────────────────────────────────────────────────
1. host/port 환경변수화 (저위험, 개발환경 무회귀 필수)
────────────────────────────────────────────────────────────
web_server.py:366, routes/batch_route.py:2649의 `host="127.0.0.1"` 리터럴을 각각
환경변수로 교체:
  MV_BIND_HOST (기본값 "127.0.0.1")
  MV_BIND_PORT (기본값 8000 / batch_route.py는 8001)
기본값이 그대로 루프백이므로 환경변수 미설정 시 지금까지의 개발 동작과 완전히 동일해야
한다. web_server.py:335, web_server.py:352-353의 안내 print, docs/AUTH_SETUP.md의
관련 서술도 새 환경변수 방식에 맞게 갱신.

────────────────────────────────────────────────────────────
2. 배포 체크리스트 문서 신설 (docs/DEPLOYMENT_CHECKLIST.md)
────────────────────────────────────────────────────────────
아래 항목을 포함해서 새로 작성:
  - MV_BIND_HOST/MV_BIND_PORT를 0.0.0.0 등으로 열기 전, 반드시 TLS 종단(리버스 프록시
    권장, 대안으로 uvicorn ssl_keyfile/ssl_certfile 직접 설정도 가능) 여부를 결정할 것.
    TLS 없이 열면 Basic Auth 자격증명 및 SQL/불일치 레코드 원문이 평문 노출됨을 명시
    (DEPLOYMENT-IP-HOST-HARDCODING-SCOPE-DIAGNOSE.txt §3-5 그대로 인용).
  - 8000(web_server.py)과 8001(batch_route.py, 일괄검증 독립 실행) 둘 다 같은 절차를
    적용해야 함(하나만 열면 일괄검증 독립 실행만 조용히 접속 불가) — AUTH_SETUP.md의
    8001 누락 갭도 이번에 같이 보완.
  - `MV_AUTH_DISABLED` 환경변수가 운영 장비에 남아있지 않은지 배포 전 확인 필수(남아있으면
    인증이 통째로 우회됨).
  - 배포 방식(git clone vs 파일 복사)에 따라 개발용 DB 프리셋 14건(`db_presets_*.json`,
    `db/migration_validator.db`의 mv_db_preset 테이블, `auth_users.json`)이 그대로
    운영 장비로 따라갈 수 있음을 명시하고, 배포 전 정리(삭제 또는 운영용 값으로 교체) 여부를
    체크 항목으로 둘 것 — 코드로 강제하지 말고 사람이 확인하는 체크리스트로.
  - 네트워크/방화벽/VPN 구성은 이 문서에서 다루지 않는다는 것도 명시(인프라 계층, 현장마다
    다름 — 각 배포 담당자가 별도로 결정).
  - `ui/csr_display_helpers.py:766`의 `http://localhost:8000/...` 안내 문구를, 배포
    환경에서도 올바르게 보이도록 상대경로 또는 동적 생성으로 수정.
