작업명 : COMBO-MISMATCH-VIA-PK-ROW-COMPARISON-BYPASS-DIAGNOSE

코드 수정 없이 조사만 해줘.

배경: 오늘 세 차례 조사(M85/M88/이번 청크조사)에서 "조합(다축 GROUP BY 집계)
검증"이 그룹 완결성 문제(전체를 다 봐야 확정)로 조기중단이 불가능하다는
결론이 반복 확인됐다. 사용자가 근본적으로 다른 접근을 제안했다:

"불일치 레코드를 추출하는 방식(5단계 드릴다운)은 PK끼리 원본/목적을
1:1로 비교하는 거잖아. 조합도 GROUP BY로 집계해서 비교하는 대신, 그냥
PK 행 비교(원본 REGION_CD/STATUS_CD 값 vs 목적 REGION_CD/STATUS_CD 값)로
하면 안 되나?"

핵심 통찰: 아까 예로 든 "REGION+STATUS가 서로 뒤바뀐 레코드" 문제는, 사실
GROUP BY 집계 없이도 "그 행의 REGION_CD 필드 값이 원본과 목적에서 다르다"는
**순수 행단위 필드값 비교**만으로도 잡을 수 있는 것 아니냐는 것이다. 만약
그렇다면, 이건 PK_RANGE_CHUNK(행단위 비교, 이미 조기중단 가능)로 이미 잡을
수 있는 문제이고, GROUP BY 기반 "조합" 검증 자체가 애초에 불필요할 수 있다.

────────────────────────────────────────────────────────────
조사 항목
────────────────────────────────────────────────────────────
1. 5단계 상세 레코드 비교(불일치 그룹 클릭 시 나오는 "PK_STR/REGION_CD(원본)/
   REGION_CD(목적)/STATUS_CD(원본)/STATUS_CD(목적)/..." 표)가 실제로 어떤
   컬럼들을 비교하는지 확인해라 — GROUP BY 축으로 쓰인 컬럼(REGION_CD,
   STATUS_CD)의 실제 값 자체도 원본/목적 필드값으로 비교 대상에 포함되는지,
   아니면 SUM 대상 컬럼(AMT, QTY)만 비교하는지 확인해라.
2. 만약 GROUP BY 축 컬럼 자체도 행단위 필드값 비교에 포함된다면, "원본에서는
   REGION_CD=A인데 목적에서 같은 PK가 REGION_CD=B로 바뀐" 경우가, 순수
   PK_RANGE_CHUNK(행단위 비교, GROUP BY 없이) 만으로도 이미 잡히는지 확인해라
   — 아까 예시(REGION+STATUS 뒤바뀜)를 실제로 재현해서, GROUP BY 조합
   검증 없이 순수 행단위 비교만으로 이 케이스가 걸리는지 실측해라.
3. 만약 순수 행단위 비교로 이미 잡힌다면, "조합(GROUP BY SUM/COUNT 집계)
   검증"이 실제로 잡아내는 것 중, 행단위 비교로는 못 잡는 케이스가 남아
   있는지 확인해라 — 예를 들어, 개별 레코드는 정상인데 집계 단계에서만
   드러나는 문제(예: 원본에는 있는데 목적에는 아예 없는 행이 다른 그룹의
   행과 우연히 합계가 맞아떨어지는 경우 등)가 이론적으로 가능한지, 실제로
   그런 사례가 있는지 판단해라.
4. 만약 "GROUP BY 조합 집계"가 잡아내는 문제 중 상당수(또는 전부)가 이미
   행단위 비교로도 잡힌다면, "조합 검증"이라는 별도 기능 자체의 필요성이
   얼마나 되는지 재평가해라 — 완전히 불필요한지, 아니면 행단위 비교가
   못 잡는 특정 케이스(예: 집계 함수 자체의 오류, 타입 캐스팅 문제 등)를
   위해 여전히 필요한지 구분해라.

────────────────────────────────────────────────────────────
완료보고
────────────────────────────────────────────────────────────
- 1~4번 각각의 답(2·3번은 가능하면 실측 재현 포함).
- 종합 판단: "조합 GROUP BY 집계 검증"을 "행단위 PK 비교"로 대체하거나
  보완할 수 있는지, 오늘까지의 M85/M86/M88 결론에 영향을 주는지.
- 코드 수정 없음. 작업명 첫줄/마지막줄.
