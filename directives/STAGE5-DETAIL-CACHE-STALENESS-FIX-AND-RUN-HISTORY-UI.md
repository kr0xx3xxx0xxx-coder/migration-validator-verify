작업명 : STAGE5-DETAIL-CACHE-STALENESS-FIX-AND-RUN-HISTORY-UI

BACKLOG.md M96 항목을 먼저 읽고 시작해줘. 승인 완료 — 실제 구현 착수.

배경: 이관팀이 실제 데이터를 재이관(수정)한 뒤 검증팀이 동일 조건으로
재검증하면, 5단계 상세 레코드(그룹 드릴다운) 캐시가 fingerprint에 데이터
버전/최종수정시각이 전혀 없어서 예전(이관 전) 결과를 그대로 반환할 위험이
확인됐다. 2·4단계(COUNT/통계검증)는 매번 새로 실행되므로 이 문제와 무관
(항상 정확) — 문제는 5단계 상세 레코드 캐시에만 국한된다.

────────────────────────────────────────────────────────────
1. [핵심] 데이터 변경 감지 — 예전 캐시를 정직하게 무효화
────────────────────────────────────────────────────────────
완전 자동 감지(체크섬 등)는 과도한 엔지니어링일 수 있으니, 아래 저비용
방식을 우선 검토해라:
  - 4단계(통계검증)는 매번 새로 실행되어 그 그룹의 원본/목적 COUNT·SUM이
    항상 최신이다. 5단계에서 캐시된 상세 레코드(run)를 반환하기 직전에,
    그 캐시된 run이 저장하고 있는 그룹 요약값(원본/목적 카운트 등)과
    "지금" 4단계가 새로 계산한 같은 그룹의 요약값을 대조해라.
  - 두 값이 다르면(=데이터가 실제로 바뀌었다는 강한 신호), 캐시를 자동
    무효화하고 새로 스캔해라(또는 최소한 "데이터가 변경된 것 같습니다,
    다시 스캔하시겠습니까" 같은 명확한 경고를 사용자에게 보여주고 자동
    재스캔은 사용자 확인 후 진행해도 된다 — 둘 중 더 안전하고 구현이
    간단한 쪽으로 판단해서 진행해라).
  - 코드 조사 후 이 방식이 신뢰할 만한지(요약값만으로 데이터 변경을
    놓치지 않고 감지할 수 있는지) 먼저 판단하고, 허점이 있으면 완료보고에
    명시해라 — 완벽한 해법이 아니어도 "아예 감지 안 하는 것"보다는 훨씬
    나은 안전장치이니 이 방향으로 진행해도 된다.

────────────────────────────────────────────────────────────
2. "최근 5개 차수" 이력 UI
────────────────────────────────────────────────────────────
- 백엔드: `exact_diff_run` 테이블에서 같은 fingerprint의 run들을 created_at
  DESC로 최근 5건 가져오는 조회 메서드를 신규로 만들어라(기존
  get_run_by_fingerprint의 LIMIT 1을 참고해서 LIMIT 5 버전으로).
- 프론트: 5단계 불일치 레코드 그리드 근처에, 이 5개 차수를 선택할 수 있는
  드롭다운(또는 탭)을 추가해라 — 선택하면 기존 run_id 기반 페이지 로더로
  그 차수의 결과를 불러오게 해라.
- 각 차수 항목에 최소한 "실행 시각"은 표시해라(예: "2026-08-12 14:30").
  그룹/테이블명까지 라벨링하려면 group_id/target_table 저장 로직을 보강
  해야 하는데, 이번 범위에 포함할지는 시간 되는 대로 판단해라(1번 항목이
  우선순위가 더 높다).

────────────────────────────────────────────────────────────
검증(필수, 실제 클릭)
────────────────────────────────────────────────────────────
- 1번: 실제로 원본 또는 목적 데이터를 의도적으로 수정한 뒤(불일치를
  해소하거나 새로 만드는 방향으로), 동일 조건으로 재검증했을 때 5단계
  상세 레코드가 새로 반영된 결과를 보여주는지(캐시 무효화가 실제로
  작동하는지) 실측으로 확인해라.
- 2번: 같은 조건으로 여러 번 재실행한 뒤, "최근 5개 차수" 드롭다운에
  실제로 그 이력들이 최신순으로 나열되는지, 클릭하면 그 차수의 결과가
  정확히 나오는지 확인해라.
- 관련 테스트 서브셋 + baseline 대조, 신규 회귀 0건.
- CLAUDE.md 필수 회귀(virtual/complex) 최종 1회.
- 완료보고: 파일:라인, 1번 데이터변경 감지 실측(전/후), 2번 차수이력 실측,
  커밋해시. 작업명 첫줄/마지막줄. 코드 변경이 있으니 서버 재기동 필수,
  재기동 시각·HEAD 커밋 해시 명시.
