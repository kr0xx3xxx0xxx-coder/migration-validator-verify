작업명 : NEON-CAPACITY-FULL-TARGET-PLUS-INTERNAL-SRC-5PCT-OVER

NEON-PG-50M-45M-MISMATCH-FIXTURE-LOAD.txt(직전 완료, 512MB 캡 발견·900K/810K
축소 적재)를 먼저 읽고 시작해줘. 승인 완료.

배경: Neon 클라우드 PostgreSQL(PostgreSQL_tobe)이 프로젝트 전체 512MB 하드
스토리지 캡을 가지고 있음이 확인됐다. 사용자가 계획을 다음과 같이 재조정했다:
목적(TGT) 테이블 하나를 Neon에 만들어 512MB 한도를 최대한 채우고, 원본(SRC)은
내부망 PostgreSQL에 목적 대비 5% 더 많은 행수로 구성한다.

────────────────────────────────────────────────────────────
1. Neon 기존 데이터 삭제 (사용자 명시 승인)
────────────────────────────────────────────────────────────
Neon(PostgreSQL_tobe, neondb)에 있는 기존 테이블 전부를 삭제해라 — 오늘 이전
작업이 만든 tgt_orders(186MB) 등을 포함해 전부. **사용자가 이번엔 명시적으로
삭제를 승인했다** — 이전엔 확인 없이 삭제하지 말라고 했었지만, 이번 지시에서
"neon 기존 데이터 다 지우고"라고 명확히 지시했다.

삭제 전, 지울 테이블 목록과 각 용량을 완료보고에 남겨라(무엇을 지웠는지 기록).

────────────────────────────────────────────────────────────
2. 목적(TGT) 테이블 — Neon 512MB 한도 최대한 채우기
────────────────────────────────────────────────────────────
목적 테이블 딱 1개를 Neon에 만들어라. 행당 용량을 실측(오늘 900K건이 70MB였으니
행당 약 81.4바이트)해서, **안전 여유(예: 캡의 5~10%)를 남기고 나머지를 전부
채우도록** 행수를 계산해라 — 정확한 숫자는 실측해서 산정해라(억지로 짐작하지
말고 실제 삽입하면서 용량을 모니터링해라).

컬럼 구성은 오늘 만든 것(id/region_cd/status_cd/amt/qty/item_nm)과 동일하게
유지해라(재사용).

────────────────────────────────────────────────────────────
3. 원본(SRC) 테이블 — 내부망 PostgreSQL, 목적 대비 5% 더 많게
────────────────────────────────────────────────────────────
내부망 PostgreSQL(PostgreSQL_Inter_asis 프리셋, 192.168.0.150)에 원본 테이블을
만들어라 — 행수는 2번에서 실제로 만든 목적 테이블 행수의 정확히 105%(5% 더 많이).

**절대 원칙(반드시 지켜라): 이 내부망 PostgreSQL 서버에 이미 존재하는 다른
테이블은 그 어떤 것도 건드리지 마라** — DROP/TRUNCATE/UPDATE/DELETE 전부 금지.
새 테이블(고유한 이름, TB_ 접두어 회피)을 하나 새로 만드는 것만 허용된다. 작업
시작 전 기존 테이블 목록을 스냅샷으로 남기고, 작업 후 그 목록이 그대로인지
(새 테이블 1개만 추가됐는지) 대조해서 완료보고에 포함해라.

────────────────────────────────────────────────────────────
검증
────────────────────────────────────────────────────────────
- Neon 목적 테이블 실제 COUNT, 실제 사용 용량(512MB 대비 몇 %인지).
- 내부망 원본 테이블 실제 COUNT가 목적의 정확히 105%인지 계산 확인.
- 내부망 서버의 다른 테이블 목록이 작업 전/후 동일한지(신규 테이블 1개만 추가)
  대조 결과.
- 화면 COUNT 사전검증까지 실행해서 두 테이블 간 차이가 기대값(목적의 5%)과
  일치하는지 확인.
- 완료보고: 삭제된 기존 테이블 목록+용량, 목적 테이블 최종 행수·용량·캡대비 비율,
  원본 테이블 행수(목적의 105% 검산), 내부망 기존테이블 무결성 대조 결과, 화면
  COUNT 검증 결과. 작업명 첫줄/마지막줄.
