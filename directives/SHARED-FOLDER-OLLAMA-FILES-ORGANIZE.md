작업명 : SHARED-FOLDER-OLLAMA-FILES-ORGANIZE

코드 저장소는 건드리지 않는다 — 순수 파일 정리 작업(X드라이브 파일시스템).

배경: `X:\Projects\_shared\`에 `ollama`(모델 저장 폴더) 외에도
`ollama_serve.log`·`OllamaSetup.exe`가 최상위에 그냥 흩어져 있다. 나중에 다른
공유 프로그램이 설치되면 이런 느슨한 파일들이 서로 섞여서 알아보기 어려워진다.

────────────────────────────────────────────────────────────
구현
────────────────────────────────────────────────────────────
`_shared` 최상위에는 **각 프로그램별 하위 폴더만** 있고, 그 프로그램 관련 파일은
전부 그 하위 폴더 안에 들어가야 한다:

1. `_shared\ollama_serve.log`를 `_shared\ollama\` 안으로 이동해라.
2. `_shared\OllamaSetup.exe`를 `_shared\ollama\`(또는 `_shared\ollama\installer\`)
   안으로 이동해라 — 나중에 폐쇄망 반입 시 이 설치파일도 같이 챙겨야 하니, 모델
   폴더와 뚜렷이 구분되게 하위폴더를 만들어 넣는 것도 고려해라.
3. `_shared\README.md`는 그대로 최상위에 둬라 — 이건 `_shared` 폴더 전체(여러
   프로그램 공유)를 설명하는 문서라 예외다. 다만 내용에 "각 프로그램은 자기 하위
   폴더 안에 관련 파일을 전부 모아둔다"는 규칙을 한 줄 추가해라(향후 다른 공유
   프로그램을 설치할 세션이 이 관례를 따르도록).
4. 이동 후 실제로 Ollama가 정상 작동하는지 재확인해라 — 특히
   `ollama_serve.log`는 실행 중인 서비스가 쓰고 있을 수 있으니, 이동 전 서비스를
   잠깐 멈추고 이동 후 다시 켜는 순서로 해라(로그 파일 자체 위치는 Ollama 설정과
   무관할 가능성이 높지만, 실제로 서비스 재기동 후 문제없이 로그가 계속 쌓이는지
   확인).

────────────────────────────────────────────────────────────
검증(필수)
────────────────────────────────────────────────────────────
- `_shared` 최상위에 `ollama` 폴더와 `README.md`만 남았는지 확인(다른 느슨한
  파일 없음).
- Ollama 서비스가 이동 후에도 정상 작동하는지(포트 11434 LISTEN, gemma3:4b 응답
  정상) 재확인.
- `_shared\ollama\` 하위 파일 목록 최종 확인.

완료보고: 이동 결과, 재검증 결과. 코드 저장소 변경 없음.
