작업명 : STATS-SAMPLE-ONLY-DISPLAY-NECESSITY-RECONSIDER-DIAGNOSE

코드 수정 없이 조사만 해줘.

배경: M98에서 STATS_SAMPLE_ONLY가 "참고용 판정일 뿐, 실제 실행은 항상 전체스캔
(STATS_DIRECT_AGG와 동일 엔진)"이라는 게 확인됐다. 사용자가 근본적인 질문을
했다: "실제 실행 집계전략(STATS_DIRECT_AGG)과 화면에 표시되는 전략명
(STATS_SAMPLE_ONLY)이 다른데, 왜 이걸 사용자에게 보여주는가? 어차피 실행 안
되는 걸 보여줄 필요가 있나?"

────────────────────────────────────────────────────────────
조사 항목
────────────────────────────────────────────────────────────
1. STATS_SAMPLE_ONLY(및 같은 그룹 STATS_BUCKET_AGG/STATS_PARTITION_AGG)를
   화면에 표시하기 시작한 원래 설계 의도를 확인해라 — git 커밋 이력, 코드
   주석, 관련 기존 완료보고서(verify 저장소)를 찾아서 왜 "참고용" 판정을
   실제 전략명처럼 노출하기로 결정했는지 확인해라. 다음 중 어느 쪽에
   가까운지 판단해라:
   (a) "이 케이스는 원래 표본검증이 이상적인데 엔진이 없어서 전체스캔으로
       대체 실행 중이다"라는 사실 자체를 사용자에게 알려서, 향후 표본
       엔진이 필요하다는 신호(로드맵/우선순위 근거)로 쓰려는 의도
   (b) 단순히 "이 케이스는 비용이 크다"는 경고를 주려는 의도(전략명이
       아니라 경고 목적이 우선)
   (c) 별다른 의도 없이 실행 계획과 표시 로직이 애초에 분리 설계되면서
       생긴 부산물(의도적 설계 아님)
2. 오늘 확인된 N1(M81, 화면-실행 불일치 문제)과 이 사안이 같은 종류의
   문제인지 판단해라 — N1은 "화면에 뜬 전략과 실제 실행 전략이 달라서
   생기는 혼란"이었는데, STATS_SAMPLE_ONLY도 정확히 같은 패턴(화면=SAMPLE_
   ONLY, 실행=DIRECT_AGG)인지 확인해라.
3. 만약 이게 사용자에게 실질적으로 혼란만 주고 실익이 적다면(예: 사용자가
   이 정보로 뭘 할 수 있는지 불명확하다면), 표시를 없애거나(실제 실행
   전략명인 STATS_DIRECT_AGG로 통일해서 보여주기) 개선하는 방향이 나은지
   판단해라. 반대로 실익이 있다면(예: 이 사실을 알아야 사용자가 다른
   조치를 취할 수 있다면) 그 근거를 명확히 제시해라.
