작성일 : 2026-08-05

대상   : 개별검증 4단계(통계검증 실행) '통계검증 SQL' 섹션


1. 요청 요약
──────────────────────────────────────────────────────────────────────────────
4단계 SQL 섹션에서 ① 복사 버튼과 그 클릭 핸들러 제거, ② 스크롤 동기화 체크박스와 기능 제거,
③ 목적지(Target) SQL 을 왼쪽·원본(Source) SQL 을 오른쪽으로 교체(라벨과 SQL 박스가 함께 이동),
④ 두 라벨에 동일한 들여쓰기 적용.


2. 수정 대상 파일 정정
──────────────────────────────────────────────────────────────────────────────
요청서는 ui/tabler_renderer.py 를 지목했으나, 4단계 SQL 섹션의 마크업과 복사·스크롤 동기화
로직은 ui/js_sql_preview.py(renderSQL 컴포넌트)에 있다. 실제 수정은 두 파일에 걸친다:
  · ui/js_sql_preview.py   — 마크업·핸들러(요구사항 1~3)
  · ui/tabler_renderer.py  — 라벨 들여쓰기 CSS(요구사항 4) + 배치 패널 주석 정합


3. 무엇을 고쳤나
──────────────────────────────────────────────────────────────────────────────
(1) 복사 버튼 제거 — .btn-copy 2개와 인라인 onclick="copySQL('srcBox'|'tgtBox', this)" 삭제.

(2) 스크롤 동기화 제거 — '🔗 스크롤 동기화' 토글(label + #mvSqlSyncChk)과 그 토글만 담고 있던
    .mv-sql-cmp-bar div 를 통째로 삭제. 개별검증 전용 바인더 mvSqlSyncBind(srcBox/tgtBox id
    하드코딩)와 그 호출부(renderSQL 끝의 mvSqlSyncBind() 호출)도 함께 삭제했다.

(3) 좌우 순서 교체 — .sql-panel 두 개의 순서를 목적지 → 원본으로 바꿨다. 라벨과 SQL 박스는
    같은 .sql-panel 안에 함께 들어 있으므로 통째로 이동한다 = 라벨과 그 아래 내용이 어긋날
    구조적 여지가 없다(실측으로도 교차 확인 — 5장 참고).

(4) 라벨 들여쓰기 — 2단계 COUNT SQL 라벨이 이미 쓰는 변수(--mv-count-sql-label-indent, 10px)를
    그대로 재사용한다. 값을 새로 만들지 않으므로 두 단계의 들여쓰기가 항상 같고, 규칙 하나가
    목적지·원본 두 라벨을 함께 잡으므로 칸별로 어긋날 수 없다.
      #sqlOut .mv-sql-cmp-grid .sql-hdr h3{padding-left:var(--mv-count-sql-label-indent)}
    선택자를 #sqlOut(4단계 SQL 출력 host)으로 한정한 이유: .mv-sql-cmp-grid 는 일괄검증 SQL
    상세 패널도 함께 쓰는 공용 클래스라, 한정하지 않으면 이번 범위 밖인 일괄검증 라벨까지
    들여쓰기가 번진다.


4. 삭제하지 않고 남긴 것과 그 근거 (요구사항 1의 '죽은 코드 금지'에 대한 판단)
──────────────────────────────────────────────────────────────────────────────
요청서는 "연결된 JS 함수도 죽은 코드로 남기지 말 것"을 요구했다. 조사 결과 아래 셋은
**살아 있는 사용처가 있어 죽은 코드가 아니며, 지우면 일괄검증이 깨진다** — 그래서 남겼다.

  · copySQL(id, btn)
      일괄검증 SQL 상세 패널의 복사 버튼이 렌더 후 이 핸들러를 연결한다.
      ui/tabler_renderer.py: btn.onclick = function(){ copySQL(btn.getAttribute('data-copy-target'), btn); }
  · mvSqlSyncToggle(on)
      같은 패널의 토글이 인라인으로 호출한다: onchange="mvSqlSyncToggle(this.checked)"
  · window._mvSqlSyncOn
      그 패널의 자체 바인더(_mvBatchSqlSyncBind)가 읽는 상태 플래그.

즉 이번 작업으로 실제 '죽은 코드'가 된 것은 mvSqlSyncBind 하나이며, 그것만 삭제했다.
이 판단은 테스트로도 고정했다(6장) — 4단계에서 사라진 것과 일괄검증에서 살아 있는 것을
각각 단언하므로, 나중에 누가 "안 쓰는 함수"로 오인해 지우면 테스트가 잡는다.

부수 정리: 배치 바인더 위의 주석이 "개별검증 mvSqlSyncBind 은 id 하드코딩이라 재사용 불가"
라며 삭제된 함수를 근거로 들고 있어, 현재 사실(스크롤 동기화가 남은 곳은 배치 패널뿐)에
맞게 고쳤다.


5. 실측 검증 (운영과 동일한 인프로세스 서버 + 실제 브라우저)
──────────────────────────────────────────────────────────────────────────────
드라이버 : driver_stage4_sql_box_copy_scrollsync_verify.py
대상     : Oracle_asis → Oracle_tobe (NXDNP.MV_SCATTER_SRC → MV_SCATTER_TGT, 100만행)
           GROUP BY STATUS_CD · SUM AMT,QTY
방법     : 1~3단계를 실제 클릭으로 통과한 뒤 [통계검증 SQL 생성]까지 실행하고, #sqlOut 안에
           실제로 그려진 DOM 을 읽는다. before 는 동일 절차를 worktree(E:\_wt_s4sql)에서 측정.

  판정 기준을 마크업 문자열이 아니라 실제 렌더 결과로 잡은 이유:
    · 좌우 순서는 CSS(flex order 등)로 뒤집힐 수 있으므로 getBoundingClientRect().left 로 본다.
    · 들여쓰기는 인라인 스타일이 아니라 getComputedStyle 의 padding-left 실측값으로 읽는다.
    · 스크롤 동기화는 '요소가 없다'로는 기능이 죽었는지 알 수 없다(바인더가 살아 있으면 토글
      없이도 계속 동기화된다). 그래서 실제로 한쪽을 스크롤하고 반대쪽 scrollTop 을 읽었다.
      대상 SQL 이 짧아 두 박스 모두 스크롤 여지가 0 이면 결과가 항상 0/0 이라 무의미하므로,
      두 박스의 max-height 를 잠시 40px 로 줄여 강제로 스크롤 가능 상태를 만든 뒤 측정하고
      원복했다(표시 계층 일시 조작 — SQL 원문·판정과 무관).

7. 비판적 검토
──────────────────────────────────────────────────────────────────────────────
  · heuristic 증가 : 없음.
  · scoring        : 해당 없음.
  · explainability : 중립. 복사 기능이 사라져 사용자가 SQL 을 클립보드로 옮기려면 드래그 선택이
                     필요하다. SQL 원문은 화면에 그대로 보이고 박스 안에서 선택 가능하므로
                     정보 접근 자체는 막히지 않는다. (요청에 따른 의도적 제거)
  · 보안           : 해당 없음(표시 계층, 새 데이터 노출 없음).
  · 테스트 가능성  : 개선. 존치/삭제 판단이 테스트로 고정돼, 나중에 copySQL 등을 '미사용'으로
                     오인해 지우는 사고를 잡는다.
  · 구조 부채      : 소폭 감소. 4단계 전용 스크롤 바인더가 사라져 스크롤 동기화 구현이
                     배치 패널 한 곳(_mvBatchSqlSyncBind)으로 모였다.
  · 남은 위험      : 공용 클래스(.mv-sql-cmp-grid / .sql-hdr / .btn-copy)를 일괄검증과 계속
                     공유한다. 이번엔 선택자를 #sqlOut 으로 한정해 번짐을 막았지만, 앞으로도
                     이 영역을 손볼 때 같은 주의가 필요하다(코드 주석에 근거를 남겼다).
