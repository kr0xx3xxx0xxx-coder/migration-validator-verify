1. 요청 요약과 배경
────────────────────────────────────────────────────────────────────────────
'통계검증규모' 타일이 오늘 순수 등급명('중형')만 남도록 정리되면서, 사용자가 "그래서 대략
얼마나 걸린다는 건지" 감을 잡을 수 없게 됐다. 등급 경계 cost 를 이미 있는 cost→ms 환산식으로
되돌리면 각 등급의 시간대가 그대로 나온다(오늘 실측 §6-3):
  cost 12.90 → 1.91초 (소형/중형 경계) · 14.15 → 6.23초 (중형/대형) · 15.50 → 22.28초 (대형/초대형)
이 값을 재사용해 등급 뒤에 시간대를 병기한다. 등급 산정 로직은 건드리지 않는다.

2. 구현
────────────────────────────────────────────────────────────────────────────
■ services/strategy/stats_strategy_planner.py (값 생성 — 단일 출처)
   · grade_time_bands()     : [(등급, lo_ms, hi_ms), …]. lo/hi 는 _GRADE_BANDS 의 cost 경계를
                              _cost_to_ms() 로 환산해 '매번 계산'한다. 최하위 lo=None,
                              최상위 hi=None(개방형).
   · grade_time_hint()      : '약 2초 이하' / '약 2~6초' / '약 6~22초' / '약 22초 이상'
   · grade_time_hint_full() : 툴팁용 — 시간대 + '로컬 접속 기준' + 원격 고정 가산 안내
   · _fmt_sec_num()         : ms→초 표시(1초 미만 소수 1자리, 그 이상 정수 반올림)
   ★ 요구사항 3 — 경계 숫자·시간 문자열을 어디에도 하드코딩하지 않았다. 상수는 _GRADE_BANDS 와
     _COST_MS_SLOPE/_COST_MS_INTERCEPT 뿐이며, 둘 중 무엇이 바뀌어도 문구가 자동으로 따라간다
     (테스트 [C]에서 monkeypatch 로 실증).
   ★ 요구사항 5 — _scale_grade(등급 산정)는 한 줄도 바꾸지 않았다. 부가설명은 별도 함수다.

■ routes/strategy_route.py (전달)
   · 응답에 grade_time_hint / grade_time_hint_full 추가. planner 함수를 그대로 호출한다
     (라우트에서 따로 계산하지 않음). provisional_grade 는 종전대로 순수 등급명 — 기존 소비처
     및 "잠정 접두 없음" 계약(tests/test_strategy_planner.py) 불변.

■ ui/tabler_renderer.py (표시)
   · 인라인 : 타일 값 = '중형 (약 2~6초)'  ← 등급만으로는 정보가 부족해 한 눈에 보이게 병기
   · 툴팁   : '통계검증 규모: 중형 (실측 기준) · 예상 소요: 약 2~6초(로컬 접속 기준) — 원격 DB 는
              접속·왕복 고정 가산이 더 붙습니다.'
              → 오늘 COUNT 소요 타일이 쓴 '값은 짧게 · 근거는 툴팁' 관례를 그대로 재사용.
   · 화면은 서버 문구를 그대로 쓴다. 경계 cost·환산 계수를 화면에서 다시 만들지 않는다
     (테스트 [G]가 12.9/14.15/15.5/0.4100/2.0076 유출 여부를 검사).
   · 표시 지점 일치: 타일 scaleText 와 실행계획 상세 rows 의 '통계검증 규모' 행을 같은 문자열로

     실측에서 확인했고, 코드 주석에 그 사실을 명시했다.

■ 줄바꿈 규칙 보정 (.mv-qr-tile-val, 같은 파일)
   부가설명을 붙이자 종전 CSS word-break:break-all 이 '중형 (약 2~6' / '초)' 처럼 숫자와 단위
   사이를 갈랐다(실측 스크린샷 확인). 한글은 어절 단위로 끊는 keep-all 이 맞다:

     §3-⑤ 에서 2단계 COUNT 타일로 실측 확인).

· 하드코딩 재발 위험 — 가장 큰 위험이었다. 문구를 상수 문자열로 박아두면 밴드 재조정 때 조용히
  거짓말이 된다. 전부 _GRADE_BANDS + 환산식에서 계산하도록 했고, monkeypatch 테스트로 추종을
  실증했다. 라우트·화면에도 시간대 문자열·경계 숫자가 남지 않았음을 테스트로 막아 둔다.
· 정확도 한계(명시 필요) — 이 시간대는 로컬 실측 37건 회귀식 기반이고 밴드 일치율은 85.0%다.
  '약'·범위 표기와 '로컬 접속 기준' 한정어로 단정적 예측처럼 보이지 않게 했다. 원격은 고정
  가산이 더해진다는 사실을 툴팁에 명시한다.
· 화면 공간 — 타일이 좁아(≈150px) 인라인 병기는 두 줄로 접힌다. 종전 CSS 가 숫자와 단위 사이를
  갈라 읽기 어려웠으므로 한글 어절 단위 줄바꿈(keep-all)으로 바로잡았고, 식별자(is-mono)는
  종전 동작을 유지해 테이블명 표시 회귀를 막았다(§3-⑤ 실측).
· 등급 판정 영향 — 없음. _scale_grade 무수정이고 실측 5개 케이스 전부 before=after 동일.
· 남은 사실(범위 밖) — 실행계획 상세표의 '통계검증 규모' 행은 _TILE_MOVED 필터로 렌더되지
  않는다(타일로 이동됨). 같은 문자열을 계속 조립해 두되 주석으로 명시했다.
