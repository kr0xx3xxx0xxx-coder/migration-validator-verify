2. S2 변경 내역 (BACKLOG.md:36-67)
────────────────────────────────────────────────────────────────────────
  [제목] 축 A 만 반영하던 문구를 2축 구조로 교체
    이전: "문자 PK 지정 시 60% 미조회 후 "일치" 오판정 — 청크 경계 신뢰성 게이트가 없다"
    이후: "문자 PK 지정 시 조용한 오판정 — 축 A(경계 절단) + 축 B(merge-join 정렬 전제 위반),
           청크 신뢰성 게이트가 없다"
    사유: 기존 제목이 "60% 미조회 → 거짓 일치" 라는 축 A 단독·단일 방향 서술이라
          축 B(규모 무관 상시, 판정 방향 반대)를 담지 못함.

  [근거 보고서] `CHARACTER-PK-SILENT-FALSE-MATCH-1M-REPRODUCE.txt` (§2·§3 / §6) 추가

  [추가된 본문 — 초안 원문 유지]
    - 100만행 규모 재현 완료 실측(픽스처 MV_CSPK_SRC 1,000,000 / MV_CSPK_TGT 990,000,
      참값 누락 10,000행)
        · 문자키(TO_CHAR(g)) → 재이관 64,997건 + 목적 단독 54,998건(참값의 6.5배),
          status=READY, 경고 0건
        · 숫자키 대조군 / zero-pad 문자키 대조군 → 각각 정확히 10,000건
    - 원인 2축 확정 + "S2 기존 서술은 축 A 만 다룸" 명시
        A. 경계 절단 — 100만행에선 1건(0.0001%), 심각도는 규모가 아니라 '최대값과 10^k 의 거리'
        B. merge-join 정렬 전제 위반 — ORDER BY 는 문자 정렬 / WHERE 바인드는 숫자(암묵 형변환)라
           범위는 맞고 순서만 틀림. merge_chunk(pk_range_chunk.py:35) 의 'PK 오름차순' 전제 붕괴.
           5만행 chunk 1개에서 순서 역전 4,500회 실측. 규모 무관 상시.
    - 판정 방향 양방향: 거짓 '일치'(25만행 사례) / 거짓 '불일치'(100만행 사례)
    - 대응 방향 갱신: 기존(MIN/MAX 타입 검사·커버 확인)만으로는 축 B 차단 불가.
      ORDER BY 를 키의 '비교 의미'(숫자 캐스트)와 일치시키거나 문자 키의 chunk 경로 진입 차단.
    - 한계 고지(불변): HTTP 자동 경로는 여전히 재현 안 됨
      (자동 경로는 DIRECT merge 강제 — agg_diff_route.py:903-905, chunk 진입 시 int() HOLD).

  [보존] 기존 상세·대응 방향·한계 고지 문단은 삭제하지 않고 그대로 두고 그 뒤에 추가분을 붙였다.
