1. 무엇을 왜 했는가
────────────────────────────────────────────────────────────────────────
WHITEBOX-TEST-BEHAVIORAL-CONTRACT-PILOT-DIAGNOSE 에서 확인된 문제는 "테스트가
프로덕션의 계약이 아니라 렌더 산출물의 문자열을 붙들고 있다"는 것이었다. 그래서
계약이 그대로인데도 정당한 리팩터(헬퍼 추출, 인자 추가, 배열 항목 추가, 클래스 추가)만으로
테스트가 깨졌고, 최근 30일간 '프로덕션 변경 0 + tests/ 만 수정' 커밋이 5건 발생했다.

이번 1단계는 그 8파일을 실제 동작계약(behavioral contract)으로 전환한 것이다.
공용 헬퍼(tests/contract_utils.py)는 0단계에서 이미 설치돼 있었고, 이번엔 그 6개 헬퍼만
사용했다(새 계약 헬퍼 발명 없음). 프로덕션 파일은 한 줄도 건드리지 않았다.

2. 전환 원칙(무엇을 무엇으로 바꿨는가)
────────────────────────────────────────────────────────────────────────
· DOM 원문 통째 비교
    (예) 'id="mvStepNavBar" class="mv-sticky-step-nav mv-step-nav-inpage" style="display:none" hidden>'
    → 요소를 id 로 찾아 class 토큰 집합/속성 단위로 검사. 속성 순서·클래스 추가에 안 깨진다.

· 배열/객체 리터럴 원문 비교
    (예) "'sqlCard', 'sampleCard', 'singleValidationNav', 'mvExecProgress']"
    → 단계별 카드 배열의 '멤버십' 계약 + 음성 계약(execResultCard 가 4단계에 없어야 함).
      닫는 대괄호를 단언에 포함시켰던 탓에 '배열 끝에 항목 추가'가 곧 실패였던 구조를 제거했다.

· 함수 시그니처 원문
    (예) "function _singleInvalidateDownstream(fromKey, opts)"
    → has_function(파라미터 목록 무관) + 반드시 본문 단언/음성 계약을 동반.
      존재 계약만 걸면 검증 강도가 떨어진다는 파일럿 자기비판을 그대로 지켰다.

· 금지 호출 반복문(for forbidden in ...: assert forbidden not in fn)
    → calls_absent(...) == []  — 실패 시 '어떤 금지 호출이 남았는지'가 메시지에 드러난다.

· 수동 슬라이스/서브프로세스 배관
    → function_body(중괄호 매칭) / listener_body(앵커 쌍) / run_node 로 통일.
      각 파일이 제각각 복사해 두었던 _extract_fn·_run_node·_slice 를 전부 위임으로 교체했다.
      고정 길이 절단은 한 곳도 남기지 않았다.

· 유지한 것: node 실행 계약(이미 행동 검증이므로 하니스만 공용화), UI 한글 문구
  (문구 자체가 사용자와의 계약), 제거 확인(not in)은 식별자 단위로 좁혀 유지.

이 과정에서 내가 새로 쓴 계약 2건의 약점이 드러나 즉시 보강했다(이게 mutation 을 돌린 이유다).
  · M9: load 보강 계약을 "_renderSingleStepNav 문자열이 콜백에 있다"로 썼는데, 같은 콜백에
    `typeof _renderSingleStepNav === 'function'` 이 있어 실제 '호출'을 지워도 통과했다.
    → 호출 형태(정규식)를 요구하도록 수정.
  · M14: 위임 가드를 "_mvStepNavDelegated 부분 문자열 존재"로 썼는데 _mvStepNavDelegatedX 로
    개명해도 통과했다. → 단어 경계 + 읽기/쓰기 쌍(2회 이상) 요구로 수정.

또 하나 확인된 사실: 잠금(disabled) 단계는 마크업 생성과 위임 핸들러 양쪽에서 2중으로 막고 있다.
그래서 한 겹만 제거하면 클릭 '행동'은 그대로이고 행동 테스트가 통과하는 것이 정답이며,
두 겹을 동시에 제거한 M12c 에서 비로소 행동 테스트가 실패한다. 즉 그 테스트는 죽지 않았다.
마크업 계층의 회귀는 별도 계약(M12/M12b)이 각각 잡는다.

· 긍정: 정당한 UI 리팩터가 테스트를 깨지 않는다(7dc5b1e 실증). 실패 메시지가

  헐거웠고 보강했다. 앞으로도 전환 시 mutation 을 반드시 함께 돌려야 한다.
· 근본 원인 미해결: 렌더러가 여전히 python 문자열 안의 거대 JS(ui/tabler_renderer.py)라는 구조는
