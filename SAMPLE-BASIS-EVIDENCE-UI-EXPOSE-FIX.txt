✅ 작업 완료 - SAMPLE-BASIS-EVIDENCE-UI-EXPOSE-FIX - 표본(5만행) 절단으로 수집된 고유값에 '표본 5만행 기준' 근거를 저장→평탄화→화면(비고·선정사유·툴팁)까지 배선, 전수 스캔은 표기 없이 무회귀

════════════════════════════════════════════════════════════════════════════════
1. 배경 — 무엇이 갭이었나
════════════════════════════════════════════════════════════════════════════════
백로그 F27. 직전 작업(PROFILE-RECOLLECT-SAMPLING-TIMEOUT-GUARD-FIX)이 재수집 distinct 수집에
SAMPLE_SRC(5만행) 상한을 걸면서, 표본이 실제로 잘린 경우 각 컬럼 근거에 '표본 5만행 기준'
(sampled / sample_limit / distinct_basis / row_count_basis)을 snapshot 의 column_profiles_json 에
저장하도록 해 두었다. 그런데

  services/profile_snapshot_service.py :: _load_profile_stats_from_snapshot_impl

이 snapshot → profile_stats 변환에서 고정 5개 키(row_count / non_null_count / null_ratio /
distinct_count / distinct_ratio)만 남기고 근거 필드를 버렸다. 소비자(후보 표시)는 그 뒤 어디에서도
'이 고유값이 표본 추정치'라는 사실을 알 수 없었고, 화면에는 전수 값과 똑같은 모양으로 표시됐다
= 조용한 과소추정(explainability 훼손).

실측으로 확인한 규모: asis01.t_as_n_etl01(42,000,024행) 재수집 시 row_count 는 50,000 으로 잘리고
distinct 도 그 표본에서만 계산되는데, before 화면은 '프로파일 기반: 고유값 1개'로만 표시했다.

2. 위치 확인 — 지침의 '겹침 시 보류' 조건 처리
════════════════════════════════════════════════════════════════════════════════

BLOCKED-RESPONSE-TOTAL-ELAPSED-TIME-ADD-FIX)과 겹치지 않는다. 작업 중 다른 세션이 커밋한
49d8287(ADMOVR-PROJSCOPE) · 4ddbbb4(BLOCKED-ELAPSED)의 변경 파일과도 교집합 0.

7. 비판적 검토 — 남는 위험과 미해결 갭
════════════════════════════════════════════════════════════════════════════════
(1) '그룹당 평균 N행'은 여전히 무근거로 읽힌다.
    선정 사유의 '그룹당 평균'은 row_count/고유값으로 계산되는데, 표본 절단 시 row_count 도 표본
    건수(50,000)라 실제 평균과 다르다. 이번엔 근거를 '고유값' 값에만 정확히 귀속시켰다
    (row_count 출처가 evidence_contract 인 경로가 있어 문장 전체에 꼬리표를 달면 거짓이 될 수 있음).
    → 후속 과제: 표본 기반 row_count 를 쓰는 파생 지표(그룹당 평균/예상 그룹 수)의 근거 표기.

(2) 개별검증 라이브 profile 경로에는 이 근거가 아예 없다.
    services/column_profile_service.py 는 같은 _SAMPLE_LIMIT(5만)로 표본을 뜨면서 sampled 플래그를
    남기지 않는다. 즉 '표본인데 표기 없음'이 개별검증 라이브 수집 경로에 그대로 남아 있다
    (이번 지침 범위는 재수집→snapshot 경로). 같은 방식으로 확장 가능 — 별도 지침 권장.

(3) 표기 대상이 GROUP BY 비고에 한정된다.
    SUM 후보 비고는 NULL 계열 chip 이라 표본 근거를 싣지 않았다(툴팁 통계줄에는 공통 적용).

(4) 화면 폭 — chip 이 '프로파일 기반: 고유값 1개 (표본 5만행 기준)'로 길어졌다. 비고 열은 chip
    2개 초과 시 tooltip 으로 접히는 기존 규칙이 있어 레이아웃 붕괴는 실측에서 확인되지 않았다.

(5) heuristic/scoring 영향 없음 — 하드코딩 규칙 추가 0, 점수·선정 로직 미변경(표시 전용).
    근거 문자열은 수집 시점 저장값을 재사용하므로 표기와 실제 수집 조건이 어긋날 수 없다.
