3. 38.29px 의 원인 분해 (요구 ③은 "지우면 맞겠지"가 아니라 실제로 재서 확인)
────────────────────────────────────────────────────────────────────────
①의 처리시간 줄이 24.28px 이므로 그것만으로는 38.29px 이 설명되지 않는다(14px 부족).
나머지를 특정하려고 전용 프로브(count_stage2_gap_source_probe.py)로 '단계 탭 바 하단 ~ 카드
상단' 사이에 실제 자리를 차지하는 요소를 두 단계 모두 전수 열거했다.

  1단계: 탭 바 하단 213.98 → 카드 상단 225.98 (간격 12px, 사이 요소 없음)
         · #queryReviewCard 는 #mvResultArea '밖'에 있어 탭 바 바로 아래에 붙는다.
  2단계: 탭 바 하단 238.27 → 카드 상단 264.27 (간격 26px)
         · 사이 요소: #stickyProgressBar (top 252.27, height 2px)
         · 내역: 탭 바 margin 12px + stickyProgressBar margin-top 2px + 높이 2px
                 + margin-bottom 10px = 26px  → 1단계보다 14px 더 씀

즉 38.29px = 24.28px(처리시간 줄) + 14px(#stickyProgressBar) 로 정확히 나뉜다.

#stickyProgressBar 가 무엇을 그리는지도 소스로 확인했다 — 아무것도 그리지 않는다:
  · 자식 #singleStepNav 는 코드 전체에서 아무도 채우지 않는다(단계 탭은 전역 #mvStepNavBar 담당).
  · .sp-row-steps 는 인라인 display:none('구 구조 — DOM 동기화용 보존, 화면 비노출' 주석).
  · #sp-rowInfo 는 _setSpInfo 가 모든 분기 끝에서 항상 display='none' 으로 되돌린다.
  · 남는 렌더는 장식용 border-bottom:2px 뿐 → 세로 공간 14px 만 점유하는 잔재.
