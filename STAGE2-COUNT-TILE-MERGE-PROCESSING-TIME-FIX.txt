1. 요청 요약
──────────────────────────────────────────────────────────────────────────────
2단계 화면에 나란히 있던 두 타일 — 'COUNT 소요'(원본/목적 개별시간 2줄)와
'COUNT 총시간'(합계 1줄) — 을 하나로 합친다. 개별시간 값을 'COUNT 총시간' 타일 자리로
옮기고, 'COUNT 소요' 타일은 로직까지 함께 삭제한다. 합쳐진 타일의 라벨은 '처리시간'.


2. 무엇을 고쳤나
──────────────────────────────────────────────────────────────────────────────
수정 파일은 표시 계층 한 곳(ui/tabler_renderer.py)뿐이다. 값 계산·판정 로직은 한 줄도
건드리지 않았다.

  (1) _MV_COUNT_TILE_ORDER 에서 'elapsed' 제거
      → 타일 목록이 [목적 테이블, 원본 테이블, 목적건수, 원본 건수, 차이, 처리시간, 상태]
        7개가 된다.

  (2) _MV_COUNT_TILE_LABEL 의 'proc' 라벨을 'COUNT 총시간' → '처리시간' 으로 되돌림
      직전 규약(STAGE-TILE-DEDUP-CLEANUP-SEQUENTIAL-FIX 파트 C-2)이 '처리시간'을
      'COUNT 총시간'으로 바꿨던 이유는 "옆 칸 'COUNT 소요'와 개별 vs 총을 라벨만으로
      구분할 수 없다"였다. 두 타일이 하나로 합쳐지면서 그 혼동 자체가 사라졌으므로
      원래 라벨로 되돌린다. 1·3·5단계 타일이 모두 '처리시간'이라 단계 간 라벨도
      다시 일관해진다.

  (3) 가상 컬럼 주입 장치(_MV_COUNT_TILE_VIRTUAL)와 _mvCountTileCols 의 주입 루프 삭제
      이 장치는 'COUNT 소요' 타일 전용이었다. 타일이 사라졌으므로 함께 걷어냈다
      (죽은 코드 잔존 금지 — 요구사항 3).

  (4) _mvCountTilesHtml 의 'elapsed' 분기 삭제 → 'proc' 분기에서 통합 렌더
      개별시간은 _mvCountTileElapsed(옛 'COUNT 소요' 타일이 쓰던 함수 그대로),
      총시간은 공유 rows 의 row.proc(옛 'COUNT 총시간' 타일이 쓰던 값 그대로)다.
      새 계산은 만들지 않고 두 기존 값을 한 타일에 모으기만 했다(요구사항 2).

  (5) _mvCountTileElapsed 자체는 삭제하지 않고 유지 — 호출부만 바뀌었다(요구사항 3 단서).

공유 컬럼정의 _mvCountColumns()(ui/grid_helpers.py)는 손대지 않았다. 일괄검증 COUNT
그리드 등 다른 호출부가 같은 정의를 쓰므로, 여기를 고치면 2단계 밖까지 바뀐다.


3. 표기 형태와 그 근거 (요구사항 1·6)
──────────────────────────────────────────────────────────────────────────────
값은 아래 3줄이다.

    원본 0.09초
    목적 0.09초
    총 0.10초

  · 줄바꿈 규격: 기존 다중값 타일과 같은 '배열 → <br> 이어붙이기' 방식을 그대로 썼다
    (3단계 GROUP BY 타일·4단계 실행시간 타일과 동일). 새 포맷을 만들지 않았다.
  · 구분선은 넣지 않았다. 기존 다줄 타일 어디에도 구분선 규격이 없어서, 넣으면 그 자체가
    새 포맷을 만드는 셈이 된다. '총 ' 접두어만으로 개별과 합계가 구분되므로 3줄 나열로
    충분하다. 이 '총 N초' 접두어도 새로 만든 것이 아니라 4단계 다중세트 표기에서 이미
    쓰던 표현을 재사용한 것이다.
  · 실측 캡처로 확인한 결과, 타일 박스 높이(min-height 85px) 안에 3줄이 잘림 없이 들어간다.

툴팁은 세 값을 모두 설명하는 형태로 통합했다. 실측값:

    원본 92ms / 목적지 88.7ms · 총 104.7ms(병렬 실행, 차액은 서버 파싱·COUNT SQL 생성
    오버헤드) · COUNT SQL 생성방식: PARSED_MODEL_COUNT_SQL

이는 개선이기도 하다 — before 실측에서 'COUNT 총시간' 타일은 툴팁이 아예 비어 있었고
(측정 JSON: tip=""), 지금은 그 자리에서 개별·총·차액 사유·SQL 생성방식을 모두 읽을 수 있다.


4. 값 부재 케이스(무회귀 설계)
──────────────────────────────────────────────────────────────────────────────
개별시간이 없는 응답(DB 미연결/오류)은 통합 분기를 아예 타지 않고 기존 일반 경로로
내려간다. 즉 합치기 전 'COUNT 총시간' 타일과 완전히 동일하게 한 줄 값 또는 '-' 로
그려진다. 실행 전(c=null)에는 다른 미실행 타일과 같이 '—' 다(즉시표시 규약 유지).

7. 비판적 검토
──────────────────────────────────────────────────────────────────────────────
  · heuristic 증가 : 없음. 판정 규칙을 새로 넣지 않았다.
  · scoring        : 해당 없음.
  · explainability : 개선. 개별·총·차액 사유·SQL 생성방식이 한 툴팁으로 모인다.
                     before 의 'COUNT 총시간' 타일은 툴팁이 비어 있었다.
  · 보안           : 해당 없음(표시 계층, 새 데이터 노출 없음).
  · 테스트 가능성  : 유지. 통합 로직이 표시 계층 한 함수 안에 있고 node 하니스로 값·툴팁·
                     경계(값 부재/한쪽만/10ms 미만)를 모두 단언한다.
  · 구조 부채      : 감소. 타일 전용 가상 컬럼 주입 장치가 사라져 _mvCountTileCols 가
                     단순해졌다(숨김 규칙 하나만 남음).
  · 남은 위험      : 라벨을 '처리시간'으로 되돌리면서, 이전 규약(파트 C-2)이 우려했던
                     "개별 vs 총 혼동"이 재발할 여지가 이론상 있다. 다만 그 우려는 두 값이
                     서로 다른 타일에 있을 때의 것이고, 지금은 한 타일 안에서 '총 ' 접두어로
                     명시 구분되므로 실질 위험은 없다고 판단했다.
