4. 영향도 재확인 — diagnosis 판정이 실제로 바뀌는 컬럼
════════════════════════════════════════════════════════════════════════
(예: 오늘 본 C_DATE 900건짜리)
  · 현행 recommender: C_DATE(distinct 900) → 날짜형이지만 카디 mid(≤1000) → GB 후보/조합 진입
    (절대상한 60 없음, 날짜 durable 없음) → '추천/후보'로 노출될 수 있음.
  · 현행 groupby_scoring: 900 > safe_group_max(200) → EXC_CARDINALITY_HIGH(배제).
  · 통합 후: classify_cardinality → 900 > 60(절대상한) → excluded=True. 이후 date durable
    판정으로 '월/분기/연 변환 가능'하면 date_bucket 구제(엔진과 동일), 변환 불가(초 단위)면
    배제 유지. → 즉 통합 후 diagnosis 도 메인 화면과 동일하게 '기간 변환 구제' 를 받음.
  결론: 실제 판정이 바뀌는 컬럼군 =
   (1) distinct 60~200 사이 일반 컬럼: recommender 는 '후보'였으나 통합 후 절대상한으로 배제.
   (2) distinct 60~1000 날짜 컬럼: 통합 후 date_bucket 구제 경로 확보(현재는 recommender 무구제
       /groupby_scoring 200 초과 단순 배제).
   (3) PG 음수 n_distinct 컬럼: 현재 recommender/scoring 은 unknown 처리 → 통합 후 비율 등급화.
  실제 UI 영향 범위:
   - 전수검증/배치 상세 '3.후보추천' 표시(candidate_recommendation): recommender 산출 —
     단, 라이브 producer 부재로 도달 빈도 낮음(자문 엔드포인트). 영향 '표시 정합' 위주.
   - 드릴다운 전략 화면(strategy-orchestrate, tabler_renderer:17362): rank 추천 GB 개수 변동 →
     route_drilldown 의 group_by_candidate_count 변동 → next_action 이 바뀔 수 있음(실질 영향 ★).
