■ 무엇을 왜 고쳤나
  직전 작업에서 남긴 부수 갭을 처리했다. 마법사 5단계 화면(ui/execute_result_renderer.py)은
  실행 응답 최상위의 total_src / total_tgt 두 값으로 두 가지를 그린다.
    ① 요약 하단 표기 "원본 그룹 수: N / 목적지 그룹 수: M"        (renderer 909-910·948)
    ② 경고 박스 항목 "그룹 개수 실측 불일치 — 원본 N개 / 목적 M개"  (renderer 438·465-470)
  그런데 단건 스냅샷(single_validation_snapshot)에는 두 값이 저장되지 않았다. summary_counts 에도
  (matched/diff/src_only/tgt_only/total_groups/compared_groups 뿐) 없고 최상위에도 없었다.
  그래서 같은 run 이라도 스냅샷만으로 재구성하는 화면(현황판·재조회)은 ①을 "— / —"로 비우고
  ②를 아예 표시하지 못했다. 값은 이미 실행 응답에 있으므로(services/stats_execute_service.py:531)
  저장 범위만 넓히면 되는 문제였고, 판정 로직은 손대지 않았다.

■ 지시 2번에 대한 정정 보고 — '그룹 수 불일치가 강등을 유발하는 케이스'는 만들 수 없다
  지시는 "그룹 수 불일치가 강등(_rvDowngrade)을 유발하는 케이스를 만들어 A/B/C 로 실측"이었다.
  실측 결과 그런 케이스는 구조적으로 존재할 수 없다는 것을 확인했으므로 그대로 보고한다.

  _rvDowngrade = _hasXform && allOk 이고, _hasXform 은 ①값 변환 감지 ②그룹 수 실측 불일치의 OR 이다.
  ②만으로 강등이 나려면 allOk(diff=src_only=tgt_only=0)이면서 total_src ≠ total_tgt 여야 한다.
  그런데 비교 엔진(services/stats_execute_service.py:398-455)에서
      total_src = |S|(원본 그룹 키 집합),  total_tgt = |T|,
      src_only  = |S \ T|,                 tgt_only  = |T \ S|
  이므로 항상  total_src − total_tgt = src_only − tgt_only  가 성립한다.
  따라서 allOk(둘 다 0)이면 그룹 수는 반드시 같아진다 — ② 단독 강등은 도달 불가능한 분기다.

  실측으로도 확인했다(group_count_downgrade_reachability_probe.py).
    - 순수 누락 케이스(NORTH 미이관)   : total_src=4 total_tgt=3, src_only=1 → allOk=False (강등 아님)
    - NULL→값 변환 흡수 케이스(t_gbnullx): total_src=3 total_tgt=3 → 그룹 수 불일치 자체가 없음
      (원본 통계 SQL 이 이관식 CASE 를 반영해 원본도 3그룹으로 집계되기 때문)
    - 두 케이스 모두 항등식 성립. 무작위 그룹 집합 5,000쌍 시뮬레이션에서도 항등식 위반·반례 0건.

  그래서 이번 2필드의 실효는 '강등 판정 복원'이 아니라 '그룹 수 표기와 그룹 개수 실측 불일치
  경고 항목의 복원'이다(둘 다 allOk 여부와 무관하게 표시되는 경로다). 검증 2·3 이 그 실효를
  A=B≠C 로 실증한다. 직전 작업 보고서에 남긴 "그룹 수 불일치 갈래의 강등을 재구성할 수 없다"는
  표현은 이번 실측에 따라 "그 갈래는 강등이 아니라 표시를 잃는다"로 정정한다.
