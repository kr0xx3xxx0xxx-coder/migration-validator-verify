1. 배경과 결정
────────────────────────────────────────────────────────────────────────
검증 현황판은 개별검증 / 일괄검증 / 통계검증 3개 섹션을 항상 펼쳐서 보여줬다. 실사용에서는
대부분의 시간 동안 세 섹션 중 한둘만 활성이고 나머지는 "진행 중인 ... job 이 없습니다" 안내문만
차지해 화면 노이즈가 됐다(수정 전 실측: 활성 0건일 때도 섹션 영역이 237px 를 차지).

탭 분리는 "동시에 여러 종류가 도는 상황을 한눈에 본다"는 현황판 본래 목적을 깨뜨리므로 채택하지
않았고, 절충안으로 "활성 job 이 있는 섹션은 자동 펼침, 0건인 섹션은 헤더 한 줄로 축소"를 택했다.
0건 섹션도 완전히 숨기지 않고 헤더 한 줄로 남겨 존재 자체는 항상 보이며, 클릭하면 수동으로
펼쳐 볼 수 있다.

■ 구현 요지
  (1) 상태 모델 — 소스별로 두 값만 둔다.
        active : 서버가 내려준 활성 job 유무(자동 상태)
        manual : 사용자가 직접 지정한 상태(null = 지정 없음 → 자동 상태를 따름)
      표시 상태 = (manual == null) ? active : manual
      manual 은 **활성 유무가 실제로 바뀔 때(0↔N)만** 해제한다. 같은 상태로 폴링이 반복되는
      동안에는 사용자가 펼쳐 둔 섹션을 서버 갱신이 도로 접지 않는다(사용자 조작 우선).

  (2) DOM 재생성 금지 — 기존에는 폴링(3초)마다 #jdSections 를 innerHTML 로 통째 재생성했다.
      · 섹션 골격(헤더 + 본문 컨테이너)은 data-jdsec-ready 로 최초 1회만 생성
      · 본문은 HTML 문자열이 실제로 바뀐 섹션만 교체(_MV_JD.secHtml 캐시와 비교)
      · 헤더 건수 문구는 textContent 로만 갱신
      · 접기/펼치기는 클래스 토글(is-collapsed)뿐 — 노드를 버리거나 다시 만들지 않는다
      오늘 고친 CANDIDATE-CHECKBOX-FLICKER-REVALIDATION-FIX 와 같은 취지다. 다만 그 경로의
      _mvMorphPaneHtml 은 후보 pane 전용 전역 플래그(_mvCandPaneMorph)와 검증용 통계 전역
      (_mvCandMorphStat)에 묶여 있어, 3초 폴링이 그 전역을 계속 덮어쓰면 후보 pane 검증 하니스를
      오염시킨다. 그래서 함수를 호출하지 않고 같은 원칙만 따랐다(호출부 없는 자족 구현).

  (3) 전환 효과는 캐럿 회전 0.15s 뿐이다. 높이 애니메이션은 쓰지 않았다 — 높이 측정 리플로우가
      폴링 주기와 겹치면 오히려 깜빡임을 만든다.

  (4) 접근성 — 헤더에 role="button" / tabindex="0" / aria-expanded 를 부여하고 Enter·Space
      키로도 토글된다.

5. 비판적 검토(문제점 · 위험 · 대응)
────────────────────────────────────────────────────────────────────────
- 정보 은폐 위험 : 0건 섹션을 접으면 "그 종류가 화면에 없다"는 오해가 생길 수 있다.
  → 헤더를 항상 남기고 "개별검증 진행 중 0건" 문구를 그대로 표기했다. 완전 숨김은 쓰지 않았다.
- 상태 폭발 위험 : 접힘 상태를 서버·저장소에 남기면 새 저장 계층이 생긴다.
  → 세션 메모리(_MV_JD.sec)에만 둔다. 새로고침하면 자동 상태로 복귀한다(영속화 없음 = 부채 없음).
- 사용자 조작 무시 위험 : 폴링이 사용자 클릭을 되돌리면 "버튼이 먹통"으로 체감된다.
  → 0↔N 실제 전환에서만 수동 지정을 해제하도록 규칙을 좁히고, 양방향(수동 펼침/수동 접기)을
    실측으로 확인했다.
- 깜빡임 재발 위험 : 폴링마다 DOM 을 다시 만들면 오늘 고친 문제가 되살아난다.
  → 골격 1회 생성 + 변경분만 교체 + 클래스 토글로 처리하고, 노드 동일성까지 실측·테스트했다.
- heuristic / explainability : 새 임계값·가중치를 도입하지 않았다. 판단 입력은 "활성 job 수"
  하나뿐이고, 그 값은 서버 DTO 를 그대로 쓴다. 수동 지정 중임을 화면에 표식으로 밝힌다.
