작업명 : BATCH-VALIDATION-SEQUENTIAL-EXECUTION-AND-BLOCKING-HTTP-FIX
✅ 작업 완료 - 그룹 전체 통계검증(#2 run-wrapper)을 비동기 전환 + 테이블 간 제한 병렬 + 전체 상한으로 개선(개별검증 무영향), 실 오라클 x2.57 병렬 speedup·브라우저 즉시응답 113ms 실측

[설계문서 반영]
- docs/BATCH_VALIDATION_SPEED_IMPROVEMENT_DESIGN.md 의 B1(ValidationScheduler + 프로필 연결 예산 제한 병렬,
  개별 core 재사용)과 C1 요지(백그라운드화로 worker 비점유)를 '공식 경로에만' 배선. 새 설계 없이 문서 계획대로 구현.
- 정확성 전제 준수: 개별검증 facade(run_single_validation_standard) 및 순차 run_batch_rows 는 원형 보존(수정 0).
  병렬은 신규 함수 추가(별도 실행경로/비교 알고리즘 생성 없음 — run_batch_row 를 그대로 반복 호출).

[① 비동기 전환]
- POST /api/batch-groups/{gid}/run-wrapper 가 lock 획득·plan 로드·row 구성(동기) 직후 즉시 job 을 백그라운드
  데몬 스레드로 시작하고 job_id(execution_run_id)를 반환. 배치 전체 완료까지 blocking 하던 동기 요청 제거
  (worker 장기 점유·브라우저/프록시 타임아웃 위험 해소).
- 신규 services/batch/wrapper_async_job.py 가 수명주기(진행 갱신 → 전체상한 → 결과저장 → 상태종료) 관리.
- 클라이언트는 기존 GET /batch/runs/{id}/execution-status 폴링으로 진행/완료 확인.
- UI(ui/tabler_renderer.py runWrapperValidation): 단일 await fetch 를 'async 응답 → _mvAwaitBatchExecTerminal
  로 execution-status 폴링 완료 대기 → 결과 조회' 로 전환(비-async/스킵/409 응답은 기존 경로 유지).
  ※ 이 UI 편집분은 동시 진행 세션의 커밋 592d003 에 함께 포함되어 HEAD 에 반영됨(served HTML 에서 확인).

[② 병렬화]
- 신규 services/batch/wrapper_parallel_runner.run_batch_rows_parallel 이 ValidationScheduler + ResourceBudget 로
  run_batch_row 를 '테이블 간 제한 병렬' 실행. 같은 원본/목적 DB 프로필(db_type/host/port/dbname)은
  max_concurrent_per_source/target_profile 상한으로 동시연결 억제, 서로 다른 프로필/무관 테이블은 병렬.
  기본 보수값 전역 4·프로필당 3(정책 batch_scheduler_config / 호출 override / env MV_BATCH_SCHED_CONCURRENCY 로 조정).
- 연결: 각 worker 스레드가 run_batch_row 내부 request_connection_scope 로 '자체 연결'(thread-local) → row 간 공유 없음.
- 순서: 비순차 실행이나 원래 index 로 정렬 수집(결과 순서 보존).
- 안전장치:
  · registration(SQLite 쓰기)은 register_fn 주입 단일 lock 으로 직렬화(원격 DB 검증은 병렬 유지) → 'database is locked' 회피.
  · 진행/취소 상태는 per-call 함수(update_progress/is_cancel_requested)로 접근(단일 sqlite 연결 cross-thread 공유 금지).
  · 일시중지/취소는 batch_pause_control row-gate(worker admission 경계) + STOP_REQUESTED cancel_check 로 협조적 중단.

[③ 배치 전체 상한 / 취소]
- batch_overall_timeout_sec(기본 7200초, 정책 조정) 경과 시 이후 row 미실행 후 STOPPED(진행 중 row 는 완료 — 협조적).
- 명시 취소: 기존 '중단' 버튼(execution-status STOP_REQUESTED) + batch_pause_control cancel 이 백그라운드 job 을 즉시 정지.
- 운영 즉시토글: env MV_BATCH_ASYNC_PARALLEL(async on/off, 무위험 롤백), MV_BATCH_SCHED_CONCURRENCY(동시수).

[④ 개별검증 무영향 확인]
- run_single_validation_standard facade 미수정. 배치 실행 레벨(신규 병렬/비동기 모듈)만 추가. route 는 조기 return 1개만 삽입.
- 순차 run_batch_rows(기존 계약·테스트 대상)도 원형 보존. flag off 시 기존 동기 순차 경로로 완전 fallback.
