[문제]
services/candidate_postcount_finalize.py 의 _date_catalog_stats() 가 방언과 무관하게
fetch_postgres_column_stats(PG 전용 — db_type != 'postgresql' 이면 즉시 {} 반환)를 호출.
→ 오라클에서는 이미 존재하는 컬럼통계 어댑터(OracleAdapter.fetch_column_stats,
  supports_column_stats()=True)가 있는데도 이 L1 경로가 '조용히 빈 값 {}' 만 반환.
  결과: 날짜버킷 후보의 raw_distinct/null_ratio/raw_row_estimate 등 catalog 근거가 오라클에서 유실.

[수정] (services/candidate_postcount_finalize.py 단일 파일 — 지시 준수)
_date_catalog_stats() 에 방언(dbt) 인자 추가 + 방언별 통계 출처 분기:
  - postgresql : fetch_postgres_column_stats(pg_stats/pg_class, schema 인자 지원) — 기존 경로 그대로(회귀 방지)
  - oracle 등  : get_adapter(dbt).fetch_column_stats(ALL_TAB_COL_STATISTICS/ALL_TABLES)
                 — PG 와 동일 shape 를 반환하는 '이미 존재하는' 어댑터 재사용(새 어댑터 작성 없음)
  - 미지원 방언 : supports_column_stats()=False → 빈 dict(L2 범위추정 폴백)
호출부(_collect_date_bucket_profiles)가 dbt 를 넘기도록 1줄 수정.

'통계 없음' 원인을 로그로 구분(지시 #2):
  (A) 미지원 방언       → DEBUG "L1 catalog 통계 미지원 방언(<dbt>) — L2 범위추정으로 폴백(통계 조회 생략)."
  (B) 어댑터 정상 호출·통계 0건 → INFO "L1 catalog 통계 0건 — 어댑터(<dbt>) 정상 호출됐으나 대상 테이블(<t>)
                                       통계 미수집 추정(gather stats 미실행 등) → L2 범위추정 폴백."
  ⇒ '옛 PG전용 함수 오호출로 조용히 빔' 과 '어댑터 정상 호출됐으나 통계 자체가 없어서 빔' 을 명확히 구분.

L4(DATE_TRUNC PG전용, ORA-00904)는 지시대로 이번 범위 밖 — 기존 L2 범위추정 폴백 그대로 유지.
