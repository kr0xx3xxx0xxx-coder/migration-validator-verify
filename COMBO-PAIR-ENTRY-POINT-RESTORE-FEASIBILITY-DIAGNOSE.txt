[4] 자동 vs 명시적 트리거 — 권고: 명시(opt-in) 유지
────────────────────────────────────────────────────────────────────────────────
정책 이력 재확인: 과세분화 방지 의도는 처음부터 있었으나(81b556b) 그때는 자동이었다.
자동→명시 전환(e8603fb)의 근거는 "실행계획 단일화"이지 과세분화가 아니었다.

항목별 위험 판단
  그룹 폭주(과세분화)   낮음     상한 100그룹·하한 100행·구분효과 3중 가드 실측 동작
  결과 표시 폭주        낮음     표시 축소는 등급과 별개(MAX_DISPLAY_ROWS 200 + 페이징)
  대량 COUNT 불일치     이미 차단 COUNT_MAJOR_DIFF 에서 pair 금지(§25)
  실행 비용             실재 위험 가드는 예상 그룹 수만 본다 — 스캔 비용은 전혀 못 막는다

비용 실측(t_combo 1,200행, 3회, /generate+/execute 왕복)
  1회차  단일축 385ms  조합 373ms  (0.97x)
  2회차  단일축 256ms  조합 301ms  (1.17x)
  3회차  단일축 302ms  조합 220ms  (0.73x)
→ 조합 세트 1개 = 단일축 세트 1개와 동급 비용(테이블 전체 집계 1회 추가).
  자동 ON 은 축 N개에서 총 실행 시간 +1/N 을 무조건 부과(2축 +50% / 3축 +33%).
  대상이 수천만~1억 행인 도구에서 요청하지 않은 전체 스캔 추가는 공짜가 아니다.

권고 근거 3가지
  1) 가드의 사각지대가 비용 축이다 — 결과 크기는 막지만 실행 시간은 못 막는다
  2) 자동 ON 의 최대 장점(거짓 안심 제거)은 오늘 배너로 이미 확보됐다
  3) 자동이면 데이터에 따라 조합 실행 여부가 갈리는데 사용자가 통제할 수 없다

후속 검토 후보(범위 밖): table_load_profiles 규모 등급 '소형' 대상에 한정한 조건부 자동 ON
