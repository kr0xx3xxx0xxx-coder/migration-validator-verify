1-A. 상단 그리드 "실행시간" 깜빡임 원인
  ▸ 판정: 실제 결함(불필요한 재렌더링). 다만 "값 자체가 틀리다"는 의심은 근거 없음(값은 안 바뀜).
  ▸ 원인: 그룹을 처음 클릭(캐시 미적중, 재이관 PK index 최초 prepare)하면
    _mvPkEnsurePrepared(ui/tabler_renderer.py:17612~17625)가
      ① fetch 시작 직후 1회, ② .then/.catch(응답 도착) 시 1회
    총 2회 이상 _mvRepaintStage5Tiles()를 호출한다. 이 함수는
    host.innerHTML = _mvStage5TilesHtml(r, ctx) 로 상단 타일 그리드 전체를 매번
    통째로 교체한다(ui/grid_helpers.py:1370~1388) — "실행시간" 칸도 예외 없이 DOM 노드가
    파괴·재생성된다. 같은 패턴이 _mvPkPrewarm(ui/tabler_renderer.py:18653~18665)에도 있다.
  ▸ "실행시간" 값은 window._mvStage5ProcMs 기반(_mvStage5ProcInfo, 아래 1-B)이고
    이 값은 재이관 PK 준비 상태(_mvPkState)와 무관하게 통계검증 실행 시점에 이미 고정된다.
    즉 재렌더 전/후로 표시 문자열은 동일한데, DOM 을 통째로 다시 그리는 과정에서
    그 짧은 순간 셀이 비었다가 다시 채워지는 것처럼 보인다(=사용자가 본 "깜빡임").
  ▸ 코드 수정 필요 여부: 예(권장). 수정 방향은 "값이 바뀌지 않은 칸까지 통째로 지우지 않기" —
    예) _mvRepaintStage5Tiles 를 '실행시간' 칸 하나만 갱신하는 부분 갱신 경로로 바꾸거나,
    prepare 시작 시점 호출(값 변화 없음)을 제거하고 완료/실패 시 1회만 남긴다.
    이번 작업은 조사까지만 — 실제 수정은 사용자 승인 후 별도 지시로 진행한다.

1-B. 상단 그리드 "실행시간"이 정확히 무슨 값인가
  ▸ 판정: 현재 표시값은 "4단계 실행시간 전체"가 아니라 "그룹생성(불일치 계산·비교)만의 시간"이다.
    이는 오류가 아니라 STAGE5-EXEC-TIME-GROUPGEN-SPLIT(과거 작업)에서 의도적으로 좁힌 값이다.
  ▸ 근거(_mvStage5ProcInfo, ui/grid_helpers.py:1195~1235):
    - window._mvStage5ProcMs = 4단계 전체 벽시계(원본조회+목적조회+그룹생성/비교, 순차 실행 시
      합·병렬 실행 시 max 기준) — 이 원값 자체는 안 바뀐다.
    - 표시 텍스트만 = 전체시간 − (병렬이면 max(원본,목적), 순차면 원본+목적) = "그룹생성 시간"만.
    - 이유(코드 주석 그대로): 총시간을 '실행시간' 칸에 그대로 두면 "5단계(그룹생성) 자체 소요"로
      오독된다는 실측 지적이 있었다(예: 23.15초=원본10.91+목적11.21+그룹생성1.03인데 이름표만
      보고 전체를 5단계 소요로 읽음). 그래서 그룹생성분만 분리해 보여주고, 총시간·원본·목적
      개별값은 툴팁(마우스 오버)에 그대로 남겼다.
  ▸ 결론: 화면 값 자체는 설계대로 동작 중 — "적다"고 느껴진다면 그룹생성만 보고 있기 때문이며,
    전체 내역은 같은 칸의 툴팁에서 확인 가능하다. 코드 결함 아님.

1-C. 하단 [고정] "5단계 불일치 그룹추출: 12.18초"의 의미
  ▸ 판정: 결함 아님 — "그룹 존재"와 "그 그룹의 상세 PK 레코드 추출"은 서로 다른 작업이다.
  ▸ 이 값은 5단계 전체나 "불일치 그룹이 이미 다 만들어졌는가"와 무관하다. 통계검증 실행(4단계)
    시점에 diff/src_only/tgt_only 집계(=불일치 그룹 목록)는 이미 서버에서 계산 완료된 상태로
    5단계에 넘어온다 — 이건 "그룹 존재"다.
  ▸ 반면 이 카드 값은 "그 그룹들 중 사용자가 실제로 클릭해서 펼쳐 본, 가장 최근 그룹 하나"의
    재이관 대상 원본 PK 목록을 서버(/agg-diff/prepare + pk-records)에서 실제로 조회해 온
    소요시간(detail_ms)이다(_mvStage5SetGroupPerf, ui/tabler_renderer.py:28020~28030 /
    표시부: :27980~27995). 그룹을 하나도 안 열었으면 0.00초.
  ▸ 스크린샷의 "완료" 2개 / "미확인" 다수 상태가 바로 이 구분과 정확히 대응한다 — "완료"는 그
    그룹의 상세 PK 추출을 이미 마쳤다는 뜻이고, "미확인"은 그룹(불일치 자체)은 존재하지만 아직
    클릭해서 상세를 뽑아본 적이 없다는 뜻이다. 12.18초는 "완료" 표시된 그룹 중 가장 최근에 클릭한
    그룹 하나의 실제 추출 소요이지 그룹 생성/전체 소요가 아니다. 이 값 자체는 오늘 이미
    STAGE5-BATCH3-AMTQTY-INDENT-TOTALGROUP-LASTCLICK 로 "가장 최근 클릭 1건"으로 수정된 로직이며,
    이번 재확인으로 의도대로 동작함이 다시 확인됐다.
