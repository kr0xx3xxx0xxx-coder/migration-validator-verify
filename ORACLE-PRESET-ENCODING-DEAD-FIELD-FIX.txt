4. 대응방향 선택 근거 — (b) 안내문구 (선행 커밋에서 채택, 본 보고서에서 타당성 재확인)

채택: (b) 입력칸 유지 + "드라이버가 UTF-8 로 고정되어 이 값은 사용되지 않습니다(접속에 미반영)"

근거 3가지:
  1) 화면 관례 일치 — 같은 폼의 고급 옵션 항목은 전부 note 문구를 달고 있다
     (Connect Type / Driver Mode / PostgreSQL sslmode·connect_timeout / MySQL charset 등).
     "설명 note 로 제약을 알린다"가 이 화면의 기존 규약이며, (b)가 여기에 정확히 부합한다.
  2) 기존 preset 키 보존 — db_presets_*.json 에 encoding/nencoding 키가 이미 있다.
     입력칸을 제거하면(a안) 수정→저장 시 폼이 만든 dict 에서 해당 키가 빠져
     기존 저장값이 조용히 소실될 수 있다. 무해한 값이지만 "저장하면 없어지는" 부작용을
     피하는 쪽이 안전하다.
  3) 오해 해소라는 목적 자체는 note 로 충족된다 — 사용자가 "설정했는데 반영된 줄 아는"
     상황은 note 노출로 해소되며, 입력칸 제거보다 변경 범위(=회귀 위험)가 작다.

(a안 제거를 택하지 않은 이유의 요약: 목적 달성도는 동일한데 회귀 표면이 더 크다.)
