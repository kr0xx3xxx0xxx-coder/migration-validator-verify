2. 기술적 장벽이 실제로 존재하는지
────────────────────────────────────────────────────────────
[COUNT] SELECT COUNT(*) 뿐이라 방언차 자체가 없음 — routes/count_route.py 에 게이트가
아예 없어 실측대로 이기종 정상 작동.

[GROUP BY/SUM SQL 생성 계층] 이미 이기종 대응 아키텍처다.
  - generator/sql_generator.py SqlGenerator.generate() 는 db_type_src / db_type_tgt 를
    "완전히 독립된" 파라미터로 받아 각자 방언으로 SQL 을 생성한다(같은 값으로 강제하는
    코드 없음). services/stats_sql_builder.py build_stats_sql() 도 src_db_type/tgt_db_type
    을 그대로 전달한다.
  - 날짜 GROUP BY 기간변환(stats_sql_builder.date_trunc_expr)은 "어느 방언이든 동일한
    canonical 문자열(월 202607/분기 2026Q3/년 2026)을 만들어 원본/목적 비교 키가 어긋나지
    않는다"고 명시적으로 설계돼 있음 — 즉 이기종 비교를 이미 전제하고 설계된 부분이 존재.
  - 결론: "오라클용 빌더/PG용 빌더를 같은 논리적 GROUP BY 요청에 대해 동시 호출"하는
    구조는 이미 갖춰져 있다. 재설계가 필요한 부분이 아니다.

[결과 비교(원본 vs 목적) 단계] — 여기가 실제 미비 지점이다.
  - services/stats_execute_service.py:254 _to_dict() 의 GROUP BY 키 매칭:
      key = tuple(str(rd.get(k, '')) for k in gb_keys)
    드라이버가 반환한 파이썬 값을 단순 str() 캐스팅만으로 키를 만든다. 타입별 canonical
    정규화가 전혀 없다. 같은 DBMS 쌍(PG-PG, Oracle-Oracle)에서는 양쪽 드라이버 반환 타입이
    같아 문제가 드러나지 않았지만, 이기종(cx_Oracle NUMBER↔Decimal/float vs psycopg2
    int/Decimal, CHAR 우측 패딩, NLS 포맷 등)에서는 같은 논리값이 다른 문자열이 될 위험이
    실재한다(예: Oracle 100 → '100.0', PG 100 → '100' → 거짓 src_only/tgt_only).
  - SUM 값 자체 비교(services/numeric_compare_policy.compare_numeric)는 이미 허용오차
    기반이라 상대적으로 안전하지만, "행을 정렬시키는 키" 쪽에는 그런 관용도가 없다.
  - 이는 HASH_BUCKET 의 canonical hash 계약(services/diagnosis/hash_contract.py — 타입태그
    +길이접두 결합의 결정적 인코딩)만큼 크지는 않다. HASH_BUCKET 은 "전체 컬럼 조합을 해시로
    묶어 버킷 분배"하는 구조라 인코딩 발산이 대량 오탐으로 증폭되지만, 통계검증은 GROUP BY
    컬럼(최대 3개, 프로젝트 규칙)만 키로 쓰고 그마저도 사람이 확인 가능한 값 단위 비교라
    영향 범위가 훨씬 좁다.

3. 결론
────────────────────────────────────────────────────────────
(c) 중간 — 부분적으로 장벽이 있고 부분적으로는 "다른 기능의 안전장치를 그대로 차용해
    막아둔 미구현"이다.
  - SQL 생성(어댑터 구조)은 이미 이기종을 지원할 수 있게 돼 있다 → 이 부분은 재설계 불필요.
  - 결과 비교의 GROUP BY 키 정규화가 없다는 점은 실재하는 기술 리스크이나, HASH_BUCKET
    수준의 근본적 재설계가 아니라 "타입별 canonical 변환 함수 한 개 신설 + 적용" 규모다.
  - 현재 게이트 자체는 "오라클 개방" 작업의 부산물로, 통계검증을 위해 별도로 위험을 분석한
    결과가 아니라 HASH_BUCKET 원칙을 안전측으로 넓게 적용한 것 — 즉 (a)로 단정하기엔
    근거 문서가 "미검증"이라고 스스로 밝히고 있고, (b)로 단정하기엔 키 매칭 정규화라는
    실제 공백이 남아있다.
