0. 요약
═══════════════════════════════════════════════════════════════════════════════
백로그 F26 — `INSERT INTO t SELECT a,b,c ...`(INSERT 컬럼 목록 미기재) 형태는 재이관
wrapping 별칭 추출이 NO_INSERT_COLUMN_LIST 로 실패해 드릴다운이 무조건 HOLD 였다.
목적지 테이블의 **정의 순서(ordinal)** 를 근거로 안전 조건을 전부 충족할 때만 위치 기준
매핑으로 정상 처리하도록 지원 범위를 넓혔다. 애매한 케이스는 그대로 HOLD.

핵심은 "넓혔다"가 아니라 "오매핑이 없다"이며, 실 DB 값 검증으로 확인했다(§4).

═══════════════════════════════════════════════════════════════════════════════
1. 요구사항 1의 답 — parse_result.insert_cols 는 위치 기준이 아니다 (★설계 분기점★)
═══════════════════════════════════════════════════════════════════════════════
지침은 "parse_result.insert_cols 가 위치 기준으로 이미 채워져 있는지 확인" 을 요구했다.
확인 결과 **아니다**. parser/sqlglot_parser.py:203-211 이 INSERT 컬럼 목록이 없을 때
insert_cols 를 SELECT 의 alias/컬럼명으로 **이름 추론**해 채운다:

    if not insert_cols:
        for sexpr in sel.expressions:
            if isinstance(sexpr, exp.Alias):   insert_cols.append(sexpr.alias.upper())
            elif isinstance(sexpr, exp.Column): insert_cols.append(sexpr.name.upper())
            else:                               insert_cols.append(sexpr.sql(...).upper())

그 값은 원본 쪽 이름이라 목적지 정의 순서와 무관하다. 지침이 제안한 "insert_cols 를 위치
기준으로 빌려 쓰기" 를 그대로 했다면 아래가 조용히 오매핑된다:

    원본  T_SRC (b, a)          목적지 T_TGT (a, b)      ← 같은 이름, 다른 정의 순서
    이관  INSERT INTO T_TGT SELECT b, a FROM T_SRC
    DB 실제 적재 : src.b → tgt.a , src.a → tgt.b        (SQL 표준 = 정의 순서)
    파서 추론값  : insert_cols=[B, A]
      → src 의 b 를 'B' 로 alias → 목적지 B 와 비교 → 전 행 불일치를 날조

따라서 위치 기준의 근거를 **파서 추론값이 아니라 목적지 DB 카탈로그의 ordinal 순서**로
바꿔서 구현했다. 이 원리는 새 가정이 아니라 코드베이스에 이미 승인된 규약이다 —
services/select_star_expansion.py 가 "target 컬럼 목록 없음 → target metadata 로 확장,
ordinal mapping" 을 같은 방식으로 쓰고 있다.

2. 안전 조건 (전부 충족할 때만 넓힌다 — "확실한 것만 넓히기")
═══════════════════════════════════════════════════════════════════════════════
services/reimport_positional_columns.py 에 단일 출처로 모았다.

 (1) 원문이 INSERT 문이고 INSERT 컬럼 목록이 실제로 없다
     · 목록이 있으면 이 경로 대상 아님 — 원문이 명시한 매핑을 외부 값으로 덮지 않는다
 (2) 본문이 SELECT 이거나, 모든 브랜치가 SELECT 인 UNION 이다
 (3) 어느 브랜치에도 `*` / `alias.*` 가 없다 (위치 확정 자체가 불가) — DB 조회 전에 차단
 (4) 목적지 접속으로 컬럼 메타를 실제로 조회했고 결과가 비어 있지 않다
     · 접속 없음 / 조회 실패(None) / 빈 결과 → 전부 HOLD. 접속 없이 위치를 추정하지 않는다
 (5) 조회 결과에 중복 컬럼명이 없다
     · 어댑터 build_tgt_column_meta_query 는 스키마 필터 없이 table_name 으로만 매칭한다
       (PG/Oracle 공통). 동명 테이블이 여러 스키마에 있으면 두 테이블 컬럼이 섞여 순서가
       무의미해지는데, 중복 이름이 그 오염의 신호다
 (6) **모든** 브랜치의 projection 수 == 목적지 컬럼 수
     · 우리가 새로 만든 가정이 아니라 DB 자신이 이 INSERT 를 받기 위해 요구하는 조건과 같다
       (개수가 다르면 원래 이관 SQL 자체가 실행 불가였을 것)
     · Oracle invisible / MySQL generated 컬럼처럼 암묵 목록에서 빠지는 컬럼이 있으면 개수가
       어긋나 여기서 자동으로 걸린다
 (7) AST 의 INSERT 대상 테이블 == 검증 목적 테이블
     · 다르면 어느 테이블의 정의 순서를 따라야 할지 확정 불가

ordinal 근거의 출처: db_query_service._cmn_fetch_tgt_col_meta (기존 단일 출처 재사용, 새
카탈로그 SQL 미작성). 전 방언이 ordinal 정렬 보장 — PG/MySQL/MSSQL: ORDER BY
ordinal_position, Oracle: ORDER BY column_id.

3. 전/후 실측 (형태 판정)
═══════════════════════════════════════════════════════════════════════════════
대상 SQL: INSERT INTO T_TGT SELECT S1, S2, S3 FROM T_SRC WHERE GB = 'A'
          (+ UNION ALL 변형)

┌───────────────────────────────────┬──────────────────┬──────────────────────┐
│ 케이스                            │ 전               │ 후                   │
├───────────────────────────────────┼──────────────────┼──────────────────────┤
│ 컬럼목록 없음 · 개수 일치         │ HOLD             │ 정상 파생            │
│ 컬럼목록 없음 · UNION · 개수 일치 │ HOLD             │ 정상 파생            │
│ 컬럼목록 없음 · 개수 불일치       │ HOLD             │ HOLD (사유 구체화)   │
│ 컬럼목록 없음 · SELECT *          │ HOLD             │ HOLD (DB 조회 안 함) │
│ 컬럼목록 없음 · 목적지 접속 없음  │ HOLD             │ HOLD (동일)          │
│ 컬럼목록 없음 · 메타 조회 실패    │ HOLD             │ HOLD                 │
│ 컬럼목록 없음 · 중복 컬럼명       │ HOLD             │ HOLD                 │
│ 컬럼목록 없음 · 목적 테이블 불일치│ HOLD             │ HOLD                 │
│ 컬럼목록 명시(단순/UNION/CTE)     │ 정상             │ 정상 (완전 동일)     │
│ MERGE / bare SELECT               │ HOLD(NOT_INSERT) │ 동일                 │
└───────────────────────────────────┴──────────────────┴──────────────────────┘

HOLD 사유 문구도 사실과 맞췄다(전: 원인 뭉뚱그림 → 후: 구체 사유 부착).
  예) "... [SELECT projection 수(2)와 목적지 컬럼 수(4개)가 달라 위치 기준으로 맞출 수
       없습니다]"

4. 실 DB 값 검증 — 오매핑 없음 확인 (필수 요구사항)
═══════════════════════════════════════════════════════════════════════════════
스크립트: scripts/dev_e2e/no_insert_column_list_positional_live_verify.py
접속    : PostgreSQL_Inter_tobe (192.168.0.150 / tobe)   ※ 비밀번호 미출력·미기록
픽스처  : 전용 이름(mv_f26_*) 생성 후 종료 시 DROP — 기존 데이터 미접촉, 잔존 0건 확인

함정 설계: 원본과 목적지가 **같은 컬럼명을 다른 정의 순서로** 갖게 만들고, 이관 INSERT 를
DB 가 직접 실행하게 해 정답(ground truth)을 DB 자신의 위치 기준 의미로 만들었다.

  [0] DB 가 실제 적재한 목적지 내용(정답) — (a, b)
        ('B1', 'A1') / ('B2', 'A2') / ('B3', 'A3')
        → src.b 가 tgt.a 로, src.a 가 tgt.b 로 들어갔다(위치 기준 의미 확인)

  [1] 수정 전(목적지 접속 미전달)
        HOLD — 이 SQL 형태는 원본 이관 SELECT 재구성에 실패해 ...

  [2] 위치 기준 컬럼 확정(목적지 ordinal 조회)
        확정 컬럼   : ['A', 'B']
        파서 추론값 : ['B', 'A']   ← 이 값을 썼다면 순서가 뒤집힌다

  [3] 수정 후 파생 SQL
        원본  : SELECT * FROM ( SELECT b AS A, a AS B FROM mv_f26_src ) mv_reimport_src
        목적지: SELECT A, B FROM mv_f26_tgt

  [4] 값 검증 — 파생 원본 SQL 결과 vs 목적지 실제 내용
        row1  원본('B1','A1')  목적지('B1','A1')   일치
        row2  원본('B2','A2')  목적지('B2','A2')   일치
        row3  원본('B3','A3')  목적지('B3','A3')   일치
        → 전 행 일치: 올바른 컬럼끼리 비교됐다(오매핑 없음)

  [5] 대조군 — parse_result.insert_cols(파서 추론값)을 그대로 썼을 때
        row1  원본('A1','B1')  목적지('B1','A1')   불일치
        row2  원본('A2','B2')  목적지('B2','A2')   불일치
        row3  원본('A3','B3')  목적지('B3','A3')   불일치
        → 전 행 불일치: 파서 추론값을 썼다면 오매핑이 **실제로** 발생했다(설계 근거 확인)

  [6] 안전조건 미충족(목적지 4컬럼 vs SELECT 2개) — 실 DB
        위치 기준 확정: 실패 — SELECT projection 수(2)와 목적지 컬럼 수(4개)가 달라
                        위치 기준으로 맞출 수 없습니다
        파생 결과     : HOLD
        → 애매한 케이스는 여전히 HOLD(안전측 유지)

  판정: PASS — 위치 기준 매핑 정상, 오매핑 없음

※ [5] 대조군이 이 작업의 가장 중요한 산출물이다. 지침이 제안한 방식(insert_cols 를 위치
   기준으로 빌려 쓰기)을 그대로 구현했다면 이 픽스처에서 전 행이 오매핑됐을 것이다.

7. 남은 위험 / 미해결 (정직 보고)
═══════════════════════════════════════════════════════════════════════════════
 · 목적지 컬럼 메타 SQL 이 스키마 필터 없이 table_name 으로만 매칭하는 기존 갭은 이번에
   고치지 않았다(완료 모듈 임의 수정 회피). 중복 컬럼명 게이트(2-(5))로 방어하지만,
   "동명 테이블이 서로 완전히 다른 컬럼명을 갖고, 합산 개수가 우연히 projection 수와
   일치" 하는 극단 사례는 이론상 통과할 수 있다. 근본 해소는 메타 조회의 스키마 한정이
   필요하며 별도 작업 대상이다.
 · 통계검증(stats) 경로는 이번 확장을 적용하지 않았다(재이관 wrapping 한정). 같은 형태의
   통계검증 wrapping 은 종전 동작 유지 — 범위를 의도적으로 좁혔다.
 · 위치 기준 매핑이 발동하면 목적지 컬럼 메타 조회 1회가 추가된다. 다만 이 경로는 수정
   전 즉시 HOLD 로 죽던 경로이므로 기존 정상 경로의 비용 증가는 없다.
