1. 무엇이 문제였나
================================================================================
5단계 '통계검증 실행 결과' 표 위에는 항목 필터 탭(전체 / COUNT / AMT / QTY)이 있다.
지표 탭을 누르면 그 지표가 실제로 차이난 그룹만 남는다(재실행 없이 클라이언트 렌더).

그런데 그 상태에서 **페이지 번호를 누르면 필터가 조용히 풀렸다.**
탭 버튼은 계속 활성(주황)으로 남아 있어서, 사용자는 여전히 그 지표로 걸러진 화면을
보고 있다고 믿는다. 실제로는 '전체' 결과의 그 페이지가 통째로 덮어써진 상태다.

원인은 한 줄이다.

    function _execGoResultPage(p) {
      if (window._execSrv) { _execSrvGo(p); return; }      // ← 필터 상태를 보지 않는다
      ...

_execSrvGo() 는 항목 필터(col filter)를 서버에 넘기지 않는다. 그래서 서버는 '전체'
기준 페이지를 돌려주고, tbody 가 그것으로 교체되면서 필터가 사라진다.

표시 건수 드롭다운(20/50/100)도 같은 계열의 누락이었다.

    function _execSetPageSize(v) {
      if (window._execSrv) { window._execSrv.page_size = ...; _execSrvGo(1); return; }
      window._execResultPageSize = ...                     // ← 서버 모드면 여기에 못 온다

지표 탭은 클라이언트 렌더라 window._execResultPageSize 를 쓰는데, 서버 페이지 모드면
첫 줄에서 return 해버려 그 값이 영원히 갱신되지 않았다. 즉 지표 탭에서는 표시 건수를
바꿔도 아무 일도 일어나지 않았다.

두 결함 모두, 오늘 REIMPORT-DRILLDOWN-TAB-SCOPE-CACHE-AND-COLUMN-SPLIT-FIX(66e4a30)가
_execSetColFilter() 에 넣은 조건

    if (window._execSrv && !window._execColFilter) { _execSrvGo(...); return; }

과 같은 판단이 필요한 자리인데, 그 조건이 이 두 함수에는 안 들어가서 생긴 누락이다.

================================================================================
2. 무엇을 고쳤나
================================================================================
새 조건 어휘를 만들지 않고, _execSetColFilter 가 이미 쓰던 조건식을 **글자 그대로**
두 함수에 재사용했다(코드베이스 일관성 요구사항).

    function _execGoResultPage(p) {
      if (window._execSrv && !window._execColFilter) { _execSrvGo(p); return; }
      window._execResultPage = p; _execRenderResultPage();
    }
    function _execSetPageSize(v) {
      if (window._execSrv && !window._execColFilter) {
        window._execSrv.page_size = parseInt(v, 10) || 50; _execSrvGo(1); return;
      }
      window._execResultPageSize = parseInt(v, 10) || 20; window._execResultPage = 1;
      _execRenderResultPage();
    }

동작 요약:
  · 항목 필터 ON  → 서버로 안 보낸다. 클라이언트 렌더로 페이지 이동/표시 건수 처리.
  · 항목 필터 OFF('전체' 탭) → 기존 서버 페이지 경로 그대로. 아무것도 바뀌지 않는다.

'전체' 탭의 서버 페이지 유지·복원(오늘 고친 그 기능)은 조건상 도달 경로가 동일하므로
불변이며, 실측으로도 확인했다(아래 4-C).

── B. 표시 건수 드롭다운 ────────────────────────────────────────────────────

BEFORE: COUNT 탭에서 _execSetPageSize('2') 호출 →
        srv.page_size 만 2 로 바뀌고 _execResultPageSize 는 50 그대로(client_unchanged=True)
        → 지표 탭 표시량 변화 없음

AFTER : 화면 드롭다운(select#execPageSize)을 실제 선택 조작
        20건 선택 → _execResultPageSize=20 (srv 50 불변)
        100건 선택 → _execResultPageSize=100 (srv 50 불변)
        50건 선택 → _execResultPageSize=50  (srv 50 불변)
        표시건수 2 적용 시 3페이지로 실제 분할(위 A 참조)

  ※ 정직한 한계: COUNT 탭의 그룹이 5개뿐이라 20/50/100 사이에서는 **화면에 보이는 행 수가
    달라질 수 없다**(셋 다 5행 전부 표시). 그래서 "값이 실제로 반영되는가"는
    _execResultPageSize 갱신 + 페이징 재계산으로 확인했고, 눈에 보이는 분할 변화는
    표시건수 2건 케이스로 확인했다. 드롭다운 3개 값 모두 client 값이 정확히 따라간다.
  ※ 서버 값(srv.page_size)은 지표 탭 조작으로 바뀌지 않는다 — '전체' 탭 복귀 시
    서버 페이지 기준이 흔들리지 않게 하기 위함이며 실측으로 불변 확인.
