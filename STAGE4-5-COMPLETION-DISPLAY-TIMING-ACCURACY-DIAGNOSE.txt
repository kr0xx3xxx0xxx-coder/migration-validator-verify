           4단계 처리시간의 측정 구간은 "세트 실행 루프 종료"에서 끝나는데, 5단계 화면을
           실제로 채우는 재이관 대상 레코드 수집은 바로 그 지점 '이후에' 비동기로 시작한다.
           측정 구간 안에서 끝나는 것은 그룹별 불일치 요약(집계값)뿐이고, 재이관 목록은
           측정 구간 밖에서 40초를 더 쓴다.

1-2. 선택 조건 — 사용자 사례와 동일하게 맞췄다
     GROUP BY  REGION_CD + STATUS_CD  (2축 → 다중 세트 경로 _runExecutePlanSets 분기)
     SUM       AMT, QTY
     실행 경로 단계별 [▶ 통계검증 실행] (원클릭 아님)

     이 조건이 사용자 사례와 같다는 근거:
       · 실측 결과 전체 그룹 31 · 일치 20 · **불일치 11그룹** — 지침이 말한 "11개 불일치 그룹"과 일치.
         (REGION_CD 축은 누락 g 가 전부 MOD(g,20)=0 → R01 한 그룹에 몰려 1그룹,
          STATUS_CD 축은 10그룹에 균등 분산 → 1 + 10 = 11)
       · 4단계 처리시간 24.12초 — 지침이 말한 25.94초와 같은 규모(§9 편차 설명).

1-3. 측정 방법
     실 브라우저(Playwright)로 1~5단계를 실제 클릭해 통과시키고, [▶ 통계검증 실행] 클릭
     '직전'에 페이지 안에 100ms 주기 계측판을 심어 각 DOM/전역상태가 **처음 채워진 시각**을
     1회씩만 기록했다. 스크립트가 임의로 시간을 재지 않고, 화면이 실제로 바뀌는 순간만 남긴다.

     드라이버 : scripts/dev_e2e/stage45_completion_display_timing_measure.py (신규, dev 전용)
                1~3단계 클릭 절차는 기존 scatter_mismatch_perf_measure 모듈을 그대로 import 재사용.
     산출     : scripts/dev_e2e/_stage45_completion_display_timing_run1.json          (1회차)
                scripts/dev_e2e/_stage45_completion_display_timing_run2_hintoff.json  (2회차 대조)
                각각 마크·2초 샘플·네트워크 타임라인 포함.
     회차     : 같은 조건으로 2회 측정했다(§2-4). 2회차는 §9-1 의 교란요인을 차단한 대조군이다.

     화면이 4단계에 머물러 있어도 5단계 pane 의 DOM 은 그대로 렌더된다(가림 클래스만 적용)
     → DOM 기준 시각 = 사용자가 5단계로 이동했을 때 보게 될 완료 시각과 같다.

     본 작업은 그 코드를 수정하지도 되돌리지도 않았고, 대신 **2회차를
     MV_ORACLE_PARALLEL_HINT=off 로 돌려 그 영향을 차단한 대조 측정**을 추가했다(§2-4).
     · 실측된 힌트의 영향 : COUNT 는 17.41초(ON) ↔ 50.58초(OFF) 로 크게 달랐다.
       반면 통계검증 세트 실행은 24.12초(ON) ↔ 19.20초(OFF) 로 **OFF 쪽이 더 빨랐다** —
       이 경로에서는 힌트 효과보다 버퍼 캐시 온도·동시 부하 변동이 우세하다는 뜻이다.
       (힌트의 효용 판정은 이 작업의 범위가 아니며, 여기서는 교란 가능성만 다룬다.)
     · 결론에 대한 영향 : 없다. 간극은 "prepare 가 벽시계 종료 '이후에' 발사된다"는 코드
       구조에서 나오며, DB 가 빨라지든 느려지든 그 순서는 바뀌지 않는다. 실제로 힌트 ON/OFF
       두 회차 모두 간극이 나타났고(39.90초 / 50.79초), OFF 쪽이 오히려 더 컸다.

9-2. 2회 측정이다(1회 아님)
     §2-4 의 두 회차는 서로 다른 설정(병렬힌트 ON/OFF)·다른 캐시 상태에서 수행됐고, 결과값은
     동일하고 타이밍 구조도 동일했다. 또한 각 회차마다 계측판 수치가 서버 자체 계측
     ('불일치 추출 완료' 37.95초 / 46.58초)과 오차 0.7초 이내로 일치했다(§2-3).
     따라서 "표시 밖에 40~51초 규모의 후처리가 있다"는 결론은 안전하다.
     다만 절대시간(19~24초, 40~51초)은 실행마다 흔들리므로 단일 수치로 인용하지 말 것.

9-3. 측정하지 않은 것
     · 사용자 사례(25.94초) 그 실행 자체의 후처리 시간 — §4 의 69초는 비례 추정치다.
     · 원클릭(run-standard) 경로의 실측 — 코드 대칭(§3-5)으로만 판단했다.
     · GROUP BY 3축·PAIR 세트 포함 실행.

9-4. 안전
