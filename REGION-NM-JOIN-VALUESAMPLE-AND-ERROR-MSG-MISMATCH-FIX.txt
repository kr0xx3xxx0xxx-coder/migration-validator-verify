■ 2. 작업범위 B — JOIN 파생 컬럼 값샘플 배선공백 수정
  게이트 존재 이유 확인(커밋이력/주석, 짐작 아님):
    services/column_profile_service.py 주석(PROFILE-COLLECTION-CTE-JOIN-COLUMN-REFERENCE-FIX) —
    "base 테이블에 없는 컬럼을 섞어 조회하면 값 샘플 SELECT 한 건이 통째로 실패해(ORA-00904)
    정상 컬럼 샘플까지 같이 잃는다"는 과거 결함의 재발 방지책 → 의도된 안전장치.
    다만 같은 파일의 collect_column_profiles()(distinct/null 집계용)는 이미 JOIN 을 CTE
    (_build_from_join_clause + WITH SRC AS)로 안전하게 감싸 처리하고 있었다 — 즉 "JOIN 자체가
    기술적으로 불가능"이 아니라 "값샘플 조회 함수(_collect_sample_values_bounded)만 그 안전
    빌더를 재사용하지 않고 단순 SELECT col FROM from_table 로 짜여 있어 JOIN 컬럼에 못 쓰던"
    단순 미구현으로 판정. → 새 샘플링 로직을 발명하지 않고 기존 _build_from_join_clause(profile
    CTE 가 이미 쓰는 JOIN-safe FROM 빌더)를 값샘플 조회에도 재사용해 해소.

  수정 파일:
    - services/column_profile_service.py
        _collect_sample_values_bounded(): from_clause/join_clauses/where_clause 선택 인자 추가.
          has_join 이고 from_clause 를 받으면 _build_from_join_clause 로 FROM+JOIN 을 재구성해
          조회(위치기반 매칭, AS alias 불필요 — 기존 단일테이블 경로와 동일 패턴). from_clause
          미전달(레거시 호출부)이면 기존과 동일하게 캐시만(무회귀).
        collect_column_profiles() 내부 호출 지점도 이미 갖고 있던 from_clause/join_clauses/
          where_clause 를 그대로 전달.
        resolve_candidate_sample_values(): 동일하게 from_clause/join_clauses/where_clause
          선택 인자 추가, has_join 이어도 from_clause 있으면 조회 진행하도록 게이트 완화.
    - services/candidate_postcount_finalize.py
        finalize_recommendation_postcount() 의 resolve_candidate_sample_values 호출에
        from_clause/join_clauses/where_clause(이미 함수 인자로 보유) 전달 추가.

  실측 중 추가 발견(부수 결함, §B 완결에 필요해 함께 수정) — stale 배지 재동기화 누락:
    admin_audit_verdict 는 postcount 재확정으로 정상 갱신되지만, "⚠ 관리컬럼 미확인" 배지의
    표시 근거(ambiguous_audit_evidence)는 1단계 analyze 시점에 candidate_display_enricher.
    attach_ambiguous_audit_evidence() 가 in-place 로 부착한 값이 그대로 남아, verdict 가
    AMBIGUOUS→CONFIRMED 로 바뀌어도 postcount 이후 재호출되지 않아 배지가 stale 하게 남았다
    (실측으로 확정 — id() 비교·before/after 후보 dict 직접 비교). 이 상태로는 sample_values
    수정만으로 REGION_NM 배지가 실제로 사라지지 않아 §B 목적을 완결하지 못하므로 함께 수정:
      - candidate_display_enricher.attach_ambiguous_audit_evidence(): verdict 가 더 이상
        AMBIGUOUS 가 아니면 그 자리에서 evidence 를 pop 해 idempotent 하게 함.
      - candidate_postcount_finalize.finalize_recommendation_postcount(): 반환 직전
        attach_ambiguous_audit_evidence(gb+sm) 재호출로 최종 verdict 기준 배지 근거 동기화.
