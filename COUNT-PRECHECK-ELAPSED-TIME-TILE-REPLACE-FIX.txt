작업명 : COUNT-PRECHECK-ELAPSED-TIME-TILE-REPLACE-FIX
작성일 : 2026-08-04
대상   : 개별검증 2단계(COUNT 사전검증) 상단 타일 — '검증항목' → 'COUNT 소요' 교체
수정   : ui/tabler_renderer.py 1개 (제품 코드)


────────────────────────────────────────────────────────────────────────────
1. 요청 요약과 배경
────────────────────────────────────────────────────────────────────────────
2단계 타일의 3번째 칸 '검증항목'은 값이 항상 'COUNT' 로 고정이라 타일 한 칸을 차지하면서
정보량이 0이었다. 그 자리에 서버가 이미 /count 응답에 담아 보내는 원본/목적지 개별 COUNT
소요시간(source_count_elapsed_ms / target_count_elapsed_ms)을 표시한다.

지금 특히 필요한 이유(실측으로 재확인):
  오늘 완료된 COUNT-PAIR-PARALLEL-EXECUTION-FIX 이후 원본/목적지 COUNT 는 병렬로 실행된다.
  이번 실측에서 원본 21,876.8ms + 목적 20,329.0ms = 42,205.8ms 인데 총시간(processing_ms)은
  21,888.7ms 였다. 즉 총시간에서 개별 소요를 역산하는 것이 원리적으로 불가능하다.
  개별값은 응답에서 직접 읽어 표시하는 방법밖에 없다.


────────────────────────────────────────────────────────────────────────────
2. 구현 — 공유 정의 오염 없이 '타일 표시 계층에서만' 교체 (진단서 R1 대응)
────────────────────────────────────────────────────────────────────────────
공유 컬럼정의 `_mvCountColumns()`(ui/grid_helpers.py, 567행)는 한 글자도 건드리지 않았다.
교체는 전부 ui/tabler_renderer.py 의 2단계 타일 계층에서만 이뤄진다.

  · `_MV_COUNT_TILE_ORDER`   : 'check' → 'elapsed' (순서 규약)
  · `_MV_COUNT_TILE_DROP`    : 신설 — 타일에서만 'check'(검증항목) 컬럼을 숨긴다
  · `_MV_COUNT_TILE_VIRTUAL` : 신설 — 타일에만 있는 가상 컬럼 'elapsed'(COUNT 소요) 주입
  · `_mvCountTileCols()`     : 위 두 규약을 반영해 컬럼 배열을 재구성(원본 배열 비파괴)
  · `_mvCountTileElapsed(c)` : 신설 — 값/툴팁 생성. 응답 필드를 그대로 읽는다(새 계측 없음)
  · `_mvCountTilesHtml()`    : 'elapsed' 필드만 별도 분기로 다줄 렌더
  · `_mvCountPreknownRow()`  : 실행 전 즉시표시에서 `check:'COUNT'` 제거 (요구사항 3)

값/표시 규격은 전부 기존 것을 재사용했다(새 포맷 발명 없음).
  · 다줄 값  : 3단계 GROUP BY 타일의 kind:'multi' 규격 그대로 — 배열을 `<br>` 로 이어
               `<span class="mv-qr-tile-val is-mono">` 안에 표시
  · ms→초    : 기존 `_mvFmtStageDur`(처리시간 타일이 쓰는 것) 그대로. 소수 2자리,
               10ms 미만은 '0.01초 미만'
  · 값 부재  : 기존 '—'(is-empty) 경로 재사용. 새 분기를 만들지 않았다(진단서 R4)

툴팁(요구사항 1 + 차선안 절충):
  원본 {source}ms / 목적지 {target}ms · 총 {processing}ms(병렬 실행, 차액은 서버 파싱·COUNT
  SQL 생성 오버헤드) · COUNT SQL 생성방식: {count_generation_method}

3. 실측 검증 — 실제 운영 서버 + 실 DB 브라우저 실측

    생성 오버헤드) · COUNT SQL 생성방식: PARSED_MODEL_COUNT_SQL"
   → 개별시간 + 총시간 + 오버헤드 설명 + 차선안(생성방식) 전부 정확히 표시됨.

     OS 레이어에 그려져 Playwright 스크린샷에 찍히지 않으므로, 위 전문은 DOM 속성 직접
     판독으로 확인했다(JSON 증적 D_툴팁_전문 필드). before 의 같은 자리는 툴팁이 '' 였다.

5. 비판적 검토 (위험과 대응)
────────────────────────────────────────────────────────────────────────────
· 공유 정의 오염(R1) — 가장 큰 위험이었다. DROP/VIRTUAL 두 규약으로 타일 계층에만
  국한했고, grid_helpers.py 는 diff 0줄이다. 재발 방지 가드 테스트도 추가했다.
· heuristic 증가 — 없음. 새 판정·새 임계값·새 계측이 없고, 서버가 이미 보내는 필드를
  포맷만 바꿔 표시한다.
· explainability — 오히려 개선. 병렬 실행 때문에 총시간에서 역산 불가였던 개별 소요를
  화면에 드러내고, 근거(개별 ms·총 ms·차액의 정체)를 툴팁에 남긴다.
· 남은 사실(이번 범위 밖, 참고) — 2단계 커맨드바 버튼을 결과 렌더 후 한 번 더 누르면
  `_mvShowCountSqlGate` → `_mvRenderCountHeaderOnly(true)` 가 #countResult 를 placeholder
  로 되돌려 방금 채운 타일 값이 전부 '—' 로 지워진다(before/after 동일하게 재현). 이번
  변경과 무관한 기존 동작이며, 이 실측에서는 클릭을 정확히 2회로 제한해 회피했다.
