     Basic realm="nxDTV", charset="UTF-8"
   → 브라우저 팝업이 표시할 realm 값이 코드값과 정확히 일치함을
     프로토콜 레벨에서 증명(이 값이 팝업 내용의 유일한 출처).

2) 실제 브라우저(Edge, InPrivate) 팝업 실측 — 미인증 상태로
   http://127.0.0.1:8000/ 접속 시 네이티브 Basic Auth 로그인
   팝업이 실제로 뜸을 스크린샷으로 확인
     (01_auth_popup_realm.png, 크롭 01b_realm_text_crop.png).
   ⚠ 발견 사항(이번 변경과 무관한 브라우저 사양): 현재 설치된
   Edge/Chromium 버전은 팝업 UI 안에 realm 문자열 자체를 더 이상
   렌더링하지 않는다(피싱 방지 목적으로 최신 Chromium이 origin만
   표시하도록 변경됨 — "이 사이트에 액세스하려면 로그인 하세요 /
   http://127.0.0.1:8000에 필요한 권한 부여"만 표시, realm 텍스트
   없음). 이는 realm 값과 무관하게 모든 realm에서 동일하게
   나타나는 브라우저 동작이라 변경 전/후 화면상 차이가 없다 —
   따라서 "화면에 nxDTV 텍스트가 보이는지"는 육안으로는 확인
   불가능했고, 위 1)의 프로토콜 실측이 유일하고 확정적인 증거다.

3) 인증 성공/실패 동작(이번 변경과 무관, 정상 작동 확인) —
   임시 격리 계정 파일(MV_AUTH_USERS_FILE, 운영 auth_user DB
   미변경)로 발급한 테스트 계정에 대해 직접 HTTP 요청으로 실측:
     - 올바른 자격증명            → HTTP 200
     - 잘못된 비밀번호            → HTTP 401
   Basic Auth는 헤더 기반 무상태 인증이라 브라우저가 보내는 것과
   동일한 메커니즘 — 이 실측이 곧 브라우저 로그인 성공/실패 동작의
   증명이다.

재확인). 화면 자동화(SendKeys) 중 그 다른 세션의 대화창 입력란에
테스트 문자열이 실수로 입력된 적이 있으나 전송(Enter)되지는 않았다
— 추가 자동화는 즉시 중단했다. 사용자에게 해당 창을 직접 확인해
달라고 안내가 필요할 수 있음.
