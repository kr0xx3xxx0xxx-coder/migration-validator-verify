1. 문제 정의
────────────────────────────────────────────────────────────────────────
routes/count_gate_route.py:234 는 선행 작업(COUNT-GATE-ROUTE-DIALECT-AND-ALIAS-FIX)에서
이미 미지원 방언(mysql/mssql)을 스트리밍 시작 전에 차단하도록 수정돼 있었다.

    if db_type not in EXPORT_SUPPORTED_DB_TYPES:      # ("postgresql", "oracle")
        return {"ok": False, "reason_code": "EXPORT_DIALECT_UNSUPPORTED", "error": ...}

그런데 UI 쪽 mvCountGateSideExport(ui/tabler_renderer.py) 는 응답을 무조건

    .then(function(resp){ return resp.blob(); })

로 받아 one_side_<side>_records.csv 로 저장했다. 그 결과:

  · 서버가 명시적으로 "차단했다"고 알려준 JSON 이 CSV 확장자를 달고 사용자 PC 에 저장된다.
  · 화면에는 아무 오류도 뜨지 않는다 — 사용자는 정상 CSV 를 받았다고 오인한다.
  · 즉 서버 사전게이트가 UI 에서 소비되지 않는 "반쪽 배선" 상태였다.

같은 경로는 미지원 방언 외에도 입력 누락("side/SQL/접속 필요")과 내부 예외("CSV 생성 중 오류")를
동일하게 JSON 으로 반환하므로, 세 종류의 서버 차단이 모두 조용히 파일로 저장되고 있었다.

2. 수정 내용 (ui/tabler_renderer.py — mvCountGateSideExport)
────────────────────────────────────────────────────────────────────────
응답 Content-Type 을 먼저 확인하는 분기를 넣었다.

  (1) Content-Type 에 json 이 포함 → CSV 가 아니라 서버 차단/오류다.
      resp.json() 으로 파싱해 reason_code / error 를 화면에 표시하고, 파일은 저장하지 않는다.
      · 표시 문구: "전체 CSV 생성 실패 [<reason_code>] — <error>"
      · JSON 파싱마저 실패하면 HTTP 상태코드를 붙여 표시(무한 침묵 방지).
      · FastAPI 는 dict 반환과 422 검증오류를 모두 application/json 으로 내려주므로 한 분기로 덮인다.
  (2) JSON 이 아니면서 !resp.ok → "서버 오류(HTTP nnn)" 로 표시.
  (3) 그 외(정상 CSV 스트림) → 기존과 동일하게 blob 다운로드.
      부가로 성공 안내 한 줄과 URL.revokeObjectURL(30초 뒤) 만 추가했다.
  (4) fetch 자체 실패(네트워크) → catch 에서 통신 오류로 표시.

오류 표시는 새 UI 컴포넌트를 만들지 않고, 같은 영역에서 이미 쓰이던 패턴을 그대로 재사용했다:
#mvRangeDiagOut 컨테이너 + 붉은 글씨 한 줄(color:#b4472a; font-size:.78rem) —
mvCountGateSidePreview / mvRunRangeDiagnosis 와 완전히 동일한 방식이다.
(#mvRangeDiagOut 이 없으면 기존 두 함수와 똑같이 countGateBox 아래에 생성하고,
 countGateBox 조차 없는 예외 상황에서만 alert 로 폴백한다.)

범위 준수
  · 지침 범위 밖인 range-diagnosis / one-side-preview 버튼은 손대지 않았다.
  · 선택 사항이던 "미지원 방언일 때 버튼 사전 비활성화"는 의도적으로 넣지 않았다.
    EXPORT_SUPPORTED_DB_TYPES 를 JS 쪽에 복제하는 순간 서버-클라이언트 두 곳에 지원 방언
    목록이 생겨 CLAUDE.md 가 금지하는 heuristic 하드코딩 증가/이중 진실 문제가 된다.
    서버 응답이 단일 진실로 남는 "응답 기반 사후 처리"만으로 지침의 필수 범위를 충족한다.
    (지침에도 이 방식만으로 완료 인정으로 명시돼 있다.)

8. 남은 사항 / 알려진 한계
────────────────────────────────────────────────────────────────────────

  같은 결함이 없다(확인만 하고 미수정).
