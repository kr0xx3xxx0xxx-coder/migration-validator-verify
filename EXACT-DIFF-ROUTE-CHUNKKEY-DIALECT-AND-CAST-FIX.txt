■ [지시1] L139 dialect 배선
  _resolve_key → resolve_confirmed_chunk_key 에 실제 접속 방언 전달.
  접속 db_type 을 공통 헬퍼 _to_sqlglot_dialect 로 도출(신규 매핑 없음).
  혼합 방언(원본≠목적)은 기존 동작(postgres) 유지.

  근본원인 실측:
    dialect=postgres -> SELECT 1 FROM ... WHERE SEQ_NO IS NULL LIMIT 1     ← 오라클 ORA-00933
    dialect=oracle   -> SELECT 1 FROM ... WHERE SEQ_NO IS NULL FETCH FIRST 1 ROWS ONLY
  실패 연쇄: _has_null=None → confirm_chunk_key=None → _resolve_key=("","") → 사유 없는 조용한 HOLD

■ [지시2] L177/178 캐스트 방언 분기 + 별칭 개명
  _scope_eq_expr 신설 — 지원 4개 방언 모두 처리:
    oracle     TO_CHAR((col)) = '값'          (exact_diff/dialects/oracle.py _txt 와 동일 규칙)
    postgres   (col)::text = '값'             (기존 표현 그대로 유지)
    mysql      CAST((col) AS CHAR) = '값'
    mssql      CAST((col) AS NVARCHAR(4000)) = '값'
  별칭 __sf → mv_scope_src / mv_scope_tgt (문자 시작, ORA-00911 회피)

     → 4개 모두 TCP 타임아웃

           SQL 렌더/인자 배선은 운영과 동일 경로 → 측정값은 DB 유무와 무관하게 결정적.
     Before=baseline worktree(f54c957), After=현재 트리, 동일 harness.

  오라클 / SCOPE=ON (전체>5만 & scope<=5만 — UI tabler_renderer.py:16549 조건)
    Before  dialect 전달 False(→기본 postgres)
            SELECT * FROM (...) __sf WHERE (DEPT_CD)::text = 'A1''B'
            ❌ `::` 캐스트(DPY-4010) + 밑줄 선두 별칭(ORA-00911) + 조용한 HOLD
    After   dialect 전달 True / 값=oracle
            SELECT * FROM (...) mv_scope_src WHERE TO_CHAR((DEPT_CD)) = 'A1''B'
            ✅ 실행 불가 패턴 없음 · chunk key 정상 확정(SEQ_NO)
            따옴표 이스케이프(A1'B → 'A1''B') 유지 확인

  오라클 / SCOPE=OFF
    Before  SQL 자체는 정상이나 dialect 미전달은 동일 → chunk key 확정 실패
    After   oracle 위임 → 정상. (1)번 결함은 SCOPE 여부와 무관하게 오라클 전 경로 해당

  실제 ASGI 앱(web_server:app) POST /exact-diff/run 경유로도 동일 확인
    HTTP 200 · chunk dialect=oracle · src_sql 에 TO_CHAR 렌더
