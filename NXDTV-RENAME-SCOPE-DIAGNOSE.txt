1단계 — 화면 표시명 변경 (ui/tabler_renderer.py 2줄 + 로고 글자 1글자)
  · 위험도: 낮음. 사용자가 즉시 체감하는 변경이면서 파급 범위가 가장 좁다.

2단계 — 폴더명 변경 (X:\Projects\Migration_Validator → nxDTV 등)
  · 위험도: 코드 자체는 무위험(하드코딩 경로 없음, db_paths.py 동적 계산).
    유일한 진짜 위험은 Claude Code auto-memory 프로젝트 키 단절(1절 참고).

  · 권고: 1단계 다음으로, memory 이관 계획이 선 확정된 상태에서 진행.

3단계 — DB 파일명 변경 (db/migration_validator.db → nxdtv.db 등, 선택 사항)
  · 위험도: 중간. 49개 파일 리터럴 동시 수정 필요, 그중 다수가 운영 DB
    오염 방지 가드/테스트라 회귀 테스트 전량 재확인 필수.
  · 화면 비노출 항목이라 효용 대비 리스크가 높다 — 보류를 권장하며,
    사용자가 굳이 원할 경우에만 별도 승인 후 착수.

4단계(보류 강력 권장) — "mv" 접두사 전면 리네이밍
  (CSS class, JS 함수명, 환경변수 MV_DATA_DIR 등)
  · 위험도: 가장 높음. 규모가 수천 건 단위이고, ui/*.py 다수가 완료 모듈이라
    "완료 모듈 임의 리팩토링 금지" 규칙에 정면으로 걸린다. 화면에 노출되지
    않는 순수 내부 코드 관례라 사용자 가치 대비 리스크가 압도적으로 크다.
  · 권고: 이번 단계별 착수 범위에서 제외하고, 필요성이 명확해질 때까지 보류.
