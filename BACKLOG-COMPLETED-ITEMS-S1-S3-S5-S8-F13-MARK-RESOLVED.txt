6. push (verify 저장소 운영 규칙 준수)
================================================================================
BACKLOG.md 의 'verify 저장소 운영 규칙' 섹션대로, 공유 작업트리
(E:\verify_reports)에 직접 커밋하지 않고 origin/main 기반 임시 worktree 에서
자기 파일만 커밋·push 했다.

  git -C E:/verify_reports fetch origin
  git -C E:/verify_reports worktree add --detach <scratchpad>/vw_backlog origin/main
  # 임시 worktree 에서 BACKLOG.md 만 수정 → add → commit → push origin HEAD:main
  git -C E:/verify_reports worktree remove <scratchpad>/vw_backlog

착수 시점 공유 트리 상태 관찰(참고):
  E:\verify_reports\BACKLOG.md 에 미커밋 변경이 남아 있었으나, 내용 대조 결과
  origin/main 대비 '신규 서술이 추가된' 것이 아니라 'verify 저장소 운영 규칙' 섹션
  (origin/main 에 이미 push 된 30abd35)이 빠진 옛 사본이었다. 즉 공유 트리 사본에
  고유 내용은 0줄이며, 이번 작업은 origin/main(= 최신 정본) 위에서 수행했다.
  → 운영 규칙이 지적한 'ahead 오인' 사고 패턴을 그대로 회피했다.
