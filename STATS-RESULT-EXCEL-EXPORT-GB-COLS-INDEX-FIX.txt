1. 요청 요약

routes/stats_result_route.py 의 레코드 Excel(시트 '재이관 대상 레코드') 컬럼
결정식이 gb_cols(문자열 리스트)를 튜플로 착각해 [p[0] for p in basis["gb_cols"]]
로 처리했다. "STATUS_CD"[0] = "S" 가 되어 sv.get("S") 는 항상 None 을 반환했고,
화면 '전체 상세 보기'에는 정상 표시되는 GROUP BY 컬럼값이 Excel 에서는 헤더가
첫 글자만 남고 값은 전부 빈칸으로 유실됐다. 이 인덱싱을 문자열 계약에 맞게
수정하고, before/after 실 다운로드 대조와 STREAM/CHUNK 회귀 없음을 실측 확인했다.

수정 범위를 좁힌 근거
  · 제거한 것은 '바깥쪽' p[0] 하나뿐이다. head["columns"] 가 (컬럼명, 표시명) 쌍이라
    안쪽 g[0] 로 컬럼명만 꺼내는 처리는 지시대로 그대로 두었다.
  · 다만 이 바깥쪽 p[0] 는 gb_cols 분기와 head["columns"] 분기 '양쪽에' 걸려 있었다.
    즉 head["columns"] 분기도 g[0] 로 이미 컬럼명(문자열)을 꺼낸 뒤 다시 p[0] 로 첫
    글자만 남기고 있었으므로 두 분기 모두 같은 결함이었다. p[0] 제거는 gb_cols 계약을
    바로잡으면서 head["columns"] 분기의 동일 결함도 함께 해소하며, 튜플 언패킹(g[0])
    자체는 건드리지 않는다. 별도 동작 변경이 아니라 같은 결함의 동일 원인 해소다.
  · row_compare_columns 가 있는 분기(STREAM/CHUNK)의 식은 한 글자도 바뀌지 않았다.

(D) CHUNK 실 DB 라이브 측정은 미획득 — 별건 원인 명시
    SKEW·COMBO 픽스처로 compare_strategy=PK_RANGE_CHUNK_COMPARE 를 실행하면
    chunk job 이 시작 직후 FAILED 로 끝나 run head 자체가 생성되지 않는다.
    job 오류 전문(실측):
      column _s.ID does not exist
      LINE 1: SELECT min(_s."ID"), max(_s."ID") FROM (SELECT (id) AS ID, ...
    원인: 파생 SQL 이 (id) AS ID 로 따옴표 없는 별칭을 만들어 PostgreSQL 이 id 로
    소문자 폴딩하는데, PK min/max 조회는 _s."ID" 로 따옴표를 붙여 조회한다.
    이번 Excel 수정과 무관한 CHUNK 경로 별건이며 지시 범위 밖이라 수정하지 않았다.
    (그래서 CHUNK 회귀는 위 (C) basis 계약 replay 로 확인했다.)
