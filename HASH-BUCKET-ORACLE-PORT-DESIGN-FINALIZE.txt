■ 1. 표현식 대응표 (완성본) — 선행 진단 9행 요약표 → 18행 전수표
  ┌────┬──────────────────────────────┬───────────────────────────────────────────────┐
  │ #  │ PG 표현식                    │ 오라클 대체식                                 │
  ├────┼──────────────────────────────┼───────────────────────────────────────────────┤
  │ E1 │ md5(x)                       │ LOWER(RAWTOHEX(STANDARD_HASH(x,'MD5')))       │
  │ E2 │ left(h,8)                    │ SUBSTR(h,1,8)                                 │
  │ E3 │ 'x' || <hex8>                │ 불필요(제거) — PG hex 리터럴 문법 전용        │
  │ E4 │ ::bit(32)                    │ TO_NUMBER(<hex8>,'XXXXXXXX')                  │
  │ E5 │ ::bigint                     │ 불필요 — TO_NUMBER 결과가 NUMBER              │
  │ E6 │ (expr) 괄호                  │ 동일                                          │
  │E7a │ (expr)::numeric              │ 불필요 — TM9 가 숫자 직접 수용                │
  │E7b │ trim_scale(...)              │ TO_CHAR(x,'TM9')                              │
  │E7c │ ...::text                    │ + 선행 0 복원 REGEXP_REPLACE 2중(exact_diff 규격)│
  │ E8 │ (expr)::text  [DATE_TIME]    │ TO_CHAR(CAST(x AS TIMESTAMP),'YYYY-MM-DD"T"HH24:MI:SS.FF6') │
  │ E9 │ (expr)::text  [TEXT]         │ TO_CHAR(x)                                    │
  │E10 │ CASE WHEN e IS NULL THEN…END │ 동일(문법 공통) — 단 오라클은 ''=NULL(§2.2)   │
  │E11a│ length(val)                  │ LENGTH(val)                                   │
  │E11b│ length(val)::text            │ TO_CHAR(LENGTH(val),'TM9')  ← 진단표 G 정정   │
  │E11c│ '<tag>:'||…||':'||val        │ 동일                                          │
  │E12 │ 구성요소 || 결합             │ 동일 (VARCHAR2 4000자 한계 주의)              │
  │E13 │ 키canon+compare canon ||     │ 동일                                          │
  │E14 │ 'hbw1' || <canon> (salt)     │ 동일 — 실측 h32 976348671 양측 일치           │
  │E15 │ <h32> & (n-1)                │ BITAND(<h32>, n-1)                            │
  │E16 │ _H32 재사용                  │ E1~E5 조합                                    │
  │E17 │ sum(<h32>)                   │ 동일 — 오버플로 없음                          │
  │E18 │ 별칭 __HB1/__KH/__RH         │ HB1/KH/RH 로 개명 필요(ORA-00911)             │
  └────┴──────────────────────────────┴───────────────────────────────────────────────┘
  pow2_floor(n) 은 순수 Python(SQL 미방출) — 방언 무관, Base 공통 유틸 유지.

■ 2. 어댑터 분리 설계안 (exact_diff _CANONICAL_ADAPTERS 선례 답습)

■ 3. same-DBMS 가드 설계 반영 — 3계층
  L1 (능력/계획) capabilities.hash_bucket_pair_status(src,tgt) 신규 = 단일 출처
                 조건: src==tgt AND 양쪽 hash_bucket==SUPPORTED
                 소비: multi_scope.py:195-198(후보 emit), drilldown_strategy(NEXT_HASH)
  L2 (실행 진입) adapters/multi_scope_adapter · individual_adapter — 계약 해석 지점
                 실패 시 HOLD_UNSUPPORTED_DB, DB 접근 이전 차단
  L3 (계약)      hash_contract.get_hash_contract_pair — 방언 불일치면 (None,사유)
                 → 빌더가 계약을 얻지 못해 혼합 SQL 생성이 물리적으로 불가능

  ★ 가드를 db_type 쌍이 살아있는 경계에 둬야 하는 결정적 이유(설계 핵심):
    routes/diagnosis_route.py:_routing_dialect(:81) 은 src≠tgt 이면 dialect 를 "postgres" 로
    접어버린다. 하류 multi_scope 는 sqlglot 렌더 방언 1개만 받으므로 혼합 페어를 구분할 수
    없다. dialect 값으로 계약을 고르면 "혼합 페어가 조용히 PG 계약으로 실행"되는 최악의
    시나리오가 된다.

  capabilities 개방 방식: _ORACLE 의 hash_bucket / canonical_hash_contract 를
    NOT_SUPPORTED → SUPPORTED 로 항목만 올리고, "오라클↔오라클만" 조건은 페어 함수에만 둔다.
    (MATRIX_ITEMS 는 단일 DBMS 능력 표기 계약이라 페어 개념이 없음 — capability(dbms_type)
     시그니처가 단일 인자)
  ROADMAP step4 문구 정정 필요: "DBMS 간 동일 canonical hash" → "same-DBMS 페어 한정"
    (현 문구는 cross-DBMS 동일성을 목표로 읽혀 설계와 모순)
  cross-DBMS(PG↔오라클) HASH_BUCKET 은 영구 차단 — 성능이 아니라 정합성 문제.

■ 4. __HB/__KH/__RH 별칭 처리 판단
  결론: 동반 처리한다. 단 이식 이전의 독립 선행 단계(step ①)로 분리 — 커밋 2개.
  근거: (a) 별칭을 두면 오라클 HASH_BUCKET 은 ORA-00911 로 100% 실행 불가 → 이식해도 산출물 0
        (b) 개명은 방언 무관 변경이라 계약 분리 이전에 PG 회귀만으로 단독 검증 가능
        (c) KEY_RANGE __BKT/__RNG → KR_BKT/KR_RNG 선례 존재
  개명 규칙: HB / KH / RH — 반드시 대문자.
    근거: 실행 core 가 groupby_cols 를 대문자 정규화(stats_execute_service.py:259,271).
          소문자로 개명하면 readback 이 깨진다(KR_BKT 가 대문자인 것과 동일 이유).
  함께 처리해야 하는 3가지(놓치면 회귀):
    1) tests/test_underscore_alias_oracle_regression_static.py:226 의 @unittest.expectedFailure
       는 개명 즉시 "unexpected success = 테스트 실패"가 된다. 같은 커밋에서 마커 제거 +
       KNOWN_ORACLE_UNSAFE(:397) 항목 삭제 필수.
    2) 리터럴 직접참조 — 프로덕션 1건 + 테스트 4파일
       · 프로덕션: multi_scope.py:600 _scope_key_sig 의 startswith("__HB") 하드코딩.
         개명 후 이 필터가 무력화되면 bucket level 키가 scope 서명에 섞여, 매 wave 마다 전부
         신규 그룹으로 오인 → 오류 없이 활성 cell 이 부풀어 오르는 조용한 회귀.
         hb.BUCKET_ALIAS 참조로 전환 필수.
       · 테스트: test_diagnosis_multi_scope(502-503,527-528,545,550) /
         test_diagnosis_row_diff(30,49,57,64,78,91) / hash_bucket_5m(152) / hash_bucket_e2e(223)
    3) 저장된 resume 상태 비호환 — 영속 pending_cells 키가 "__HB1".
       개명 후 row_diff._cell_condition(:70) 의 while 매치가 0회가 되어 bucket 조건 없이 조용히
       진행될 수 있다(오류 없이 오답 = 최악 실패 모드).
       → 계약 버전 bump(hashv1→hashv2)로 방어. diagnosis_route.py:656,847 동일성 검사가
         EVIDENCE_CHANGED 로 재개를 차단한다. 별칭 개명 커밋에서 버전도 반드시 함께 올린다.
  별도로 남기는 것: row_diff 의 k0/c0 별칭은 개명 불필요 — 밑줄 선두 아님 + readback 이
    위치 기반(row_diff.py:164-166)이라 대소문자 폴딩과 무관.

■ 조사 중 새로 발견한 결함 3건 (선행 진단 미포착 — 설계에 반영 완료)
  [신규1] DATE_TIME 단일 ntype 이 DATE/TIMESTAMP/TIMESTAMPTZ 를 뭉갠다
    key_evidence._norm_type(:16-25) 이 date/timestamp/timestamptz/time 을 전부 DATE_TIME 하나로
    정규화한다(계약이 받는 타입태그는 NUMBER/DATE_TIME/TEXT 3종뿐). 선행 진단표 F 의
    TO_CHAR(x,'…FF6') 를 그대로 구현하면 DATE 컬럼 키에서 ORA-01821 로 깨진다.
    → 해결: TO_CHAR(CAST(x AS TIMESTAMP),'…FF6') 로 통일. CAST 가 DATE 에 .000000 을 채우고
      TIMESTAMP 는 보존 → 한 식으로 양쪽 커버. ntype 어휘 확장은 PG 계약까지 흔들므로 미채택.
    잔여 한계: TIMESTAMP WITH TIME ZONE 은 CAST 가 오프셋을 버림(PG ::text 도 세션 TZ 의존이라
      양 방언 모두 원래 세션 의존) → 세션 고정 대응으로 귀결.
  [신규2] 오라클 빈문자열=NULL → NULL 마커 의미가 방언별로 갈린다
    값 ''(빈문자열): PG canonical = "S:0:" / 오라클 canonical = "S#N"
    same-DBMS 안에서는 무해(양측 동일). cross-DBMS 에서는 같은 논리값이 다른 canonical →
    거짓 불일치. same-DBMS 가드가 "취향"이 아니라 정합성 필수 조건임을 보여주는 두 번째 근거
    (첫 번째는 숫자 TM9 vs trim_scale). → 계약 클래스에 cross_db_comparable=False 로 코드 강제.
  [신규3] NLS 세션 의존 (P1) — TO_CHAR(x,'TM9') 는 NLS_NUMERIC_CHARACTERS 소수점 문자를 따른다
    (',' 세션이면 12,5). src/tgt 오라클 인스턴스 세션이 다르면 거짓 불일치.
    현 코드베이스에 NLS 고정(ALTER SESSION)이 전무(exact_diff 포함 — 기존 노출분).
    → 해결: 3인자 TO_CHAR(x,'TM9','NLS_NUMERIC_CHARACTERS=''.,''') 로 식 자체에 고정
      (세션 설정에 비의존). 날짜는 이미 명시 서식이라 안전.
