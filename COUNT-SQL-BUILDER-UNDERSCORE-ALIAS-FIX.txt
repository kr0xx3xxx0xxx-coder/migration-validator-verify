■ 지시 1) 별칭 생성 지점과 "복잡 SQL에서만 발동"의 의미
────────────────────────────────────────────────────────────────────────
생성 지점 (운영 2곳, 현재 모두 문자 시작 이름):
  - services/count_sql_builder.py:213
      sel.set("expressions", [exp.alias_(exp.Literal.number(1), "mv_count_marker")])
  - services/validation_sql/source_stats_sql_builder.py:27  _COUNT_MARKER = "mv_count_marker"
      └ 88행 (COUNT-only 축소), 162행 (final_projs COUNT-only)

"복잡 SQL에서만 발동"의 의미 — 맞습니다. 단순 COUNT 는 이 경로를 타지 않습니다.
  - 마커는 build_subquery_wrapped_count_sql() 안에서만 만들어집니다. 이 함수는
    원본 SELECT 를 서브쿼리로 통째 감싸는(wrapping) 경로 전용입니다.
  - 단순 INSERT INTO t SELECT ... FROM a WHERE ... 는 wrapping 없이
    COUNT(*) 재구성 경로로 처리되어 마커 자체가 생성되지 않습니다.
  - wrapping 이 선택되는 조건이 곧 CTE(WITH)/JOIN/window(ROW_NUMBER OVER)/복잡 projection
    등을 포함한 SQL 이므로, 결과적으로 "복잡 SQL 에서만" 이 별칭이 SQL 에 등장했습니다.
  - 예외: SELECT DISTINCT 는 projection 이 행 수에 영향을 주므로 축소하지 않습니다
    (count_sql_builder.py:211 _is_distinct 가드) → 이 경우도 마커 미생성.

왜 오라클에서만 터졌나:
  sqlglot exp.alias_ 가 선행 밑줄을 safe 로 판단해 따옴표 없이 렌더 → `1 AS __mv_count_marker`.
  PostgreSQL 은 비인용 밑줄 시작 식별자를 허용하지만 오라클은 불허 → ORA-00911.

     실행 실패 → ORA-00911: _: invalid character after AS      ✓ 재현

생성된 원본 COUNT SQL(오라클):
    SELECT COUNT(*) AS CNT
    FROM (
    WITH ranked AS (
      SELECT x.ID, x.C_NUM,
             CASE WHEN t.AMT IS NULL THEN x.C_NUM_PS ELSE ROUND(x.C_NUM_PS + t.AMT, 2) END AS C_NUM_PS,
             ..., ROW_NUMBER() OVER (PARTITION BY x.C_CHAR ORDER BY x.ID) AS rn
      FROM NXDNP.MV_ORA_XDIFF_SRC x
      LEFT JOIN NXDNP.MV_ORA_TEST_SRC t ON MOD(x.ID, 300) + 1 = t.ORDER_ID
    )
    SELECT 1 AS mv_count_marker
    FROM ranked WHERE rn >= 1
    ) src_count
