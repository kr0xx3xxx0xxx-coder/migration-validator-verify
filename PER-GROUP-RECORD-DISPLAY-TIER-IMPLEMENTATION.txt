작업명 : PER-GROUP-RECORD-DISPLAY-TIER-IMPLEMENTATION
✅ 작업 완료 - 그룹당 표시 레코드 3단계(P1 전부/P2 대표20/P3 숫자만) + 상한강제(500/5,000) + 조기중단 통일, 실 브라우저 실측 전항목 PASS·회귀 신규실패 0건

■ 요청 요약
  "그룹 하나당 몇 건의 불일치 레코드를 화면에 보여줄지" 3단계 기준을 설정 가능하게 추가하되 상한을 코드로 강제.
    ~N1(기본 100, 상한 500)      : 레코드 전부 나열
    N1+1 ~ N2(기본 1,000, 상한 5,000) : 대표 PK 20건만 + 안내 + Excel 유도
    > N2                          : 레코드 나열 없이 '불일치 N건' 숫자만 + Excel

■ 기존 조기중단(101) 메커니즘과의 통합 정리 (task #1)
  - 기존: agg_diff_route.py 의 복합/문자 PK DIRECT 드릴다운이 early_stop_abs=101 하드코딩(>100 판정용).
  - 통합: 하드코딩 101 을 '그룹당 대표경계(representative_max)+1'(기본 1,000 → 1,001)로 통일.
    → '전부 나열' 경계(P1)와 조기중단 임계가 사실상 같은 지점이라는 사용자 지적을 반영, 단일 설정값으로 두 소비처
      (조기중단 임계 + pk-records 응답 주입)를 구동. 중복 로직 신설 없음.
  - 단일 출처: services/per_group_display_policy.per_group_policy_dict() 가 (경계 3값 + early_stop_abs) 를 한 번에 산출.

■ 3단계 + 상한 구현 내용
  1) services/per_group_display_policy.py (신규 순수모듈, 단위테스트 32/32 PASS)
     - decide_per_group_display(count, full_list_max, representative_max, representative_n, count_uncertain)
       → P1(PG_FULL) / P2(PG_REPRESENTATIVE) / P3(PG_COUNT_ONLY) 판정 + 표시 플래그 + 안내문구.
     - clamp_per_group_thresholds(): 상한 강제(full≤500, rep≤5,000) + 경계 역전 방지(full>rep 이면 rep 을 full 로 상향).
     - decision_to_dict / per_group_policy_dict: 서버 단일판정 근거를 응답에 실어 클라이언트가 읽음(표시축소=은폐 방지).
  2) config/size_threshold_registry.py: PER_GROUP_FULL_LIST_DEFAULT/CAP(100/500), REPRESENTATIVE_DEFAULT/CAP(1000/5000)
     리터럴 단일 출처. D1~D4(항목11)·scan-rows(1~10)와 '다른 축'임을 주석으로 명시.
  3) 조기중단 배선: routes/agg_diff_route.py _per_group_policy() 헬퍼 + prepare 의 early_stop_abs 통일 +
     pk-records 응답(READY / sample-early-stop 경로)에 per_group_policy 주입.
  4) 렌더러(ui/tabler_renderer.py):
     - 공유 헬퍼 _mvPerGroupDecide / _mvPerGroupBannerP2 / _mvPerGroupBannerP3 / _mvPerGroupExcelLink(전역 export 재사용).
     - _mvRiLoadGroupPage(주 경로): P1=전부(페이징) / P2·P3=대표 repN 조회 후, 분포 count 캡(약 1,000)에 무관하게
       scope 조회의 '정확한 전체값(total_count)'으로 P2/P3 재판정(과대조회 방지 — 조회는 항상 repN 건).
     - _mvPkLoadPage(보조 경로): P3=숫자만 / P2=배너+페이징을 대표 repN 건까지 캡.
     - 하드코딩 100/101/1000 제거 → 서버 per_group_policy 경계를 단일 출처로 사용.

■ 설정 화면 구성 (task #4·#5)
  - 기존 '전역 검증 정책 설정'(policy 탭)에 신규 카드 '그룹당 표시 레코드 단계' 추가:
    · 전부 나열 경계 [건] (기본 100 · 최대 500) — 입력 + 의미 설명 + placeholder
    · 대표만 표시 경계 [건] (기본 1,000 · 최대 5,000) — 입력 + 의미 설명 + placeholder
    · 기존 '저장' 버튼 공용. 저장은 SQLite(db/migration_validator.db, validation_policy_settings)로 영속.
  - 저장 시 서버가 clamp 한 값을 입력칸에 되돌려 표시(예: 99999 입력 → 500 으로 조정된 값 노출).
  - 전역설정 시작 게이트(global_settings_gate) 섹션/라벨에도 편입 → 검증 실행 전 확인창에 자동 포함.
  - 서버 재기동 후 반영(web_server reload=False — 코드 반영은 재기동 필요, 설정 '값'은 즉시 반영).

■ COUNT-GATE 기준과의 교차점검 결과 (task #6)
  - per-group 상한 : 500 / 5,000 → 축 = '그룹 하나를 펼쳤을 때 렌더할 불일치 레코드 수'.
  - COUNT-GATE     : MAJOR_ABSOLUTE_DIFF_MIN=1,000 / CRITICAL_ABSOLUTE_DIFF_MIN=1,000,000 / CRITICAL_MIN_LARGER_COUNT=100,000
                     → 축 = '테이블 전체 COUNT(원본 vs 목적) 차이'로 후속 단계 차단/경고를 판정.
  - 결론: 두 값은 '서로 다른 수량'을 판정하며, 같은 값을 비교하는 지점이 코드상 전무 → 모순 없음.
    per-group 은 '표시'만 바꾸고 PASS/WARNING/SKIP 판정을 건드리지 않으며, COUNT-GATE 는 그와 독립적으로 동작.
