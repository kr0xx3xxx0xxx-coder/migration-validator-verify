1. 결론
────────────────────────────────────────────────────────
채택 결론: "개별 서버들이 동시에 다운 — 서버별 개별 확인 필요"
  단, '우연한 동시 다운'이 아니라 공통 원인(동일 물리호스트/동일 스위치·전원)
  가능성이 높음.

기각된 가설:
  - "VPN/게이트웨이 연결 끊김" → 기각.
      게이트웨이 192.168.0.1 정상 응답(1ms), 대상 3대는 이 PC와 동일 서브넷
      on-link 라 VPN 터널 경로 자체가 개입하지 않음.
  - "특정 서브넷만 막힘 — 방화벽/라우팅 정책" → 기각.
      .10 / .150 / .151 / .211 전부 192.168.0.0/24 동일 서브넷·동일 게이트웨이.
      서브넷·VLAN 차이로 "10번만 살아있음"을 설명할 수 없음.
      또한 실패 지점이 ARP(L2)이므로 L3 방화벽/라우팅 정책으로는 설명 불가.

핵심 논리:
  동일 L2 세그먼트에서 ARP 응답이 없다(MAC 00-00-00-00-00-00, State Unreachable)
  → 상대 호스트가 해당 세그먼트에 존재하지 않는다는 뜻.
  방화벽은 ARP를 필터하지 않고, 라우팅 정책은 on-link 트래픽에 개입하지 못한다.
  남는 가능성은 (a) 서버 전원 오프/NIC 다운/랜 분리, (b) 스위치 포트 shutdown
  또는 VLAN 재배치, (c) 서버 IP 변경 — 세 가지뿐이며 이 PC 단독으로는 구분 불가.

11. 권장 확인 순서 (IT/서버 담당)
────────────────────────────────────────────────────────
1) .150 / .151 / .211 이 동일 물리 호스트(하이퍼바이저) 위 VM 인지, 또는 동일 스위치·
   동일 전원 계통에 물려 있는지 확인 → 해당되면 상위 장비 전원/링크부터 점검
   (3대가 동시에 사라진 사실 자체가 공통 상위 원인을 강하게 시사)
2) 서버 콘솔 / IPMI·iDRAC 로 전원 상태 및 OS 기동 여부 확인
3) 스위치 포트 link status·VLAN 배치 변경 여부 확인 (포트 shutdown / VLAN 이동)
4) IP 변경 가능성: 라우터(192.168.0.1) DHCP 클라이언트 목록에서 해당 서버들이
   다른 IP 로 재등록됐는지 확인
5) 복구 후 재확인 명령:
     ping 192.168.0.150 / .151 / .211
     Test-NetConnection 192.168.0.150 -Port 5433
     Test-NetConnection 192.168.0.150 -Port 5434
     Test-NetConnection 192.168.0.151 -Port 1523
     Test-NetConnection 192.168.0.151 -Port 1524
     Test-NetConnection 192.168.0.211 -Port 3309
   → ARP 해석이 먼저 살아나야(ping 응답 또는 Neighbor Reachable) TCP 테스트가 의미 있음
