    덕분).

[검증-2] 실제 배치 실행 2회(같은 batch_run_id, 완료 exec 2건+) 재현 + FK 정확성 실측
  실행: acquire_run_lock → save_wrapper_results → complete_run(result_execution_run_id=...) 를
  실제 서비스 함수로 batch_run_id="F10_REPRO_TEST_BATCH" 에 대해 1.1초 간격으로 2회 수행
  (execution_run_id 가 초 단위 timestamp 라 간격 필요).
    run1: exec_id=exec_f02ffac7fb874e13, result_execution_run_id=F10_REPRO_TEST_BATCH-20260806142835
          target_table=MV_F10_TABLE_RUN1
    run2: exec_id=exec_dc876297c9b344df, result_execution_run_id=F10_REPRO_TEST_BATCH-20260806142836
          target_table=MV_F10_TABLE_RUN2
  결과: batch_execution_state 에 같은 batch_run_id 로 완료 exec 2건 생성됨(C 시나리오 재현).
    각 행의 result_execution_run_id 가 자기 실행의 값과 정확히 일치(exec1→res1, exec2→res2).
    result_execution_run_id 로 batch_wrapper_result 를 조회하면 res1→MV_F10_TABLE_RUN1,
    res2→MV_F10_TABLE_RUN2 로 각 회차의 결과만 정확히 분리 조회됨 — 기존에는 batch_run_id
    만으로 조회 시 어느 회차 결과인지 구분 불가(32.4% 오배정 원인)였던 것이 이 FK 로 완전히
    해소됨을 실측 확인. 재현용 테스트 행은 검증 직후 DELETE 로 정리(운영 데이터 오염 없음).
