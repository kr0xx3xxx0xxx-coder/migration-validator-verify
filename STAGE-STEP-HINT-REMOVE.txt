────────────────────────────────────────────────────────────────────────
1. 배경과 요청
────────────────────────────────────────────────────────────────────────
개별검증 화면 상단, 단계 탭 아래에 있던 "현재 단계: [설명]" 안내문구(mvStepHint)가
계속 잘못된 값을 보여주는 문제가 직전 수정(93f4ca1, 보는 탭 기준으로 통일)에도
해소되지 않아, 사용자가 문구와 그 자리(공간) 자체를 완전히 제거하기로 결정했다.

작업 중 추가 요구사항이 들어왔다 — 개별검증 화면의 안내 박스를 단계 탭 '위'로 옮기고
오른쪽 정렬, 문구는 적용범위 안내로 교체.


────────────────────────────────────────────────────────────────────────
2. 수정 내용
────────────────────────────────────────────────────────────────────────

[A] mvStepHint 완전 제거 (개별 · 일괄 모두)

  ① DOM        : <div id="mvStepHint" class="mv-step-hint"> 삭제 (mvStepNavBar 내부)
  ② CSS        : .mv-step-hint{...} / .mv-step-hint b{...} 삭제
                 → 문구뿐 아니라 그 요소가 차지하던 padding(5px 2px 7px) 공간까지 소멸
  ③ setter     : _mvSetStepHint(html) / _mvSetStepHintOwned(owner, html) 삭제
  ④ 문구 테이블 : _MV_SINGLE_HINT(개별 5단계) / _MV_BATCH_HINT(일괄 5단계) 삭제
  ⑤ 호출부     : 개별 nav 렌더(_renderSingleStepNav) 1곳,
                 일괄 nav 렌더(renderBatchStepNav) 1곳,
                 이동 차단 안내 4곳 — 전부 제거 또는 대체(아래 [B])
  ⑥ 파생 죽은코드: _batchGateIdToNum(Gate 단계 id → 일괄 단계번호) 삭제.
                 이 함수의 용도는 '현재단계 문구 매핑' 단 하나였고, 문구 제거로
                 유일 호출부가 사라져 함께 정리했다.
                 (_mvHideStepNavBar 안의 hint 정리 코드도 함께 제거)

[B] 이동 차단 사유는 유지 (안내 위치만 교체)

  안내문구 줄이 사라지면서, 잠긴 단계를 클릭했을 때 아무 반응이 없어지는 문제가
  생긴다. 사용자가 '왜 안 넘어가는지' 알 수 없게 되므로, 새 UI 컴포넌트를 만들지 않고
  이 코드베이스가 이미 같은 목적으로 쓰는 alert 패턴(_mvNotifyRunActiveBlocked 와 동일
  방식)을 재사용한 _mvNotifyNavBlocked 로 4개 메시지를 옮겼다.

    · 변경으로 재검증이 필요한 단계입니다. 먼저 재분석/선행 단계를 완료하세요.
    · 아직 완료하지 않은 단계로는 건너뛸 수 없습니다. (완료한 단계는 상단 탭에서 자유 이동)
    · 현재 단계의 변경을 먼저 적용(실행 버튼)해야 다음 단계로 이동할 수 있습니다.  (탭/하단 버튼 2경로)
    · 선행 단계를 먼저 완료하세요. (잠긴 단계로 이동 불가)

  ※ 이는 지침에 명시된 항목은 아니지만, 문구 제거를 문자 그대로만 적용하면 차단이
     '무반응'이 되는 회귀가 생기므로 판단해 유지했다. 판정·이동 허용 로직은 불변이다.

[C] 개별검증 안내 배너 이동 + 문구 교체 (추가 요구사항)

  · 위치  : #tab-analyze 내부 최상단  →  단계 탭 바로 위(#mvAnalyzeScopeNotice)
  · 정렬  : 좌측 정렬(전폭)          →  오른쪽 정렬(내용 폭, inline-block)
  · 문구  : (구) 개별검증은 SQL 1건을 임시로 분석·확인하는 보조 도구입니다.
                공식 검증 작업에 포함할 누락 쿼리는 [일괄검증] 메뉴에서 같은
                검증 작업명(batch_name)으로 보완 업로드하세요.
            (신) 단일테이블 1개만을 검증 및 등록하는 기능입니다.
                다수 테이블의 검증은 [일괄검증] 메뉴를 사용합니다.
  · 링크  : [일괄검증] 은 이 화면이 이미 쓰는 좌측 메뉴 링크 마크업을 그대로 재사용
            → <a href="#" onclick="showTab('batch');return false"><strong>[일괄검증]</strong></a>
            (구 문구에서는 [일괄검증] 이 <strong> 텍스트일 뿐 링크가 아니었다.
             요청대로 '기존 링크 마크업 재사용'을 적용해 실제 링크가 되었다 — 실측 확인)
  · 스타일: 배경·테두리·모서리·글자크기 모두 종전 그대로.
            배너가 #tab-analyze 밖으로 나가면서 CSS selector 의 `#tab-analyze ` 한정만
            떼어냈다(`#tab-analyze .analyze-info-banner` → `.analyze-info-banner`).
            선언 자체는 한 글자도 바꾸지 않아 외형 동일 — 실측 computed 값으로 확인.
  · 범위  : 개별검증 전용. 공용 shell 에 두되 표시 토글을 _mvShowStepNavBar 의
            owner('analyze') 기준으로 걸어 일괄검증 화면에서는 나오지 않는다.
            비검증 화면에서는 _mvHideStepNavBar 가 함께 접는다(여백 0).

6. 비판적 검토 (남는 위험 / 판단이 필요했던 지점)
────────────────────────────────────────────────────────────────────────
· [차단 안내를 alert 로 옮긴 것] 지침에는 '호출 자체를 없애라'고 되어 있었으나, 그대로
  적용하면 잠긴 탭 클릭이 무반응이 된다. 기존 코드베이스가 같은 상황에 이미 쓰는 alert
  패턴을 재사용해 사유만 남겼다. 다만 문구 줄(수동적 안내)과 달리 alert 는 능동적
  차단이라 잠긴 탭을 반복 클릭하면 팝업이 반복된다. 거슬리면 제거 또는 토스트 전환을
  별도로 요청하면 된다.
· [배너를 공용 shell 로 옮긴 점] 개별검증 전용 요소가 개별/일괄 공용 컨테이너 영역에
  놓였다. 표시 토글을 owner 기준 한 곳(_mvShowStepNavBar/_mvHideStepNavBar)에만 두어
  분기가 흩어지지 않게 했지만, 향후 세 번째 검증 화면이 생기면 이 토글을 반드시
  같이 봐야 한다.
· [현재 단계 표시의 단일 출처] 문구 제거로 '현재 단계'를 알리는 표시는 탭 배지 ·
  N단계 처리시간 · 하단 커맨드바 3곳으로 줄었다. 셋 다 _singleViewStep(보는 탭) 기준
  이라 이번 제거로 표시 불일치 소지가 오히려 줄었다.
· heuristic/scoring/explainability 영향 없음 — 판정 로직 무변경, 표시 계층만 수정.
· 보안 영향 없음 — 입력/접속/쿼리 경로 무관.
