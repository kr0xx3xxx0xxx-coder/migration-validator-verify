■ [지시 2 근거] 방언 렌더 매트릭스 — DB 없이 결정적으로 확인(실행 로그 발췌)
  5-a  key_evidence._null_probe_sql (chunk key NULL probe)
       postgres → SELECT 1 FROM ... WHERE ORDER_ID IS NULL LIMIT 1
       mysql    → SELECT 1 FROM ... WHERE ORDER_ID IS NULL LIMIT 1
       oracle   → SELECT 1 FROM ... WHERE ORDER_ID IS NULL FETCH FIRST 1 ROWS ONLY
       tsql     → SELECT TOP 1 1 FROM ... WHERE ORDER_ID IS NULL
  5-b  match_key_evidence._dup_present (MATCH_KEY 중복 probe)
       postgres → ... GROUP BY ORDER_ID HAVING COUNT(*) > 1 LIMIT 1
       oracle   → ... GROUP BY ORDER_ID HAVING COUNT(*) > 1 FETCH FIRST 1 ROWS ONLY
       tsql     → SELECT TOP 1 COUNT(*) AS C FROM ... HAVING COUNT(*) > 1
  5-c  diagnosis_route._count_rows
       4방언 모두 → SELECT COUNT(*) AS C FROM ...   (문법 차이 없음 → LIMIT 계열 결함 아님)
  → (C)의 미위임 7곳은 전부 5-a/5-b 를 호출한다. 즉 오라클 세션에서 postgres 렌더가 나가
    'LIMIT' 이 오라클로 방출되는 것이 코드 경로상 확정.

■ [지시 3] 오라클 실측 — 이번 회차 수행 불가(사유 명시)
  라이브 실측을 시도했으나 대상 DB 서버가 TCP 레벨에서 도달하지 않아 측정 자체가 불가했다.
    Oracle_asis            192.168.0.151:1523   TCP 미도달(timeout)
    Oracle_tobe            192.168.0.151:1524   TCP 미도달(timeout)
    PostgreSQL_Inter_asis  192.168.0.150:5433   TCP 미도달(timeout)
    PostgreSQL_Inter_tobe  192.168.0.150:5434   TCP 미도달(timeout)
  로컬 NIC 는 192.168.0.22 로 동일 서브넷에 있으며 샌드박스 해제 후에도 동일 → 코드 문제 아닌
  DB 서버 미가동/망 단절. (참고: 과거 DPY-6005 사례는 TCP 는 붙고 서비스만 미등록이었으나,
  이번엔 TCP 자체가 안 붙으므로 다른 상태다.)

  대체 근거 — 동일 SQL 형태에 대한 기존 라이브 실측 인용(재측정 아님, 인용임을 명시):
   · LIMIT: E:\verify_reports\ROUTES-DIAGNOSIS-CONFIRM-ROUTING-DIALECT-DELEGATION-FIX.txt L39~43
       dialect=postgres 렌더 실행 → ORA-03049: SQL keyword 'LIMIT' is not syntactically valid
                                    following '...WHERE id IS NULL '
       dialect=oracle  렌더 실행 → 정상
   · 밑줄 별칭: 같은 보고서 L83~86 → ORA-00911: _: invalid character after AS
  미실측 항목(정적 판정만, 향후 DB 복구 시 실측 필요):
   · `FROM (...) __cg` 처럼 별칭이 테이블 별칭 위치일 때의 정확한 오류코드(ORA-00911/00933 중 어느 쪽인지)
   · `::text` 오라클 실행 오류코드
   · count_gate/exact_diff 라우트 종단 응답 형태
  ※ 진단 스크립트는 TCP 도달성을 먼저 판정하고 도달 시 자동으로 라이브 실측·PG 대조군까지
    수행하도록 작성돼 있어, DB 복구 후 재실행만 하면 위 미실측 항목이 즉시 채워진다.
