[2] 편중 그룹 표시 등급 — D1 오분류 실재, 화면 멈춤 위험은 없음

[등급 산정 기준 — 경로마다 축 A 정의가 다름]
  · services/stats_execute_service.py:547 (통계검증 그룹표)
      축A = 불일치 '그룹 수'(diff+src_only+tgt_only) / 축B = 전체 그룹 수
  · routes/agg_diff_route.py:1223 (재이관 드릴다운)
      축A = 실제 '레코드 건수'(pg["total"]) / 축B = 불일치 그룹 수
  · 구조적 관찰: 통계검증 경로는 축A ≤ 축B 가 항상 성립(불일치 그룹 ≤ 전체 그룹)해
      max(a,b) 가 언제나 축B — 축A 는 등급에 영향을 주지 못한다(reason 라벨만 AXIS_A_*).
      두 축 설계가 이 경로에서 사실상 1축으로 붕괴해 있다.

      표시 축소는 별도 장치가 담당 — MAX_DISPLAY_ROWS(200)+클라 페이징, 재이관 서버 페이징.
  (b) 통계검증 그룹표에는 D1 배너가 아예 표시되지 않음(화면 텍스트 '표시 등급 D' 검색 false).
      D1~D4 배너는 재이관/드릴다운 경로에서만 노출(combo 에서는 정상 노출 확인).
      → 잘못된 문구가 사용자에게 보이지도 않는다. 단, 등급 표시 기능이 이 화면에서
        동작하지 않는다는 뜻이기도 하다.
  (c) 실제 드릴다운은 D4 로 정확히 보호됨 — 편중 그룹 행 실클릭 결과:

       불일치 20건(그룹 1개) — 수집이 조기중단되어 대표 표본만 저장되었습니다."

      → 10만 건을 나열하려는 시도 자체가 없다(표본 조기중단 → early_stopped 강제 D4).
      추가 방어: per_group_display_policy(100건 경계) — combo 200건 그룹은 P3(숫자만)로 렌더 확인.

[3] 두 사안의 연관성 — 독립 사안으로 판단
────────────────────────────────────────────────────────────────────────
· 원인 계층이 다르다 : 조합 뷰=실행계획 계층(세트 분해) / 편중 등급=표시 판정 계층(축A 정의).
· 조합 뷰가 생겨도 편중 오분류는 남는다 : 축A 가 '그룹 수'인 한, 저카디 컬럼이 1개뿐인
  테이블(SKEW 형태)에서는 조합 축 자체가 없어 동일 증상이 그대로 재현된다.
· 완화 방향이 반대다 : 조합 뷰는 그룹을 잘게 쪼개는 방향, 편중 문제는 한 그룹 안 레코드 규모를
  등급에 반영하는 문제. 쪼개면 증상이 가려질 뿐 판정 기준이 고쳐지지 않는다.
· 공통 뿌리는 하나 있다 : 두 사안 모두 '그룹 단위 숫자'와 '행 단위 숫자'를 같은 자리에 놓는다.
  조합 판정 부재는 그룹 집계가 행 차이를 상쇄해 감추고, 편중 오분류는 그룹 수가 행 건수 자리에 들어간다.
  묶어서 정리하는 것은 가능하나 설계 판단 사안이며 이번 진단의 권고 범위 밖.
