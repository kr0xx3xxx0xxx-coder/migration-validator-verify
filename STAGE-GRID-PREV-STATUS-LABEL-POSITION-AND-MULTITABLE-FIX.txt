── §C 원본 2개 이상 줄바꿈 (신규 구현) ──────────────────────
- 현재 구조 확인: 개별검증 각 단계 그리드는 대표 원본(primary_source_table)만 한 셀에 표시,
    나머지 원본(JOIN/UNION)은 '한 셀에 몰아넣기'가 아니라 아예 미표시(숨김)였음.
- 다중 원본 경로 확인: 개별검증에도 JOIN/UNION 시 validation_context.source_tables 가
    2개 이상으로 채워진다(sqlglot 추출). → 이 경로로 재현.
- 구현: _mvExpandRowsPerSrcTable(신규) — 원본이 2개 이상이면 각 단계 그리드를
    '원본 테이블당 한 행'으로 분할(표시 전용 — 판정/집계/API 불변).
    · 원본 테이블 셀만 행마다 다르게 표시.
    · SQL 단위 값(COUNT/상태/이전단계 상태)은 대표(첫) 행에만 두고, 참조 원본 행은 비운다
      (값 뒤섞임 방지 — JOIN/UNION 은 하나의 SQL 이라 원본별 개별 COUNT·상태가 존재하지 않음).
    · 목적 테이블은 정책상 1개 → 모든 행에 동일 표시(각 원본이 이 목적지로 이관됨을 명시).
    · 적용 그리드: 쿼리검토 / COUNT / 후보 / 통계구성 / 결과확인(5개).
- 재현 화면·실측: 개별검증 쿼리검토(1단계) — JOIN SQL
    INSERT INTO NXDNP.MV_ORA_XDIFF_TGT (...) SELECT x.*, t.CHANNEL_CD ...
    FROM NXDNP.MV_ORA_XDIFF_SRC x LEFT JOIN NXDNP.MV_ORA_TEST_SRC t ON ...
    → source_tables = [NXDNP.MV_ORA_XDIFF_SRC, NXDNP.MV_ORA_TEST_SRC] (2개)
    실측 행 분할(스크린샷 multi_1_query.png):
      No.1 : NXDNP.MV_ORA_XDIFF_SRC | ...XDIFF_TGT | 입력10 | 추출10 | 10/10 | 조건 있음 | 조인 1개 | 정상
      No.2 : NXDNP.MV_ORA_TEST_SRC  | ...XDIFF_TGT | (SQL 단위 값 비움)
    → 원본 2개가 각각 다른 행으로 분할되고 값이 뒤섞이지 않음을 확인.
