6. 핵심 결론
------------
물리적으로 분리된 오라클(로컬)↔클라우드 PostgreSQL(Neon) 환경에서 **네트워크 연결과
COUNT 레벨 비교는 완전히 정상 동작**한다(3번 COUNT_ONLY 실측). 그러나 이 도구는 현재
**GROUP BY/SUM 통계검증 "실행" 단계를 원본↔목적지가 동일 DBMS(PostgreSQL↔PostgreSQL
또는 Oracle↔Oracle)인 경우로만 지원하도록 설계돼 있어**, Oracle→PostgreSQL 조합은
개별/일괄 모두 실행 단계에서 HOLD된다(코드 3곳에서 교차 확인: single_validation_run_facade.py,
diagnosis/dbms/capabilities.py, ui/tabler_renderer.py의 서버·클라이언트 이중 게이트).
따라서 오늘 지시서의 원래 동기였던 **P13(parallel_sides) 재측정은 Oracle→PostgreSQL 조합으로는
수행 불가**하다 — 재측정하려면 **동일 DBMS 쌍을 물리적으로 분리**해야 한다(예: 내부망
PostgreSQL_Inter_asis/tobe ↔ Neon 클라우드 PostgreSQL_tobe/NEW_tobe, 둘 다 PostgreSQL).
코드 수정은 이번 작업에서 발생하지 않았다(신규 1회성 드라이버 스크립트 2개만 scripts/dev_e2e/
에 추가, 기존 코드 무변경, 코드 저장소 git commit/push 없음).
