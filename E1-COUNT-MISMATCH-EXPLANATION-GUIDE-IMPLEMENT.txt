3. 안전조건 4가지 각각 검증 결과 (지시서 §2)
════════════════════════════════════════════════════════════════════════
(a) 화면 판정값·수치는 서버 계산값만
    → generate_guide() 반환 dict 에 src_count/tgt_count/is_matched 등 판정 필드가 아예 없음
      (test_service_output_has_no_count_or_verdict_fields 로 정적 확인·통과). 화면 4요약카드/
      COUNT-GATE 배지 렌더 코드(_countSummaryCardsHtml/_mvCountGateHtml)는 이번 작업에서
      한 줄도 건드리지 않음 — 그대로 서버 /count 응답 값만 사용.
(b) 모델에는 집계 통계량·컬럼명만, 실 레코드 값 금지
    → CountMismatchGuideInput 필드는 건수/차이/비율/테이블명/WHERE 존재 여부(불리언, 원문 아님)/
      컬럼명 목록뿐(test_guide_input_has_only_aggregate_fields_no_record_values 로 필드셋 고정 확인).
      WHERE 원문은 절대 전송하지 않음(값 리터럴 포함 위험 때문에 존재 여부만 boolean 화 — 조사가
      권고한 것보다 한 단계 더 보수적으로 설계).
(c) 단정문 금지 — 제안형만
    → 프롬프트 지시 + _sanitize_or_reject() 정규식(원인은/이유는/틀림없이/확실히 + 습니다/입니다)
      이중 방어. "원인은 X입니다"류 3건 전부 폐기 확인, "확인해보세요"류 2건 전부 통과 확인
      (pytest 5건 통과).
(d) 미기동/장애 시 기존 하드코딩 문구로 폴백
    → LLM 비활성/explain() 예외/explain() None 반환 3가지 경로 전부 fallback_result() 로 수렴함을
      개별 테스트로 확인(3건 통과). 폴백 문구는 기존 3줄 고정 안내와 완전히 동일(_FALLBACK_TEXT).
