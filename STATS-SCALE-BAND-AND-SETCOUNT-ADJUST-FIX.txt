1. 배경과 범위
════════════════════════════════════════════════════════════════════════════
STATS-SCALE-COST-BAND-BENCHMARK-MEASURE 는 실측 41건으로 다음을 확인했다.
  · 현행 밴드(8/16/24)는 실측 0.16초~82초(×507) 전 구간을 '잠정 중형' 하나로 뭉갠다.
  · 밴드 재조정(안①)만 하면 시간대 일치율 75.0%, 세트 수 반영(안②)까지 하면 80.0%.
  · 카디널리티 전송(P2/안③)은 현행 가중치로는 오히려 악화(순위상관 +0.854 → +0.499).

이번 지침은 사용자 승인된 안① + 안② 만 구현한다. 안③(카디널리티)·원격 ×1.05 →
고정 가산(§5-4)·cost 재정의(안④)는 범위 밖이며 손대지 않았다.

[2-3] basis(근거) 기록 — 판정에 영향 없는 explainability 추가
  + "estimated_scan_rows_effective": scan_effective
  + "scan_set_multiplier": set_multiplier
  **estimated_scan_rows 자체는 원값(한 세트가 스캔하는 행수)으로 유지**했다.
  이 값은 cost 뿐 아니라 plan_stats_strategy 의 전략 ID 게이트(card_near_scan,
  huge_unindexed_scan, PARTITION_AGG 의 scan > 10,000,000)와 화면 표시가 함께
  읽는다. 여기에 보정값을 넣으면 다축 테이블의 **통계전략 ID 자체가 바뀌어**
  이번 지침 범위(등급 판정) 밖의 동작 변경이 생긴다. 지침이 요구한 것은
  "cost 계산 시 사용하는 스캔 행수" 보정이므로 cost 항에만 적용하고, 보정값은
  근거로만 별도 기록했다. (전략 ID 불변은 §6-2 에서 실증)

[2-4] 동반 테스트 갱신 — tests/test_strategy_remote_flag_evidence.py
  test_remote_changes_only_cost_and_grade 는 "remote 여부로 등급이 한 단계
  갈린다"를 8,000행 케이스로 확인하고 있었다. 8,000행은 옛 첫 경계(8.0)에
  걸치던 값이라(cost 7.806 / 원격 8.197) 밴드 이동 후에는 양쪽 다 '소형'이 된다.
  계약(remote → 등급 한 단계)은 그대로 두고 **새 첫 경계(12.5)에 걸치는 규모**로
  교체했다: 1,000,000행 · GB 1축 · SUM 0 → cost 12.000(소형) / ×1.05 = 12.600(중형).
  이 테스트는 이번 밴드 변경으로 전제가 무효화된 유일한 테스트다.

8. 비판적 검토
════════════════════════════════════════════════════════════════════════════
  긍정적 효과
    · 등급이 처음으로 실제 소요시간을 구분한다(구분력 0 → 4등급 전부 사용, 80.0%).
    · 상수 3개 + 곱셈 1개라 되돌리기가 쉽다(롤백 = 커밋 1개 revert).
    · 다중 GROUP BY 의 실제 실행 형태(N세트 순차)가 처음으로 비용 모형에 들어왔다.

  구조적 문제점
    · 밴드는 여전히 방언·호스트 무관 고정 상수다. 오라클 5,000만행이 PG 3,000만행보다
      cost 는 높은데 5배 빠른 역전(§3-7)이 그대로 남아 있고, 실제로 오분류 3건이 여기서
      나온다. 근본 해소는 안④(throughput 실측 배선)이며 별도 지침이 필요하다.
    · group_axis_count 를 '세트 수'로 쓰는 것은 제품 실행 경로(단일축 N세트)에서만 참이다.
      화면이 보여주는 조합 SQL 을 그대로 실행하는 경로가 생기면 과대평가가 된다
      (지금도 조합 대조 케이스 1건이 그 이유로 오분류). 표시/실행 SQL 불일치(§7-4)가
      해소될 때 이 곱셈도 함께 재검토해야 한다.

  운영상 위험
    · 낮음. 서버 재기동 없이도 다음 /strategy/plan 호출부터 새 등급이 나오지만,
      실행 중 서버는 옛 모듈을 들고 있으므로 반영에는 재기동이 필요하다(운영 반영 시 유의).
    · 등급은 표시 전용이다. 실행 차단·전략 선택·저장 게이트 어디에도 쓰이지 않으므로
      오판정이 사용자 작업을 막지 않는다(§6-2 로 전략 ID 불변 실증).

  heuristic / scoring / explainability 영향
    · heuristic 하드코딩은 늘지 않았다(상수 3개 교체). 오히려 근거 없는 임시값이
      실측 근거값으로 바뀌었고, 출처 주석을 코드에 남겼다.
    · explainability 는 개선됐다 — grade_basis 에 유효 스캔값과 배수를 함께 저장하므로
      "왜 이 등급인가"를 응답만으로 설명할 수 있다.
    · scoring 은 여전히 미성숙하다. scan:group 실측 비율 4.3:1 vs 현행 1:2.5 의 역전은
      안③ 범위라 이번에 손대지 않았다 — '잠정' 접두를 유지한 이유다.

  지금 구현 여부: 진행 (완료)
