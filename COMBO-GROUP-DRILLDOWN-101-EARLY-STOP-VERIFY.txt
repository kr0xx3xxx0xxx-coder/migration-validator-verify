작업명 : COMBO-GROUP-DRILLDOWN-101-EARLY-STOP-VERIFY
✅ 조사 완료 - 조합그룹 드릴다운은 단일축과 완전히 동일한 코드경로이나, 실측한 두 시나리오
   (소규모/대규모) 모두 101건 조기중단이 발동하지 않음(설계상 정상 — 결함 아님)

[1] 코드 경로 동일성 확인
    (routes/agg_diff_route.py:1288-1330, ui/tabler_renderer.py:17686-17711, 28246-28256)
 - 조합 그룹 클릭(_mvStage5OpenGroup, tabler_renderer.py:28229)은 group_key 의 컬럼=값 쌍을
   pairs 배열로 만들어 그대로 _mvRiEnterRecordsView → scope={col,val,pairs} 로 넘긴다
   (단일축은 pairs 1개, 조합은 2개 이상 — 그 외 차이 없음).
 - 서버 /agg-diff/prepare 는 scope.pairs 개수와 무관하게 동일한 _scope_eq_expr AND 결합으로
   src_sql/tgt_sql 을 좁힌다(agg_diff_route.py:1298-1320) — 단일축·조합을 구분하는 분기
   코드 자체가 없다(주석: "조합검증(PAIR) 그룹은 GROUP BY 축이 2개 이상이라 조건도 2개 이상").
 - 실측(스크린샷 05/06): 조합 그룹(R01|S01)과 단일축 그룹(R01)이 완전히 동일한 UI 레이아웃·
   동일한 엔진(PK_RANGE_CHUNK_COMPARE)·동일한 판정 로직으로 렌더된다.
 → 결론: 코드 경로는 100% 동일(축 개수는 WHERE 조건 개수 차이일 뿐, 나머지 메커니즘 불변).

[2] 101건 조기중단(early_stop_abs) 적용 여부 — 조건부이며, 축 개수와는 무관
 - early_stop_abs=101 은 오직 req._unique_native_key=True 일 때만 강제 세팅된다
   (agg_diff_route.py:1224-1238 _resolve_native_pk_key 폴백, :1326-1330). 이 플래그는
   표준 신뢰 PK 판정(TRUSTED_PHYSICAL_PK)이 실패한 복합키/문자키 전용 폴백 경로에서만 켜진다.
 - 표준 케이스(단일 숫자 PK, 가장 흔한 구성 — 이번 픽스처 포함)에서는 _unique_native_key 가
   세팅되지 않고, 대신 choose_compare_strategy() 가 "그 그룹 scope 의 행수" 기준으로 실행
   엔진을 고른다(ui/tabler_renderer.py:17686-17702 useStream 판단과 동일 기준):
     · scope 행수 < detail_stream_min_rows(정책 기본 50,000)
         → stream=false → prepare_reimport_pk_index() 실행(비-stream, early_stop_abs
           파라미터 자체가 없는 함수) → 정확한 건수 그대로 반환.
     · scope 행수 ≥ 50,000
         → stream=true 이지만 M81 전환정책이 PK_RANGE_CHUNK_COMPARE 를 선택
         → CHUNK 엔진은 그룹 완결성(group completeness) 제약으로 조기중단이 불가능
           (기존 결론 [[조기중단M85재확인]]·[[청크조기중단도불가]] 와 동일 제약)
         → 정확한 건수 그대로 반환.
 - early_stop_abs=101 이 실제로 개입하는 prepare_reimport_pk_index_stream(DIRECT-merge)
   경로는 "_unique_native_key=True(복합/문자 PK 폴백) + scope 행수가 stream 임계값 초과"
   라는 좁은 조합에서만 열린다 — 이 조건에 조합/단일축 구분은 아예 없다(축 개수 분기 코드 자체
   부재이므로 이 창구가 열리면 조합·단일축 모두 동일하게 101에서 멈춘다).

[4] 결론
 - 조합 그룹 드릴다운은 단일축 그룹 드릴다운과 완전히 동일한 코드/엔진/판정 경로를 탄다 —
   조합 전용 특수처리·분기가 존재하지 않는다(정상, 결함 아님. 사용자 질문 1번 답: 예, 동일 경로).
 - "101건 조기중단이 조합 그룹에도 그대로 적용되는가?"에 대한 정확한 답은 단순 예/아니오가
   아니라 "축 개수와는 무관하게, 그 그룹의 scope 행수와 PK 신뢰판정 결과에 따라 결정된다"이다
   (사용자 질문 2번 답: 메커니즘은 동일하게 존재하나, 실제 발동 여부는 축 개수가 아니라 규모·
   PK종류에 달려있다).
 - 실측 결과(사용자 질문 3번 답): 표준적인 단일 숫자 PK 테이블에서는(가장 흔한 구성) 조합이든
   단일축이든 101건 조기중단이 실제로는 거의 발동하지 않는다 — 작은 그룹은 애초에 조기중단
   파라미터가 없는 비-stream 경로를 타고, 큰 그룹은 CHUNK 엔진(그룹 완결성 제약으로 조기중단
   구조적 불가)을 탄다. early_stop_abs=101 이 실제로 개입하는 창구(복합/문자 PK 전용
   DIRECT-merge 폴백)는 극히 좁고, 그 창구 안에서는 조합·단일축이 완전히 동일하게 취급된다.
 - 결함이 아니라 기존 아키텍처(그룹 규모·PK종류별 실행엔진 자동선택)의 자연스러운 결과다.
 - 코드 수정 없음 — 조사·실측 전용.
