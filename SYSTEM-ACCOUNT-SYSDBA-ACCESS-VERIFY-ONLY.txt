6. 해석 및 유의사항 (변경은 하지 않음)
================================================================================
(1) SYSDBA 접속 불가는 비밀번호 문제가 아니다.
    동일 비밀번호로 SYSTEM 일반 접속이 성공했으므로 자격증명은 유효하다.
    비밀번호 파일에 SYS 만 등록되어 있어 SYSTEM 에는 SYSDBA 권한이 없다.
    → "SYSTEM 으로 SYSDBA 접속해서 복구" 경로는 현재 구성에서 성립하지 않는다.

(2) RMAN 기반 아카이브 정리는 현재 자격으로 불가하다.
    RMAN target 접속은 SYSDBA 또는 SYSBACKUP 을 요구하는데 SYSTEM 은 둘 다 없다.
    SYS 계정 비밀번호는 이번 확인 범위 밖이며 시도하지 않았다.

(3) SYSTEM 이 가진 ALTER SYSTEM / ALTER DATABASE 로 아카이브 목적지 변경 등은
    이론상 가능하나, 이번 지침이 명시적으로 금지한 쓰기 작업이므로 실행하지 않았다.
    또한 dest_1 이 MANDATORY 이므로 목적지 변경은 부작용 위험이 크다.

(4) 조회 시점에는 아카이빙이 11:04 까지 진행된 흔적이 있고 archiver 도 STARTED 이다.
    즉 ORA-00257 은 "영구 고장"이 아니라 디스크 여유가 바닥날 때마다 재발하는
    상태로 보이며, 근본 해소는 arch 디렉터리(13.89GB, 1,460개) 정리 또는
    호스트 디스크 확보가 필요하다 — 모두 이번 범위 밖이다.

(5) 후속 작업이 필요하다면 선택지는 다음과 같다(어느 것도 이번에 수행하지 않음):
    a. SYS 계정 자격증명 확보 후 SYSDBA/RMAN 경로로 아카이브 정리
    b. 컨테이너 호스트(73672623873a) OS 레벨 접근으로 arch 디렉터리 정리
    c. SYSTEM 의 ALTER SYSTEM 권한으로 아카이브 구성 조정 (부작용 위험 검토 필요)
