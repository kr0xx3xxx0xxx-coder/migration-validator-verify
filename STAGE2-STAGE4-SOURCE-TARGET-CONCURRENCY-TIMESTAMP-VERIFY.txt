작업명 : STAGE2-STAGE4-SOURCE-TARGET-CONCURRENCY-TIMESTAMP-VERIFY
✅ 작업 완료 - 2단계(COUNT)·4단계(통계검증 실행) 원본/목적 쿼리 동시 실행 여부를 실측 타임스탬프로 증명

■ 방법
  - 코드 추정이 아닌 실측: 실제 실행 지점 2곳에 임시 계측(시작/종료 time.time() 절대시각 +
    threading.current_thread().name)을 추가해 scratchpad/_concurrency_probe.log 에 append 기록.
    · 2단계: services/count_common_service.py::_run_one_count_side (COUNT 실 실행 지점)
    · 4단계: services/stats_execute_service.py::_fetch_src / _fetch_tgt (통계검증 SELECT 실 실행 지점)
  - 실 DB: Oracle asis/tobe(db_presets_src.json "Oracle_asis" / db_presets_tgt.json "Oracle_tobe"),
    스키마 NXDNP, 테이블 MV_CSPK_SRC(100만행)/MV_CSPK_TGT(99만행). SELECT/COUNT 전용, DDL/DML 없음.
  - 2단계는 run_count_pair() 를 MV_COUNT_PAIR_PARALLEL=1 로 3회, =0(대조군)으로 1회 실행.
  - 4단계는 실제 라우트(routes/execute_route.py::_stats_execute_inner)와 동일하게
    services.single_validation_run_facade._different_physical_db(src_db, tgt_db) 로
    req.parallel_sides 를 자동 결정(강제 대입 없음) → asis/tobe 는 서로 다른 물리 DB라 True 로 결정됨
    → services/stats_execute_service.py::execute_stats_validation() 3회 실행.
  - 계측 완료 후 services/count_common_service.py, services/stats_execute_service.py 는
    git checkout -- 으로 원상복구(diff 0). 임시 실행 스크립트(scratchpad)도 삭제.
