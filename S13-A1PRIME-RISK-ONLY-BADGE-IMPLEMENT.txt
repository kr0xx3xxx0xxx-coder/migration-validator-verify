사용자 승인: **A1'(위험 전용 배지)** 채택. _applyCsrBadges(선정상태 배지 원형)는 판정
단일출처(Live vs Preview) 보호를 위한 의도적 봉인 상태 그대로 유지하고, 완전히 새로운
경량 배지 하나만 추가했다.

     skip).

1-4. 배선 지점: _fetchCsrPreview() 안 2곳(캐시 히트 경로 / 신규 fetch 성공 경로) —
     _csrRows 확정 직후 _applyCharCapacityRiskBadge() 호출. 이 함수는 Stage3 후보 선택

     위에 배지만 얹는 방식이며, 판정 로직 자체는 완전히 무수정.

2. 발견 사항 — 기존 _applyCsrBadges 의 DOM 셀렉터는 이미 stale
================================================================================
_applyCsrBadges(원형)는 label.cs-item / label.querySelector('.cs-col') 을 찾는데, 현재
Stage3 개별 후보표(renderColSelect/buildRow)는 label.cs-item 마크업을 쓰지 않고
tr[data-cand-role] / td.ict-tc-stscore 구조로 바뀌어 있다(grep 결과 label.cs-item 클래스
정의 자체가 코드에 없음 — 정의된 CSS 도 없음). 즉 원형을 그대로 되살렸어도(A1) DOM
불일치로 동작하지 않았을 것 — A1' 신규 함수는 현재 실제 마크업(td.ict-tc-stscore)을
기준으로 새로 작성했다.
