작업명 : COUNT-ONLY-PLAN-STALE-PLAN-DRILLDOWN-BUG
✅ 작업 완료 - COUNT-only(전체합계) 그룹 드릴다운의 STALE_PLAN 막다른 길을, 스트림 prepare PREPARING 폴링 추가로 근본 수정(실 오라클 250k 브라우저 실측 확증)

[정확한 재현 절차]
- 대상: NXDNP.MV_ORA_XDIFF_SRC(250,000) → MV_ORA_XDIFF_TGT(249,950), 의도적 50건 누락(+값 불일치)
- 원본/목적: Oracle_asis → Oracle_tobe, 포트 8000, 인증 ON(전용계정 e2e), 실 브라우저 클릭스루(강제주입 없음)
- 1단계 분석 → 2단계 COUNT(불일치 250,000/249,950) → 3단계에서 GROUP BY 후보 전부 체크 해제(COUNT+SUM만, SUM=C_NUM/C_NUM_PS)
  → 4단계 통계검증 생성+실행 → 5단계 "전체합계" 행 펼침
- before: 전체합계 펼침 즉시 "STALE_PLAN — 최신 실행계획 증적이 없습니다. 최신 계획으로 통계검증을
  다시 실행한 뒤 그룹 상세를 여세요." 재현(재실행으로도 동일).

[정확한 원인 — 코드 위치와 조건]
- STALE_PLAN 판정: ui/tabler_renderer.py _mvPkLoadPage 내부 `if (!d.total)` 하위 분기
  `if (!((window._execPlanRun||{}).planFp))` — 즉 'total 없음 AND planFp 미설정' 두 조건이 동시 성립할 때만 출력.
- 대량(250k) 재이관 prepare 는 스트림 비동기 job 이라 그룹 클릭 즉시 완료되지 않고 status=PREPARING·
  total=null 로 응답한다. 소량 테이블은 prepare 가 '동기'(즉시 READY)라 이 문제가 나타나지 않는다.
- prewarm(_mvPkPrewarm)은 PostgreSQL·5만행 이하에서만 실행된다(line ~16937) → 오라클/대량은 prewarm
  이 없어 그룹 클릭 시점에 비로소 prepare 가 시작되고 곧장 PREPARING 을 받는다.
- 그룹행 드릴다운 로더 _mvPkLoadPage 는 PREPARING(진행 중)을 인식/폴링하지 않고 total=null 을 그대로
  아래 `!d.total` 분기로 흘려 결과로 오판했다. COUNT-only 실행 경로는 window._execPlanRun 을 세우지
  않아(planFp 미설정) 위 두 조건이 모두 성립 → STALE_PLAN 으로 표시됐다.
  (GROUP BY 케이스는 클릭한 그룹의 total>0 이거나 소량 테이블이라 이 조건이 가려져 정상처럼 보였다 —
   즉 STALE_PLAN 이 COUNT-only 에서만 두드러진 이유.)

[오늘 고친 MATCH-KEY-PK-INDEX(dd455c0)와의 관계]
- dd455c0 는 '재이관 PK index 를 찾을 수 없습니다'(서버 재기동으로 store 소멸)를 `!d.ok`(에러) 경로에서
  1회 자동 재-prepare 로 복구한 수정이다.
- 이번 증상은 `d.ok===true` + status=PREPARING(진행 중) 경로라 dd455c0 의 복구 분기에 애초에 도달하지
  않는다. 태스크 가설대로 '다른 코드 경로'이며, 그래서 그 수정이 이 경로엔 적용되지 않았다.

[수정 내용 — 프론트 한 곳, 저장 설계·서버·오라클 경로 불변]
- ui/tabler_renderer.py _mvPkLoadPage: pk-records 응답이 status==='PREPARING' 이면 결과로 확정하지 말고
  "재이관 대상 준비 중… (현재 저장 N건 · 완료되면 자동 표시)" 안내를 그리고 1.5초 간격으로 재조회한다.
  · 그룹 오픈당 최대 200회(약 5분) 상한으로 무한 폴링 방지, 초과 시 '준비 지연' 안내로 폴백.
  · 패널을 닫으면 wrap(DOM) 부재로 다음 틱에 자동 종료(누수 없음).
  · PREPARING 응답은 캐시하지 않음. READY/EARLY_STOPPED 등 확정 상태에서만 기존 렌더 진행 + 폴링 카운터 정리.
- 저장(store) 설계·서버 라우트(agg_diff_route)·오라클 경로는 일절 변경하지 않음(표시/폴링만 보정).
