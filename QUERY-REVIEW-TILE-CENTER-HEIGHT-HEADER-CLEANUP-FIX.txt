■ 1. 배경과 요청 범위

직전 작업 QUERY-REVIEW-RESULT-TILE-LAYOUT-FIX 로 개별검증 1단계 '쿼리 검토 결과'가
Tabulator 그리드에서 9개 타일(카드) 레이아웃으로 바뀌었다. 그 결과물에 대한 미세조정
3건을 요청받았다.

  (1) 각 타일 위쪽 라벨 텍스트(목적테이블/원본테이블/입력컬럼수 등)를 좌측 정렬에서
      가운데 정렬로 변경. 단 박스(값 영역) 자체의 정렬은 그대로 유지.
  (2) 값 박스의 세로 높이를 기존 대비 20~30% 정도만 증가. 과도한 확대 금지.
  (3) '쿼리 검토 결과' 제목 옆 보조 설명 문구
      'FROM → 목적지 매핑 · JOIN · WHERE' 삭제. 제목 자체는 유지.

수정 대상 파일은 ui/tabler_renderer.py 한 개로 한정됐고, 실제 변경도 그 범위를
벗어나지 않았다.


■ 2. 수정 전 상태 실측 (before)

수정에 착수하기 전에 먼저 before 를 캡처했다. 과거 이 프로젝트에서 '수정을 먼저 하고
나중에 before 를 잡으려다 동시 세션 재기동으로 캡처 창이 사라진' 사고가 있었기 때문에,
실행 중인 서버(수정 전 모듈을 이미 메모리에 올린 상태 — web_server 는 reload=False 라
.py 편집이 자동 반영되지 않는다)를 그대로 두고 브라우저로 먼저 관측했다.

관측 경로는 실 DB 기반이다. 내부망 PostgreSQL 페어(PostgreSQL_Inter_asis →
PostgreSQL_Inter_tobe)에 실제로 접속하고, 개별검증 화면 1단계에 진입해 쿼리검토를
실행한 뒤의 화면을 쟀다.

  · 라벨 computed textAlign : start (좌측 정렬)
  · 라벨 텍스트 좌여백/우여백 : 0px / 71px  (좌측에 붙어 있음 — 값은 가운데라 축이 어긋남)
  · 값 박스 실제 높이        : 68px (9개 타일 전부 동일)
  · 값 박스 computed min-height : 68px
  · 값 박스 상/하 padding    : 10px / 10px
  · 카드 헤더 전체 텍스트    : "쿼리 검토 결과 FROM → 목적지 매핑 · JOIN · WHERE"
  · 헤더 보조 span 개수      : 1개 (class="text-muted ms-2")

즉 요청 3건 모두 '고쳐야 할 상태'임이 수치로 확인됐다.


■ 3. 수정 내용

ui/tabler_renderer.py 에서 CSS 2개 규칙과 HTML 1줄만 손봤다.

  (1) .mv-qr-tile-label 에 text-align:center 추가
      값은 이미 박스 안에서 가운데 정렬돼 있는데 라벨만 좌측이면 라벨과 값의 축이
      어긋나 보인다. 라벨을 박스와 같은 축으로 맞췄다.

  (2) .mv-qr-tile-box 의 min-height 68px → 85px, 상하 padding 10px → 13px
      요청받은 20~30% 범위 안에서 잡았다. 높이는 정확히 +25%, 상하 padding 은 +30%.
      값 글자 크기·굵기(1.05rem/700)는 건드리지 않았으므로 글자는 그대로이고 위아래
      여백만 늘어난다. 박스 폭·테두리·배경도 불변이다.

  (3) 카드 헤더의 보조 설명 span 제거
      <h3 class="card-title">쿼리 검토 결과</h3> 한 줄로 정리했다. 삭제 이유(타일
      라벨이 같은 정보를 항목별로 이미 표시하므로 중복 안내였다)는 HTML 주석으로
      남겼다. 제목 문자열 자체는 그대로다.

diff 규모는 10줄 추가 / 6줄 삭제이고, 그중 절반은 변경 사유를 적은 한글 주석이다.
값 계산 로직, 타일 렌더 함수(_mvQrTileHtml / _mvQueryReviewTilesHtml), 컬럼 정의
(_mvQueryReviewColumns)는 일절 건드리지 않았다.


■ 4. 수정 후 상태 실측 (after)

.py 편집은 실행 중 서버에 자동 반영되지 않으므로 서버를 재기동했다(기존 프로세스를
자식까지 종료 후 재시작). 재기동 후 서빙되는 HTML 을 직접 받아 CSS 가 실제로 바뀐 채
나가는지 먼저 확인하고, 같은 절차로 브라우저 관측을 반복했다.

  항목                    before        after
  ─────────────────────────────────────────────
  라벨 computed textAlign  start        center
  라벨 좌여백 / 우여백      0 / 71px     35 / 36px
  값 박스 실제 높이         68px         85px       (+25.0%)
  값 박스 min-height       68px         85px
  값 박스 상/하 padding     10 / 10px    13 / 13px
  헤더 보조문구 존재        True         False
  헤더 전체 텍스트          "쿼리 검토 결과 FROM → …"  →  "쿼리 검토 결과"
  헤더 보조 span 개수       1            0
  제목 '쿼리 검토 결과' 유지  True         True

라벨 가운데 정렬은 computed style 값만이 아니라 실제 렌더 위치로도 확인했다. Range 로
라벨 텍스트 노드의 렌더 영역을 재서 라벨 박스 좌우 끝과의 간격을 잰 결과, 9개 타일
전부 좌여백과 우여백 차이가 1px 이내로 대칭이었다(예: 목적테이블 35/36, 컬럼매핑수
35/35, 조인 53/52). before 는 전부 좌여백 0px 이었다.

요청 3건 모두 반영됐다.

■ 8. 남는 참고사항

삭제한 보조문구는 렌더 텍스트에서는 완전히 사라졌지만, 삭제 사유를 적은 HTML 주석
안에 문구 원문이 인용돼 있어 페이지 소스에는 문자열이 남는다. 화면에는 보이지 않고
이 프로젝트가 HTML 주석으로 변경 이력을 남기는 관행을 따른 것이지만, 만약 서빙되는
HTML 을 문자열 grep 으로 검사하는 절차가 있다면 이 한 곳이 걸린다는 점은 알고 있어야
한다. 실측 스냅샷은 innerText 기준이라 이 주석에 영향받지 않는다.
